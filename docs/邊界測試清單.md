# 邊界測試清單

上線前要**親手點過**的極端情境。

**這裡刻意沒有 happy path。** 正常的動線由 66 支端對端測試自動盯著
（`tests-e2e/`），人再點一遍沒有換到任何資訊。這一份列的是
**測試不容易做、而且踩中會留下壞資料**的那幾種 —— 大部分是
「不熟悉操作的人第一天會做的事」。

## 怎麼用這一份

每一條四欄：**怎麼做 → 預期行為 → 驗收標準 → 對到哪一條規則**。

- **驗收標準**寫的是「怎麼算過」。看不出來就是沒過 ——
  「應該沒問題吧」不算過。
- 在 **staging** 上做，不要在正式環境上做（怎麼分見 [STAGING.md](./STAGING.md)）。
- 踩到跟預期不一樣的，記到 `.scratch/` 開一支 issue，格式見
  `docs/agents/issue-tracker.md`。

## A. 連點與競態

一個人在手機上會做的第一件事：**沒反應就再按一次**。

| # | 怎麼做 | 預期行為 | 驗收標準 |
|---|---|---|---|
| A1 | 「問這輪的時間」→ 對同一位客戶**連按兩下**「產生連結」 | 只產生**一條** | 設定 → 稽核紀錄裡只有一筆 `create`；那一位客戶只出現一張訊息卡 |
| A2 | 「依客戶」抽屜裡**連點兩下**同一張待辦 | 只寫一次 | 那一列只變一次（勾起來就停住，不會勾起來又彈回去）；稽核紀錄只有一筆 |
| A3 | 壓表的記錄面板**連按兩下**「加這一筆」 | 只有一筆來訪 | 日曆上那一天只有一段，不是兩段 |
| A4 | 兩台裝置（或兩個分頁）**同時**勾同一張待辦 | 兩邊最後都是「已完成」 | 重新整理兩邊，狀態一致；不會一邊勾起來一邊反勾 |
| A5 | 加購那張表**連按兩下**送出 | 只加一筆額度 | 客戶詳情那一排卡片沒有兩張一模一樣的 |
| A6 | 「簽療程單」的收尾面板連按兩下送出 | 次數只扣一次 | 客戶詳情的「已完成」只 +1 |
| A7 | 表單那一頁（客戶端）連按兩下「送出」 | 只有一份答案 | 收件匣裡只有一筆 |

> 對到的規則：`toast.withSaveState()` 的 `key`（防連點），
> `tests/save-guards.test.js` 會掃出漏傳的地方。

## B. 日期的邊界

這一組全部要靠**改裝置的日期**或**挑遠一點的月份**才碰得到。

| # | 怎麼做 | 預期行為 | 驗收標準 |
|---|---|---|---|
| B1 | 客戶詳情 → 不能的時間 → 記一次 → **選這個月**（不是下個月） | 記得下去 | 「新增」那一排的第一顆就是**當月**；存完之後壓當月的表用得到它 |
| B2 | 在**已經過去的日期**上記一筆隨手記 | 記得下去 | 日曆上那一天看得到它，字是變色的，但**不進「逾期」那顆數字** |
| B3 | 8/31 排一筆、9/1 排一筆，然後去壓 9 月的表 | 各自吃到各自那個月的「不能的時間」 | 卡片上那一塊的抬頭寫著「9月不能的時間」；如果九月沒問過，寫的是「還沒問9月的時間」而**不是拿八月那份硬算** |
| B4 | 月底最後一天發出的表單連結，**隔天**再打開 | 還打得開（刻意寬鬆） | 客戶那一頁正常顯示，不是「這個連結找不到」 |
| B5 | 表單連結放到**下下個月**再打開 | 打不開 | 顯示「這個連結已經過期」之類的訊息，而不是一片空白 |
| B6 | 日曆翻到 **2/29**（閏年）與 **12/31** | 兩天都畫得出來、點得下去 | 格子在、點下去抽屜出得來 |
| B7 | 「問這輪的時間」從 1 月往前一格 | 換到**上一年的 12 月** | 抬頭寫著 12 月，名單跟著換 |
| B8 | 死線跨月：來訪排在 **9/1**，任務的死線應該是 **8/31** | 死線是來訪日的**前一天** | 那一列寫的是 8/31，不是 9/1 也不是 9/2 |
| B9 | 跨過午夜（把裝置時間調到隔天）再打開 app | 「今天／明天」那兩顆數字跟著換 | 昨天的「今天」變成「逾期」 |

## C. n返（三返、四返…）

這是這一輪新的東西，一筆舊資料都沒有，所以每一條都要點過。

| # | 怎麼做 | 預期行為 | 驗收標準 |
|---|---|---|---|
| C1 | 一位**還沒有任何健檢**的客戶，去壓表看那一排 | 「＋ n返」**整顆不出現** | 不是灰掉按不下去，是根本沒有那一顆 |
| C2 | 健檢**排了但還沒結案**的客戶，選「＋ n返」 | 講出來為什麼沒有候選 | 「這是哪一次健檢的」底下寫著「還沒有做完的健檢可以接」，**不是一片空白** |
| C3 | 同一次健檢**連續加三場** | 返數預設一路變成三、四、五返 | 每次點開「＋ n返」，被按下去的那一顆往後跳一格 |
| C4 | 同一次健檢加**兩場三返** | 只**提醒不擋** | 存檔前的警告寫著「這一次健檢的三返已經約在 X 了」，而且**存得下去** |
| C5 | 加了三返之後，回客戶詳情看次數 | **一個數字都沒有變** | 健檢與二返兩張卡上的「剩 N」跟加之前一模一樣 |
| C6 | 加了三返之後，去看那位客戶的「約二返」待辦 | **完全沒有被影響** | 該在的還在、該收的收了，跟加之前一樣 |
| C7 | 加了三返之後，**把那一次健檢取消掉** | 資料健檢看得見這件事 | 設定 → 資料健檢列出那個孤兒（三返指到一筆不再是「已完成」的健檢） |
| C8 | **一位什麼次數都用完**的客戶，加一場三返 | 走日曆那條路加得了 | 壓表牆上沒有他（正常）；日曆 → 那一天 → ＋ → 新增來訪 → 選他 → 選得到「＋ n返」 |
| C9 | 選了「＋ n返」之後**改回一般的額度** | 返數要被清乾淨 | 存進去的那一段**沒有** `followupNth`；不會跳出「不可以同時指定額度」 |
| C10 | 同一天同一筆來訪裡放**二返＋三返** | 兩段都存得下去、各自正確 | 二返扣了一次額度，三返一次都沒扣 |
| C11 | 加了三返之後看試算表 | 接在那一次健檢的欄位底下，**同一格兩行** | `8/8 二返(醫師甲)` 換行 `9/20 三返(醫師乙)`；矩陣**沒有多一列** |
| C12 | 三返的醫師先不選，存起來 | 存得下去，只提醒 | 試算表上印 `9/20 三返()` —— 空括號代表「約了但醫師還沒定」 |

## D. 網路與離線

打開 DevTools 的 Network → Offline，或者直接開飛航模式。

| # | 怎麼做 | 預期行為 | 驗收標準 |
|---|---|---|---|
| D1 | 離線狀態下勾一張待辦 | 八秒後換一句話 | 那句話**不可以有「失敗」兩個字** —— 資料已經在本機了，說失敗你會再存一次 |
| D2 | 離線狀態下在抽屜裡勾三筆，然後恢復連線 | 三筆都送出去了 | 重新整理之後三筆都還是「已完成」 |
| D3 | 離線狀態下打開 app（冷啟動） | 畫面畫得出來 | 不是白屏；最上面有一條常駐的離線提示 |
| D4 | 弱網（DevTools → Slow 3G）切換「問這輪的時間」的月份 | 不會出現半份名單 | 要嘛還在載入，要嘛整份換好，不會一半是上個月一半是這個月 |
| D5 | 弱網下按「產生連結」，在轉圈的時候**再按一次** | 只產生一條 | 同 A1 |
| D6 | 離線 → 勾一筆 → **直接關掉 app** → 恢復連線 → 重開 | 那一筆有送出去 | 待辦上那一筆是「已完成」 |

## E. 資料看起來壞掉的時候

這一組模擬「主檔被動過」與「資料是舊的」，都是真的發生過的形狀。

| # | 怎麼做 | 預期行為 | 驗收標準 |
|---|---|---|---|
| E1 | 設定 → 課程主檔停用一個**已經被排過**的課程 | 用過它的客戶**不會從清單上消失** | 「壓表登記」那一頁照樣列得到他；日曆上舊的那幾筆照樣印得出課程名 |
| E2 | 刪掉一筆**已經被來訪用到**的額度 | 資料健檢列出孤兒 | 設定 → 資料健檢 → 看得到「這個時段指向的額度已被刪除」 |
| E3 | 客戶**填完表單之後**才重發一條新連結 | 舊的那份答案還在收件匣 | 「客戶填好的時間」看得到那一份；新連結那一位在「等待回覆」 |
| E4 | 同一位客戶同一個月**兩份**「不能的時間」（拿舊資料） | 資料健檢列出來，**不自動合併** | 兩份的摘要都看得到，你自己刪掉不要的那一份 |
| E5 | 把一位客戶**停用** | 他從壓表牆與「問這輪的時間」消失 | 客戶總覽的「看已停用的」找得回來；他既有的來訪還在日曆上 |
| E6 | 一筆**匯入的舊來訪**（沒有時間、沒有器材） | 存得回去 | 打開來訪編輯器改一個欄位、按儲存，不會被「時間格式不對」擋住 |
| E7 | 額度的計數欄位手動改壞（或拿有問題的舊資料） | 對帳列出差異 | 設定 → 資料健檢 → 次數對帳看得到；按「修正」之後兩邊一致，而且稽核紀錄有一筆 |
| E8 | 有**醫療禁忌**（例：體內金屬）的客戶，排一段用超磁場的復能 | **硬性擋下來** | 那顆器材丸子是劃掉的、按不下去；這是全系統唯一真的會擋你的地方 |

## F. 反覆與收尾

| # | 怎麼做 | 預期行為 | 驗收標準 |
|---|---|---|---|
| F1 | 勾掉「追蹤健檢報告」→ 到「已完成」把它**拿回來** | 退回上一站 | 「約二返」跟著收起來，「追蹤健檢報告」回到未完成 —— **不是把它刪掉** |
| F2 | 「依客戶」抽屜裡勾一筆 → **往下甩掉抽屜** → 再點開同一位 | 狀態是對的 | 那一筆還是勾掉的（在抽屜裡劃著線），底下卡片的數字也對 |
| F3 | 抽屜開著的時候按**手機的返回鍵** | 關掉抽屜，**不換頁** | 還在待辦中心，而且還在「依客戶」那一格 |
| F4 | 客戶詳情按「編輯」，打到一半按返回鍵 | 回到那個人的詳情頁 | **不是整個離開這位客戶** |
| F5 | 取消一筆**已經去 Examine 掛過號**的來訪 | 產生一張「取消 Examine」 | 待辦的「改時間／取消」那一段看得到它 |
| F6 | 一次清掉「已完成」的十幾筆 | 二次確認，講出筆數 | 確認框寫著「清掉 N 筆」與「還原得回來」；清完之後設定 → 已刪除項目找得回來 |
| F7 | 收工前開「看今天做了什麼」 | 今天做的每一件都在 | 兩種分組（照人／照流程）切換之後，**兩邊的筆數一樣** —— 一則都不可以被丟掉 |

## G. 上線前最後一次

這幾條是每次要推上正式環境之前跑一遍的，不是每天做的。

- [ ] `npm test`（單元與靜態守衛）全綠
- [ ] `npm run test:rules`（Security Rules 跑在模擬器上）全綠
- [ ] `npm run test:e2e`（66 支端對端，約二十幾分鐘）全綠
- [ ] 在 **staging** 上把上面 A–F 每一組至少各挑兩條點過
- [ ] 備份**還原過一次**（不是只有匯出，是真的還原回去看資料在不在）——
      做法見 [STAGING.md](./STAGING.md)
- [ ] 試算表那一側的指令碼版本對得上（推一次，看試算表真的動了）
- [ ] 手機上冷啟動一次（第一次開、沒有快取）
- [ ] 深色模式下把每一頁掃一遍（有沒有哪一塊還是淺的）
