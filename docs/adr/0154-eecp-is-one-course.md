## 背景

「EECP體驗」是她自己要的第二門課，三次改動疊起來：課程名裡有「體驗」、`slotName()` 又替體驗的段接一次 `(體驗)` →
`EECP體驗(20)(體驗)`。她 10/18：

> 5. 如圖5，EECP只有一個EECP 不用EECP 體驗
> 應該要是這樣，EECP可以選60 20，以及可以選體驗/送的
> 目前似乎可以變成EECP體驗（體驗）？有點多餘
> 所以只要留一個EECP就好，預設是60分鐘 ，不選體驗/送的，然後如果選20就預設是體驗這樣可以嗎

> 5. 你說「EECP體驗」那一門停用、不刪 … 我希望他直接不要誒 … 不要在靠資料健檢處理，一開始匯入時就應該是好的

> 2. 已經存成「EECP體驗」的舊來訪，要不要改成「EECP、20 分、體驗」ans : 要，但我希望如同我最上面說的，除了資料健檢多一列之外我希望下次我再匯入的時候就是最新的了

## 決定

**種子上只留一門 EECP**：約的時候選 20／60（`bookingMinutes`，ADR-0122）、預設 60、不是預設體驗。「EECP體驗」那一門**刪掉、不留停用的**。

**課程多一格「體驗的時候排幾分」**（`course.trialMinutes`，設定 → 課程 →「其他設定」；EECP 填 20）。讀只有 `masterData.js` 的 `trialMinutesOf()`，
「這個分鐘是不是體驗」只有 `isTrialMinutes()`。不寫死 EECP：之後別門課要一樣的行為她自己填。存得下去要：

- 可以當體驗的課（`canBeGift()`：健檢、二返除外）
- 在那門課體驗時按得到的時長裡（約的時候選的＋買的時候分的，`minuteChoicesFor()`）
- **不等於預設時長** —— 等於的話，她重按一下預選好的那一顆就把一段扣額度的變成體驗

**時長**：`slotMinutes()` 的順序變成 **這一段選的 → 體驗的時候排幾分 → 品項 → 額度 → 課程 → 60**（第二層只看送的／體驗的段）。
體驗沒選就是 20；她按了 60 就是 60（第一層）。每一個呼叫端都把 `giftKind` 交下去（表在 `.scratch/staging-polish-2026-10-18/issues/09` 的「做完時留下的」）。

**20 ⇔ 體驗**（她：「選20就預設是體驗」）：扣著那門課額度的段，在「排多久」按了「體驗的時候排幾分」→ 那一段換成那門課的體驗
（`entitlementId: null`、`giftKind: 'trial'`），選擇跳到「送的／體驗…」那一顆。**三個入口同一支** `slotOptions.js` 的 `trialFromMinutes()`：
壓表（`[data-minutes]`）、來訪編輯器（`readDraft()`）、拍 Abovee 的確認層（`pickMinutes()`）。

- **反過來不自動**：體驗的段按 60 照樣是體驗 60；要扣額度她按那一顆額度，時長回到預設（跟「換了額度要重設」同一個時機）
- 「送的／體驗…」裡按 EECP → 20 分、體驗（她：「選體驗 → 預設 20」）
- 有「體驗的時候排幾分」的課排在「送的／體驗…」展開之後的**第一排**（她最常約的體驗就是它），那一顆的時長寫 20。
  沒有額度的新的一段照舊預設功醫門診（`defaultGiftCourse()` 只挑預設體驗的課 —— EECP 正式課要扣，不拿它當預設）

**名字**：扣額度的 EECP 現在是 `EECP(60)`（一門課有兩種長度時那個數字才有資訊，同 `二返(60)`，ADR-0122）、體驗的是 `EECP(20)(體驗)`；
貼給客人的那一句照舊不帶。試算表那一列「EECP（體驗）」不因為時長分成兩列（`kindOf()` 照課程＋種類）。

## 拍 Abovee

- **`EECP20` → EECP、20 分、體驗**：不再是一個寫法（整格比對會搶走、拆不到分鐘），拆成「EECP＋20 分」，20 ＝ 體驗的時候排幾分 → 那門課的體驗，
  不看身上有沒有額度（同 ADR-0148 的預約來源「體驗」）。預約來源寫「正式課」的 `EECP20` 一樣是體驗（她 10/5：「EECP20 就是 EECP 體驗」）。
  `EECP60`、`EECP` → 正式課。她自己把一列 `EECP20` 換回扣額度：那一列多一句（`trialSay()`，收著也看得到）
- **app 上已經有那一段、扣法不一樣 → 要改的**（照 ADR-0149「照片為準」）。以前 `EECP20` 是另一門課、永遠配不上 app 上的 EECP 60；
  合成一門之後同一個時間、同一門課 —— 不比的話被認成安安靜靜的「已經記了」，**那一段照舊扣額度**：
  - 照片是體驗（預約來源寫體驗，或分鐘＝體驗的時候排幾分）、app 那一段扣著額度 → 「改成體驗 20 分，不扣（還 1 次）」一行、預設勾
  - 照片清楚是正式課（那門課有「體驗的時候排幾分」、照片上的分鐘寫著別的：`EECP60`）、app 那一段是體驗或送的 → 「改成扣『EECP』、60 分（扣 1 次）」：
    扣哪一筆照新的那一列挑額度那一套（只看還有剩的）；挑不出來不先勾、講為什麼
  - 已完成的鎖著：只提醒（「要你看」），要改去日曆解鎖
  - 別的課沒拍到預約來源那一欄看不出是不是體驗 —— 照舊不比
  - 套上去（`applyPhotoCharge()`）只動那一段的扣法與時長（`entitlementId`、`giftKind`、`minutes`、`endsAt`），狀態、開始時間、診間一格都不碰；
    寫之前比對她看到的那一份。次數的括號照樣讀計畫的 `rows`，確認框那一句「照 Abovee 改成體驗、不扣次數 N 段（還 N 次）」
  - **改了時間又改了扣法**（2026-10-19 補，她：「做，照你的建議」）：Abovee 上把 10:00 的 EECP 60 改到 11:00 又改成 `EECP20` ——
    拿得準的改期那一對也比扣法，同一列兩行（改期、扣法），扣法的勾跟著改期（改期沒先勾就不先勾：只改扣法不搬，對不上照片上任何一列）。
    新的那一段的時長照扣法套過之後的那一段（體驗 20），不照讀照片那一刻的 60

## 來訪編輯器把一段既有的從扣額度改成體驗（或反過來）：原地改

她 10/18 選的（兩種做法給她選：原地改、或當成改課程走 ADR-0108 的取消＋重新排）：

> the confirm dialog says "This slot becomes a trial, no package charge — remember to change it to EECP20 in Abovee too."

開始時間與課程都沒變，所以**不是改期**：不取消、不長「取消 Abovee」、不退回待確認。存檔前多一道確認（`consequences.js` 的 `chargeSwitchConsequences()`）：
那一段改成什麼、不扣哪一筆（還幾次 —— 拿 `counts()` 試算前後的差，ADR-0070）、「Abovee 上記得改成 EECP20」（別的課是「預約來源改成體驗」）。

## 舊資料

**正路是合併檔一開始就對**（staging-polish 11：`EECP體驗` → EECP＋體驗、合併檔升 v8；staging 合進去之後 `npm run staging:reset` 重匯）。
資料健檢最後一項「『EECP體驗』那一門還在」是保險（她：「除了資料健檢多一列之外」）：

- 指著那一門、沒扣額度的段 → EECP 的體驗、20 分、名字快照照 EECP，**狀態不動**
- 那一門身上有額度、或有段扣著額度 → 只列不修（那是當初買的，要變成什麼她決定）
- 沒有東西擋著 → 同一顆按鈕把那幾段改好、接著刪掉那一門（軟刪除）
- 主檔上的 EECP 還沒有「體驗的時候排幾分」→ 先按「主檔有幾格還沒跟上」（約的時候選時長與體驗排幾分**同一列一起補** —— 分開按的話課程存不回去）

## 判準

> **這一行會不會讓一段體驗被算進 EECP 的額度，或反過來？**

（ADR-0148 那一句的延伸。）以前靠「兩門課」自然擋著的，現在每一條路各一個測試：三個入口按 20、拍 Abovee 讀 `EECP20`、拍 Abovee 對上扣法不一樣的既有段、
來訪編輯器原地改、候選補的那一段（`tests/eecp-one-course.test.js`、E2E `72`）。

## 後果

- 月曆與讀取卡片上每一段扣額度的 EECP 會從「EECP」變成「EECP(60)」
- 「體驗的時候排幾分」是課程上的一格：她之後可以替別門課填（IN 30 體驗那種本來就是買的時候分的，不用填）
- 拍 Abovee 的「要改的」那一塊多一種（扣法）；同一列又要改狀態時，次數分開算、不重複
- 兩張照片同一個時間一張寫 `EECP20`、一張寫 `EECP60`：現在是同一門課，被當成「看起來是同一段」（`flagRepeats()`）—— 只留一列先勾，不會記兩段（她 2026-10-19：「照這樣記」）
