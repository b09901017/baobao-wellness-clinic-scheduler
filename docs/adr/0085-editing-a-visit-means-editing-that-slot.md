# ADR-0085：改一筆來訪，就是改她點的那一段

日期：2026-09-09
狀態：已接受
延伸：[ADR-0080](./0080-a-read-card-draws-the-slot-she-tapped.md)（點一段，
讀取卡片就只畫那一段）—— 這一支把同一條線延伸到編輯器與抬頭。

## 背景

她 2026-09-08，在 ADR-0080 把讀取卡片改成只畫一段之後：

> 如果我要修改某一筆來訪，就請讓我只能修改這一個時段的東西，而不是讓我
> 還可以新增還可以修其他時段的東西。

2026-09-09 再確認了一次，並且補上一句：

> 我也根本不需要知道這天還有另外多少個時段，不需要。

## 每一條路本來就知道是哪一段

清查過所有進得了編輯器的路：

| 入口 | 帶得到 `slotIndex`？ |
|---|---|
| 日／週那一列點一下 → 讀取卡片 → 鉛筆 | ✅ `visit:<id>:<第幾段>`（ADR-0080） |
| 抽屜那一列點一下 → 讀取卡片 → 鉛筆 | ✅ 同上 |
| 長按 → 「改這一筆」 | ✅ `runVisitAction()` 收得到 |
| 月檢視的色條 | 不可點（點的是那一天，開抽屜） |
| 客戶詳情／待辦中心／進度追蹤 | **沒有鉛筆**（ADR-0056） |

**只是進去之後把那個數字丟掉了。**

## 決定

**一、`mountEdit()` 收一個選填的 `slotIndex`。**

帶了就只畫那一段、沒有「＋新增一個時段」、沒有整筆的狀態卡與危險區。
沒帶就照舊全部 —— 網址那條路（`renderEdit()`）沒有段落資訊，
畫成空的比畫太多糟（同 `slotsToShow()` 的兩條退路）。

**二、沒畫出來的那一段整個回原本那一個物件。**

`readDraft()` 底下那一段是靠 `key()` 保留原值的（欄位沒畫出來時
`v[...]` 是 `undefined`）—— **但那只保護得了列得出名字的欄位**。
那一段身上還有 `attended`、`status`、`followupNth` 這些沒有欄位的格子，
它們會被 `...slot` 帶過去，卻擋不住底下那幾行寫死的 `null`。
所以是 `if (!isEditable(ctx, i)) return slot;`，不是「小心地重組一份一樣的」。

**三、整筆的那幾顆只在整筆都在畫面上時出現。**

她點一段進來改，看到「取消這一筆來訪」是講不通的 —— 那一顆動的是那一天
全部。整筆的狀態仍然改得動，路在日曆上長按那一列（ADR-0056、0060）。

**四、新增那條路不受影響。**

日曆的「＋新增一個時段」留著、壓表記完一段接著記下一段也留著。
她 2026-09-09：「新增的時候不論是在壓表還是日曆這邊新增，我希望一樣可以
一次新增多筆多個時段。」

**五、抬頭印那一段的狀態（`statusForCard()`）。**

資料從 ADR-0081 起就逐段了，但讀取卡片與長按選單的抬頭還在印整筆那一個。
那個落差**是真的會發生的**：加兩段沒問過客人的進去，整筆就退回「待確認」
（`visitStatusFrom()`），而她點的可能是早上那段已經談定的。

**六、「第 2 段（共 5 段）」的後半拿掉。**

她說不需要知道那天還有幾段。**但「取消一整天（5 段）」那個數字留著** ——
那不是資訊，是煞車：要按的是真的會取消五段的按鈕（ADR-0070）。
她 2026-09-09 明確同意這條界線。

**七、掛號那幾張標「這一天共用」。**

任務綁的是一整筆來訪（掛號是一天去一次，`tasksForVisit()` 的去重），
所以同一張會出現在那幾段的卡片上，勾掉一次兩邊都掉。
**只在那一天真的不只一段活著時標** —— 每一次都寫等於把那一行變成裝飾。

## 後果

- `summaryByDate()` 的 `pending` 改成逐段數。月檢視底下畫的是一段一條色條，
  頂端寫「1 待確認」而底下兩條琥珀色是兩種單位混用。
- **只畫一段時那一段身上沒有 ×**：`slotXButton()` 的規矩是「只有一段時不給」，
  而她看到的就是一段。取消走底下的狀態卡或長按選單，那裡問得比較清楚。
