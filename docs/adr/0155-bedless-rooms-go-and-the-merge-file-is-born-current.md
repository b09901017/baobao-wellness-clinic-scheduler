# ADR-0155：沒寫哪一床的點滴8、VIP7 拿掉；合併檔一開始就是新的

日期：2026-10-18
狀態：已接受
推翻（舊的一個字都不改）：

- [ADR-0127](./0127-bed-rooms-are-rooms.md)「點滴8 與 VIP7 留著、停用：它們是『沒選床位』的那一間」那一段，
  連同它的「拍 Abovee 那一格沒寫床認成它」「舊行事曆只寫 `.8` 照舊對到點滴8」。8A／8B、7A／7B 是四間各自的診間 —— **照舊**

延伸：[ADR-0154](./0154-eecp-is-one-course.md)（同一次她說的：「EECP體驗」那一門也是直接刪、合併檔一開始就對）、
[ADR-0079](./0079-the-equipment-decides-who-and-the-rooms-have-no-four.md)（沒有床位這一層 —— 照舊）。

## 背景

ADR-0127（10/6）把點滴8、VIP7 留在種子上、停用：她那一句「沒選床位就寫 .8，VIP7 等等不要留空」要成立，
主檔上就得有一筆叫「點滴8」的東西 —— 舊來訪印診間、Abovee 那一格沒寫床、舊行事曆只寫 `.8`，三條路都靠它。

10/18 談 EECP 合成一門時，那一門的打算也是「停用不刪，舊的來訪還指著它」。她回：

> 你說「EECP體驗」那一門停用、不刪 … 我希望他直接不要誒，你說舊的來訪還指著它，但能不能幫我去改合併檔就好，
> 反正現在我也還沒有真的開始使用，隨時都可以清空重來，沒有舊的之分，我要匯入時是新的就好，
> 包含你說的點滴8，vip7還多少，一樣，沒有舊資料的問題，刪掉之後幫我合併檔更新就好
>
> 不要在靠資料健檢處理，一開始匯入時就應該是好的，

查過（10/18，只數數字）：她 10/17 那一份合併檔一段沒床位的點滴8、VIP7 都沒有（只有 8A／8B／7A／7B）；
Abovee 5–10 月 353 列的點滴8 每一列都寫著床 A 或床 B。

## 決定

**種子上刪掉 `room-iv8`、`room-vip7`，不留停用的。** 排得到的照舊 22 間；種子上一列停用的都沒有了
（`seedData()` 那一套留著 —— 哪天又有一列停用的才不會一載入就選得到）。

**只寫點滴8、沒寫哪一床的 → 診間留空，講一句請她選。** 猜 8A 還是 8B 都是替她決定，而那兩間各排一位、撞期照各自算。

- **拍 Abovee**：`點滴室8`、`4樓休7` 認診間的四步都對不到 → 空著（`abovee.js` 的 `roomByText()` 一個字都沒改，改的是註解）。
  那一列收著也看得到「照片上寫『點滴室8』，沒寫哪一床 —— 點開選一間」（`bedMissingIn()` 判，句子在 `aboveeImport.js` 的 `nearSay()`）；
  她選了一間那一句就不講了。不擋：診間空著的段本來就存得下去（「還沒選診間」那一句照舊）
- **合併檔**：`merge.mjs` 的 `roomOf()` 對只寫 `.8` 的回 `null`（`.8A`、`點滴8床B` 照舊是那一間），
  報告的摘要多一行「沒寫哪一床的點滴8　N 段」（`bedlessSlots()`；沒有這種段時報告一個字都不變）。
  那一行只是數字、不是要她決定的一項，決定頁不多一種
- 名字照舊**照名字認**（`masterData.js` 的 `bedRoomOf()`／`isBedlessOf()`）：「拆成 A／B 的那一間」不用在主檔上，
  `{ name: '點滴8' }` 問得出 8A —— 合併檔與拍 Abovee 都這樣問

**她的主檔上還有那兩間（或她自己又建了一間「點滴8」）時，那一間照舊認得**：`roomByText()` 第 3、4 步比的是她主檔上的名字，
來訪編輯器的 `keep`、拍 Abovee「app 是 8A、照片沒寫床不算不一樣」那幾條都留著 —— 它們問的是主檔，不是種子。

## 還留著那兩間的資料庫（保險，不是正路）

正路是 staging 合進去之後 `npm run staging:reset` 重匯合併檔。資料健檢「診間清單跟建議的不一樣」那一項多認一份名單
（`health.js` 的 `BEDLESS_ROOMS`，只認種子那兩個 id、名字沒改過的）：

| 那一間 | 做什麼 |
|---|---|
| 沒有任何一段排在它上面（刪掉的來訪不算） | **刪掉**（軟刪除，「已刪除項目」還原得回來）。確認框不講「排在那一間的來訪印不出診間」—— 一段都沒有 |
| 有段排在上面、她還開著（10/6 之前的資料庫） | **停用**（ADR-0127 那一條照舊）：新排的選不到，那幾段照樣印得出 `.8` |
| 有段排在上面、已經停用 | 不報：沒有要做的事（已完成的那幾段診間也改不了），報了就是一列按不掉的提醒 |

「來訪上還記著床位」（`moveBedToRoom`）照舊：點滴8 床 A 的段搬到 8A 之後，點滴8 上一段都沒有了，下一次就是「刪掉」。
沒有另開一項：這兩間本來就是那一項在管的（以前叫它停用），新的一項只會把同一件事拆成兩列。

## 合併檔一開始就是新的：`baobao-merge/v8`

她同一句的後半是「刪掉之後幫我合併檔更新就好」—— 種子刪了「EECP體驗」那一門（ADR-0154）、刪了點滴8，合併檔就要一開始寫對，
不靠資料健檢事後搬。

- **行事曆寫「EECP體驗」→ EECP 的體驗**：`merge.mjs` 的 `TOKENS` 那一條多第四格（`giftKind: 'trial'`），課程寫 EECP。
  時長照種子上 EECP 的「體驗的時候排幾分」（20）—— `endOf()` 跟 app 的 `slotMinutes()` 同一個順序：她的決定寫了幾分 → 體驗的時候排幾分 → 品項 → 額度 → 課程 → 60
- **那個 token 不吃舊表 EECP 那一格的勾**（`sameSlot()`）：以前兩門課自然配不上；合成一門之後配上的話，那一天的體驗會被當成扣額度的那一次，
  而舊表那一格勾著的正式課安靜地沒了配對。一邊是送的／體驗、另一邊不是的不配，照舊各自進報告
- **候選也帶 `giftKind`**：`futureVisits`／`missingFromSheet` 只帶課程，app 的 `addExtraVisits()` 照課程判扣不扣 —— 課程寫成 EECP 之後，
  她勾一筆體驗的候選會扣掉那位唯一一筆 EECP 額度。所以候選送的／體驗的那幾筆帶 `giftKind`（一般的沒有這個鍵，同段），app 照它不扣任何一筆、健檢與二返除外。
  **這是新欄位，所以升 v8**：只加欄位不升版的話，v7 的 app 會安靜地照課程扣。v1～v7 照收（沒有那一格的照舊照課程推）
- **決定檔還寫著舊的課名**（「加一段」的 `course: 'EECP體驗'`）照 `TOKENS` 認成 EECP 的體驗（`renamedCourse()`）；指名一門主檔沒有的課進 ⓪d，講得出是哪一門
- **舊表有一列叫「EECP體驗」**：不猜它是什麼（買的是 EECP 的次數？送的？），那一列不匯、⓪b 講它合成進 EECP 了 —— 以前那一句叫她「先去主檔把課程建起來」，對這一門是錯的。
  她的舊表 10/18 數過一列都沒有（「EECP體驗」只在第 14 列當註記出現，那一條照舊）

## 後果

- 匯進來的段一段都不會落在點滴8、VIP7；月曆上不會再出現 `.8`、`vip7`（只剩她主檔上還有那兩間的資料庫）
- `capacity: 2` 那一筆跟著點滴8 一起沒了 —— ADR-0094 的機制留著，種子上沒有一間填它
- 拍 Abovee 的確認層、合併檔那一行都只是退路：她的資料裡現在一段都沒有
- 合併檔升 `baobao-merge/v8`：**正式站要先是這一版才收得下這一份**（舊版的 app 整份拒收，不會安靜地吃掉候選那一格）
