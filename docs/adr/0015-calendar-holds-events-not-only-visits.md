# 日曆放的是行程，來訪只是其中一種

SPEC 第 4.9 節說 TimeTree 可以退場，但第 8.6 節的日曆只畫得出來訪。她 TimeTree 上實際
記的東西比來訪多得多：休假、公出、顧客會、生日、要聯絡誰。那些沒有客戶、沒有課程、
沒有額度，卻和來訪擠在同一週裡决定她那天走不走得開。日曆少了它們，
她就得同時開兩個 app，而那正是這一頁要取消掉的事。

所以新增一個 `events` 集合：標題、分類（自訂，各自一個顏色）、起訖（支援跨天與全天）、
地點、備註，以及一個**選填**的客戶關聯。**來訪不搬進去** —— 來訪有狀態機、額度、任務、
稽核，那些一個通用行程扛不起來。日曆頁把兩種東西畫在同一格裡，來訪一律用主色系、
一般行程用它自己的分類色，點下去各自回到自己的編輯畫面。

不做 TimeTree 的共享成員。她現在的三本日曆有一本是給家人的，那需要多帳號與共享權限，
是第 12 步的事；在那之前分類只是她自己的分類。

## Consequences

`firestore.rules` 要為 `events` 開一個洞（預設全拒），`firestore.indexes.json` 要補
「依起訖日期排序」的索引；跨天事件要能被「這一週有哪些事」查到，所以查詢用
`startsAt <= 週末 && endsAt >= 週初`，兩個欄位都要索引。

行程與來訪同樣不硬刪除、同樣寫稽核（SPEC 第 6.1、6.2 節）—— 誤刪一筆「9/20 出國」
跟誤刪一筆來訪一樣痛。

月檢視因此要在手機上也打開（SPEC 第 8.6 節原本只給 iPad）。理由變了：一格裡要塞的
不再是客戶名字，而是「那天有沒有事、是什麼顏色的事」，那件事在 55px 寬的格子裡看得出來。
需要看是誰，點下去就有當天的清單。
