# ADR-0093：已經發生的那一筆匯進來，一張任務都不長

日期：2026-09-16
狀態：已接受
延伸：ADR-0066（紀錄是來訪之後才出生的任務）、ADR-0027（登記任務等客人確認）、
ADR-0029（匯進來的來訪依匯入當下的日期決定狀態）

## 背景

2026-09-16 上線前健檢拿她那份 `import.json` 整份模擬了一次匯入：
`countNewTasks()` 回 **18**，而那 18 張**全部是「寫紀錄」、全部掛在已經發生的
來訪上**（9 張二返 ＋ 9 張復健科醫師門診），死線 5/21 到 9/15 ——
**逾期 18、今天到期 0、未來 0**。

而匯入那一頁印的是相反的話：

> 還沒發生的那幾筆會產生 18 筆登記待辦；已經發生的一筆都不會長

`SPEC.md` 第 6.10 節與 `data/legacyImport.js` 的檔頭也都寫著「已經發生的那些
一筆都不長」。那兩句是 2026-09-04 加「寫紀錄」（ADR-0066）**之前**寫的，
而匯入這條路沒有跟上：

- `data/legacyImport.js` 對每一筆跑 `syncTasksForVisit(visit, [], …)`
- `domain/taskRules.js`：`if (t.kind === RECORD_TASK_KIND || acceptsNewTasks(visit.status))`
  —— **紀錄那一族刻意不走 `acceptsNewTasks()`**（那是 ADR-0066 的重點），
  而匯入的過去來訪是 `done`，`acceptsRecordTasks('done')` 是開的

她 2026-09-16：

> 對於未來的要長，對於過去的如果不會有問題的話就不長，或是當已完成，都可以，
> 但是對於未來發生的還沒到的都要長

## 決定

**匯進來的來訪，已經發生的那一筆一張任務都不長；還沒發生的照舊。**

規則只在 `domain/taskRules.js` 的 `importedTasksFor()`，兩個呼叫端共用：
寫入端 `data/legacyImport.js` 的 `importPlan()`，與匯入頁那個數字
`domain/mergeImport.js` 的 `countNewTasks()`。

**「已經發生了嗎」不在那一支裡判斷。** 那是 `domain/mergeImport.js` 的
`statusFor()` 的工作（ADR-0029），而它的答案就寫在 `visit.status` 上：
`done` ＝ 已經發生、`confirmed` ＝ 還沒發生。

## 為什麼

**這條規則是「已經發生了嗎」，不是「濾掉寫紀錄那一種」。**

掛號那一族本來就被 `acceptsNewTasks()` 擋著，所以今天看起來只有紀錄那一族
受影響。照種類寫一份濾法，**下一種任務長出來的那天會漏掉它**，而症狀跟這一次
一模一樣：一批一出生就逾期的紅字，加上一句講反了的確認文案。照「已經發生了嗎」
寫的不會。

**ADR-0066 一個字都不改。** 那一支說的是「那一場沒做完就沒有東西可以寫」，
而它針對的是**她自己記的那一場**：她記完一場二返，那張「寫紀錄」是真的要做的事。
匯進來的那一場不一樣 —— 那份紀錄她去年就寫進耀聖了。兩件事的差別不在種類，
在**這筆資料是從哪裡來的**。

**`data/legacyImport.js` 的檔頭以前寫著「匯入不是多開一個特例，是停止繞過
既有的規則」，那句話這一次不成立。** 既有的規則（`acceptsNewTasks()`）只管掛號
那一族，而 SPEC 6.10 要的是「不分族」—— 所以這裡確實多了一道閘門，而那道閘門
就是這一支 ADR。

## 後果

- 匯入頁那兩段文案現在講的是真的會發生的事（ADR-0070）
- 她那份 import 匯完之後，資料健檢的「逾期任務」從 18 列變成 0 列
- **正常存檔那條路一個字都沒變**：她記完一場二返照樣長「寫紀錄」
- 檔案自己寫著 `confirmed` 而日期已過的那一種（`statusFor()` 刻意聽它的那一種）
  照舊會長掛號任務。她那份 import 裡有 0 筆，而那個判斷有依據，不要拿一個
  算出來的結果去蓋掉它
- `tests/merge-import.test.js` 多一組，其中一條刻意盯著「這不是濾掉寫紀錄」
