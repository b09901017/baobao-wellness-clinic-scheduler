# 「問這輪的時間」是待辦中心的一列，範圍照壓表那道濾網，但順序不照它的計分

她的流程第一步是「和客戶確認方便的時間，然後記進 app」。app 一直收得下那件事
（`customers/{id}/availability`，原文與解析後的規則並存），也一直算得出誰還沒問
（`domain/scheduling.js` 的 `needsAvailability`）—— 但那個結果**只出現在壓表卡片牆上**。
她得先開一個壓表批次才知道要問誰，而在她的流程裡問時間發生在**開批次之前**。

所以待辦中心多一列「問這輪的時間」。這一支記的是它的三個邊界。

## 誰算「還沒問」：身上還有剩餘次數的人

用 `customerPools()` 的 `totalRemaining > 0`，也就是 `buildCustomerQueue()` 已經在用的
**同一道濾網**。次數用完的人本來就不用排，問了她也排不進去。

兩個沒有選的：

- **全部啟用中的客戶**。最省事，但二十幾位裡會混進次數早就用完、這一輪根本不會排的人，
  而這一列的數字就會永遠停在二十幾 —— 一個永遠不會變小的數字，她看兩次之後就不看了。
- **再窄一層：這個月一次都還沒排的**。這會和 `buildCustomerQueue()` 註解裡已經寫下的
  決定相反（「這個月已經排過的**不會**被排除，因為客戶一個月本來就會來好幾次」）。
  同一個問題兩套答案，比多列幾個人糟。

**「從來沒問過」和「問過但過期了」都算，因為它們本來就是同一件待辦**（SPEC 第 4.3 節：
過期即失效，需重新詢問）。`currentCollection()` 已經把過期的濾掉了，所以這件事不必另外做 ——
但**畫面上要分得出來**：前者一定是漏的，後者是週期到了。點進去是兩區，不是一長串。

## 順序不照 `domain/scheduling.js` 的計分

`CLAUDE.md` 有一條規矩：任何「先看誰」的排序或推薦名單都要用 `scheduling.js` 的同一組計分，
理由是同一位客戶在兩個畫面排名不同，她不會知道哪個算數。**這一頁是那條規矩的邊界，
不是它的例外**：它問的不是「先看誰」而是「先**問**誰」，而她是整批問完，不是挑一個。

真正讓我們決定的是代價。那組計分要 `daysSinceLast`，也就是要多讀半年的來訪；
而**沒有那份資料時每個人的「距上次」那一項都會拿滿分**，排出來的順序等於沒排 ——
用一個看起來像排過、其實是假的順序，去換她最常開的那一頁多一次查詢，兩頭都輸。

改成用手上就有的東西排：**從來沒問過的最前面，其餘最久沒問的先**。收集日期
（`collectedAt`）就在可用性那份資料裡，一個欄位都不用多讀，而且這個順序對這一頁
是真的有意義的 —— 最久沒聯絡的最該先問。

同樣的理由，剩餘次數走 `cached`（額度上的計數欄位，ADR-0004）而不是從來訪現算。
這一列要回答的是「值不值得問」，不是「還剩幾次」，清單頁讀快取本來就是那一支的結論。

## 先把頁面畫出來，這一列等資料回來再補

它要多讀三份資料（客戶、額度、可用性），而待辦中心是她一天開十幾次的那一頁。
所以照資料健檢那顆徽章的作法（ADR-0008 的 `scanHealth`）：`paint()` 先跑完，
這一列的位置留著，資料回來再填進去。讀失敗就當這一列不存在 ——
它是提醒，不是這一頁的主體，為了它把已經畫好的待辦換成一句錯誤訊息，代價更大。

額度與可用性都是 collection group query，**各一次**，不是一位客戶一次。

## Consequences

`domain/scheduling.js` 多一支 `customersToAsk()`。它和 `buildCustomerQueue()` 共用
`customerPools()` 與 `currentCollection()`，所以「誰值得排」「問到了沒」仍然只有一份實作 ——
分開的只有「怎麼排序」，而那正是這一支要記下來的決定。

**ADR-0001 沒有被推翻。**「待收集時間」仍然是推導狀態，這一列只是讓它在壓表之外
也看得到；`CLAUDE.md` 那條「先看誰用同一組計分」也沒有被推翻，它的界線變清楚了。

數字是 0 的時候整列不畫。一列寫著 0 的提醒，在一頁專講「現在有幾件事」的畫面上是雜訊
（同 `scanHealth` 沒問題時整張卡不出現的理由）。代價是她沒辦法從首頁點進一個空的清單，
而那裡本來就沒有東西。

**她之後想做的「讓客戶自己填表單」沒有被擋死。** 表單填的東西進來一樣是先進 `rawText`
再解析（SPEC 第 4.3 節），這一列讀的是「有沒有一份有效的收集」，不管那份收集是誰打的字。
