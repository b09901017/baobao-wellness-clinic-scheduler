# 警示只能講真的會發生的事，多講跟少講一樣糟

2026-09-04 她要求補齊「反向操作」的後果提示，信裡舉了一個範例文案：

> ⚠️ 注意：該健檢已排定二返（日期：YYYY/MM/DD）。若將追蹤報告拿回未完成，
> **將會取消已約好的二返預約**與後續待辦！

**那句話在這個系統裡是假的。**

## 為什麼是假的

拿回一張待辦，走的是 `data/tasks.js` 的 `setDone()` →
`followupOpsAfterTaskChange()`。它產生的每一個操作都落在 `tasks` 這個集合裡，
**一筆 `visits` 都沒碰**。系統不會、也不該替她取消一場已經跟客人約好的來訪
—— 那是 ADR-0002 的整句話：app 記錄決定，不做決定。

真的會發生的只有三件：

1. 「寄報告給醫師」還沒勾的那一張被軟刪除
2. 「約二返」還沒勾的那一張被軟刪除
3. 「追蹤健檢報告」本身回到未完成（ADR-0068）

那一筆已經約好的二返來訪一個欄位都不會變。

## 決定

**畫面上的每一句後果，都要對得上真的會發生的那一組操作。**

兩個方向一樣糟，而它們的失敗方式不同：

| | 症狀 | 為什麼糟 |
|---|---|---|
| **少講** | 拿回報告，寄報告那一張靜靜不見了 | 她下次會問「我明明勾過，怎麼不見了」，然後開始不相信這個畫面 |
| **多講** | 說「會取消已約好的二返」 | 她會不敢按。**而嚇錯一次之後，真的該停的那一次她也不會停** |

所以「二返已經約好」那一行講的是：

```
9/20 那一場二返已經約好了 —— 那一筆來訪不會被動到，只有上面那幾張待辦會被收走
```

日期照樣印出來（讓她知道系統看到了那一場），但把「不會被動到」講死。

## 怎麼保證對得上：同一台引擎，不寫第二份

那幾句話不是照著規則在畫面上再推論一次算出來的。`data/visits.js` 的
`previewTaskChange()` 跟真的會寫下去的 `followupOpsAfterTaskChange()`
**共用同一段身體**（`chainPlans()`），差別只有 return 不 commit。
`domain/consequences.js` 的 `untickConsequences()` 收那份結果，把它翻成句子。

兩份實作遲早會有一份跟 `syncFollowupTasks()` 分岔，而分岔的症狀是
「確認框說會收掉兩張，實際上收掉三張」—— 那比不講還糟。

同一支檔案的檔頭已經為同一件事寫過一次：兩個入口各自寫死「Abovee」，
而健檢壓的是 Examine，所以那句話在健檢上錯了兩次。這一輪順手把取消／刪除
那兩道也收進來（`cancelConsequences()`），現在它們講得出**是哪一個系統**。

## 只有兩種反向操作會問

全站十種反向操作裡，只有「追蹤健檢報告」與「約二返」拿回來會收掉別的張。
其餘八種（Examine、耀聖、寫紀錄、寄報告給醫師、隨手記⋯）什麼都不會發生。

**那八種不問。** `home.js` 批次勾那一段已經寫過同一句話：多問一次她會學會
閉著眼睛按，而那讓真的該停的那次也停不下來。判準不是種類，是
`preview.remove` 裡真的有沒有東西 —— 沒有就 `untickConsequences()` 回 `null`。

## Consequences

- 讀不到後果（網路不通）時**放行不擋**。那個動作在離線時照樣寫得進本機快取
  （`ui/toast.js` 的檔頭），為了一句說明把它擋下來是本末倒置。
- 這一道確認多打一輪讀取（確認框一次、真的寫的時候一次）。只有鏈上那兩種
  走得到，而她一天拿回來的次數是個位數。
- `tests/consequences.test.js` 有一支測試逐句掃過那幾行，**只要出現「取消」
  兩個字就紅**。那不是在測措辭，是在測「不可以嚇她」這條規則。
- 這條規則不只管這一輪。之後任何一句新的後果說明，判準都是同一句：
  **它對得上真的會跑的那段程式碼嗎？**
