# ADR-0077：貼給客人的那一句不寫器材，她自己看的那一格只寫器材

日期：2026-09-07
狀態：已接受
推翻：ADR-0075 沒有被推翻；`domain/naming.js` 2026-09-06 那一版的「LINE 草稿預設同一般」被這一支取代

## 背景

2026-09-06 那一輪把一段來訪的名字拆成三種寫法（月檢視／一般／LINE 草稿），
其中 LINE 草稿的預設是「跟一般一樣」，也就是 `復能(SIS)`。

她隔天實際點過之後說：

> 我和客人的草稿只會有復能或靜脈雷射
> 然後我自己看月曆會是當天我壓的器材

同一輪她還指出三件對不上的事：

- 加購那一排裡「復能」與「ILIB」被別的課程隔開了
- 「四選一」那一顆按不出來
- 額度的名字（`超磁場(60)`）看不出它跟 `復能三選一(60)` 是同一類東西

## 決定

**一、貼給客人的那一句只講課程，一個器材字都不寫。**

`slotName(slot, master, 'line')` 直接回課程那一半，連器材都不查。
`復能 - 三選一（60）` 那一筆那天壓了超磁場，LINE 草稿仍然是「復能」；
ILIB 那個課程的 LINE 名設成「靜脈雷射」，因為客戶看不懂那三個字母。

連帶的結果：**器材主檔上的 `lineName` 從此畫不出來**，所以
設定 → 名稱怎麼寫那一頁的器材列不再給那一格。留著一個永遠不會出現在
任何地方的輸入框比沒有還糟 —— 她會填，然後找不到它在哪裡。

**二、額度的名字是「課程 - 哪一種（幾分鐘）」。**

```
復能 - 三選一（60）    復能 - 四選一（30）
復能 - SIS（60）       復能 - INDIBA（30）    復能 - 高能量雷射（60）
ILIB（60）
```

兩件事跟前一版不同：

- **單買一台也帶著「復能」**。以前叫 `超磁場(60)`，跟三選一那一筆並排時
  看不出是同一類東西 —— 而它們扣的是同一種次數、走同一條排班路。
- **後半用別稱不是全名**（`SIS` 不是 `超磁場`）。她自己講的、寫的都是 SIS，
  而別稱正是「她怎麼叫這個東西」那一格。沒設別稱的自己退回全名。

**三、「哪一種」那一排只有復能自己的器材，ILIB 不在裡面。**

ILIB 在「買了什麼」那一排自己有一顆，而且**緊接在復能後面**。
判準不是名字：接在復能後面的是「擁有四選一裡那幾台器材、但自己不是復能」
的課程，也就是 ADR-0075 那條推導的另一端。

**四、月檢視接上分鐘：`SIS(60)`。**

同一台機器有 30 與 60 兩種規格，而它們是**兩筆不同的額度**。少了那個數字，
月檢視上兩者長得一模一樣。只有「這個課程有兩種以上規格」時才接
（`durationChoicesOf()`）—— 健檢永遠是 120 分，寫出來只是把那一格擠掉一個字。
括號用**半形**：一格是七分之一個螢幕寬。

**五、讀取卡片印得出「這一段扣的是哪一筆」。**

她的原話：

> 我壓表那邊應該可以看我現在有甚麼額度……然後就記錄起來這次壓表是扣哪個？
> 為什麼日曆不知道

時段身上一直都有 `entitlementId`，缺的只是**名字**。名字**不存進時段** ——
那會變成快照的快照，她在資料健檢按一下改名之後那一行就停在舊的。
改成呼叫端把那一位客戶的額度帶進來：客戶詳情手上本來就有，
日曆／待辦中心／進度追蹤則是**點開那一下才讀那一位**（同 `fillMirror()`
既有的規矩），跟任務一起讀、一次重畫。

**六、「四選一」按不出來時，資料健檢要講得出原因。**

那一顆要有一台 `courseId` 不是復能的器材才組得出來，而 ILIB 那一台是
2026-09-06 才進種子資料的。既有資料庫上沒有它，於是那一顆按不出來，
**而畫面上跟「本來就沒有那一種」長得一模一樣**。
新增一列「器材主檔少了一台」，可以一鍵建起來。

同一個形狀還有一列**「課程沒填可選時長」**：復能與 ILIB 在種子上是 `[30, 60]`，
既有資料庫上那一格是空的，症狀是「幾分鐘」那一排整排不出現、名字少了後面那個
數字、月檢視也分不出 30 與 60。**只在那一格是空的時候報** —— 她自己填成 `[60]`
是一個決定，不可以被一顆按鈕改回去。

## 為什麼

**三個地方的讀者不同，所以名字不同。**

| 誰在看 | 看到什麼 | 為什麼 |
|---|---|---|
| 客戶（LINE） | `復能`、`靜脈雷射` | 客戶不需要知道是哪一台，也看不懂 SIS |
| 她（月檢視） | `SIS(60)` | 一格放不下五六個字，而她要認的正是「哪一台、幾分鐘」 |
| 她（一般、試算表） | `復能(SIS)`、`復能 - 三選一（60）` | 一個是那天做了什麼，一個是當初買了什麼 |

**「同一件事的兩半」不重複寫。** ILIB 同時是課程與器材主檔上的第四台，
兩邊全名一樣。所以 `ILIB` 不會被印成 `ILIB(ILIB)`，也不會因為別稱是 `IL`
就變成 `ILIB(IL)` —— 比的是**全名**不是畫出來的那兩個字。

## 後果

- 既有額度身上的名字是購買當下的快照（ADR-0003），**不會自己跟上**。
  資料健檢的「復能額度還叫舊名字」認得出三代自動名字（`復能`、
  `復能三選一`、`復能三選一(60)`、`超磁場(60)`），一鍵改成新的。
  **她自己打的名字一個字都不動。**
- 器材的 `lineName` 欄位留在資料上（既有資料不動），只是畫不出來也改不到。
- `nameOf(eq, 'line', { as: 'equipment' })` 退回別稱，跟另外兩種一樣 ——
  留著那個參數只為了呼叫端不用先判斷是哪一種。

## 其他做法

**LINE 草稿寫「復能(SIS)」，讓客戶知道用哪一台。** 她明確不要：
客戶問「SIS 是什麼」她要多解釋一次，而那不是客戶要決定的事。

**額度名字沿用 `超磁場(60)`，靠畫面分組。** 分組只在加購那一張表上成立，
而這個名字會流到試算表、稽核紀錄、LINE 之外的每一個畫面。名字自己講清楚
比每一個畫面各自分組可靠。

**把 ILIB 也放進「哪一種」的單買那一排。** 那會有兩條路買到同一個東西
（單買 ILIB 的池 vs ILIB 課程的 single），而兩邊算出來的次數會對不起來 ——
一個要診間、一個要治療師，指派規則也不同（ADR-0075）。
