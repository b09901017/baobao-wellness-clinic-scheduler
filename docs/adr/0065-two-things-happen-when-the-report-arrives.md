# 報告到手的那一刻有兩件事要做

2026-09-03 她要的：

> 二返，目前只有事前去壓兩個系統，事後簽療程單，其實還需要有事前要把報告寄給
> 醫生（也就是當我拿到健檢報告的時候），除了要約二返，還要寄健檢報告給醫生
> （這是之前沒有加到的）。

她自己的筆記把順序寫得更清楚：

```
二返   前  (1) 寄報告給醫生
           (2) 三系統
```

「(1)」是她標的。

## 名字用「醫師」不是「醫生」

`CONTEXT.md` 的詞條是**醫師**，`_Avoid_` 明列「醫生」。她口語講醫生沒關係，
畫面上要用詞彙表的詞。

## 決定：第二站是兩張，不是第三站

ADR-0042 的鏈條原本是一條線。「寄報告給醫師」的觸發條件跟「約二返」
**一模一樣**（報告到手的那一刻），所以它不是第三站，是第二站的第二張：

```
                                   ┌─▶ 寄報告給醫師   死線 勾掉那天+7
健檢結案 ─▶ 追蹤健檢報告 ──勾掉──┤
             死線 健檢日+21        └─▶ 約二返         死線 勾掉那天+7
```

**兩張共用 `followupDueDays`，不開第三個設定值** —— 它們是同一個動作的兩半，
給兩個可調的天數只會讓她某天發現兩張的紅字時間不一樣而想不起來為什麼。

## 為什麼要拆成兩圈算：`owed()` 會把它默默吃掉

這是整個決定真正的重點，也是唯一一個不寫下來就一定會被「修掉」的地方。

`syncFollowupTasks()` 的第一圈長這樣：

```js
const want = owed(pair, visits);
if (!want) continue;                       // ← 這裡
...
for (const t of openTasks) {
  if (wanted.get(t.visitId)?.kind === t.kind) continue;
  remove.push(...)                         // ← 沒在 wanted 裡的一律收掉
}
```

`owed()` 算的是「**做完的健檢**比**約掉的二返**多幾次」。她一去把二返約好，
那一場就變成 `booked`、`owed` 掉到 0、`continue` 一跑 —— 那一次健檢整個退出
候選名單，於是**還沒寄出去的報告那一張會被掃掉，而畫面上什麼都不會說**。

所以寄報告走**第二圈**，在 `owed` 那道閘門外面：

```
第一圈（既有的，一個字都沒動）
  照 owed 決定哪幾次健檢該有「追蹤健檢報告 / 約二返」

第二圈（新的）
  凡是「追蹤健檢報告已經勾掉」而且那一筆健檢還是已完成的，
  就該有一張「寄報告給醫師」—— 報告寄了沒，跟二返約了沒是兩件事
```

這跟 ADR-0042 那句「替她刪待辦比留著更糟」是同一個判斷，只是換了一個入口。

## 舊資料不補產生

這一支上線前就停在「約二返」那一站的健檢，從來沒有過追蹤報告那一張
（`stationFor()` 的第 2 條路），所以它們不在 `doneReport` 裡，自然不會長出
寄報告 —— 這是「由構造保證」，不是另外寫一條例外。

方向跟 ADR-0042 相反但判斷一樣：那一批她多半早就寄出去了，補一批紅字出來，
她第一件事是全部勾掉，而那讓稽核紀錄多了一批假的「做完了」。

## ADR-0042 哪一半還活著

| | 狀態 |
|---|---|
| 中間真的少了一個動作（去問報告出來了沒） | **活著**，一個字沒改 |
| 「約二返」的死線從勾掉那天算，不從健檢日算 | **活著**，而且新的那一張照抄 |
| 鏈式只有這一段，簽療程單不鏈式 | **活著** |
| 既有的「約二返」不收掉 | **活著**，而且是新的第二圈不補產生的理由 |
| 「一站一張」 | **被這一支推翻**。第二站是兩張 |

## Consequences

- `domain/followups.js` 多一個 `SEND_REPORT_TASK_KIND`，`syncFollowupTasks()`
  多第二圈。**`stationFor()` 一個字都不改** —— 它回答的仍然是
  「第一圈那條線走到哪一站」。
- `taskRules.js` 的 `CHAIN_KINDS` 要加。少加的話，健檢那一筆一存檔
  `syncTasksForVisit()` 就會因為「來訪裡沒有需要這個任務的課程」而把它刪掉。
- `data/visits.js` 的 `chainKinds` **刻意不加**：勾掉寄報告不會讓鏈條上任何
  東西改變，放進來只會讓每一次勾掉它都多打三次讀取。
- `todoFlow.js` 的 `FLOW` 插在追蹤報告與約二返中間。兩張死線一樣，
  所以先後只能由那一份決定（ADR-0043：段裡的順序不能交給死線）。
- **收掉的理由只有一種**：報告那一張被拿回來了。它不會因為「二返約好了」
  而消失 —— 那是另一件事，而理由字串講錯會讓她下次查稽核時查錯方向。
