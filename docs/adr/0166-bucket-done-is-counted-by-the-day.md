# ADR-0166：逾期／今天／明天的「已完成」照日子算，任務、簽療程單、隨手記一起列

日期：2026-10-21
狀態：已接受
推翻：[ADR-0152](./0152-today-counts-close-and-dated-notes.md) 決定 4 的最後一句（「『已完成』那一格照舊只有任務」）。ADR-0152 其餘照舊。
延伸：[ADR-0162](./0162-tomorrow-counts-tomorrows-visits.md)（明天那一格）、[ADR-0044](./0044-a-dated-note-goes-on-the-calendar.md)（有日期的隨手記）、
[ADR-0001](./0001-scheduling-queue-state-is-derived.md)（簽療程單是推導的）。

## 背景

ADR-0152 讓逾期／今天／明天的未完成算進簽療程單與有日期的隨手記，已完成那一格刻意沒動：它是 `tasksData.listDone()`
（勾掉的時間最近的 200 張任務）照死線切。上線第一天她（2026-10-20）：

> 我發現待辦首頁，的今天，他的已完成是不是裝飾啊 ? 我勾起來的怎麼沒有跑到已完成，就是已完成只能放今天的，
> 到了明天後，未完成就會到逾期，已完成就會清空，但只是這邊呈現清空，再隨手記那邊或月曆其他地方不會被清掉，你懂嗎，
> 就是我想要今天份的點進去後可以看到已完成和未完成，包含重其他地方點的完成也是放已完成

三個洞：隨手記與簽療程單勾掉了哪一格都不在；逾期的已完成是「所有死線過了、做完的任務」，只會越積越多；
死線今天、幾週前就勾掉的任務，被之後勾的兩百張擠出 `listDone()` 就不見了。她同意的表（「可以照表」）在決定 1。

## 決定

1. 三頁的已完成**照日子算**，規則只在 `domain/todoFlow.js` 的 `doneBuckets()`，跟未完成那一側的 `todoBuckets()` 寫在一起：

   | | 勾掉的任務 | 簽療程單（一位一天一件） | 有日期、勾掉的隨手記 |
   |---|---|---|---|
   | 逾期 | 死線過了、**今天才勾的** | 日子過了、**今天才簽完的** | 沒有（隨手記不會逾期，ADR-0152 決定 2） |
   | 今天 | 死線今天（哪一天勾的都算） | 今天的、每一段都結了 | 掛今天的 |
   | 明天 | 死線明天（提早勾的） | 沒有（明天的還簽不了） | 掛明天的 |

   **到了明天，昨天那幾件自然不再是「今天的」**，已完成那一格就空了 —— 一筆都不用刪，隨手記、日曆、客戶詳情照舊在。
   「簽完」＝一段都不開著、至少一段已完成或未到（`visits.js` 的 `daySignedOff()`，`visitsToClose()` 的另一半）；整天取消的不算。
   不管在哪一頁勾的都算：判斷看的是資料上的 `done`／段的狀態，不是在哪裡按的。

2. **「今天才」問那一刻存下來的時間**：任務是 `doneAt`、簽療程單是來訪的 `statusAt`（整筆狀態變的那一刻 —— 一天最後一段結掉時一定會變），
   兩格都是 UTC 的 ISO 字串，一律過 `dayOf()` 換成裝置那一天；查詢的起點是 `dates.js` 的 `startOfDayISO(today)`（台灣 00:00 換成 UTC）。

3. **一出生就做完的不算**：`createdAt` 與 `updatedAt` 是同一刻的那幾筆（`doneBuckets()` 裡的 `bornDone()`）。
   照片放掉的「取消 Abovee」、匯進來的取消段、拍 Abovee 新記一筆已完成的那一天 —— 它們從來不在未完成那一側，
   出現在已完成會是一件「我沒做過」的事；逾期那一格尤其：上週的照片今天才記，一整排從沒逾期過的會出現在「今天才做完的逾期」。
   兩格都是 `repo.commit()` 寫的伺服器時間，同一次寫入裡的伺服器時間是同一個值；她勾、簽的那一下是另一次寫入，`updatedAt` 一定換。

4. 讀的那一側：任務照死線另外查（`tasksData.listDoneDue()`，不再靠 `listDone()` 的最近 200 筆）與照勾掉的時間查（`listDoneSince()`），
   來訪照日子（`listByDate()`）與照 `statusAt` 查（`visitsData.listStatusChangedSince()`，新的 (deletedAt, statusAt) 索引），
   隨手記照日子（`notesData.listBetween()`）。**已完成那一側讀不到（索引還在建、離線）時未完成照畫**，那一塊講一句。
   這是畫面用的，不拿去算次數或存檔。

5. 三頁的已完成**只給看與拿回來**：拿掉「清掉這 N 筆」與每一列的垃圾桶，隨手記那幾列不接長按。
   她說的「清空」是「這邊呈現清空」—— 在這一頁按下去真的把隨手記刪掉，跟她說的相反。
   點任務、點隨手記拿回來；點簽好的那一天開讀取卡片（簽好的段鎖著，不從這裡退回）。Examine、耀聖那種分類頁的已完成不動。

6. **首頁三顆數字不動**：照舊只數未完成（`todoBuckets()` 一個字都沒改）。

## 沒有選的

- **已完成照舊照死線切、只是多收隨手記與簽療程單**：逾期那一格會永遠積著所有做完的過期任務，「到了明天就清空」也不成立。
- **一出生就做完的照樣列**：最簡單，但逾期那一格會冒出她沒碰過的整排；而今天那一格列進去，未完成＋已完成就不再是「這一頁出現過的事」。
- **「一出生」用時間差判（建立之後幾秒內做完的）**：她確認完馬上去 Examine 掛號、一分鐘內就勾掉也是她做的 —— 那一張不見正是她回報的那個洞。
  同一次寫入的伺服器時間一樣，比的是「之後有沒有再被寫過」，不靠猜一個秒數。
- **三頁的已完成照舊給垃圾桶，只是隨手記那一塊不給**：同一頁兩種規矩，她分不出哪一列按了會刪。要刪去隨手記那一頁或分類頁。

## 後果

- 一出生就做完的那一筆，之後被寫過一次（改了記一句、系統對齊了死線）就會出現在已完成 —— 那一刻它也確實被動過，不藏。
- 已完成那一側多三到四個讀取（看是哪一頁），只在點進那一頁時讀；首頁不讀。
- 部署之後 (deletedAt, statusAt) 索引建好之前，逾期那一頁的已完成讀不到，那一塊講一句「現在讀不到」，未完成照常。
