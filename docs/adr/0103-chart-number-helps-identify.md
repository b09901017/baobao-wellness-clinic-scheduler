# ADR-0103：認人時名字與病歷號一起比，對不上就不挑

日期：2026-09-17
狀態：已接受
推翻：`CONTEXT.md`「病歷號」那一條的「**只顯示，不參與任何計算**」
延伸：[ADR-0050](./0050-the-health-check-can-rename-an-imported-note.md)（病歷號是一則備註）、
[ADR-0099](./0099-ai-only-copies-the-words.md)（AI 只抄字）

## 背景

拍 Abovee（issue 13）與療程單（issue 14）都要知道照片上那一列是 app 裡的哪一位客戶。
照片上有兩個線索：名字，與病歷號（Abovee 補零到八位的 `00001234`；療程單的「客戶編號」是同一個號碼）。

她 2026-09-17：

> f 病歷號可以拿來認 Abovee 上的人嗎 ? 可以拿來交叉比對，人名和病歷號

只用名字：同名的兩位分不開，AI 抄錯一個字就認不得（2026-09-17 考試 Abovee 姓名 9/10，ADR-0100）。
只用號碼：病歷號是舊表匯入時從姓名格解析出來的一則備註（ADR-0050），不是每一位都有。

## 決定

**名字與病歷號一起比，規則只在 `domain/identify.js` 的 `identifyCustomer()`**，兩個入口共用：

| 答案 | 條件 | 畫面上 |
|---|---|---|
| `both` | 名字與病歷號都對上同一位 | 認得 |
| `nameOnly` | 名字對上一位，沒有號碼說不是他 | 認得（標一個小記號） |
| `numberOnly` | 病歷號對上、名字不一樣 | **請你選** |
| `conflict` | 名字對上 A、號碼對上 B；或名字對上的人身上的號碼跟照片不一樣 | **請你選** |
| `ambiguous` | 同名好幾位、號碼分不開 | **請你選** |
| `none` | 都對不上 | app 裡沒有這位 |

- **後三種一律不挑一位**：回候選，`customer` 是 null
- 比之前正規化：號碼去空白、去前面的 0；名字去所有空白、全形半形一致、英文不分大小寫
- 病歷號**照舊從備註讀**（`病歷號 1234`，舊的說法「姓名欄的編號：」也認），**不另開欄位**
- 已刪除、已停用的客戶不參與

## 為什麼對不上時不挑「最像的」

挑一個的話，那一段時間會記到別人身上，而畫面上看起來是認得的 —— 跟「讓 AI 直接回客戶 id」
（ADR-0099 拒絕的做法）是同一種錯：**錯值長得跟對的一模一樣**。空著讓她選一次，
比存進去一個看起來對的錯人便宜。

## 為什麼不開一個病歷號欄位

它現在是一則備註，而她在客戶詳情上看到的也是那一則小丸。開欄位要搬既有資料、改編輯表單、
改試算表，換到的只是「讀的時候少解析一次前綴」。這一支只讀，不需要那個欄位。

## 後果

- `CONTEXT.md` 病歷號那一條改成「參與認人，不參與次數、排序、查詢」
- 病歷號備註打錯一個數字，照片帶入時那一位會變成 `conflict` 要她選 —— 那正是這個規則該做的事
- 兩位客戶共用同一個號碼（資料打錯）又同名 → `ambiguous`，不挑
