# 資料健檢只算不寫，一鍵修正只有計數欄位

SPEC 第 6.6 節要求資料健檢「顯示差異並提供一鍵修正」，但七項檢查裡只有**次數對帳**存在明確的正解：計數欄位是快取、真相永遠是 `visits`（ADR-0004），所以重算的結果不需要任何判斷。其餘六項（孤兒資料、狀態異常、額度超用、衝突殘留、逾期任務、資料過期）的「修正」都要先決定她想要什麼 —— 過期的來訪該標 `done` 還是 `no_show`、撞在一起的兩筆該動哪一筆 —— 那是 app 看不到 Abovee 就答不出來的問題（ADR-0002），所以**這六項只顯示差異並提供跳到那一筆的連結**。

## Consequences

資料健檢頁唯一會寫入的動作是把 `doneCount` / `bookedCount` 改成重算值，而且照樣走 `repo.commit()`，所以有稽核紀錄也能復原。一次修多筆時整批寫在同一個 commit 裡：修了 12 筆卻只退得回 1 筆，比不能復原還危險。

代價是六項檢查會一直掛在那裡直到她自己去處理，資料健檢頁不會自己變乾淨。這是刻意的 —— 會自己消失的提醒等於沒有提醒。
