# 紀錄是來訪之後才長出來的任務

2026-09-03 她要的：

> 二返……事後（客人來完後）要寫二返紀錄。然後營養諮詢也是要寫紀錄。

筆記裡的原文：

```
二返      後 → 曜聖寫二返紀錄
營養諮詢  (1) 療程單
          (2) 打諮詢紀錄（曜聖醫美櫃檯）
```

兩件事在系統裡是同一種：**客人走了之後，要去外面那個系統補一份文字紀錄。**

## 為什麼這是一個全新的任務家族

現有的任務全部長在**來訪之前**：

| | 現有的（Examine、耀聖） | 新的（寫紀錄） |
|---|---|---|
| 什麼時候長出來 | 客人**確認**之後（ADR-0027） | 那一場**做完**之後 |
| 死線 | 來訪日的**前一天** | 來訪**那一天** |
| 取消來訪時 | 要回頭去外部系統收回登記 | 沒有東西要收 —— 那一場沒發生 |

## 決定

**一種任務種類 `寫紀錄`，課程主檔上一個布林 `needsRecord`，死線＝來訪那一天。**

### 逐課程，不逐類別

`CLAUDE.md` 寫著「規則綁在類別上，不逐課程設定」，而這一條是例外，
判準是「**同一個類別裡的課程會不會不一樣**」：二返是 A 類、營養師諮詢是
`null` 類，而同樣 A 類的復健科醫師門診**不用**寫。

既有的例外有四個（`needsTreatmentForm`、`followupCourseId`、`requiresDoctor`、
`requiresEquipment`），這是第五個。

### 為什麼不是逐課程自訂名稱

「寫二返紀錄」「寫營養諮詢紀錄」讀起來更精確，代價是 `domain/todoFlow.js` 的
`FLOW` 認不得自訂的種類，於是它們會**全部落進「來訪前一天」那一段的最後面**
（`stageOf()` 對認不得的一律回 `before`）—— 一張事後才做的紀錄排在掛號中間，
比名字模糊糟得多。

而且那一列本來就講得出是哪一場：`taskLine()` 給的是**種類・來訪那一天・課程**，
所以她看到的是「寫紀錄 / 9/20(六)・二返」。

### 為什麼死線是來訪那一天

這件事就是當天做的（她的筆記把它排在「療程單」後面同一段），隔天還沒寫就
**真的**是逾期。ADR-0042 那句「一個系統只要製造出一批紅了但做不了的東西，
紅色就不再是訊號」在這裡是反過來的 —— 這一張紅的時候她真的做得到。

**不新增設定值。** 沒有一個天數要調。

## 唯一的陷阱：`tasksForVisit()` 不可以跟著狀態變

`domain/taskRules.js` 的註解早就寫過為什麼：

> 「該有」不等於「現在就產生」…… 這一支同時被用來**比對現有的任務**，
> 而那個比對不可以跟著狀態變，否則來訪一結案，她還沒做完的登記就會被靜默收掉。

紀錄那一族剛好相反：**那一場沒做完就沒有東西可以寫**。所以來訪從已完成被改回
已確認、或改成未到時，還沒勾的那一張就該收掉 —— 而那要靠
`recordTasksForVisit()` 回空陣列才做得到。

兩支的差別因此不是疏忽，是兩條不同的規則。做法是把兩件事各自拆成兩層：

```
該有哪些（比對用）    tasksForVisit()        不看狀態
                      recordTasksForVisit()  看狀態，理由在上面

長不長得出來（產生用） acceptsNewTasks()      === 'confirmed'
                      acceptsRecordTasks()   === 'done'
```

## Consequences

- **收掉那一張的理由分兩種**：課程被移出來訪了（「來訪裡已經沒有需要這個任務
  的課程」）與課程還在但那一場沒做完（「那一場沒有做完，沒有紀錄要寫」）。
  印一句對不上的理由，她下次看稽核紀錄會查錯方向。
- **`no_show` 不長。** 人沒來，沒有紀錄要寫。
- 待辦中心排在⑥「來訪之後」那一段的**最前面**：她自己就把它寫成「後」，
  而它是客人走了之後立刻做的，追蹤報告是三週後的事（ADR-0043）。
- **UI 上講「任務什麼時候產生」的那幾句要加一句，不是改掉**。現在有兩個時機，
  而畫面上只講一個，她第一次看到那張待辦時會以為是壞掉了。
