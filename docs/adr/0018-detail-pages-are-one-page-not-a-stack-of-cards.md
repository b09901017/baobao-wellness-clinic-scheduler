# 詳情頁是一頁，不是一疊卡片；少用的東西從底部滑出來

客戶詳情頁原本是九張並排的白卡：基本資料、額度、來訪、LINE 訊息、本輪可用性、隨手記、任務、變更紀錄、停用與刪除。使用者的原話是「這種由上排到下的卡片設計我也覺得不直觀好看」。

問題不在卡片本身，在**九張卡看起來像九件事**，其實是同一個人的九個面向；而且每一張的視覺份量一樣重，所以「一年點兩次的變更紀錄」跟「每天要看的剩餘次數」長得一樣大。

我們改成：

- **名字直接坐在紙上**（`.hero`），不包卡片。這一頁講的就是這個人。
- **段落用細標題加一條髮絲線分隔**（`.section`），不是一張張白卡。只有真正是「一格一格的資料」的東西（額度、可用性收集）才保留卡片外框。
- **順序照她問問題的順序排**：名字 → 備註 → 這個月什麼時候來 → 不能的時間 → 還剩幾次 → 來過幾次 → 隨手記 → 任務。這是使用者指定的順序，理由是客戶臨時打來問的就是前三件。
- **「這個月」是一排橫著捲的日期卡**，不是一條直的清單 —— 一眼看得到有幾次，往右滑看得到後面還有什麼。
- **一年點兩次的東西收成最底下的一排小標籤**（LINE 訊息、變更紀錄、停用與刪除），點了從底部滑出面板。給它們一整張卡等於天天提醒她那件事存在。

## 底部面板是全站共用的一支

`ui/components/sheet.js`。日曆點某一天、備註編輯、來訪紀錄看全部都走它。兩個實作上的決定：

**掛在 `<body>` 上而不是掛在 view 裡。** view 每點一顆泡泡就重畫一次，掛在裡面的面板會當場消失。代價是它不會隨著換頁自動消失，所以它自己聽 `hashchange` 收掉 —— 否則會變成一個蓋在新畫面上、內容還是舊畫面的面板。

**`≥900px` 改成置中的對話框。** iPad 橫式上底部抽屜要跨過整個螢幕才關得掉。

## 日曆點一天也走同一支

SPEC 第 8.6 節原本寫「點一天跳到日檢視」。實際用起來那是整頁切換：她點下去只是想知道「這天卡了什麼」，卻把「我在看八月」這個脈絡整個換掉。改成**月曆整片留在原地，那一天的內容從底部滑出來**，面板裡可以直接新增來訪或個人行程，往下滑掉就回到剛剛那個月。

日／週／月三種檢視本身沒有變，日檢視仍然是那一段的完整版面，只是不再由「點一天」進入，而是由頂端的日週月切換進入。

## Consequences

`ui/views/audit.js` 的 `listHtml()` 改成 export：整頁的稽核與詳情頁的面板用同一組列，不要各畫一份。

客戶詳情頁的來訪與任務只列最近幾筆，超過就收進「看全部」的面板。這是刻意的：她十次打開這一頁有九次是在看「還剩幾次」，一條三年份的來訪清單只會把額度推到螢幕外。
