# ADR-0095：匯進來的額度用 app 的寫法，算不出來的保留她原本的字

日期：2026-09-16
狀態：已接受
延伸：ADR-0078（全站只有三種名字）、ADR-0054（健檢的等級住在額度上）、
ADR-0002（app 記錄她的決定，不替她做決定）

## 背景

匯進來的額度名稱原文照抄舊試算表的療程列名。她那份 import 的 137 筆額度
有 **31 種寫法**：`Inbody`、`復健門診`、`物理諮詢`、`營養諮詢`、`體適能分析`、
`復能(1小時)`、`ILIB 60mins`、`ILIB (60mins)`、`ILIB 30`、`SIS(60min)`、
`任選(30min)`、`復能(30min)`、`復能三選一(60)`⋯⋯

而她之後在 app 裡加購的會叫 `身體組成分析`、`ILIB(60)`、`復能-三選一(60)`
（ADR-0078）—— **同一位客戶身上兩種名字並排，看起來像兩種東西**。
資料健檢的「復能額度還叫舊名字」只認得歷代**自動**名字，這一批裡只有 4 筆
按得到修正。

她 2026-09-16：

> 這個能不能幫我全部匯進去的時候都一併改名，改成新版 app 的寫法

而算出來會掉字的那幾筆（`12萬健檢`、`5萬健檢(腸道)`、`營養針`、`EECP體驗`）：

> 這15筆都放入⋯⋯讓我之後逐筆改

## 決定

**一、「她買一筆會叫什麼」搬進 domain。**

`autoLabel()` 與 `keptLabel()` 從 `ui/components/buy.js` 搬到
`domain/entitlements.js`。它們是規則不是畫面（「這一池叫幾選一」「健檢的等級
接在前面」），而第二個消費端出現的那一天，匯入就得從一個 UI 元件借規則 ——
SPEC 第 10 節說規則住 `/domain`。同 `poolName()` 2026-09-08 搬家的理由。
`buy.js` 轉出去給既有的呼叫端，新的呼叫端直接讀 domain 那一支。

**二、匯入時算一次，算得出來才改。**

`domain/entitlements.js` 的 `importedLabel()`，**只在匯入那一刻跑**：

| 形狀 | 改成 | 為什麼算得出來 |
|---|---|---|
| 擇一池 | `poolName()` ＋ 時長 | 名字 100% 由器材與時長決定，舊字帶不了別的 |
| 分得出時長的課程（ILIB）| `timedLabel()` | 同上 |
| 舊表的別稱（對照表上那五個）| 正式名稱 | 兩個字講的是同一件事 |
| 其餘 | **原字不動** | 帶著算不出來的資訊 |

實跑她那份 import：**改名 116 筆、保留原字 21 筆**（其中 6 筆本來就一樣）。

**三、健檢的等級解析進 `tier`。**

`12萬健檢` → `tier: '12萬'`。那樣名字**一個字都不會變**
（`tieredLabel('12萬','健檢')` 就是 `12萬健檢`），而 ADR-0054 要的那一格補上了。
解析不出來的（`x萬健檢`）留空 —— **不要猜一個金額**。實跑補上 10 筆。

**四、保留原字的那幾筆由資料健檢列出來**（ADR 的落地在 issue 05），
一筆一列、**沒有修正鈕**，她改一筆少一列。

## 為什麼

**「算得出來」的判準是「舊字帶不帶得了別的東西」，不是「像不像」。**
`復能(1小時)` 與 `復能-三選一(60)` 講的是同一件事，因為那一池的名字完全由
器材與時長決定 —— 舊字裡沒有別的資訊。`5萬健檢(腸道)` 不一樣：`(腸道)` 是
她寫進去的東西，而 app 沒有任何欄位裝得下它。

**寧可不改。** 改錯的成本不對稱：改掉一個名字，那個資訊就不在了；不改的成本
是她在資料健檢上看到一列，點兩下自己改。這也是 ADR-0002 的同一條判準。

**別稱那張表只收「同一個東西的兩種寫法」。** `EECP體驗` 不在表上，而且
永遠不該進去 —— 「體驗」是她寫的東西，不是 EECP 的別稱。

## 後果

- 匯完之後資料健檢的「復能額度還叫舊名字」是 0 列
- 配出來的二返沿用健檢的名字（`followupDraft()` 抄 `source.label`），
  而健檢不改名，所以二返的名字也不會變
- **合併檔一格欄位都沒加，不升版**。她那份 `import-2026-09-16.json` 照樣用
- `ui/components/buy.js` 的行為一個字都沒變（既有測試綠）
- 她之後在 app 裡改過的名字一個字都不會被碰 —— `importedLabel()` 只在匯入跑
