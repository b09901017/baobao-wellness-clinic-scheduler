# 臨床提醒是一種什麼都不擋的永久限制

2026-09-03 她要的：

> 目前不是可以幫客人備註體內有金屬嗎，要多備註一個，血管難打，就是我壓表的時候
> 要能明顯看到這個客人是血管難打，像體內有金屬那樣標記。

她筆記裡的原始場景是點滴：「預約系統註記（第一針或血管難打）」——
**壓表的那一刻**要看得到，因為那一下她要把這件事抄進 Abovee 的註記欄。

## 為什麼加一個字不夠

「體內金屬」不是備註，是**永久限制**裡的**醫療禁忌** —— 它會硬性擋掉超磁場與
高能量雷射，那是全站唯一的硬性阻擋。而它之所以出現在壓表卡片牆上，是因為
`ui/components/flags.js` 只畫會擋掉器材的那幾個字，理由寫在那一支的檔頭：

> 不擋器材的永久限制不畫。「固定禮拜五不行」也是永久限制，但一張卡上
> 十個紅字等於全都不紅。

所以把「血管難打」打進永久限制的自由輸入欄，結果是**它一個畫面都不會出現在
壓表那一頁上**（客戶詳情與來訪編輯器會，但那不是她問的地方）。

而把它塞進器材的醫療禁忌欄更糟：那會讓「禁忌」變成一個不擋任何東西的字，
而下一個讀那段程式的人會以為禁忌清單是可信的。

## 決定

**永久限制底下開第二層。**

```
永久限制（跟著客戶一輩子）
├── 醫療禁忌      體內金屬          → 硬性擋掉器材 → 卡片牆上實心紅
├── 臨床提醒      血管難打、第一針   → 什麼都不擋   → 卡片牆上茶色外框
└── 其他          固定禮拜五不行     → 什麼都不擋   → 卡片牆上不畫
```

判準，之後每加一個字都拿來問一次：

> **忘了這件事，會不會讓她在這位客人身上做錯一件事？**
>
> 會，而且錯了有實際傷害 → 醫療禁忌（做成器材的禁忌，它自己會擋）
> 會，但錯了只是那一次比較不順、要重來一次 → **臨床提醒**
> 不會，只是排班要避開 → 其他

「固定禮拜五不行」留在第三層是對的：它是**排班**的事，而排班有本輪可用性
與可用日在管，卡片牆上另外印一次只是雜訊。

## 名單做成主檔，不寫死

`config/app/clinicalFlags/{id}`，形狀跟診間、器材同一種。

- **為什麼不寫死**：她手上的筆記裡至少已經有兩個（血管難打、第一針），
  而下一個一定還會有。寫死等於每加一個字都要改程式、重新部署，
  而設定頁的第一句話就是「診間與治療師都在這裡自己加，沒有寫死在程式碼裡」。
- **為什麼不從別的地方推**：醫療禁忌是從器材主檔推出來的
  （`contraindicationTerms()`），因為它得跟器材上的字**完全相同**才擋得住。
  臨床提醒沒有對應的東西可以推，所以它自己就是那份名單。

## 為什麼不是備註

備註（`customer.marks`）是最直覺的做法，而它壞在兩個地方：

- ADR-0019 定了「顏色由使用者自己分，系統不因為顏色改變任何行為」。
  用一個固定顏色代表「血管難打」，等於推翻那一條 —— 而那一條的存在
  就是為了擋掉「紅色代表不能排」這種沒有人驗證的業務規則。
- 備註**不畫在壓表卡片牆上**（那一頁一張卡只回答一個問題，ADR-0046）。
  要讓它出現在那裡，得先讓卡片牆認得某些備註比較重要 —— 那就是在
  備註底下偷偷開一個第二層，而且是沒有名字的那一種。

## Consequences

- **多一種主檔**（設定 → 臨床提醒）。`config/{docId=**}` 已經涵蓋，
  Rules 不用開洞；`MASTER_TYPES` 走一圈，所以備份與種子自動含進去。
- **客戶身上存的是字串不是 id**（跟醫療禁忌一樣）。所以主檔上改名，
  既有客戶身上那個字不會跟著改，那顆丸子就掉回第三層。
  **不做自動搬移** —— 「這兩個字是不是同一件事」是她的判斷（ADR-0002）。
  編輯畫面上要有一句話講出來，不然她會以為改名是安全的。
- `splitFlags()` 回三份、`splitFlagsForEdit()` 回三份、`blockChips()` 改名
  `alertChips()`。順手把四個地方各自寫過一次的 `flags.map(...)` 收成一支
  `detailChips()`（客戶清單、客戶詳情、來訪編輯器、壓表的記錄面板）——
  分開寫的話這一輪一定有幾個忘了跟，而忘了跟的症狀是
  「那顆丸子在這一頁有、那一頁沒有」。
- **一個新色相都不開**（ADR-0039）。茶色（`--tea`）目前沒有被任何狀態丸用掉，
  而且它在全站的意思本來就是「次要強調」。外框而不是實心：實心會跟旁邊的
  醫療禁忌搶同一個重量，而那兩件事的後果差很多。
- **日曆上不畫。** 日曆的 `load()` 沒有讀客戶，而 `visitReadHtml()` 是四個畫面
  共用的（ADR-0018、0056）。她要的是壓表那一刻，而點滴當天那一刻由備忘錄
  回答（ADR-0067）。真的需要再回來，那時候的做法是「打開卡片時補讀一次
  那一位客戶」，不是把客戶名單塞進日曆的 `load()`。
