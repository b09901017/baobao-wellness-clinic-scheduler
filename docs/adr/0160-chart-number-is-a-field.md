# ADR-0160：病歷號是一格，照樣在備註那一段

日期：2026-10-19
狀態：已接受
推翻：[ADR-0050](./0050-the-health-check-can-rename-an-imported-note.md) 與 `domain/identify.js` 檔頭那一句「病歷號**不是一個欄位**，是客戶備註裡的一則」。
ADR-0050 的資料健檢那一項（「姓名欄的編號：」改成「病歷號」）留著，只剩搬不進那一格的那幾位會出現在那一項。
延伸：[ADR-0103](./0103-chart-number-helps-identify.md)、[ADR-0156](./0156-long-notes-and-the-notes-order.md)、[ADR-0157](./0157-line-field-is-the-name-macrodroid-opens-the-chat.md)。舊的幾支一個字都不改。

## 背景

她 2026-10-19 逐條回答上線前那份清單：

> 11. 同名的客人、app 那一位沒填病歷號時，會自動認成他而且預設打勾。現在每位都有病歷號，但之後新增的客人沒有任何地方要求填。
> 好，修，我想要之後的客人也有地方可以填病歷號，也許可以像是電話和line一樣，在客戶編輯那邊有，也幫我設計一個符合app風格的icon，專門在備註那邊呈現病歷號

我問「搬出備註之後」的那幾件，她：

> 對，但是她也不算是搬出備註吧? 她一樣在備註阿，只是多了個icon ?

病歷號從舊表匯進來時寫成一則短備註「病歷號 1234」（ADR-0050），認人從備註讀。所以新增客戶、拍訂購單建的人身上沒有那一則 ——
除非她自己記得打「病歷號 」開頭的備註；而它又佔一則短備註，壓表卡片牆與試算表的備註都畫它。

## 決定

### 一、資料上是一格，畫面上照樣在備註那一段

- `customer.chartNo`：字串或 null，存她打的原字（比對一律 `normalizeChartNo()`：去空白、去前面的 0）
- 備註那一段的順序多一種位置 `'chartNo'`，**跟電話、LINE 一樣只是位置**：值在那一格、在編輯客戶的表單裡改，沒填不畫、不佔位
  （`domain/customerNotes.js` 的 `noteItems()`）
- 沒排過順序、或順序裡還沒有它（排的時候還沒填）：接在電話、LINE 後面
- 畫面上的說法照她的：**「在備註那一段」**，不說「搬出備註」

### 二、認人兩種寫法都認

`identify.js` 的 `chartNosOf()` 先讀那一格、再讀還寫成短備註的（兩種說法都認），回傳的形狀不變 ——
`identifyCustomer()`、試算表同名分頁的尾巴、產檔那側的 `merge.mjs`、月底對帳都不用改。合併檔照舊寫短備註。

### 三、搬家只有一支：匯入時轉、資料健檢一位一顆

`customerNotes.js` 的 `chartNoMove()`：那幾則「病歷號 N」短備註拿掉、號碼放進那一格。

- **位置不變**：排過順序的，病歷號接在原本那一則的位置（第 n 個 `'mark'` 換成 `'chartNo'`，走 `notesFields()`），後面的短備註不往前錯；
  沒排過的不寫順序，照預設排在電話、LINE 後面
- **只搬號碼**：「病歷號要再問」那種她自己打的一句話留著
- **拿不準不搬**：兩則不一樣、或那一格已經是另一個號碼 → 只列出來，她決定
- 兩條路：**合併檔匯入建客戶時就轉**（`mergeImport.js` 的 `planForCustomer()`；切換那天貼的 v8 照舊寫短備註，格式不升版）、
  **既有資料庫走資料健檢**最後一項「病歷號還寫成一則短備註」（`chartNoField`，一位一顆「放進病歷號那一格」）
- ADR-0050 那一項（`chartNo`）跳過搬得進去的那幾位 —— 兩項都給一顆的話，同一批按下去兩筆都寫同一位的 `marks`，後寫的蓋掉先寫的

這一項符合資料健檢一鍵修正的三個條件（SPEC 第 6.6 節）：正解明確（那一格空著、號碼只有一個）、沒有第二種意思（拿不準的不給按鈕）、
沒有別的地方做得了（一位一位進編輯表單抄號碼、再刪那一則，二三十位）。

### 四、照片認人：名字對上、app 那一位沒有病歷號 → 不先勾，勾了順便記上

`identifyCustomer()` 多一種 `nameNoChart`（從 `nameOnly` 分出來）：名字對上剛好一位、照片上有號碼、那一位身上一個號碼都沒有。
以前那一格算 `nameOnly`、拍 Abovee 預設打勾 —— 照片上那一位可能是另一個同名、還沒建進 app 的人，而 app 那一位沒有號碼可以核對，
就安靜地記到他身上。之後新增的客人沒有任何地方要求填病歷號（她第 11 條），這一格會愈來愈常見。

- `customer` 照舊是他（多半就是他）；拍 Abovee **不先勾**（改狀態、改期、扣法、治療師／診間的預設勾一起）、排進「要你看」、講一句
- 她勾了、按記錄 → 那一位的病歷號那一格記成照片上的號碼（去掉前面的 0）；確認框講一句。療程單同一句（「是他的話照常存」），存了就記上
- **不寫**：她換成別人的列、那一位已經有號碼、同一位兩列兩個號碼
- 照片上沒有號碼（療程單常常沒有）照舊 `nameOnly`、照常勾；記上之後再拍同一張就是 `both`

## 結果

- 2026-10-19 拿她的合併檔量過（只印數字）：34 位、34 位都有病歷號 → 34 位那一格有值、短備註裡 0 則、其餘短備註 106 則一則不少、資料健檢新舊兩項都 0 位
- 壓表卡片牆、試算表的備註鏡像（`customer.notes`）不再畫病歷號 —— 卡片牆她說「對」；試算表的抬頭那一行另外補（同一輪 issue 10）
- `noteOrder` 的上限照舊 40（正常最多 35 格）；Rules 不驗 `chartNo`（同 `phone`／`lineId`）
- 稽核：`chartNo` 叫「病歷號」
