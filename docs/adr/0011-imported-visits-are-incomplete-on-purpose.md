# 匯入的來訪缺欄位是刻意的，不是漏填

舊試算表的勾選框只記得下一件事：**這個人這一天上了這個療程**。時間、器材、診間、治療師從來沒有被記錄過 —— 手寫白紙上有（`IN60LU`），但白紙不會進資料庫。所以匯入的來訪一定是不完整的，問題只在於要拿什麼填那些洞。

三條路我們選第三條。**灌 `doneCount` 而不建來訪**違反 ADR-0004：計數欄位是快取、真相永遠是 `visits`，這樣做會讓資料健檢的次數對帳每天都報一整頁對不起來，而那些差異一個都修不掉。**編一個預設時間**（例如一律 09:00）會讓日曆上長出根本沒發生過的時段，而 SPEC 第 4.3 節的原則是保留原文優先於解析結果 —— 編出來的時間連原文都不是。所以我們**讓那些欄位保持 null**，並在 `domain/visits.js` 的 `validateVisit()` 對帶有 `importedFrom` 的來訪放行時間、器材、品項、診間與治療師。

換句話說：匯入的來訪只保證三件事 —— **哪一天、上了哪個課程、扣哪一份額度**。那三件事舊表真的知道，其餘它不知道，我們也不假裝知道。

## Consequences

放寬的是那幾個欄位，不是那筆資料。客戶、日期、狀態、額度、課程照樣必填，**醫療禁忌照樣硬性阻擋**（ADR-0002 的唯一例外不因為資料來自舊系統而失效）。時間只填一半仍然是錯的：兩邊都 null 是「舊表沒有」，只填一邊是打字打到一半。

畫面上這些時段顯示成「時間不詳」而不是空白 —— 空白看起來像畫面壞了。那個字串由 `domain/visitTime.js` 的 `timeLabel()` 統一產生，不要在各個 view 各寫一次。

匯入的來訪一律是 `done`，所以它們落在 SPEC 第 6.4 節的唯讀鎖定區：她要補時間就得走更正流程，補的動作會留下稽核。這是想要的 —— 補進去的時間是她從別處回想出來的，那應該有紀錄。

代價是資料庫裡從此有兩種來訪，讀 `slot.startsAt` 的地方都要能吃 null。既有的 `domain/calendar.js`、`domain/health.js`、`domain/visits.js` 的衝突檢查本來就用 `isValidTime()` 守著，所以匯入的時段不會被算進衝突提醒 —— 那也是對的，不知道時間就談不上時間衝突。
