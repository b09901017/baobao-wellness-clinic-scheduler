# 壓表本身就是登記，所以 Abovee 不是待辦

`SPEC.md` 第 5.5 節那張類別矩陣從第一版就寫著：C 類（復能、靜脈、EECP、
營養點滴）產生一件任務，叫「Abovee」。A 類產生四件，其中一件也叫「Abovee」。

而 `CONTEXT.md` 對「壓表」的定義是：

> 在 Abovee 上把時段佔住，讓同事知道這個時段有人。排班的核心動作。

第 4.1 節則寫著，app 裡的來訪從「已壓表・待客人確認」開始，理由是
**她先在 Abovee 壓完才回 app 記錄**。

三件事湊起來就是：**那筆來訪能存在，前提就是「去 Abovee 登記」已經做完了。**
所以那張待辦從出生的那一秒起就是完成狀態，只是沒有人告訴它。她要嘛勾一次
不存在的工作，要嘛讓它掛在那裡等著變紅。

健檢同理，只是系統不同：健檢不佔 Abovee 的格子，她壓健檢的方式就是
直接到 Examine 上登記。所以 B 類的「Examine」也是同一種東西。

「打電話」則是單純不做了（2026-08-23 使用者確認）。

## 剩下的兩種有什麼不同

| | 拿掉的 | 留下的 |
|---|---|---|
| | Abovee、健檢的 Examine、打電話 | 門診的 Examine、耀聖 |
| 什麼時候做 | **壓表的當下** | 壓表之後的另一個時間點（來訪日前一天） |
| 會不會忘 | 不會 —— 沒做完就沒有這筆來訪 | 會，而且一次壓十幾位時一定會 |

這個 app 的整條理由就是右邊那一欄（`README.md`：「忘記做系統掛號」是核心痛點
之一）。左邊那一欄放進待辦，等於用同一個清單同時記「還沒做的事」與
「剛剛做完的事」，而清單一旦混進第二種，第一種就不可信了。

## 類別現在管的是兩件事，不是一串任務

```js
RULES = {
  A: { bookAt: 'Abovee',  onConfirm: ['Examine', '耀聖'] },
  B: { bookAt: 'Examine', onConfirm: [] },
  C: { bookAt: 'Abovee',  onConfirm: [] },
}
```

`bookAt` 不產生任何待辦，但它必須有一個地方記著 —— **取消的時候要知道
回去哪裡把時段放掉**。以前這件事是「查有沒有一張勾掉的 Abovee 任務」，
現在那張任務不存在了，所以改成從課程的類別直接推出來。

推導比查任務更可靠：一張任務可能被她手動刪掉、可能因為課程被移出來訪而收掉，
而「這筆來訪壓在哪個系統上」是一個不會消失的事實。

## 取消因此變成無條件的

以前：**勾過登記任務**的來訪被取消 → 產生「取消 ⋯⋯」。
現在：**任何**來訪被取消 → 一律產生「取消 {bookAt}」，加上已經勾掉的
Examine／耀聖 各自那一張。

這是嚴格變多，而且是對的：以前 C 類的來訪如果她還沒勾那張 Abovee 任務就取消了，
系統一件取消任務都不會產生 —— 但那個時段在 Abovee 上是真的被佔著的。
那是一個沒有人發現過的洞，因為它看起來像「她還沒做，所以沒有東西要收回」。

同一種取消任務只長一張（一筆健檢的 `bookAt` 是 Examine，而它身上可能也有
一張勾掉的 Examine 任務），而且已經存在的不再長第二張 —— 這一支每次存檔都跑。

## ADR-0027 沒有被推翻

「登記任務等客人確認之後才產生」還活著，只是歸它管的從四種變成兩種。
`acceptsNewTasks()` 一個字都沒改。

被推翻的是 `SPEC.md` 第 5.5 節那張矩陣的**內容**（哪些任務），
不是 ADR-0027 的**時機**。

## `null` 與 `C` 從此行為相同

沒有類別的那四種（Inbody、體適能檢查分析、物理治療師諮詢、營養師諮詢）
以前的意思是「不產生任務」。現在 C 類也不產生任務了，所以兩者只剩下
`bookAt` 這一件，而它們的 `bookAt` 都是 Abovee（2026-08-23 使用者確認：
那四種一樣要在 Abovee 佔格子）。

**不合併這兩個選項。** 合併要改既有 `config/courses` 文件的資料，而它們的
行為已經一樣了，沒有非改不可的理由。設定頁上那句說明改成講實話：
「不用掛號 — Abovee 壓表，確認後沒有後續登記」。

## Consequences

**她待辦上現有的「打電話」與「Abovee」不會消失。** 規則只擋產生
（同 ADR-0027 的作法）。已完成的是紀錄，永不硬刪除（SPEC 第 6.1 節）；
未完成的照樣列在待辦上 —— 那些是她真的還沒做的事。
`.scratch/todo-flow-rework/issues/06` 給她一次收掉的路，但那是勾完成，不是刪除。

**匯入的未來來訪從此幾乎不長待辦。** 舊表與合併檔匯進來的多半是復能與靜脈，
那些現在確認後一件登記都沒有。這跟 `.scratch/first-real-import/issues/04`
不衝突：那一支要的是「還沒發生的照 `acceptsNewTasks()` 該長就長」，
而現在「該長的」對 C 類來說就是零。門診那幾筆照樣長 Examine 與耀聖。

**「Abovee」這個字從待辦類別變成一個系統名。** 它現在只出現在
「取消 Abovee」與壓表登記那一列的說明裡。
