# 畫面上多一層東西，就多一步返回鍵退得掉的路

2026-08-24 她說：

> 「我按手機的返回鍵，很常不是真的回到剛剛那個頁面而是跳到奇怪的頁面，
> 有時候我按返回鍵就是要關掉我剛打開的東西或是回到我點開某個東西之前的頁面，
> 但現在好像都很不直觀 很奇怪？」

追下去是**三個各自獨立的原因**，而三個都要修才會直觀。

## 1. 疊上來的東西不吃返回鍵

底部面板、浮出的資訊卡片、二次確認打開時沒有推任何一筆瀏覽器紀錄。
所以返回鍵不是關掉它們，是跳走上一頁 —— 而面板又剛好聽了 `hashchange`
把自己收掉，於是畫面上發生的是「面板消失了，而且頁面也換了」。

## 2. 「回上一頁」其實是往前走

`location.hash = path` 是**推一筆新紀錄**。每一個「回上一頁」都走它，
所以「客戶列表 → 客戶詳情 → 按左上角的『客戶』」在紀錄裡是三筆，
這時候按返回鍵會回到客戶詳情 —— 她剛剛才離開的地方。

## 3. 原地換掉的畫面沒有自己的位置

客戶詳情按「編輯」、「加購」，可用性按「記一次」，做的都是把同一個 `el` 的
`innerHTML` 換掉、網址不動。所以在編輯表單上按返回鍵會整個離開這個人，
打到一半的東西沒了。

## 決定

**畫面上多出來一層東西，就多一筆返回鍵退得掉的紀錄** ——
不管那一層是一張抽屜、一張卡片、一個對話框，還是一整頁換掉的 `innerHTML`。
四種東西共用 `ui/nav.js` 的 `pushLayer()` / `pushScreen()`。

推的是 `history.pushState(state, '', location.hash)`：**網址一個字都不會變**，
所以不觸發 `hashchange`、路由不重畫。hash 路由是刻意選的（Firebase Hosting
不用特別設定就不會 404），這一支沒有動它。

「回上一頁」另外給一個動詞 `back(fallback)`：它真的退。**判斷「有沒有東西
可以退」靠自己數，不靠 `history.length`** —— 那個數字算得到她在同一個分頁上
逛過的別的網站，從 LINE 點連結進來時它是一個跟這個 app 無關的值。
數到 0 就走 fallback，而且用 `replace` 不用 push。

## 這沒有推翻 ADR-0018 與 ADR-0020

那兩支說的是「詳情頁是一頁不是一疊卡片」與「日曆從頭到尾不換頁」。
它們講的是**不要重畫整頁、不要洗掉她在看的脈絡**，不是「不要有回得去的位置」。

這個差別很容易被讀反，所以寫下來：**瀏覽器紀錄不是頁面。** 加一筆紀錄不會
讓月曆閃一下，也不會把「我在看八月」洗掉 —— 它只是讓那一顆實體按鍵有東西可退。
一個蓋住半個螢幕的面板，對使用者來說**就是**一個新的地方，只是它沒有網址。

## 代價

- **`pushState` 有頻率上限**（Safari 每 30 秒有一個數量限制）。她壓表時
  一個晚上開關面板幾百次，所以壓表那一頁的記錄面板**暫時沒有接上去**，
  而且左右滑換客戶絕對不能一位推一筆（那會變成按返回鍵倒著走過二十幾位）。
- 換頁時還開著的那幾層，畫面被 `hashchange` 收掉了，紀錄卻還在。
  `popstate` 認得這種孤兒（`history.state.__layer` 有值但堆疊是空的）並且
  自動再退一次 —— 不然她會按到一次「什麼都沒發生」的返回鍵。
- 存檔之後要 `popScreens()`，不然存完按返回鍵會回到一張**已經存過的表單**，
  看起來像沒存進去。
