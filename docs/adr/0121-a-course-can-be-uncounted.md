# ADR-0121：一段可以不扣任何額度 —— 課程上的「不算次數」

日期：2026-10-05
狀態：已接受
延伸：[ADR-0063](./0063-an-nth-followup-is-a-visit-without-an-entitlement.md)（n返 不是額度）。舊的一個字都不改。

## 背景

每一段來訪都要指一筆額度，只有 n返 例外（ADR-0063）。擋的只有一行：`validateVisit()` 的「要選一個額度」。

她 2026-10-05：

> 五、不算次數的課：功醫門診不扣額度，現在排不進去。

> 功醫門診：跟二返不同；不算次數、不簽療程單、不寫紀錄；三個系統都要壓；要選醫師

> 3. 這一輪只勾功醫門診。其他的我之後在設定自己勾「不算次數」就好。

功醫門診在設定裡建得起來，但排不進去 —— 三個入口（壓表、來訪編輯器、拍 Abovee）的「這一段要做什麼」
那一排都是**從額度長出來的**，沒有額度就沒有那一顆。

## 決定

**課程多一格 `uncounted`（設定頁的字：「不算次數」）：不用加購就排得進去，排了也不扣任何次數。**

- 排出來的那一段 `entitlementId` 是 `null`，課程就是它，`followupNth` 不碰 —— 第二種沒有額度的段
- 驗證：沒有額度的段，n返 **或課程是不算次數的**才放行
- 指派、醫師、時長、待辦、簽不簽療程單，全部照那門課自己的設定（`assignsFor()`、`doctorRuleOf()`、
  `slotMinutes()`、`systemsOf()`、`needsForm()`）—— 這一格只回答「扣不扣」一件事

## 「可以」不用額度，不是「不准」有額度

第一版寫的是「不算次數的課又指了一筆額度 → 擋下來」（同 n返：兩種身分只能挑一種）。那在功醫門診上成立，
但她說的是**之後自己勾別的課**。她一勾營養諮詢：

- 既有的營養諮詢每一段都帶著額度，`validateVisit()` 每一段都驗 —— 那幾天一律存不下去
- 種子的方案範本裡就有營養師諮詢，方案範本存不下去

所以：**有額度的照舊扣、照舊驗**。這位客戶身上如果有那門課的額度，額度那一顆照樣在那一排上，
旁邊多一顆「不扣次數」的 —— 她選哪一顆就扣不扣。方案範本、額度本身（`validateEntitlement()`）、
拍訂購單、批次建立都不擋它。

**加購那一排只是不列它**（`buy.js` 的 `courseChips()`）：一門不用加購就排得進去的課，買一筆沒有意義。

## 「這一段可以做什麼」只有一支

`domain/slotOptions.js` 的 `slotOptionsFor()` 回三種：額度（二返排最後）、「＋ n返」、每一門不算次數的課一顆。
壓表改用它；來訪編輯器的額度那一排多那幾顆（組那一段走 `slotFromPicks()` 的 `uncountedCourseId`）；
拍 Abovee 在 issue 08 接。n返 那一顆原本寫在壓表的畫面裡，一起搬過來。

後兩種在那一排上的值不是額度的 id（`NTH_PICK`、`uncountedPick()`），只活在畫面上。

## 它跟 n返 哪裡不一樣

| | n返 | 不算次數的課 |
|---|---|---|
| 課程 | 借那一次健檢配的二返 | 它自己 |
| 名字 | 讀時段上的快照（三返、四返） | 讀主檔 |
| 一定要指到一次健檢 | 是（`followupForVisitId` 必填） | 否 |
| 可以同時有額度嗎 | 不可以 | 可以（那一段就照舊扣） |

所以規則沒有寫進 `nthFollowup.js`，那一支的判準（「這一行會不會讓一筆二返被算成 n返」）一個字都沒動。

## 判準

之後每一行都可以拿來問一次：

> **這一行會不會讓一段不算次數的被算進某一筆額度，或反過來？**

查過的每一處（都靠「逐段比 `entitlementId`，null 永遠不相等」站得住，n返 走了一年的同一條路）：
次數（`counts()`／`summarize()`／`reconcile()`）、壓表卡片牆與「壓表登記」（`customerPools()` 只看額度）、
健檢鏈（`holdsExam()`／`claimedExams()` 以二返額度的 id 為軸）、資料健檢（`refState()` 對 null 回 `'none'`）、
療程單比對（不用簽的課不比）、長按選單與取消（只看狀態）。

## 確認框只講真的會發生的事

ADR-0070。這一支一起修掉三句對 n返 早就講錯的話：

- 新增：多一句「功醫門診不算次數 —— 客戶身上的數字一個都不會變」（只講沒扣額度的那幾段）
- 結案：「做了的 N 段扣掉次數」只數扣著額度的段；全是不扣的那天講「記成已完成，不扣次數」
- 取消：沒扣額度的段不講「次數也會還回來」

## 沒做的

- **試算表印不出這種段的記一句**：記一句是逐額度印的。n返 也一樣。要印得升 `SYNC_FORMAT`、她重貼 `.gs`，
  另開 issue 15
- **合併檔**每一段都要額度（`mergeImport.js`）—— 過去的功醫門診怎麼進來歸 issue 13
- **補登**（`backfill.js`）那一頁只列額度，沒有不算次數的課那一顆。補登是照額度一筆一筆補過去的次數，
  不扣次數的課沒有次數可以補；要補記一段過去的功醫門診走日曆 → 新增
- **一位完全沒有額度的客戶進不了壓表的佇列**（那面牆答的是「這個月還有誰要壓」，ADR-0041）。
  那一位走日曆 → 新增，或拍 Abovee

## 後果

- 她之後可以自己把任何一門課勾成不算次數，既有資料一筆都不會壞
- 一位什麼都沒買的客戶也排得進一段功醫門診
- 「每一段都有額度」從來不是系統的假設（`nthFollowup.js` 檔頭），現在第二個例外也走同一條路
