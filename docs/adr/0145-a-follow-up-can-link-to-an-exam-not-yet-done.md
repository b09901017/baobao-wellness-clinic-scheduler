# ADR-0145：二返可以先接上還沒做完的那一次健檢

日期：2026-10-09
狀態：已接受
推翻：`.scratch/asks-2026-09-24/issues/11` 那一句「只有已完成按得下去」（它沒有自己一支 ADR）與
[ADR-0112](./0112-records-and-the-checkup-chain-read-the-slot.md)「後果」最後一行（「這是哪一次健檢」那一排只剩已完成的健檢）。
延伸：[ADR-0022](./0022-followup-entitlements-are-expanded-in-pairs.md)（一次健檢配一場二返）、[ADR-0070](./0070-a-warning-may-only-say-what-really-happens.md)（只講真的會發生的）、
[ADR-0139](./0139-the-report-task-does-not-wait-on-the-follow-up.md)、[ADR-0142](./0142-the-booking-slot-goes-to-the-exam-whose-report-is-in.md)（接不上時名額怎麼排 —— 這一支是讓它接得上）。
舊的幾支一個字都不改。

## 背景

二返那一段上的 `followupForVisitId` 記著「這是哪一次健檢的」。2026-09-24 起那一排只有已完成的健檢按得下去
（她當時：「只有已完成按得下去可以，不要讓整個流程亂掉」）。所以健檢和二返當場一起約的那一場**接不上**，
而沒有連結的二返被 `owed()` 算成「約掉了一次」—— 這位客戶另一次健檢正開著的「約二返」在約好的那一刻被收掉。
ADR-0139、0142 都是在接不上的前提下補洞；兩支都寫著根本的解法是讓它接得上。

她 2026-10-09（逐字）：

> B 照建議的根本解法：允許先約，約的時候就綁在那次健檢上（讓「這是哪一次健檢的」那一排也列得出還沒做的健檢）。不要禁止先約，因為客人常當場一起約。

> 原則：連結只是記錄，任何一邊被取消或改期都只提醒、不連動（ADR-0070）。

五題的回答在 `.scratch/followup-link-before-exam/issues/01`「她 10/9 回的」。

## 決定

### 接得上哪幾次

**待確認、已確認、已完成、而且沒被別場活著的二返佔走的**（`followups.js` 的 `PICKABLE_EXAM`、`examChoicesFor()` 的 `pickable`）。
**取消、未到照舊接不上** —— 那一次不會有報告。三個入口（壓表、來訪編輯器、拍 Abovee）都問 `pickable`；
自動選好照舊「剛好一顆按得下去才選」，所以「一次做完＋一次排著」以後兩顆都按得下去、不替她選（她：「可以」）。

存檔驗證擋**新接上**的連結指到取消／未到的那一次。「新接上」問的是存著的那一份**這一天有沒有任何一段指著它**，不比位置：
二返自己改時間（`rebookSlot()`，ADR-0108）新的那一段接在尾巴、帶著同一個連結，照位置比會被當成新接上，
健檢後來取消了的話那一場二返連改個時間都存不下去。

### 還欠幾次（`owed()`）

**接在一次還沒做完（或取消、未到）的健檢上、還沒做的二返，不算「約掉了一次」。** 那一場是那一次健檢的，不是已經做完的那幾次的；
照舊算的話這一支等於白做（別次健檢的「約二返」照樣在約好的那一刻被收掉）。那一次做完之後它就算約掉了 —— 正好佔掉那一次。

- **指到的那一次不在手上這一份來訪裡就照舊算**：刪掉的健檢、或呼叫端只給了部分來訪（lessons 第二節）。當成沒約的話，
  存一次檔就會在資料庫裡長出一張「約二返」。
- **沒連結的照舊算**（舊資料、匯入的）—— 那一條退路一個字都不動。
- 有連結、還佔著的每一段只從一支出來（`linksOf()`）：「認領了哪幾次」「哪幾次定案了」「這一次約在哪」「幾場接在還沒做完的上面」
  以前是兩個幾乎一樣的迴圈。

「約二返」那張待辦長不長照舊問 `owed()`；客戶詳情那一句改成畫面的字與系統的帳分開（她：「二返完成才算」）——
「健檢做完 N 次：二返做完 a 次、約了 b 次（M/D…）、還沒約 c 次」，c 就是 `owed()`。

**空出來的名額只給真的還欠的那幾次**（量測抓到的，同一天補上）：以前那一場接不上、照舊算成約掉一次，剛好抵掉
「某一次舊健檢的『約二返』她先勾掉、那一場還沒記進來」那一種（ADR-0142「還沒動的同一類」）；接上之後名額空出來，
會溢到照位置算二返已經做完的舊健檢上多長一張（一出生就是錯的）。所以第一圈裡照位置算做完的那幾次最多只拿
「照舊全部算約掉」的那個數（`owedCounts()` 的 `counted`），多出來的只給還沒被照位置配到的。沒有那種連結時兩個數一樣。

### n返 同一條

她：「放寬」。`examChoicesForNth()` 與 n返 的存檔驗證都問 `PICKABLE_EXAM`；「＋ n返」那一顆只有一次排著的健檢也畫。
n返 以前每一次存檔都驗「接的那一次做完了」—— 放寬之後健檢被取消，那一天別段改一個字都存不回去，所以狀態也只驗新接上的；
「指到的那一天是一次健檢」照舊每次驗（那是資料對不對）。

### 一次健檢一場二返

回答她第 5 條：**一次健檢配一場二返**（ADR-0022：額度成對、次數一樣），要多約一場走 n返。以前只靠畫面那一排把被佔走的那一顆關掉，
而壓表那一排讀的來訪只到目標月份月底；現在存檔驗證拿全部來訪擋新接上的第二場，講出被哪一天那一場佔走。兩場本來就接同一次的舊資料照樣存得下去（資料健檢列）。

### 二返不可以比它接的那一次健檢先簽成做了

她：「簽二返時，所接的健檢沒做完就擋」。接得上排著的健檢之後才會發生：二返先 ✓ 的話那一次健檢被當成「二返做完了」，
健檢做完時追蹤健檢報告不長（ADR-0139「二返做完了才不追」），整條鏈安靜地跳過。

- 判斷只有一支（`followups.js` 的 `cannotClose()`）：接的那一次做完了，**或同一張抽屜裡健檢那一段也打了 ✓**，才放行。
  沒連結的照舊簽得下去、照舊扣（舊資料那一條退路）；接的那一次不在手上那一份裡就不擋（不知道就不擋）。
- 抽屜那一列的 ✓ 按不下去、講出原因，「全部 ✓」跳過它，✗ 照樣按得下去。
- `closeVisit()` 帶著 guard 時自己也擋（ADR-0111 的形狀）—— 抽屜存的那一下拿剛讀回來的全部來訪再問一次。

### 健檢取消、未到、改成別的課程：只講，不連動

她：「連結只是記錄，任何一邊被取消或改期都只提醒、不連動」。所以**不自動取消二返、不自動搬連結**（沒有任何一筆資料記著
「這一次是那一次改期來的」，猜就是替她接錯）。講的地方：

- **取消那一道**（日曆長按、編輯器 ×、批次取消、確認抽屜 ✗）：「M/D 那一場二返接在 M/D 那一次健檢後面 —— 不會跟著取消；
  重新約好健檢之後，回到那一場二返換『這是哪一次健檢的』」。判準是那一次**本來接得上、之後接不上了**，接在它上面的還佔著
  （`consequences.js` 的 `strandedFollowupLines()`）。四個入口共用 `cancelChainLines()` —— 以前批次取消與確認抽屜各寫一次「逐段套上取消 → 問約二返」。
  確認抽屜有 ✓ 也有 ✗ 的那一條沒有確認框，那一句講在存完那張卡片上。
- **簽療程單抽屜**健檢那一段按 ✗：同一句（「不會跟著改成未到」）。
- **改這一段**把健檢改成別的課程（`rebookSlot()`，那一筆沒有活著的健檢段了）：同一句。同一天改時間不講 —— 新的健檢段在同一筆裡，連結自動跟著。
- **另約一次健檢時**（她回的第 2 題：「要」）：壓表、日曆新增、拍 Abovee 存一段新的健檢，這位客戶有一場二返還接在取消／未到的那一次上 →
  存檔前那一道多一句「M/D 那一場二返還接在『已取消』的 M/D 健檢上 —— 要接到這一次的話，存好之後去日曆點那一場二返改」
  （`strandedOnNewExamLines()`；哪幾場只問 `followups.js` 的 `strandedFollowups()`，資料健檢也用它）。

順手修的：壓表存一段二返時那一句「待辦上那一張『約二返』會自己收掉」是寫死的 —— 以前只接得到做完的健檢才成立，接在還沒做完的上面時根本沒有那一張。
改成拿存檔真的在跑的那一支試算（`followupBookingLines()`，ADR-0070）。

## 後果

- 健檢和二返當場一起約：那一排按得下去、存得下去；別次健檢的「約二返」不再被收掉。健檢做完 → 長追蹤健檢報告、不長這一次的約二返（已經約了）。
- ADR-0142 的名額排法照舊是沒連結時的退路；先約的都接上之後，碰到它的只剩舊資料與她沒選的那幾場。
