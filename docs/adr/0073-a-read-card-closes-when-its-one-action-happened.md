# 讀取卡片在它唯一的動作**真的發生**之後自己收掉

2026-09-05 她回報日曆上勾一件待辦的動線：

> 我發現日曆的 todo 勾掉他會問確認，然後我按確認之後他又會立刻跳出要不要收回？
> …我希望是我勾掉然後按確定後，他就直接勾掉，而且不要跳出要不要收回的確認。

她沒有看錯 —— 畫面真的又問了她一次。

## 「原地重畫」在她眼裡是「跳出第二張」

`views/calendar.js` 的 `openNoteCard()` 勾完之後呼叫 `paint(next)`，而 `paint()`
的實作是 `openCard({...})`。`ui/components/card.js` 的 `openCard()`
**第一行就是 `closeCard()`**：舊那一張的節點被 `remove()`，一張全新的
`.popcard-backdrop` 塞回 `document.body`。

所以「同一張卡片換一顆按鈕」這個心智模型只存在於寫程式的人腦裡。她看到的是
一張 `aria-modal` 的對話框消失、另一張跳出來，而新那一張最顯眼的東西是主要
按鈕上的五個字：

```
拿回來，還沒做
```

那句話讀起來就是「要不要收回？」。

## 決定

**一張讀取卡片上唯一的那個動作真的發生之後，卡片自己收掉。**

判準是**寫入那一層回報的結果**，不是按鈕上寫了什麼：

```js
const next = await toast.withSaveState(plan.run, { success: plan.success });
if (Boolean(next.done) !== Boolean(current.done)) {
  closeCard();
  return;
}
paint(next);   // 沒有真的變 —— 留在原地照實說
```

## 那個 `if` 是這一支的全部

拿掉它比較順，而且十次有九次看不出差別。第十次是這樣的：

營養品的提醒只給了一部分時，`data/notes.js` 的 `recordDelivery()`
**刻意把它留成 `done: false`**，只把文字換成剩下的那幾款（她的原話：「假設我
當天忘記給了，然後可以記我給了那些多少」）。那一次她按了「勾掉」而它**沒有
被勾掉** —— 卡片這時候收掉，畫面就在說一件資料庫沒有發生的事。

那正是 SPEC 第 6.9 節與 ADR-0070 同一條線上的東西：**樂觀更新要誠實**，
畫面上的每一句話都要對得上真的發生的那一組寫入。

所以規則的完整版是：

| 資料庫 | 卡片 |
|---|---|
| 真的勾掉了 / 真的拿回來了 | 收掉 |
| 按了勾掉，但它沒有被勾掉（沒給完） | 留在原地，按鈕還是「做完了，勾掉」，文字換成剩下的 |

`tests-e2e/specs/01-products.spec.js` 的 **J-E9 就是這一格的護欄**：它在部分
交付之後讀 `[data-tick]` 的字，期待卡片還開著。下一個嫌這裡不順的人拿掉那個
`if`，J-E9 會紅 —— 那支測試存在的理由就寫在這裡。

## 底下那顆「復原」是另一件事，不動

畫面上這一刻有兩個東西可以叫做「收回」，她說的只有一個：

| | 是什麼 | 動不動 |
|---|---|---|
| 新跳出來那張卡片上的「拿回來，還沒做」 | `aria-modal` 的對話框，**擋在畫面中間** | 拿掉 |
| 底部 toast 上的「復原」 | `ui/toast.js` 的 `saved()`，8 秒後自己消失 | **不動** |

分界是「**擋不擋路**」：toast 不跳、不確認、不擋任何東西，而且它是 SPEC 第 6.3
節要求的、「按錯了救得回來」的那一半。她說的是「跳出要不要收回的**確認**」。

## Consequences

- **抽屜要自己跟上。** 卡片收掉之後，底下那一天的抽屜是她唯一看得到的東西
  —— 它在這之前從頭到尾只在 `openDay()` 那一刻畫過一次，而卡片關掉時跑的
  `render()` 重畫的是月曆那一片（抽屜掛在 `document.body` 底下，不在 `el` 裡）。
  所以這條決定同時要求 `openDay()` 提供一支就地重畫，走 `sheet.update()`
  —— 那一支不重設捲動位置，`components/sheet.js` 上的註解寫的就是
  「勾一筆隨手記不該把她捲回最上面」。
- **那幾列的監聽要接在 `onMount` 上。** `sheet.update()` 換掉整塊內容，逐顆掛
  上去的 click 跟著節點一起沒了。**只有那一圈搬進去** —— `wireLongPress()`
  與 `wireAddMenu()` 委派在 `sheet.el` 上，而它在 update 之後還是同一個節點，
  搬進去會每重畫一次多掛一組（`components/actions.js` 的檔頭記著這個 repo
  修過三次同一種）。
- **少掉一次整月重讀。** 在這之前 `paint()` 每重畫一次就觸發舊卡片的
  `onClose` → `render(el)`，也就是每按一次「勾掉」都重讀一整個月的來訪、
  行事備註、隨手記、四份主檔與備忘錄。現在一次寫入最多 `render()` 一次。
- **這條規則不只管待辦。** 之後任何一張讀取卡片長出「唯一的動作」時，判準都是
  同一句：**寫入那一層說它發生了嗎？** 說了就收掉，沒說就留在原地照實說。
  今天全站只有待辦這一種（ADR-0045：來訪與行事備註要按鉛筆才改得動）。
