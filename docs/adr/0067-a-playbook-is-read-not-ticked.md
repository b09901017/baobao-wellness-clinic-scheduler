# 備忘錄是拿來讀的，不是拿來勾的

2026-09-03 她要的：

> 我希望新增一個功能是，備忘錄，就是我可以記錄一些自己的心得或是要注意的事項……
> 像是復健科流程 這個就是屬於我會習慣的我會漸漸上手的，只需要當下打開備忘錄看
> 就好，不用什麼事前提醒或是事後提醒……在手機版可一鍵隨時查閱，
> **不需要變成打勾任務**。

這一輪三件事出自同一個問題：「哪些該變成待辦、哪些我自己記得就好」。
判準寫在 `.scratch/asks-2026-09-03/spec.md`：

> 忘了會有一個人白跑一趟、或一筆錢收不回來 → **待辦**
> 忘了只是那一次做得比較慢、比較不順 → **備忘錄**
> 忘了會讓她在客人身上做錯一件事 → **標記**（ADR-0064）

## 決定

**新的頂層集合 `playbooks`。它不勾、不上日曆、綁課程不綁人。**

```js
{
  title,        // '營養點滴'
  tag,          // '點滴' | null。分類，選填
  courseIds,    // ['course-iv-drip']。掛哪些課程，選填
  sections: [{ heading, when, body }],   // 有序
  pinned,
}
```

## 「備忘錄」這個詞原本是「隨手記」的禁用同義詞

`CONTEXT.md` 的「隨手記」`_Avoid_` 那一行本來寫著**備忘錄、筆記、便條**。
兩個東西完全不同：

| | 隨手記 | 備忘錄 |
|---|---|---|
| 誰讓它出現 | 客人臨時說的一件小事 | 她自己整理的一段流程 |
| 會不會消失 | 會 —— 勾掉就沒事了 | 不會，它是要一直查的 |
| 上日曆嗎 | 掛了日期就上（ADR-0044） | 不上 |
| 綁誰 | 選填綁客戶 | 綁**課程**，不綁人 |

2026-09-03 她的決定：**這個東西就叫備忘錄**，把「隨手記」的 `_Avoid_` 裡那一項
拿掉，然後在兩個詞條上各寫一行界線。畫面上的抬頭寫「備忘錄 / SOP」——
SOP 那三個字讓「這不是隨手記」一眼看得出來。

## 為什麼綁課程不綁人

綁客戶的東西已經有三種了（永久限制、備註、隨手記），第四種只會讓她每次都要
想一下該記在哪裡。而「點滴要注意什麼」對每一位客人都一樣 ——
不一樣的那些是臨床提醒（ADR-0064）。

## 為什麼是頂層集合，不是 `config/` 底下的主檔

主檔的東西有一個共同點：**別的資料用 id 指著它**（時段指課程、來訪指診間）。
備忘錄沒有人指著它，是它去指別人。

而且 `config.loadAll()` 會把每一種主檔全部讀進來，設定頁與壓表都在呼叫它。
備忘錄的內文是長文字，塞進去等於她每次進壓表都多下載幾千字，換不到任何東西。

## 一節可以標「時機」，那是這一整支唯一系統看得懂的東西

四個值：事前 / 當天 / 結束後 / 隨時看（預設）。**這不是我們發明的分段**，
是她自己的筆記本來就有的結構（點滴那一份寫成「前情提醒／當天／結束」）。

標了時機的那一節會在她真的在做那件事的時候自己浮出來
（`ui/components/playbookHint.js`）—— 那就是「飯後打針該何時提醒」的答案：

- 日曆上點開那一筆來訪 → 時機由 `whenForVisit()` 決定
- 待辦的「跟客人確認時間」 → 固定「事前」，因為那一頁的定義就是還沒發生，
  而**她按下那一列的時候正在打那則訊息**

**不多開一張要勾的東西。** 她自己講了「避免洗版」。

## 這一頁沒有勾選框、沒有進度、沒有百分比

一放勾選框它就變成第二個待辦中心，而她已經有一個了。這是這個決定裡最容易
被「順手加一下」破壞的一條，所以 `tests-e2e/specs/15-playbook.spec.js` 的 P8
直接數畫面上有幾個 checkbox。

## Consequences

- **入口在待辦那一頁的右上角**，跟客戶頁的「看這個月的進度」同一顆
  （她指名的做法）。導覽列一個字都不動 —— 五格變六格會讓每一格從 20% 掉到
  16.6%，而她九成的時間在前四格上。
- **閱讀頁的簽名是那條脊線**：標了時機的那幾節畫在一條由深到淺的細線上，
  一節一個節點。**一節時機都沒標的那一份不畫線**（復健科流程就是那種）——
  結構要能講出內容的真話，講不出來就不要畫。
  節點刻意**實心不空心**：空心圓圈掛在一條直線上就是一排還沒打勾的勾選框。
- **內文比一般頁面大一級、行距 1.85。** `tokens.css` 那條「縮小的是包裝，
  不是資料」在這一頁走到底 —— 這一頁上全部都是資料，而她是低頭看這台、
  手在做另一件事的時候在讀它。
- **`visitReadHtml()` 一個字都不改。** 那一支是四個畫面共用的（ADR-0018、0056），
  而客戶詳情、待辦中心、進度追蹤問的問題都不是「這一場我該怎麼做」。
- `data/playbooks.js` 有**行程內快取**（任何一次寫入就丟掉）：它要在三個地方
  被讀到，而它幾乎不變。她在另一台裝置改了這一台不會馬上知道 ——
  那被接受，備忘錄不是會對不起來的資料。
- `data/backup.js` 與 `scripts/restore-backup.mjs` 兩邊一起加了。
  那一支的檔頭記著 `notes` 與 `events` 被漏掉過一次。
