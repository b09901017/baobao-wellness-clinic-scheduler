# 舊資料匯入吃貼上的文字，不接 Google Sheets API

要讓 app 自己去讀那 20+ 張工作表，就得有一把長期有效的 Google 憑證擺在某個地方。ADR-0010 為了同一件事的反方向（把資料寫回試算表）拒絕過一次：那把金鑰會變成第三個放客戶健康資料鑰匙的地方，而它外洩的後果是全部客戶的資料外洩。匯入的方向沒有比較安全 —— 讀取權限一樣讀得到全部內容。

而且匯入是**一次性的**。為了一件這輩子只做一次（正式上線前可能做兩次：試一次、真的一次）的事去接一條要長期維護的整合，划不來。所以匯入的入口是一個文字框：她在試算表裡全選複製，貼進來，一張工作表一次；`domain/legacyImport.js` 的 `parseDelimited()` 同時吃 CSV 與 TSV，因為從畫面複製出來的是 TSV、從 Google 下載的是 CSV，兩種都要能接而不必問她那是哪一種。

## Consequences

20+ 張工作表就是貼 20+ 次。這被接受：貼上的動作在 iPad 上是兩下，而每貼一張她都會在報告上立刻看到那一張讀出了什麼 —— 一次全部吞進去反而看不出是哪一張出了問題。

沒有任何憑證、沒有任何排程、沒有第二份解析實作。要重跑就再貼一次，同名的客戶會被整張跳過（見 `domain/legacyImport.js` 的 `planForSheet()`），所以重複貼不會建出第二份。

代價是這條路沒辦法自動察覺舊試算表之後又改了什麼。這不是問題：匯入完之後試算表就不再是資料來源了（SPEC 第 4.8 節），它變成 app 產生的報表。
