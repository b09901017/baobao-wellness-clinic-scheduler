# 一次營養品購買是一筆紀錄，交付走一筆有日期的隨手記

ADR-0057 把營養品做成「一筆排不進來訪的額度」，一筆額度一個 `productId`。
2026-08-27 她講出實際怎麼記的：

> 營養品其實也算是額度，然後會有金額，次數1就是一個月2就是兩個月的，我都會一次給，
> 然後同一次裡面會有很多種類例如 營養品(5000) : 夜態美+速體淨+粒能康+GABA 7/6 順便給，
> 我都是等客人哪天有預約來，我就順便給

三件事，ADR-0057 那一版一件都表達不出來。

我們決定：**一筆營養品額度 = 一次購買。**
它有 `items[]`（好幾款）、`amountTwd`（一個金額）、`totalQty`（幾個月），
交付走一筆有日期的隨手記，結果記在額度上的 `deliveries[]`。

## 一次購買一筆，不是一款一筆

`營養品(5000)` 的 5000 是**整包**的價錢。拆成四筆額度的話，它只能重複填四次
（然後合計是 20000，錯的）或者攤分（然後每一筆都是一個她沒講過的數字）。

「7/6 一起給」同理：四筆各自有一個交付日期，而實際上只發生了一件事。

ADR-0057 沒有錯，它只是還沒問到這一層 —— 那一版解決的是「加購那一排丸子上
根本沒有營養品這個選項」，而那件事解決了。

**次數改成論「個月」**（`unitOf()`）。以前寫「份」是猜的：一次購買裡有四款，
「2 份」那個數字對不上任何東西。

## 舊資料只在讀的時候相容

`itemsOf()` 讀不到 `items` 就退回單數的 `productId`，當成一款的清單。
**不寫回去、不自動搬**（ADR-0011 的同一條原則）—— 她下次編輯那一筆時才換形狀。

`payload()` 從此把 `productId` 寫成 null。舊的那幾筆身上還有值，讀得懂就好。

## 交付不是第八種日曆顏色

她要的是「記上日曆成為 todo 然後也可以改期」。日曆上**已經有**那個東西：
有日期的隨手記就是日曆的「待辦」那一類（ADR-0044、0045）。

所以提醒就是一筆隨手記，多一個 `entitlementId` 指回那一包。改期＝改那一筆的
日期，一行程式都不用寫。**色相已經用完了**（ADR-0039），第八種一律先想
「有沒有不用顏色的畫法」，而這裡的答案是「不用新畫法，用既有的那一種」。

## 提醒是隨手記，紀錄是額度

兩份不是重複，它們的壽命不一樣：

- **隨手記會被清掉。** 她自己按「清掉這 N 筆已完成的隨手記」。
- **「7/6 給了什麼」不能被清掉。** 那是要進試算表的紀錄。

所以交付寫在額度的 `deliveries[]`，隨手記只負責提醒。勾掉那一刻兩件事寫在
**同一個 commit** 裡（`data/notes.js` 的 `recordDelivery()`）—— 分開寫的話
「勾好了、交付沒記到」會留下一筆看起來做完、其實查不出給了什麼的紀錄。

## 沒給完就留著那一筆提醒

她的原話：「假設我當天忘記給了，然後可以記我給了那些多少」。

給了兩款、還差兩款時：那一筆隨手記**不勾掉**，文字換成剩下的兩款。
留著原本那一整串她會以為四款都還沒給。

**日期不動。** 隨手記的日期不是死線（`domain/notes.js`），過了也不會變紅字；
自己往後跳一天會讓她以為是系統排的，而那不是系統知道的事。

## 建立的那一刻不猜日期

`createEntitlement()` 讓呼叫端傳 `deliverOn`，客戶詳情那一頁從已經讀好的來訪
算出「她下一次會見到這位客戶是哪一天」（`nextDeliveryDate()`）。

批次建立新客戶時**留空白** —— 新客戶身上還沒有任何來訪。
**不要退回今天**：一個掛錯日期的待辦比一個沒有日期的待辦糟，
前者她會照著做，後者她會去挑一天。

## 試算表升到格式 3

營養品以前混在矩陣裡，而那四個數字欄印的是月數 ——
「應有 2 已完成 0 已排未上 0 剩餘 2」沒有一個看得懂。

2026-08-27 她在兩條路裡選了乾淨的那一條：**營養品自己一區**，
帶金額、哪幾款、哪天給了。代價是 `SYNC_FORMAT` 升到 3，而
**她必須回 Google 試算表把 `.gs` 重新貼一次並重新部署** ——
`.gs` 收到不認得的版本會整份拒收。

那個代價是被明確接受的，不是漏掉的。`tests/sheet-script.test.js` 盯著兩側的
版本號一樣：對不上的症狀最糟 —— app 照樣推、`.gs` 整包拒收，
而失敗只留痕跡不跳彈窗（`data/sheetSync.js` 的 `noteFailure()`），
她要幾天後打開試算表才會發現數字停在某一天。

## Consequences

`entitlements` 多三個選填欄位（`items`、`amountTwd`、`deliveries`），
`notes` 多一個選填的 `entitlementId`。`firestore.rules` 只驗形狀 ——
裡面每一款指不指得到主檔在 `domain/products.js` 的 `validateProduct()` 擋，
同 ADR-0026 對 `doctorId` 的判斷。

`domain/entitlements.js` 的 `isProduct()` / `schedulable()` 兩道閘門一個字都沒改，
ADR-0057 的核心（營養品不可以流進任何「還要排幾次」）完全不受影響。

「＋ 新增…」讓她當場加一款沒有事先設定好的營養品。寫入那一下由呼叫端傳進
`commitNewProduct()`，這一支不 import `/data` —— `tests/buy.test.js` 直接載入
`components/buy.js`，而 `data/config.js` 那條路會一路 import 到 Firebase SDK 的
`https:` 網址，Node 載不動。
