# 壓表的記錄面板是疊上來的一組卡片，不是另一個畫面

SPEC 第 8.2 節原本把壓表的兩層切成兩種版型：`< 900px` 是兩個畫面（點一位進記錄，記完回卡片牆），`≥ 900px` 用 `.split` 左右並存。使用者實際用過之後要求：**點一位客戶要從中間浮出來，而且要能左右滑換下一位。**

我們把記錄面板從「另一個畫面」改成「疊在卡片牆上面的一張置中卡片」，一位客戶一張，左右滑就是上一位／下一位。三個斷點共用同一份，寬螢幕只是卡片更寬、旁邊多露一點，**不是另一套版型**。`.split` 的兩欄版型在這一頁因此用不到了。

換頁的代價比看起來大：她一次要處理二十幾位，每點一位就把「我剛剛看到誰、卡片牆捲到哪裡」洗掉一次。卡片疊上來則是牆一直在後面，關掉就回到原本的位置。左右滑則讓「下一位」變成一個手勢，而那正是這一頁最高頻的動作。

## 三個實作上的選擇

**左右滑交給 CSS 的 `scroll-snap`，不自己接 touch 事件。** 自己接會失去慣性、邊緣回彈與跨裝置的手感，滑起來就會「怪」—— 而這是她整晚都在做的動作。代價是要在每次重畫之後把捲動位置推回選中那張（`centerDeck()`），否則每點一顆泡泡畫面就跳回第一張。

**旁邊那幾張只畫認得出是誰的資訊**（姓名與剩餘次數泡泡），滑過去或點一下才展開成完整的記錄面板。全部都畫完整的話，二十三位客戶就是二十三份小日曆。

**方向鍵與手勢並存。** 卡片組的抬頭有上一位／下一位兩顆鈕，滑不動或不想滑的時候照樣換得了人 —— SPEC 第 8.0 節的「無拖拉」講的是不靠拖拉才做得到的功能，這裡的手勢只是快捷方式。

## Consequences

ADR-0014 沒有被推翻：一批仍然是一個月的一串客戶，順序仍然在批次建立當下凍結，這一頁仍然不出建議時段。改變的只是「點一位」之後發生什麼事。

選中的那一位一定留在卡片組裡，就算她把篩選切成別的 —— 正在處理的人從畫面上消失是最難懂的一種畫面。

卡片牆上的「快到期」篩選拿掉了，理由見 ADR-0019。
