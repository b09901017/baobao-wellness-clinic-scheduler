# ADR-0156：長備註是備註的長版本；備註那一段電話、LINE、長備註、短備註一起排順序

日期：2026-10-19
狀態：已接受
延伸：[ADR-0019](./0019-customer-notes-become-coloured-marks.md)（備註是短的彩色標記、`notes` 是它的純文字鏡像 —— 照舊）、
[ADR-0067](./0067-a-playbook-is-read-not-ticked.md)／[ADR-0069](./0069-a-memo-is-one-box-of-text.md)（備忘錄：一疊左右滑的卡、標題＋一大塊字 —— 長備註那一頁借它的骨架）、
[ADR-0060](./0060-a-row-answers-two-gestures.md)（長按是捷徑，要另外有一條點得到的路）

## 背景

備註（`customer.marks`）是 `{ text, color }` 的陣列，一則最多 40 字、最多 12 則 —— 設計成「掃一眼就懂的短標記」。
她有時候要記的是一大段（家人怎麼接送、打點滴前要注意的），只能拆成好幾則；10/18 切換前的檢查也真的抓到一則 51 字的。
她 10/18：

> 能不能像是備忘錄那樣，多一個地方是可以讓我記所有人的備註 … 可以像備忘錄一樣選人寫備註，有標題，然後一樣可以左右滑，搜尋人等等，
> 並且我希望綁定人之後，這個人的詳細頁面中的備註那邊，可以有一個地方看到他的長備註 … 點開以後可以在畫面中間的卡片看到完整備註
>
> 電話號碼也可以幫我呈現在備註這邊，然後也希望可以自己調整備註的順序，也許可以用拖曳的方式
>
> LINE 有填也放 … 點了就打開他的 line … 有些短備註我也會希望可以排到前面，電話，line有些人我也希望可以排到後面

10/19 她看過可以點的原型，選了：**全部是丸子**、中間那張卡**從那一則長出來**、電話與 LINE 的圖示是**線條**。

## 決定

### 長備註存在客戶身上，是備註的長版本

`customer.longNotes: [{ id, title, body }]`。標題必填（40 字）、內文 5000 字（跟備忘錄同一級）、一位最多 20 則
（Firestore 一份文件 1MB；20 則塞滿約 300KB）。

**不新開集合**：備份、稽核、刪客戶、改名全部自動跟著；Rules 只在 `validCustomer()` 多兩條型別檢查。
ADR-0067 擋的是「綁客戶的東西第四種」，這不是第四種 —— 它就是備註，只是長。

### `marks` 一個字都不改形狀

二十幾處讀 `customer.marks`（壓表卡片牆、客戶清單卡片、試算表的 `customer.notes` 鏡像、拍訂購單的「尾款」、合併檔匯入…）。
它們照舊只看到短備註：**長備註不進試算表、不上壓表卡片牆、不上讀取卡片**。

### 順序另外存一份，短備註只佔位置

`customer.noteOrder`：`['phone', 'mark', 'long:<id>', 'mark', 'line']` 這種「第幾個位置放哪一種」。
**第 n 個 `'mark'` ＝ `readMarks(customer)` 的第 n 則** —— 短備註沒有 id，給它 id 就是改 `marks` 的形狀。

- 別的入口加一則短備註（只會接在最後：拍訂購單的「尾款」）→ 沒有位置的接在最後，原本的順序不亂
- 順序裡指到不存在的東西（刪掉的長備註、清掉的電話、多出來的 `'mark'`）→ 跳過
- 不在順序裡的電話、LINE（排的時候還沒填）→ 放最前面
- **沒排過**：電話、LINE、長備註、短備註（她：「最上面一行電話，長備註，原本的短備註」）

讀這一串只有 `domain/customerNotes.js` 的 `noteItems()` 一支；存回去只有 `notesFields()`（`marks`、`notes`、`longNotes`、`noteOrder` 同一個 commit）。

**拖過順序之後短備註本身也照新的先後重排**（形狀不變、只有先後）：第 n 個佔位要指到第 n 則，換位置就是換陣列裡的先後。
所以卡片牆、客戶清單卡片上的前幾則會跟著她排的變 —— 她 10/19：「沒關係，我同意這樣處理」。

### 電話、LINE 只是位置

值照舊是 `customer.phone`／`customer.lineId`（在編輯客戶的表單裡改），沒填就不畫、不佔位。

- 電話點了撥號（`tel:`，一格寫兩支的撥第一支）；**按住複製**。按住是捷徑（ADR-0060）：
  號碼本身就印在那一顆上，也在「編輯」客戶資料那一格裡選得起來複製 —— 那是點得到的那一條路
- LINE 點了開他的 LINE：那一格是 LINE 的網址就原樣開；是 ID 就開 `https://line.me/R/ti/p/~<ID>`（`@` 開頭的官方帳號不帶 `~`）。
  **不是 LINE 的網址不當網址開**（那一格是她打的字）。表單那一格的 `?` 講一句「貼他的 LINE 連結最穩」

### 畫面

- **平常全部是丸子**（她選的），照她排的順序一排流下去；長備註是茶色那一顆（便條＋標題＋›）
- **點長備註 → 中間那張卡從那一顆長出來**（`ui/components/noteCard.js`）：返回鍵關的是卡（推一層）；可以捲、可以就地改。
  WAAPI 不吃 `app.css` 的 reduced-motion 規則，所以自己問 `matchMedia()`，是就只淡入淡出
- **調整順序在詳情頁原地拖**（`ui/components/noteReorder.js`），不在抽屜裡 —— 抽屜自己有直向拖曳，兩個搶同一個手勢。
  排的時候才變成一列一列（拖曳要固定高的列）；拖到畫面上下緣自己捲 `.app__main`；鍵盤上下鍵也排得動
- 「編輯」那一張（`ui/components/notesEditor.js`）：一則一列可以刪，加短的或長的；電話、LINE 那兩列只寫「在『編輯』客戶資料裡改」
- 抬頭的數字＝短備註＋長備註（電話、LINE 不算）

### 稽核

`longNotes`「長備註」、`noteOrder`「備註的順序」都**不進** `QUIET_IN_SENTENCE` —— 順序是她拖過的，講「改了 備註的順序」才誠實。

## 後果

- 短備註的 40 字／12 則照舊（ADR-0019 的理由還成立：掃不完的標記等於沒有標記）；長的有了去處，不用再拆
- 新增客戶那一頁照舊只有短備註（`marks.js` 的 `mount()`）—— 長備註在建好之後加
- 一位客戶的備註那一段，以前一定只有短備註；現在一位有電話的舊客戶會多一顆電話丸子（有填才有）
- 再多一個寫 `marks` 的入口時：只要是接在最後或原地改字，順序都不會亂；**要是從中間刪掉一則，要連 `noteOrder` 的第 n 個 `'mark'` 一起拿掉**
  （編輯器走 `notesFields()`，自動對）—— 不然後面的短備註會往前錯一格（錯的只會是短備註之間，不會錯到電話或長備註的位置上）
