# 次數在詳情頁現算，在清單頁讀計數欄位

三段式次數（已完成／已排未上／剩餘）的真相永遠是 `visits`，`entitlement` 上的
`doneCount` / `bookedCount` 只是快取。客戶詳情頁一次只看一位，所以把該客戶的來訪讀出來
**現算**；客戶總覽一次要畫二十幾位，現算等於把全部來訪都拉下來，所以那裡**讀計數欄位**。
兩邊對不起來時，詳情頁把差異顯示出來並提供一鍵修正，不自動偷改。

## Consequences

清單上的數字可能短暫落後於現實，這被接受：她拿清單是為了決定先看誰，
決定之後點進去看到的就是現算值。真正不能錯的地方（詳情、壓表工單）一律現算。

代價是有兩條路徑算同一件事。為了不讓它們各自演化，`domain/entitlements.js` 的
`counts()`（現算）與 `summarize()`（讀快取）放在同一個檔案，`reconcile()` 就是它們的
對帳函式；SPEC 第 6.6 節的資料健檢頁之後會用同一支 `reconcile()` 全庫掃一次。
