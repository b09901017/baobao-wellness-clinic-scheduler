# 一列回答兩個手勢：點一下是看，長按是做

ADR-0020 定了「先給看的，不先給改的」：

> 她點一筆的十次有九次只是要確認「那天幾點、誰、做什麼」。直接進表單等於
> 每一次都冒著改到東西的風險，而這一站最不能出錯的就是次數。

那條規矩是對的，而且要留著。但它對**第十次**很貴 —— 客人剛剛在電話裡說可以，
她要走的是「點那一天 → 點那一筆 → 按鉛筆 → 找到狀態卡 → 按確認」五層。

2026-09-01 她要的：

> 點一下：維持現有邏輯（看詳情）。長按：彈出快捷操作選單，
> 可以直接編輯、取消、或改變狀態。

## 決定

**一列回答兩個手勢。點一下的行為一個字都沒有變，長按多一條路。**

長按跳出來的那一張叫**快捷選單**（`CONTEXT.md`）。它省掉的是「找到那一筆」的
四層點擊，**不是那個決定本身** —— 取消一筆來訪照樣走二次確認，
四句後果一字不改（SPEC 第 6.5 節）。

## 為什麼不是每一列多幾顆按鈕

那是最直覺的做法，而且它會毀掉這幾頁。日曆抽屜一天十幾列、隨手記一頁二十幾列，
一列高度就那麼多；加三顆按鈕之後每一列都在喊，而她開那一頁是為了**掃**，
不是為了操作其中一列。ADR-0046 對壓表卡片牆講過同一件事（一張卡只回答一個問題）。

## 那張選單是一張疊上去的抽屜，不是第四種浮層

`views/home.js` 裡那句「這個 app 的浮層已經有三種了」還算數。所以
`ui/components/actions.js` 借的全部是既有的東西：`.drawer` 的樣式、
`wireDrag()` 的往下拖關掉、`pushLayer()` 的返回鍵、Escape、`hashchange` 收掉。
新的只有一件事 —— **它不會把底下那一張抽屜關掉**。

那一件事正是不能走 `openSheet()` 的原因：那一支開頭第一行就是
`closeSheet({ instant: true })`，它是**刻意的單例**（「兩張同時在畫面上滑
看起來像壞掉」）。而長按最重要的場景就是「日曆那一天的抽屜開著，長按裡面某一列」
—— 走 `openSheet()` 會把那一天整個關掉，她看完那一筆就找不回原本在看的那一天
（ADR-0020）。

也不走 `openCard()`：那一張是置中的，而長按是**拇指在螢幕下半部**做的動作。
角色也不一樣 —— 那一張是「一筆的細節，先看再改」，這一張是「直接做」。

## 有哪幾顆只寫在 domain

`visitActions()`（`domain/visits.js`）、`noteActions()`（`domain/notes.js`）、
`productActions()`（`domain/products.js`）。畫面不自己判斷，理由跟
`STATUS_VIEW` 一樣：兩份清單遲早會有一份准了一個狀態機不准的轉移，
而 Rules 不擋狀態機（ADR-0006），所以那一下會真的寫進去。

來訪那一份直接借 `nextStatuses()`，所以它不可能多出一個。

**「已完成」與「未到」不在選單上。** 那兩個是**逐段**的結果（ADR-0025：
客人做了兩段就走是會發生的事，而次數就是跟著它扣的）。整筆一起標會把那種情況
記錯，所以日子到了的那幾筆給的是一顆「客人來了，去簽療程單」，
通到待辦中心那張逐段的抽屜。

## 每一顆都要另外有一條點得到的路

`sheet.js` 的檔頭對拖曳寫過這一條（SPEC 第 8.0 節的「無拖拉」）：
**手勢是快捷方式，不是唯一的路。** 長按同理 —— 它是隱形的，而一個只有長按
才做得到的功能等於不存在。

所以每一顆在別的地方都點得到：狀態走來訪編輯器的狀態卡、勾隨手記走那一列本身、
改日期走編輯器、營養品的三顆在客戶詳情那一列（那一列因此改成點一下就開選單 ——
它不是清單裡的一列，是一個入口）。

## 450ms 與 8px

- **450ms**：400 以下會誤觸（她在抽屜裡捲動時手指常常先停一下再滑），
  500 以上會讓人覺得沒反應。
- **8px**：低於這個值捲動會被誤判成長按。
- 按壓回饋的 CSS 過場時間跟 450ms **對齊**：她看到那一列底色滿上來的瞬間，
  正好就是選單升起來的瞬間。那段等待因此是有回饋的，而不是「怎麼還沒動」。
- 底色用那一列自己的 `--kind-bg`（來訪就是狀態的顏色），所以按壓回饋順便
  再講一次「這一筆現在是哪一種」，而不是蓋掉它。

## Consequences

- 多一支 `ui/components/actions.js`，`public/sw.js` 的 `SHELL` 多一行。
- **五個入口的隨手記從此改得動**。ADR-0044 的 Consequences 記著
  「沒有編輯隨手記這條路，除了日曆上那一張卡」—— 長按補上了那個缺口
  （改日期、掛給誰、刪掉都做得到；改**文字**仍然只有日曆那一張編輯器）。
- 用 Pointer Events 而不是 touch + mouse 各接一次。`pointercancel` 是
  「抽屜正在被拖」與「她正在長按」唯一分得開的訊號。
- 長按成立之後**要吃掉接下來那一次 click**，不然手一放會同時跳出快捷選單與
  讀取卡片。`contextmenu` 也要擋（iOS 的放大鏡、Android 的系統選單），
  順帶讓桌機右鍵開同一張。
- 選單最多六顆（含「先不要」）。第七顆開始它就不是快捷方式了 ——
  她會停下來讀，而那時候該走的是編輯器。
