# ADR-0078：全站只有三種名字，「一般」那一種不存在

日期：2026-09-08
狀態：已接受
推翻：ADR-0077 的立論沒有被推翻；`domain/naming.js` 2026-09-06 那一版的
「一般＝課程全名(器材別稱)」被這一支拿掉

## 背景

2026-09-06 那一輪把一段來訪的名字拆成三種寫法：月檢視（`SIS`）、
一般（`復能(SIS)`）、LINE 草稿（`復能`）。ADR-0077 隔天把 LINE 那一種
定成「只講課程」。

她 2026-09-08 列出全站只該出現的六種項目：

```
復能-三選一(30/60)   復能-四選一(30/60)
復能-INDIBA(30/60)   復能-SIS(30/60)   復能-高能量雷射(30/60)
ILIB(30/60)
```

並且說：

> 我不希望出現復能(器材)，靜脈(IL)等其他格式，只會有以下這六種

問她「一般」那一種要改成什麼的時候，她的回答是這件事的關鍵：

> 我不太懂你的意思？以三選一然後當天做 SIS 30min 這個為例，
> app 中只會出現 在額度那邊寫復能-三選一(30)，月曆寫 SIS(30)，草稿寫復能

**她的模型只有三種字，而程式裡有四種。**

## 決定

**一、`slotName()` 只剩兩種寫法，第三種字是額度的名字。**

| 誰在看 | 哪裡 | 例 | 誰算的 |
|---|---|---|---|
| 她（當初買了什麼） | 加購、客戶詳情、壓表的額度丸子、試算表、稽核 | `復能-三選一(30)` | `poolName()` + `timedLabel()` |
| 她（那天做了什麼） | 月曆、日／週那一列、讀取卡片、來訪編輯器抬頭 | `SIS(30)` | `slotName(…, 'short')` |
| 客戶 | LINE 草稿 | `復能`、`靜脈雷射` | `slotName(…, 'line')` |

原本印 `復能(SIS)` 的三個地方（日／週那一列的副標、讀取卡片、來訪編輯器
每一段的抬頭）改印月曆那一種。讀取卡片底下本來就有一行「扣 復能-三選一(30)」
（ADR-0077 第五點），所以兩行合起來仍然完整：

```
10:30–11:00
SIS(30)・芝寧
扣 復能-三選一(30)
```

`NAME_CONTEXTS` 從 `['short','full','line']` 變成 `['short','line']`。
**認不得的情境退回 `short`** —— 漏改一個呼叫端的症狀會是「那一列整個沒有
名字」，那比多印幾個字糟得多。

**二、器材主檔上那兩格名字的分工定下來。**

```
全名   她叫它什麼           SIS、INDIBA、高能量雷射、ILIB
別稱   月曆那一格的縮寫     （空）、IN、（空）、IL
```

額度的名字讀**全名**（`復能-INDIBA(60)`），月曆讀**別稱**（`IN(60)`）。

所以那一台從「超磁場」**改名成 `SIS`** —— 她自己講的、寫的、記的都是 SIS
（ADR-0077 已經寫下這件事，只是當時把它放進了別稱那一格）。

兩邊都讀別稱的話，她列的第三種會變成 `復能-IN(60)`；兩邊都讀全名的話，
月曆那一格會是 `INDIBA(60)`，六個字塞不進七分之一個螢幕寬。

**三、額度名的標點照她寫的：半形括號、破折號兩邊不留空格。**

```
2026-09-07  復能 - 三選一（60）
2026-09-08  復能-三選一(60)
```

跟月曆那一格接分鐘的寫法一致 —— 同一個數字在兩個畫面上用兩種括號，
看起來像兩種東西。

**四、月曆的分鐘不再要求那一段有器材。**

單買 ILIB 的那一段身上沒有器材（ILIB 課程的 `requiresEquipment` 是 false），
而她列的第六種正是 `ILIB(30/60) -> IL(30/60)`。條件只剩一條：
這個課程有兩種以上規格（`durationChoicesOf()`）。

**五、設定 →「名稱怎麼寫」重畫成那六列。**

她的話是「設定就不用管復能或靜脈的課程命名，這兩個就固定用上面那六種」。

前兩列（三選一／四選一）**只給看**：它們是一種**買法**，背後沒有一筆主檔
可以存字。另外開一份存名字的地方，她改了 SIS 的別稱之後那一列會停在舊的。
那六列一列都不寫死，全部從器材主檔上的 `courseId` 推（ADR-0075），
跟加購那一排問的是同一句話。

## 為什麼

**三個地方三種讀者仍然成立**（ADR-0077 的立論）—— 只是「她自己看」的那兩個
地方（月曆與讀取卡片）用同一種寫法就夠了。多出來的那一種沒有讀者，
而一個沒有人看的寫法會在下一次改名的時候被忘記，然後某一個畫面就分岔了。

**兩格名字回答兩個問題比三格好。** 器材主檔上曾經有三格（全名、別稱、
LINE 名），而 LINE 名 2026-09-07 就已經畫不出來了。現在剩下的兩格
各自對到一個真的存在的畫面。

## 後果

- 既有額度身上的名字是購買當下的快照（ADR-0003），**不會自己跟上**。
  資料健檢的「復能額度還叫舊名字」認得出四代自動名字，一鍵改成新的。
  **她自己打的名字一個字都不動。**
- 既有資料庫上那一台還叫「超磁場」、INDIBA 還沒有別稱 —— 資料健檢新增一列
  「器材的名字跟建議的不一樣」。**兩格要同時還停在舊的才報**：她自己改過
  其中一格就是一個決定。
- 舊資料匯入的簡寫表（`.claude/skills/calendar-sheet-merge`）跟著改：
  器材那一格要跟主檔的全名一字不差，不然匯進去時那一格會留空並報一句
  「主檔裡沒有這個器材」。
- **一個邊界沒有處理**：如果她先按了「器材改名」再按「復能額度還叫舊名字」，
  那一筆叫 `超磁場(60)` 的舊額度（2026-09-06 那一代）會認不出來 ——
  `legacyPoolNames()` 是從**現在的**主檔算的，而那時候主檔已經叫 SIS 了。
  那一筆不會被改壞，只是不會被列出來，她要自己改。單買一台的額度
  2026-09-06 才買得到，所以最多兩天份。
- ~~`domain/visits.js` 的 `visitCourseLabel()` 讀的仍然是 `slot.courseName`
  快照~~ —— **2026-09-08 收掉了**（複查抓到的）。那是「拿快照當顯示名稱」，
  症狀是同一筆來訪在客戶詳情那一列寫「復能」、在日曆上寫「SIS(60)」，
  而她會以為那是兩筆。

  改成 `visitCourseLabel(visit, master)`：**帶了主檔就講顯示名稱**，走的是跟
  日曆同一支 `slotName()`；沒帶退回快照，所以既有呼叫端不用改。客戶詳情的
  來訪列與任務列、待辦中心「跟客人確認時間」那一排、`taskLine()`（含試算表的
  TODO／FINISHED 區）都帶了。

  **稽核紀錄刻意不帶**（`domain/audit.js`）：那一份記的是**當時寫下去的字**，
  主檔之後改名，歷史紀錄不該跟著變。`tests/visits.test.js` 盯著兩邊 ——
  該帶的都帶了，而稽核那一處維持讀快照。

## 其他做法

**額度也寫縮寫（`復能-IN(60)`）。** 兩邊都讀別稱，一行程式都不用改、主檔也
不用改名。她看過預覽之後選了另一個 —— 她列的第三種就是 `復能-INDIBA`。

**主檔留著「超磁場」，額度讀全名。** 那會讓額度變成 `復能-超磁場(60)`，
跟她寫的 SIS 對不上。

**保留「一般」當第四種寫法。** 六種裡沒有 `復能(SIS)`，而留著一個沒有讀者的
寫法只會在下一次改名時分岔。
