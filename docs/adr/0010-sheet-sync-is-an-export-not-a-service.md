# 試算表同步做成匯出，不做 Apps Script 定時抓 Firestore

SPEC 第 4.8 節寫「用 Apps Script 定時把資料寫回現有試算表格式」。要做到那件事，Apps Script 得拿一把 Firestore 服務帳號金鑰去讀整個資料庫 —— 那把金鑰會變成第三個放客戶健康資料鑰匙的地方（repo、Firebase Console、Apps Script 專案屬性），而它外洩的後果是全部客戶的資料外洩。同時排版邏輯會多出一份 `.gs` 的實作，跟 `domain/sheetReport.js` 講同一件事卻沒有測試。所以改成**app 產生報表、她複製或下載後貼回試算表**：`#/settings/report` 一頁，總表與逐位客戶的表都在裡面。

## Consequences

試算表不會自己更新，她貼過去才會變。這被接受：試算表現在是報表不是資料來源（SPEC 第 4.8 節），而報表本來就是「要看的時候產生一份」；她每個月坐下來整理一次，那時貼一次的成本比維護一條跨系統的定時管線低得多。

換來的是這條路上沒有任何一把長期金鑰、沒有第二份排版實作，而且報表的每一格都測得到（`tests/sheet-report.test.js`）。之後真的需要自動更新時，該補的是「排程觸發同一支匯出」，不是把邏輯搬到 Apps Script 裡重寫一次。
