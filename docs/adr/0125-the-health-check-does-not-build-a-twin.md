# ADR-0125：她已經有一筆同名的，資料健檢就不再建一筆

日期：2026-10-05
狀態：已接受
延伸：[ADR-0007](./0007-health-check-reads-only.md)（一鍵修正只做正解不需要判斷的那幾種）、
[ADR-0124](./0124-treatment-room-7-is-back.md)（治7 回來的那一列第一個用到）。舊的一個字都不改。

## 背景

`loadSeed()` 只建不覆蓋，所以種子多一筆之後，既有資料庫靠資料健檢的「種子有、她沒有 → 建起來」補
（課程、器材、診間，2026-10-05 起多了營養點滴品項）。那幾列**只比 id**：種子的 id 她沒有，就列出來。

但種子多的那一筆，她可能已經自己建了：

- 功醫門診她在 2026-10-05 之前就能在 設定 → 課程 建起來（只是排不進去）
- 治7 她說「加回去」—— 她自己在 設定 → 診間 加一間，比等這一列快

她自己建的那一筆 id 是隨機的。照 id 比的話那一列照樣出現，按下去就是**兩筆同名**。設定頁本來擋著這件事
（`validate()` 的同名檢查），而資料健檢的修正不經過那道驗證 —— 一顆按鈕繞過了一條規則。

## 決定

**「種子有、她沒有」那幾列，她還開著的那幾筆裡有同名的就不列。** 名字去頭尾空白之後一字不差才算；
停用的也算（它還在清單上、同名驗證也看得到它），刪掉的不算。

治7 那一列的還原也一樣：她自己另外建了一間治7，就不請她還原刪掉的那一間。
EECP「只能排在這幾間」補上治7 時，寫進去的是**她那一間的 id** —— 寫種子的 id 的話，限制指著一間不存在的診間，
畫面上治7 還是選不到。

## 為什麼不是別的做法

- **照樣列、按下去時把她那一筆改成種子的 id**：id 被來訪、額度指著，改不得
- **照樣列、把種子的設定蓋到她那一筆上**：她自己建的那一筆每一格都是她的決定（ADR-0002）
- **修正走一次 `validate()`、不過就擋**：她會看到一列按不下去的建議，而它永遠不會消失

## 後果

- 她自己建的那一筆**不會自動帶上種子的設定**（功醫門診的不算次數、三個系統、Abovee 上的寫法）——
  那是她在設定頁自己勾的事。名字一樣、設定不一樣時這一頁不會講
- 名字差一個字（「功醫 門診」、「治療室7」）就不算同名，那一列照樣出現；按下去是兩筆不同名的，設定頁看得到、刪得掉
- 新增一種「種子有、她沒有」的檢查要照這一條（`domain/health.js` 的 `sameNamed()`）
