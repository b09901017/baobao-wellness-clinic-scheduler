# ADR-0167：打開 app 先用手機裡的

日期：2026-10-21
狀態：已接受
推翻：2026-08-18 commit `0ae20497`「service worker 對自己的檔案改為網路優先」（那一次沒有 ADR）。
它的理由是「原本靜態檔案是快取優先，結果每次部署後打開都會先看到舊版，要再重新整理一次才更新」，
寫在 `public/sw.js` 檔頭「網路優先是為了『部署完打開就是最新的』——快取優先會讓每次改版都慢一輪」那一段。
延伸：[ADR-0016](./0016-web-fonts-with-a-system-fallback.md)（字體）、[ADR-0031](./0031-the-customer-form-is-its-own-page.md)（客戶填表那一頁）、
[ADR-0158](./0158-incomplete-read-does-not-save.md)（讀不完整不存）。舊的幾支一個字都不改。

## 背景

她 2026-10-20：

> 第一 : 我發現app有時候會載入很慢，尤其是剛打開app的時候，會卡在載入中5 6 秒，有辦法讓app先呈現畫面嗎，一般大神，資深工程師他們這都怎麼解決?，讓使用者使用起來更直覺順暢 ?

打開 app 時依序在等（讀程式碼估的；`after-golive 05` 在她手機上量，設定頁「打開要多久」）：

| 順序 | 在等什麼 |
|---|---|
| 1 | 一百多支程式檔，每一支都先問伺服器有沒有新版（`sw.js` 網路優先、`firebase.json` 給 `no-cache`），import 排好幾層 → 好幾趟來回才開始跑 |
| 2 | 登入：手機上 Firebase Auth 先載 Google 的 iframe、再換 token |
| 3 | 白名單：`accessState()` 讀 `allowedUsers/{uid}`（伺服器優先） |
| 4 | 待辦首頁：任務、來訪、隨手記、設定五份（伺服器優先），全部回來才畫 |

這四件都是網路來回，跟畫面要畫什麼無關 —— 她 99% 的打開都是「同一台、同一個帳號、還在白名單裡、資料跟上次差不多」。

## 決定一：程式檔先用手機裡的，新版本跳一條「有新版本・點一下更新」（issue 06）

- `sw.js` 照 `VERSION` 把 `SHELL` 整份預先裝好，打開 app 一支都不問伺服器。打開 app 的導覽（`/`、`/index.html`）回手機裡的 `index.html`；
  **`/form.html`（客戶在 LINE 裡點開的那一頁）與 `/__/auth/…`（Google 登入轉回來的那一頁）不碰**，照舊走網路
- 瀏覽器打開時自己會去比 `sw.js`（`no-cache`），不一樣就在背景裝新的那一份。**裝好之後不自己接管**（拿掉 `install` 的 `skipWaiting()`）：
  畫面最上面跳一條「有新版本・點一下更新」，她點了才叫等著的那一個接手、重新載入
- 她選的（2026-10-20）：「照你的建議：跳一條『有新版本・點一下更新』」—— 不是「下次打開自動換、不提示」，也不是「當下自動重新整理」（會打斷她正在打的字）
- **8/18 那一次缺的是這一條提示，不是快取優先本身**：快取優先＋自己接管＝打開那一次是舊的、要再整理一次才新，而且她不知道要再整理。
  現在打開那一次照樣是舊的，但有一條告訴她、點一下就換

### 那一條

- **放在最上面**（內容區的最上面，跟離線那一條同一個位置），不放底下：底部已經有導覽列、toast、懸浮鈕、釘住的條四樣在搶
  （`CLAUDE.md`「貼在畫面底部的東西」）。它在文件流裡，出現時內容往下讓，不蓋住任何東西
- **不擋任何操作**，右邊一顆 × 收掉。收掉之後：所有視窗都關掉時，等著的新版會自己換上 —— 下次打開（從多工畫面滑掉再開）就是新的；
  app 一直開著就照舊是舊的，下次打開還在等就再跳
- 第一次安裝時 `clients.claim()` 也會來一下 `controllerchange` —— 只有她按了更新才重新載入
- app 開著一整天也看得到新版：回到 app（`visibilitychange`）時請瀏覽器再比一次 `sw.js`

### 整份一起換

`install` 以前是 `Promise.allSettled()`（個別失敗不擋）。改成快取優先之後少一支的意思變了：那一支會**永遠**走網路（或離線時永遠缺），
而且跟別支不同版。所以改成 `addAll()`：**少一支沒下載到，這一版就不算裝好**，下次打開再試；她照舊用舊的那一份，不會新舊混著。
裝的時候不拿瀏覽器自己的 HTTP 快取（`cache: 'reload'`）。

### SDK 與字體不跟著版號清

以前它們跟 app 的檔案放同一格（`shell-vN`），換版時 `activate` 整格刪掉 → **換版後第一次離線打開會開不起來**（這個洞在網路優先時就在）。
現在放自己那一格（`external-v1`）：網址帶版本、內容不變，不用跟著清。換到這一版的那一次先從舊的那一格搬過來。

### 忘了升 VERSION 的代價變大了，所以有一道擋

以前忘了升是「慢一輪」；現在 `sw.js` 一個字都沒變，瀏覽器就不會裝新的 —— **她的手機永遠停在舊版**。
拿 git 比擋不住（CI 是 checkout 深度 1，拿不到 `develop`，只能跳過）。改成提交一份快照（`tests/shell-version.snapshot.json`：
VERSION ＋ `public/` 內容雜湊），`tests/shell-version.test.js` 重算比對：內容變了、VERSION 沒變 → 紅。**同一個 VERSION 只能對一份內容**，
所以同一支 PR 裡第二次動 `public/` 也要再加一 —— 號碼很便宜，多加一次的代價是她多點一次更新，少加一次的代價是永遠舊版。

### 逃生門

設定 →「程式」→ 重新下載程式：清掉這一台存的程式檔（只清 `shell-*`，Firestore 的資料快取與 SDK 那一格不碰）、重新整理。
萬一卡在舊版時不用叫她清瀏覽器資料。

## 決定二：這一台上次通過了，就先畫殼，登入在背景確認（issue 07）

- 白名單說可以的時候，這一台記下那個 uid（`localStorage` 的 `scheduler.allowedUid`，`data/auth.js`）。登出、沒有權限、沒登入時清掉
- 開機時記著 → **不等登入，直接畫殼**（底下那一排）；各頁照常畫，它們的讀取會排隊等登入（畫面上是那一頁自己的「載入中」）
- 登入回來之後：
  - 同一位、白名單說可以 → 什麼都不做（殼已經在）
  - 沒登入、沒有權限 → 換成登入頁／沒有權限那一頁，記的那一筆清掉 —— 下次打開直接是那一頁，不再先閃殼
  - **不同的一位** → 整個殼重畫，不拿上一個人的殼繼續
  - **連不上**（`unreachable`），而殼就是這一位的 → **留著殼**：記著他上次通過了，離線照樣用得了，雲端那一側照舊由 Rules 擋。
    不是這一位（新裝置第一次離線）→ 照舊「連不上・再試一次」
- **只記 uid，不記任何資料**。殼本身一筆資料都沒有，資料要等 Firestore 讀；伺服器那一側照舊由 Rules 擋（沒權限的人讀不到）。
  唯一不經過 Rules 的是只讀手機裡的快取（決定三），那一條先確認登入的就是記著的那一位
- **寫入等登入回答了才記是誰**（`repo.commit()` 先 `authStateReady()`）：整批都是新增的寫入不會先讀任何東西，不等的話稽核記成 `unknown`，
  而 Rules 只收 `actor == 她的 uid` —— 那一筆整批被擋。登入早就回答了的時候這一下馬上過
- 試算表推送（`sheetSync.wire()`）在確認之後才接
- 殼現在可能畫第二次：路由的 `hashchange`、離線那一條、「有新版本」那一條、回上一頁的連結各自只掛一次（換殼時先拆）
- E2E 的「登入好了」不再是底下那一排出現，是 `#root[data-access="allowed"]`（確認之後才掛）

她 99% 的打開是「同一台、同一個帳號、還在白名單裡」。被移出白名單或被登出時，她會先看到殼、過一下才換成那一頁 —— 只有那一次。

## 決定三：待辦首頁先用手機裡的資料畫，雲端回來有變再換（issue 08）

- 首頁那五份（任務、待確認、還沒結案、隨手記、設定）先讀手機裡的快取（`getDocsFromCache()`）→ 有就先畫；雲端那一份同時在讀，
  回來跟畫出來的不一樣（每一筆的 id＋`updatedAt`、設定那一份）才重畫 —— 一樣的話一個節點都不換。她 2026-10-20：數字可能閃一下（3 → 2）「可以」
- **快取那一份只拿來畫**：首頁上每一條存檔路按下去都自己重讀（確認、簽療程單抽屜讀那位客戶的全部來訪；勾待辦、勾隨手記只寫 `done`，
  健檢那一串在 `followupOpsAfterTaskChange()` 重讀）。雲端回來時改同一個 `ctx` 的內容（開著的抽屜握著它），抽屜開著時只換內容不重畫
- **不算進 ADR-0158 的 `cacheReads()`**（`repo.listCached()` 不經過 `noted()`）：那一道看的是「這一次存檔開始到寫入之間」有沒有讀到快取 ——
  她在快取那一份畫好、雲端還沒回來的那一兩秒按存檔，那一次就落在那一段裡。只拿來畫的讀取不代表 SDK 認為自己離線。
  離線時照舊擋（`listByCustomer()` 那幾條一個字沒動）
- **快取裡的東西不經過 Rules**：沒登入、換了一個帳號時，Firestore 照樣讀得出上一個人留下的。所以先問 `confirmedAsRemembered()`
  （登入回答了、登入的就是這一台記著通過白名單的那一位）才讀。被移出白名單的那一位在白名單問完之前會看到自己上次在這一台看過的那一份 ——
  那一份本來就在這一台的 IndexedDB 裡，移出白名單從來不會清它；她只有一個帳號
- 快取讀不出來（新裝置、清過資料：設定那一份不在手機裡）→ 不畫快取那一次，照舊等雲端。雲端那一份讀失敗、但快取畫過了 → 畫好的留著、講一句
- 快取讀取也要等登入回答（Firestore 要先拿到第一個 token）：省的是雲端那一趟，數字不會比登入早出來 —— 那一段是 issue 09（看她手機上的數字決定）
- 只做待辦首頁。別頁（日曆、客戶）要不要照做，量完再說

## 後果

- 被登出或被移出白名單的那一次，先看到殼、過一下才換成登入頁／沒有權限那一頁（`docs/常見問題.md`）
- 部署之後要在手機上點一次「有新版本」才看得到新版（`docs/STAGING.md` 上線檢查表）。剛部署完的第一次打開可能還沒裝好，再開一次
- 「明明改好了卻沒變」多兩個原因：沒點更新、忘了升 VERSION（後者有測試擋）
- E2E 攔不到瀏覽器去比對 `sw.js` 的那一下（Playwright 的 route 一次都沒被叫到）：`81` 用另一個網址註冊造出「新的一版在等」，
  換 VERSION 時清掉哪幾格、留哪幾格在 `tests/sw-cache.test.js` 拿假的 `caches` 跑 `sw.js` 本身
- 打包（147 支 → 1～2 支）不在這一輪：她說「量完再決定」（`after-golive-2026-10-20/spec.md`）
