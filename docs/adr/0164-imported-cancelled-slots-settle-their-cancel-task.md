# ADR-0164：匯進來的取消段，「取消 X」一出生就勾好

日期：2026-10-20
狀態：已接受
延伸：[ADR-0093](./0093-an-imported-visit-grows-no-tasks.md)（匯進來的來訪不長任務）、[ADR-0149](./0149-the-abovee-photo-status-is-what-gets-recorded.md)
（照片上已經放掉的段，「取消 Abovee」一出生就勾好）。不推翻：ADR-0106（勾過的才算做過）、ADR-0091（取消類逐段）。

## 背景

合併檔 v9（`.scratch/merge-v9-notes/`）起，匯進來的段可以是**已取消**或**未到**。她 2026-10-20：

> 如果那一整排有日期單是沒勾最下面寫得像是她忘記，就是她取消的理由，請不要全部都放入這個客戶的備註之中

她選了「建成那一天已取消的段＋取消理由」（課程與時間從 Abovee 那天取消的那一列拿）、客戶失約的建成未到。

一段取消了，`cancelTasksFor()` 就要一張「取消 X」叫她回去放那個時段。匯進來的那幾段在舊系統上**早就放掉了**。
ADR-0093 的做法是「已經發生的一張都不長」，但那一條在這裡不夠：

- 只有取消段的那一天整筆是已取消，`importedTasksFor()` 走 `syncTasksForVisit()` 的那一圈會**長一張沒勾的**
- 一段做完、一段取消的那一天整筆是已完成，匯入時一張都不長 —— 但之後**任何一次**存那一天（改一句記一句、簽療程單），
  `cancelTasksFor()` 找不到看過的一張（`seenTasks()`）蓋住那一段，就**補長一張沒勾的**

兩條路的結果一樣：待辦中心多一張叫她去放一個不存在的時段，而且是她切換那天之後第一眼看到的東西。

## 決定

**匯進來的取消段，取消類的待辦長一張已經勾好的**，跟來訪同一個 commit（`domain/taskRules.js` 的 `importedTasksFor()`）：

- 照 ADR-0149 的 `freed`：勾好的那一張才算「做過」（ADR-0106），之後再存那一天不補長
- 跟 `freed` 不一樣的是**每一種取消類都勾**，不只 Abovee。匯進來的段身上沒有任何一張掛號待辦，長得出來的只有
  「那一段壓在哪」那一種（`bookingSystemOf()`），而那一格在舊系統上一樣早就放掉了
- 說明寫「匯進來的舊資料，X 上那個時段早就放掉了，不用再去放」，不叫她回去
- 匯入頁「會多幾件要做的事」（`countNewTasks()`）只數沒勾的；勾好的那幾張另外數（`countSettledTasks()`），確認框講一句
- 已經發生的那一天其餘照 ADR-0093：一張都不長；還沒發生的段照常長掛號

未到的段不長任何取消類（它沒有被取消，`cancelTasksFor()` 只看取消的段）。

## 為什麼不是「匯入時乾脆不長，之後也不長」

那要在 `cancelTasksFor()` 裡認得「這一段是匯進來時就取消的」—— 多一個條件、多一個讀的地方，而那個條件在每一次存檔都要對。
長一張勾好的不用改任何規則：`seenTasks()` 本來就把勾過的當成做過。

## 後果

- 待辦中心的已完成那裡會多幾張「取消 Abovee」（取消的段各一張；同一天幾段一起取消的收成一張）
- 這條路沒有復原（`freed` 那一條的顧慮）：匯入沒有一顆按鈕會把這幾張軟刪除
- 新增一種會建立「已經取消」的段的匯入路，要走 `importedTasksFor()`，不要自己叫 `syncTasksForVisit()`
