# 日曆上的任何操作都不換頁，而且先給看的再給改的

ADR-0018 把「點日曆上的某一天」從整頁切換改成從底部滑出那一天，理由是她點下去
只是想知道「這天卡了什麼」，卻把「我在看八月」整個換掉。實際用過之後，同一個問題
在**其他四個入口**照樣發生：點月檢視上的人名跳去來訪編輯器、點週檢視的一列跳去
來訪編輯器、按懸浮鈕新增跳去編輯器、在那一天的面板裡選完客戶之後也跳去編輯器
（那一次尤其怪，因為它是從一張抽屜開始的）。使用者的原話是
「點了之後不要跳轉頁面」「一開始用抽屜，但是等點擊完人後就又切換畫面了」。

我們決定：**這一頁從頭到尾不 `go()`。**

## 四個入口，四個決定

**月檢視的一整格都是「打開那一天」，色條不吃點擊。** 原本可以點的只有那顆日期數字
（`::after` 撐出來的感應範圍），色條各自是連到那一筆的按鈕。改成整欄一顆按鈕、
色條 `pointer-events: none`。理由不只是「數字太小」——**同一格裡有兩種點擊結果**
本身就是問題：手指落在名字上跳去編輯器，落在旁邊的空白什麼都不會發生，
而那兩處相距不到十個像素。那一格從此只做一件事。

**點一筆先浮出讀取模式的卡片，右上角的鉛筆才進編輯器。** 她點一筆的十次有九次
只是要確認「那天幾點、誰、做什麼」。直接落進一張可編輯的表單等於每一次都冒著
改到東西的風險，而這一站最不能出錯的就是次數（SPEC 第 6 節）。

**卡片是疊在抽屜上面的第二層，不是換掉抽屜。** 抽屜講的是「那一天」，卡片講的是
「那一筆」。用抽屜開第二層會把第一層關掉，等於每看完一筆都要重新找一次那一天。
實作是 `ui/components/card.js`，`z-index` 排在抽屜（20）之上、二次確認（22）之下 ——
從卡片按刪除時，確認框必須蓋在它上面。

**編輯器就長在抽屜裡。** `visitEditor` 與 `eventEditor` 各多一組 `mountNew` /
`mountEdit`，吃 `embedded`（拿掉回上一頁的連結、卡片不再包白框）與 `onDone` /
`onCancel`（取代 `go()`）。**表單、驗證、二次確認、狀態按鈕都是原本那一份** ——
醫療禁忌的硬性阻擋只能有一個實作，兩份遲早會有一份忘記擋。路由那條路
（`#/visits/:id`）原封不動留著，客戶詳情頁仍然走它。

選完客戶之後編輯器換進**同一張抽屜**：抬頭從「8/19(三) 要幫誰排？」變成
「8/19(三) 排一筆」，內容換掉，面板本身沒有消失過。

## 抽屜可以用拖的

上面那條橫桿現在吃指標事件：往下拖過門檻關掉、往上拖撐到滿版、從滿版往下拖
回原本高度。編輯器掛進去的時候直接就是滿版 —— 一張表單本來就比一天的清單長。

`ui/components/sheet.js` 因此多了 `setTitle()` / `setNote()` / `setActions()`：
同一張面板會換好幾次內容，而**留著上一段的說明比沒有說明更糟**，它會在編輯器
上面寫著「1 件事，點一筆看細節」。

這裡自己接指標事件，而壓表的卡片組（ADR-0017）刻意不接，兩者不衝突：那裡要的是
慣性與邊緣回彈，`scroll-snap` 給得到而手寫給不到；這裡沒有慣性可言，只有
「跟著手指走、放開後決定去哪一格」，而那反而是捲動容器做不到的 ——
面板本身要能捲自己的內容。

SPEC 第 8.0 節的「無拖拉」沒有被推翻，它講的是**不靠拖拉就做不到的功能**
（ADR-0017 同一個判準）。把手本身仍然是關閉鈕，右上角還有一個叉叉，
點背景也關得掉。

## 左右滑換上一個月／下一個月

三格 `scroll-snap`：上一頁、這一頁、下一頁。滑停之後把 state 往那個方向挪一格、
重畫、靜靜捲回中間。這一段**用瀏覽器原生的捲動**，理由與 ADR-0017 相同。

兩個實作上的選擇：

**一次讀三格的範圍，不是滑到一半才去讀。** 隔壁那個月要立刻畫得出來，
不然滑到一半會看到一片空白然後跳一下 —— 那正是「絲滑」的反面。

**滑完先用手上的資料畫，再靜靜補讀一次。** 走原本的 `render()` 會先閃一下
「載入中…」，而那一閃正好落在她剛放開手指的那一刻，手感會從「翻過去了」
變成「重新載入了」。頂端的上一頁／下一頁箭頭走同一條路 ——
一個閃一個不閃會像兩個不同的功能。

判斷「滑停了」是用捲動事件停下來 110 毫秒，不是 `scrollend`：
iOS Safari 不一定發那個事件，而這一頁有一半時間跑在 iPad 上。

## Consequences

ADR-0018 沒有被推翻，是被推到底：那一支只把「點一天」從換頁改成滑出面板，
這一支把日曆上剩下的四個換頁也收掉了。ADR-0015「日曆是可以編輯的第一線畫面」
因此才真的成立 —— 原本每編輯一次就會離開這一頁一次。

SPEC 第 8.6 節「點一天跳到日檢視」在 ADR-0018 已經改掉，這裡再補一條：
**月檢視上的色條不是連結**。日／週／月三種檢視本身沒有變，日檢視仍然是議程清單
（只列有東西的那幾筆），不做成一格一小時的時間格 —— 那是另一個問題，
而她現在要解決的是「不要一直換頁」。

代價是日曆這一頁的程式碼知道了兩支編輯器的存在。這被接受：替代方案是
把編輯器複製一份成「抽屜版」，而那一份會漏掉醫療禁忌的硬性阻擋。
