# ADR-0108：改一段的時間或課程＝取消那一段、重新排一段

日期：2026-09-23
狀態：已接受
落實：SPEC 第 4.1 節「客人改時間時必須自動產生『取消舊時段』的任務，不能默默改日期」、
第 7 節規則 10「改期＝取消＋重新排」—— 兩句一直寫在 SPEC 上，「改這一段」那條路沒有照做
延伸：[ADR-0085](./0085-editing-a-visit-means-editing-that-slot.md)（改一筆來訪就是改她點的那一段）、
[ADR-0107](./0107-a-registration-task-knows-which-slots.md)（掛號逐段）

## 背景

一段已談定、Examine 與耀聖都掛好的門診 14:00 → 改這一段 → 改成 16:00 → 存：
存進去是 16:00、狀態照樣「已確認」，**沒有任何一張待辦**叫她回 Abovee 改時間、
回 Examine／耀聖把 14:00 那個號取消（2026-09-23 實跑，`.scratch/prelaunch-audit-2026-09-23/issues/13`）。

她 2026-09-23：

> 我希望會提醒回 Abovee／Examine／耀聖改時間以及回去取消已經掛好的號等等

兩種做法給她選：A「取消＋重新排」、B「原地改＋長新種類的『改時間』待辦」。**她選 A。**

## 決定

**「改這一段」改了一段待確認或已確認的開始時間或課程：舊那一段標成取消，新的時間接在尾巴一段待確認。**

- 規則只在 `domain/visits.js` 的 `rebookSlot()`；接在尾巴走 `withExtraSlot()`
- 取消掉的那一段照既有的路長「取消 Abovee」，掛過號的長「取消 Examine／耀聖」（`cancelTasksFor()`）；
  新的那一段客人說可以之後照既有的路長新的 Examine／耀聖（`newRegistrations()`，ADR-0107）——
  **一條任務規則、一種任務都沒有加**
- 存檔前一道確認框講要回去做什麼（`consequences.js` 的 `rebookConsequences()`，跟真的會長的走同一支，ADR-0070）
- **只有開始時間與課程算**（器材推出來的課程也算）。治療師、醫師、診間、記一句不影響外面那幾個系統，
  原地改、一道確認都不多跳（她 2026-09-08：「如果沒有就可以不用提醒」）
- 已完成／未到／已取消的那一段改時間是更正，不是改期 —— 照舊原地改

## 後果

- 改一次時間，日曆那一天多一段灰掉的；整天退回「待確認」（新的那一段還沒問客人）
- 選 B 的話要新增任務種類、`todoFlow.js` 的 `FLOW`、對照表、試算表那一區 —— A 一個都不用
