# 待辦「長不長得出來」跟「還算不算數」是兩條規則

2026-09-04 她實測回報：

> 我把追蹤健檢報告勾掉，已經生出寄報告以及約二返，然後我再回去把追蹤健檢報告
> 勾回去，雖然那兩張都會收起來，但是健檢報告好像沒有放回未完成。

那一張不是沒有放回未完成，是**被軟刪除了** —— 不在未完成、不在已完成，
只在「設定 → 已刪除項目」裡。

## 為什麼

`syncFollowupTasks()` 收尾只問一句話：這張未完成的待辦在不在 `wanted` 裡。
而 `wanted` 的第一道閘門是 `owed()`（還欠幾次二返）：

```js
const want = owed(pair, visits);
if (!want) continue;
```

二返一壓好（`booked`）或一勾掉（`settled`），`owed` 就掉到 0，那一次健檢
整個退出候選 —— 於是掛在它身上的**每一張**未完成待辦都不在 `wanted` 裡，
包含她剛剛才拿回來的那一張報告。

**ADR-0065 已經替「寄報告給醫師」走過同一段推論**（擠進第一圈的話，她一約好
二返，還沒寄出去的那一張就被靜默收掉）。當時只搬了那一張出來，
沒有回頭問「那另外兩種呢」。

## 決定

**三種待辦，三條各自的規則，而且「長出來」與「留著」分開問。**

| 種類 | 長出來要 | 留著要 |
|---|---|---|
| 追蹤健檢報告 | `owed > 0` —— 沒買二返額度就不該長 | **那一筆健檢還是已完成的**，就這樣 |
| 約二返 | 在 `wanted` 裡 | 在 `wanted` 裡（它本來就是 `owed` 在數的東西） |
| 寄報告給醫師 | 報告勾掉了 | 報告還是勾掉的 |

寫在 `domain/followups.js` 的 `keepsOpen()`。健檢被取消或刪掉時三種都收 ——
那才是「替她刪待辦」唯一站得住的時候：那一場沒發生，沒有東西要追。

這跟 ADR-0066 是同一個形狀：那一支把「該有哪些（比對用）」與「長不長得出來
（產生用）」拆成兩層，因為紀錄那一族的兩個答案剛好相反。這一支拆的是同一刀，
只是切在鏈條上。

## 被推翻的那一條：「二返約好了 → 未完成的追蹤報告也跟著收掉」

那是 2026-08-25 的行為，理由是「她都去約了，報告顯然拿到了」。它有兩個問題：

1. **ADR-0042 自己寫著**「沒有第二個地方記『報告拿到了沒』，那張任務的 `done`
   就是那個狀態」。從別的資料推論出那個狀態，就是第二個地方 ——
   而第二個地方遲早會跟第一個不一致，這次就是。
2. **ADR-0065 之後那個推論會弄丟一整站。**「寄報告給醫師」只在報告那一張被
   **勾掉**的時候長出來。她如果先去壓二返、還沒勾報告，收掉那一張等於
   寄報告那一站**永遠到不了** —— 她再也不會被提醒把報告寄給醫師。

所以現在：二返約好了，未完成的追蹤報告**留著**。她一勾掉它，
寄報告那一張就補上來。

## 一句話的判準

> **系統的推論不可以蓋過她剛剛按下去的那一下。**
>
> 「二返約好了所以報告一定拿到了」是推論；「她把那一張勾回去」是她的決定。
> 兩個衝突的時候，她贏（ADR-0002：app 記錄決定，不做決定）。

## Consequences

- `reasonFor()` 少一句從來沒有成立過的話。「報告拿到了」以前是追蹤報告被收掉
  的理由，而「拿到了」等於它是已完成的，而已完成的根本不會走到那個迴圈裡。
  現在那一種只剩一個理由：同一筆健檢底下有兩張，留下另一張。
- **這一支上線之前存在的資料不受影響。** 沒有任何一張待辦會因為這次改動
  被補產生或被收掉 —— 改的只有「已經在那裡的那一張什麼時候該消失」。
- 她如果先壓二返、後勾報告，現在會多看到一張「寄報告給醫師」。那是對的：
  報告確實還沒寄。
- `tests-e2e/specs/02-examine-chain.spec.js` 有兩支走**回程**的：勾掉再勾回去。
  上一輪 27 支新的端對端裡一支都沒有走回程，這個 bug 就是從那個縫裡掉出去的。
