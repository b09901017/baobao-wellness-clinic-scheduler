# 壓表卡片上只放解析出來的條件，原文收進摺疊

`SPEC.md` 第 4.3 節有一條從第一版就寫著的原則：**原文是最終依據，永遠保留、
永遠顯示在旁邊。** 壓表卡片照著做，於是「不能的時間」那一塊裡最大、字級最大的
一段是客戶的原話（`.ban__raw` 是 `--text-md`，比條件丸子大兩級）。

使用者在真的用它壓了一輪之後說：只要丸子就好，原文收起來，想看再看。

## 為什麼原文在這一頁失去了對象

原文那麼大，是為了讓她**發現解析錯了**。那是在她自己抄客戶 LINE 回覆的年代 ——
她打的字、系統讀成的規則，兩邊要並排才看得出來哪裡讀歪。

表單做出來之後（ADR-0031、0032），現在幾乎每一份可用性都是客戶自己在表單上點的，
而那份「原文」是 `domain/availabilityForm.js` **照他點的東西產生的一句話**，
不是誰打的字。它跟丸子是同一份資料的兩種寫法 —— 而且「產生的原文餵回解析器
要得到同一組規則」本身就是有測試盯著的不變量。

所以在這一頁，原文現在講的是丸子已經講過的事，佔掉的卻是她在公司電腦前
**一眼要掃到的那塊位置**。

## 收起來，不是刪掉

- **卡片牆上不放原文。** 那一層是「這二十幾位裡先弄誰」，她掃的是條件與剩幾次。
- **記錄面板上收進 `<details>`**（「他原本是怎麼說的」），一行，點開就有。
  她真的懷疑解析錯了的時候，那一下點得到。
- **可用性那一頁與收件匣完全不動。** 那兩頁的工作**就是**核對解析對不對，
  原文在那裡照樣是最大的一段。

換句話說第 4.3 節的原則沒有被推翻，被限縮的是「永遠顯示在旁邊」的範圍：
**核對的頁面攤開，使用的頁面收起來。**

## Consequences

`SPEC.md` 第 4.3 節多一句限縮、第 8.2 節的卡片欄位表跟著改。

`banBlock()` 多一個 `raw` 參數，預設 false —— 牆上與面板走同一支，
差別只有那一摺。新的 `.ban__more` 只有壓表在用。

代價是她要多點一下才看得到原文。這被接受，因為現在會需要看原文的情況
（客戶在表單以外用 LINE 補了一句、或她自己手打了一份）本來就是少數，
而那少數的每一次都還在一下的距離內。
