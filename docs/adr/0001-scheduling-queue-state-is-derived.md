# 待壓表與待收集時間是推導狀態，不存欄位

SPEC 第 4.1 節的狀態機把「待收集時間 → 待壓表」畫在來訪之前，但這兩個狀態成立的時候來訪還不存在，所以它們不是來訪的狀態，而是「這位客戶這個月這個課程還沒被排」的狀態。我們決定**不替它們建立欄位或集合**，改為每次查詢時從額度、來訪與本輪可用性即時推導：某客戶某月某課程還有剩餘次數且沒有對應來訪即為待壓表，再加上沒有有效的本輪可用性即為待收集時間。

存成欄位需要在每一次建立、取消、改期、完成來訪時同步維護，一旦漏改就會與來訪本身互相矛盾——而這正是現行試算表最痛的地方。推導值不可能不同步。

## Consequences

壓表批次的佇列是在批次**建立當下**推導並凍結順序的（SPEC 第 5.3 節），不是每次開啟都重算。這兩件事不衝突：狀態隨時推導保持正確，順序凍結是為了讓她換裝置回來時不會發現順序跳掉。
