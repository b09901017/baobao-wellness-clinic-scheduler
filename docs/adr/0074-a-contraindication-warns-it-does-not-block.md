# 醫療禁忌只提醒，不阻擋；永久限制只剩兩層

Status: accepted，取代 [ADR-0064](./0064-a-clinical-alert-is-a-permanent-limit-that-blocks-nothing.md)，
並推翻 [ADR-0002](./0002-app-records-decisions-it-does-not-make-them.md) 的例外條款

2026-09-06 使用者說：

> 有體內金屬只能壓 INDIBA（但是其他兩個也不是一定不行（只要儀器不要在金屬的
> 上方或附近），只是會強烈建議用 INDIBA），所以其實體內有金屬這件事不用硬性擋
> 不能壓其他兩個，就只要明顯的標註提醒就好，不用擋

所以醫療禁忌從**硬性阻擋**改成**選到那一台時跳出來的一句提醒**，而永久限制底下
從三層併成兩層：**警示**（什麼都不擋，但壓表那一刻要一眼看得到）與**其餘**。

## 為什麼那個例外不再成立

ADR-0002 定的是「app 是記錄者，不是判斷者」，而醫療禁忌是它唯一的例外。
那個例外當初站得住，靠的是這一句：

> 它不需要推算，只是比對客戶身上有沒有那個標記，不存在資料不完整的問題

**現在知道它其實需要推算。** 能不能用超磁場，要看儀器擺在金屬的上方還是別的地方
—— 而那件事只有站在診間裡的人看得到，app 看不到。這正是 ADR-0002 主體在講的
同一件事：用不完整的資料去擋一個看得到完整畫面的人，只會擋錯。

所以這一支**不是推翻 ADR-0002，是把它的例外收掉**。結果是：
**這個 app 從此沒有任何一個業務規則會擋下儲存。** 剩下的 errors 全部是
「這筆資料寫下去會壞掉」（沒選額度、時間格式不對、指到一筆不存在的東西），
不是「這件事不該做」。

## 為什麼兩層要合併

ADR-0064 把臨床提醒獨立成一層，理由寫得很清楚：它跟醫療禁忌的**唯一界線**
就是「會不會真的讓某個器材不能選」。那條界線消失之後，兩層在系統行為上一模一樣
（都不擋、都要在壓表卡片牆上看得到），留著只會讓她每次都要想一下該記在哪一層。

## 那「哪一台要提醒」記在哪裡

**仍然記在器材主檔上**（她 2026-09-06 選的），只是那一欄的意思從「醫療禁忌」
變成「要特別提醒的狀況」。好處是「建議改用 INDIBA」那一句是**算出來的** ——
那一池裡唯一沒有東西要提醒的那台 —— 器材主檔一改它跟著改，不必另外維護一份
「哪個狀況建議哪一台」的名單。

代價是那些字要**同時進得了警示主檔**才畫得到客戶身上。器材上有、警示主檔沒有的
那幾個字由資料健檢列出來，按一下補進去；不補的症狀是「客戶身上打了那個字，
卡片牆上什麼都沒出現」，跟做對了長得一模一樣，所以它必須被列出來。

## 樣式跟著那一個警示走

合併之後一排上可能同時有「體內金屬」「血管難打」「第一針」「怕痛」，而系統
分不出哪一個對她比較重要 —— 那是她的判斷（ADR-0002 的主體）。所以每一個警示
自己挑顏色（六色，跟客戶備註同一份名單）與填法（實心／空心），記在主檔上。
同一個作法行事備註做過一次（[ADR-0040](./0040-a-personal-event-picks-its-own-colour.md)）。

## Consequences

- **卡片牆上那顆算出來的「只能 INDIBA」拿掉了**（她指名不要）。那句話改成
  她真的選下去的那一刻才講，而且講得更完整（哪個字、建議改用哪一台、要確認什麼）。
- **時段反查不再排除任何人。** 「擇一池被禁忌全部鎖死 → 這個人真的不能來上這堂課」
  這件事以後不存在。
- **`domain/contraindications.js` 的檔名沒有跟著改。** 改檔名要動 `public/sw.js`
  的 SHELL 清單、十幾支 import 與測試，換來的只有一個更貼切的名字。同一個取捨
  這個專案做過一次：「個人行程」改名成「行事備註」之後，`category` 的
  `personal` / `leave` 沒有跟著改。
- **`config/app/clinicalFlags` 這個集合 id 也沒有改**（同上），畫面上改叫「警示」。
- SPEC 第 4.3、4.5、14 節與 `CONTEXT.md` 的「永久限制」「臨床提醒」「醫療禁忌」
  三條跟著改寫。
