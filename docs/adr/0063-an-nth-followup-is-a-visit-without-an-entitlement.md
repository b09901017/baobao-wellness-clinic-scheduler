# n返 是一場沒有額度的來訪

2026-09-02 使用者：

> 新增一個來訪項目 n返，和二返一樣，就是健檢完後會約客戶來聽醫生講解報告，
> 約第一次叫二返，第二次叫三返依此類推。不一樣的點是，二返是一定有的……
> 但是三返、四返……他不常發生，通常是客戶要求，他聽不懂或是想再聽一遍
> 我才會預約……**這個 n返，不需要先加購才能有**，而是只要有健檢的就可以選，
> 但他也沒有次數限制，沒有一定要也沒有只能到幾返。

四個硬條件：二返的東西一個字都不動、不需要額度、沒有次數上限、
一定要指得出是哪一次健檢的。

## 為什麼它不是一筆額度

`CONTEXT.md` 對「額度」的定義是「某位客戶**買到的**某個課程的次數」。
n返 沒有被買、沒有次數、扣不掉 —— 它不符合那個定義的任何一半。

硬塞成額度只有兩條路，兩條都會壞：

| 作法 | 壞在哪 |
|---|---|
| 開一筆 `totalQty` 很大的「n返」額度 | 客戶詳情那一排會多一張寫著「剩 97 次」的卡；`summarize()` 的合計、`lowRemaining()`、`customersToBook()` 全部會吃到它 —— ADR-0057 為了營養品打過同一場仗，`schedulable()` 那道閘門就是那次的產物 |
| 每約一次就把 `totalQty` 加一 | 剩餘永遠 0，看起來像用完了；而且「加購」與「排班」變成同一個動作，稽核紀錄上每一次壓表都會多一筆額度變更 |

## 決定

**n返 的時段 `entitlementId` 是 `null`**，靠兩個欄位自己站得住：

```js
followupNth        // 3、4、5……（二返身上沒有這個欄位）
followupForVisitId // 那一次健檢的來訪 id（既有欄位，n返 **必填**）
```

這不是一個新的假設。系統原本就沒有要求每一段都有額度：
`domain/visits.js` 的 `recount()` 早就寫著 `if (slot.entitlementId)`，
`domain/health.js` 的 `refState()` 對 `null` 回 `'none'` 而且不報孤兒。
硬性要求的只有 `validateVisit()` 那一行，那一行放寬了。

### 課程借二返那一個，不另外建

`courseId` 指向那一次健檢配的二返課程（從 `followupCourseId` 讀，ADR-0022）。
借了之後這幾件事**一行程式都不用寫就成立**：

- 類別 A → 客人確認之後長出 Examine 與耀聖（她要的「一樣的 todo」）
- `needsTreatmentForm: false` → 不用簽療程單，但照樣要在「簽療程單」那一列結案
- `picksDoctor()` → 選得到醫師（試算表註記的括號要它）
- `bookingSystemsForVisit()` → 取消時知道要回哪個系統放時段

開一個新課程的話，上面每一格都要她自己去主檔設定一次，而設錯的症狀是
「三返沒有長出掛號待辦」—— 畫面上什麼都不會說。

顯示的名字走 `slot.courseName`（快照，同一般時段）：`'三返'`。
主檔之後把二返改名，已經排出去的三返還是叫三返。

### 上限十返，下限三返

她說沒有上限，而 `MIN_NTH = 3` / `MAX_NTH = 10` 還是給了一個。兩個理由：

- **下限**：2 是二返，那一條路已經有了。兩條路不可以都走得到同一個數字 ——
  不然同一場回訪會有兩種存法，而兩種存法遲早會被算成兩場。
- **上限**：一個沒有上限的輸入框只會讓打錯字變成一筆看不懂的資料
  （`followupNth: 33`）。十返遠超過真的會發生的次數；真的碰到再放寬，
  資料層沒有任何欄位會因為改這個數字而要搬。

## 兩者在資料上完全不相交

這是整個設計的判準，也是「二返一個字都不動」唯一站得住的理由：

| 問的是 | 靠什麼認 | 看得到 n返 嗎 |
|---|---|---|
| `counts()` / `slotOutcome()` | 逐段比 `slot.entitlementId === id` | 不 —— `null` 永遠不相等 |
| `owed()` / `claimedExams()` / `syncFollowupTasks()` | 二返那一筆額度的 id | 不 |
| `sheetReport` 的矩陣 | 逐格比 `entitlementId` | 不（她要的就是「記在健檢底下」） |
| `domain/health.js` 的孤兒檢查 | `refState(null)` → `'none'` | 不會誤報 |
| `firestore.rules` 的 `validVisit()` | 只看 `slots is list && size() > 0` | 一個時段欄位都不驗 |

反過來，`domain/nthFollowup.js` 的 `followupsOfExam()` 是唯一把兩者放在
同一條線上的地方（試算表那一格要印「二返(...) 三返(...)」），
而它靠**呼叫端傳進來的二返額度 id 清單**認二返 —— 不傳就只回 n返。
少傳的症狀是「試算表少印一行二返」，不是「多印一行三返」：
少一行看得出來，多一行看不出來。

## 她從哪裡加約

**壓表與日曆，跟排任何一場來訪一樣。**

- **壓表**：額度那一排最後多一顆「＋ n返」，選了之後底下長出「第幾返」與
  「這是哪一次健檢的」兩排。**沒有做完的健檢就整顆不畫** ——
  一顆永遠按不下去的丸子只會讓她每次都試一下。
- **日曆的來訪編輯器**：同一組欄位。

**客戶詳情沒有「加約」按鈕。** ADR-0056 定了只有日曆改得了一筆來訪，
而加一場 n返 就是建一筆來訪 —— 從那一頁給一顆按鈕等於在那個決定上再開一個洞。
那一頁只顯示「7/13 的健檢 → 三返 9/20」這一行，接在二返那一句底下。

### 一個已知的邊界

壓表的卡片牆答的是「這個月還有誰要排」（ADR-0014），所以
**身上一次剩餘次數都沒有的客戶不在那面牆上**，也就選不到那顆丸子。
那是對的：不該為了 n返 把整面牆灌滿已經結案的人
（`bookGroupRow()` 為了同一件事把數字整個拿掉過）。

而那種情況真的會發生（客人整套上完了，回來說報告沒聽懂），
所以**日曆那一條路必須成立** —— `tests-e2e/specs/13-nth-followup.spec.js`
的 N7 盯著它。

## 試算表

接在二返底下、**同一格**、用換行分隔、照返數由小到大：

```
| 9/20 二返(夏)
| 10/8 三返(李)
```

收攏在同一格是被迫的也是划算的：手動貼上那條路是
`line[COUNT_COLS + note.dateIndex] = note.text`，一欄兩筆的話後面會蓋掉前面。
而收在一格的代價是零 —— **`SYNC_FORMAT` 一個數字都不用動**
（形狀還是 `{dateIndex, text}`，`.gs` 那側本來就 `setWrap(true)`），
所以她不用回 Google 試算表重貼腳本、不用重新部署。

**還沒約的 n返 不印。** 二返有 `二返()` 那個空括號（她自己的寫法，
意思是「這件事還沒做」），因為二返是一定要約的；n返 是加約的，
「沒有三返」是常態不是待辦 —— 印一個空的 `三返()` 等於每一位客戶的表上
都多一行永遠做不完的事。

約了但醫師還沒定的印 `9/20 三返()`：**那一種空括號是有意義的**，
那一場已經約了（日期就在前面），只是醫師還沒挑。

## Consequences

- `domain/nthFollowup.js` 是一支新檔案，不寫進 `domain/followups.js` ——
  那一支回答的三個問題都是「額度層級的一對一配對」，n返 一個都不是。
  混在一起，之後改二返的人會不小心改到 n返。
- `validateVisit()` 多三條檢查：返數的範圍、`followupForVisitId` 必填
  （二返仍然只是 warning —— 它有一整批舊資料身上沒有那個欄位，ADR-0011）、
  指到的那一筆要是一次已完成的健檢。
- 同一次健檢底下重複的返數**只提醒不擋**（ADR-0002）：改期就是取消再排一筆，
  那兩筆會同時存在一下下。
- 一筆舊資料都不用搬。`followupNth` 不存在就不是 n返，而在這之前它不存在。
