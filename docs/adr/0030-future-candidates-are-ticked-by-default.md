# 還沒發生的候選預設勾起來，已經發生的預設不勾

合併檔的三份候選清單（行事曆上有試算表沒勾的、未來的預約、對不到客戶的行事曆事件）
原本**一律預設不勾**，理由記在 `merge.mjs` 的 `importJson()` 檔頭：
「預設匯入等於替她做了決定，而錯的那幾筆會在日曆上長出她沒有的事。」

2026-08-21 她拿真資料跑過一次之後推翻了其中一半：

> 未來的就算不是客人相關也都要匯入，因為是現在紀錄的

所以預設值改成**依時間分**：日期在今天之後的預設勾起來，今天含以前的維持不勾。
規則在 `domain/mergeImport.js` 的 `defaultPicks()`。

## 為什麼這兩半的答案不一樣

**因為它們是兩件不同的事。** 已經發生的那些是**考古**：補一筆進去等於宣稱
「那天她做了這件事」，而那會扣一次次數。猜錯了沒有人看得出來，所以原本那條
「她一筆一筆決定」對這一半仍然完全正確，一個字都沒改。

還沒發生的那些是**她現在正在管理的事**。那 198 筆候選裡有出國、公出、休假 ——
漏掉一筆的後果是日曆上那天看起來是空的，然後她把客戶排進去。
而且未來的東西錯了改得掉（那筆來訪還沒發生），過去的錯了要走更正流程。

代價是她仍然要看過那一區、取消掉不要的。這比要她勾 198 次好，
而且**兩個區塊各有一顆「全不選」** —— 反悔的成本是一次點擊。

## Consequences

`include: false` 這個欄位在 app 這一側從來沒有被讀過（`picks` 是 UI 自己的狀態），
所以這一支不需要動檔案格式，舊的合併檔照樣貼得進來。`merge.mjs` 那側的
檔頭註解跟著改，因為它描述的是一件不再成立的事。

**預設值不是判斷。** 這一支沒有讓系統替她決定任何一筆該不該匯 ——
勾起來的仍然是「她按下匯入時畫面上勾著的那些」，ADR-0002 沒有被推翻。
