# ADR-0101：照片與隱私 —— 哪些送出去、哪些留下來、什麼時候真的刪

日期：2026-09-17
狀態：已接受
延伸：[ADR-0099](./0099-ai-only-copies-the-words.md)、[ADR-0100](./0100-the-first-server-code-and-its-five-locks.md)
例外：`SPEC.md` 第 6.1 節「永不硬刪除」—— **只限療程單被新版取代的那個舊照片檔**

## 背景

四種單子上有什麼（2026-09-17 看過她的照片）：

- **訂購單**：姓名、**身分證字號、生日、電話**、刷卡分期欄、買了什麼
- **方案文宣**：沒有個資
- **Abovee 畫面**：客戶姓名、病歷號、**電話**、同事的名字
- **療程單**：客戶姓名、客戶編號（＝病歷號）、每一次的日期與簽名

她 2026-09-17：

> c 訂購單上有身分證字號 可以拍照送到我自己的雲端和 AI，但不要儲存

> e 療程單被新版取代時真的刪掉，反正有紙本正本

> 4. 可以，辨識出來的字不存草稿，確認到一半離開就重拍一張

## 決定

### 送不送、存不存

| | 送 AI | 存 | 理由 |
|---|---|---|---|
| 訂購單 | ✓ | **不存** | 身分證字號、生日、刷卡欄。她同意送，不同意存 |
| 方案文宣 | ✓ | 不存 | 沒有保存價值 |
| Abovee 畫面 | ✓ | 不存 | 電話、同事的名字 |
| 療程單 | ✓ | **存** | 扣課的憑據（`CONTEXT.md`「療程單」），她要搜得到 |

- **送出去之前**瀏覽器先縮成長邊 ~2000px、重新編碼成 JPEG —— 重新編碼本身就把
  EXIF 與 GPS 丟掉了
- **辨識出來的字也不存草稿**。整個確認層只在記憶體裡，收起來就沒了；確認到一半離開
  就重拍一張（一張不到台幣 1 元）。所以沒有「進行中的辨識」那一種集合
- **抄字格式裡沒有身分證字號、生日、電話的欄位**（ADR-0099）—— 照片送出去了，
  但那幾格的字從來不會回到 app、不會進 Firestore

### 療程單照片

- 放 **Cloud Storage** 的預設 bucket，`storage.rules` 讀寫刪都要在 `allowedUsers` 裡，
  只收 `image/jpeg`、≤ 1.5MB
- bucket 在 **US-EAST1**（2026-09-17 staging 建成這一區，她確認就用它；正式環境建的時候也選
  US-EAST1，兩邊一樣）。Firestore 在 `asia-east1`，所以**療程單照片跟其他資料不在同一區**。
  接受的理由：Firebase 免費額度只給美國那三區，照片很小；模型本來就走 global 端點
  （ADR-0100），照片送出去的那一刻就已經不保證在台灣
- **被新版取代時，舊照片檔真的刪掉**。這是第 6.1 節唯一的例外，**只限照片檔**：
  新版涵蓋舊版的每一列（同一張多簽了幾列），而紙本正本在診所。
  順序一定是**新的傳上去 → 文件更新 → 才刪舊的**；反過來的話中間斷線就兩張都沒了
- 療程單那一筆**文件**照舊軟刪除；刪掉一整張療程單時照片檔**留著**（「已刪除項目」還原得回來）
- 照片**不進** `exportAll()` 的備份檔：有紙本正本，而備份檔是 JSON。
  療程單的文件（抄出來的列）要進

### 誰看得到

- **Function 不記錄照片與辨識出來的字**。log 與錯誤訊息只帶 `kind` 與錯誤碼；
  `aiUsage` 只記時間、哪一種、成功與否、估計多少錢
- **CI 與 E2E 一律用假的 AI 回應，永遠不送真照片**
- **考試（`scripts/ai-exam.mjs`）用真資料**（她：「不用假資料考試，就直接拿真資料考試」），
  用她本人的授權直接叫模型、不經過 Function；答案與結果只留在 `.local/`，終端機只印數字

### Google 那一側（2026-09-17 查 Agent Platform 的 zero data retention 與 abuse monitoring 文件）

- **不拿來訓練**：服務條款的 Training Restriction，沒有她的許可不用她的資料訓練任何模型
- **預設在記憶體快取輸入與輸出 24 小時**（不落地、專案隔離），**可以在專案層關掉** ——
  那是 Google Cloud 的設定，`docs/STAGING.md` 寫了她怎麼關
- **濫用監控**：只有自動分類器判定可疑時才記 prompt，最多 90 天，不拿來訓練；
  可以填表申請例外。拍訂購單不會觸發它，但它存在，寫下來

## 為什麼不是別的做法

- **訂購單照片也存起來備查**：她明講不要。要查的東西（買了什麼）已經變成額度了
- **療程單新版取代時也軟刪除舊照片**：舊照片是新照片的子集，留著只是一份
  身分資訊多躺在雲端，而且每兩三個月多一份
- **把照片存成 Firestore 的 base64**：一筆文件 1MB 上限，而且會跟著每一次讀客戶詳情下載

## 後果

- `storage.rules` 是新檔，要有 Rules 測試，白名單跟 `firestore.rules` 同一份
- 備份還原後療程單的卡片講得出「照片不在備份裡」
- 以後多一種單子要先回答這張表的那一列，才寫格式
