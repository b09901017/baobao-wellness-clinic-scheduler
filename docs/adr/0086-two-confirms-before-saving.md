# ADR-0086：存檔前是兩道，而第一道只在有話要講時出現

日期：2026-09-09
狀態：已接受
延伸：[ADR-0070](./0070-a-warning-may-only-say-what-really-happens.md)
（一句話只能講真的會發生的事）、[ADR-0002](./0002-app-records-decisions-it-does-not-make-them.md)

## 背景

她 2026-09-08：

> 我希望當我按下紀錄這「些」來訪（不是這次來訪）可以先提醒那個時段會導致
> 超過次數、那個時段沒有選醫生診間等等，**如果沒有就可以不用提醒**。
> 然後我按下了解之類的，才會再跳出壓 abovee 了嗎 的那些提醒。
> 所以新增來訪的這個表單最上面就不需要還有一個提醒了。

在這之前是一張**常駐在表單最上方的「提醒」卡**（`validateVisit()` 的
warnings），從打開就在那裡；存檔時只有一道 Abovee 確認，而它把逐段摘要、
後果、還有一句「app 看不到同事壓的東西」全部擠在一起。

## 決定

```
按「記錄這次來訪」
  ↓
① 「這 N 件先看一下」        ← 只在真的有 warnings 時出現
     ・「復能-三選一(60)」排完這次會超過總次數
     ・第 2 個時段還沒選治療師
   [知道了，繼續]  [回去改]
  ↓
② 「在 Abovee 壓好了嗎？」   ← 只在有新的時段時出現（ADR-0083）
     ・客戶A・9/15 09:00–10:00 復能(SIS)
     ・（後果句）
   [已確認，記錄]
```

**一、閘門是 `reviewWarnings()` 回不回 `null`，呼叫端不自己數
`warnings.length`。**「幾句話算需要問」是一條規則。

**二、句子照抄，畫面不重寫。** `validateVisit()` 的 warnings 本來就是完整
的句子。在對話框裡重寫一遍等於同一件事有兩種說法，而她會以為那是兩件事。

**三、兩顆按鈕都講出按下去會怎樣。** 「確定／取消」在這一道是模糊的：
這一道不是在問「要不要存」，是在問「你看過了嗎」。所以是
「知道了，繼續」／「回去改」（`confirmAction()` 因此多一個 `cancelLabel`）。

**四、表單最上方那張卡整個拿掉。** errors 那一塊留著 —— 那是擋著不讓存的，
不是提醒。

## 為什麼不是別的做法

**把 warnings 併進 Abovee 那一道。** 那一道問的是「你去壓了嗎」，
而 warnings 講的是「這幾段可能不對」。兩個問題擠成一張，她會兩個都不看。

**留著上方那張卡，只是多一道確認。** 她明確說「最上面就不需要還有一個提醒了」。

**把 warnings 升級成 errors（擋下來）。** 那會推翻 ADR-0002：app 看不到
完整畫面，用不完整的資料去擋一個看得到完整畫面的人只會擋錯。
第一道**永遠可以按過去**。

## 後果

- 改一段既有的時段時只會有第一道 —— 第二道問的是「壓好了嗎」，而那一格
  早就壓過了（`hasNewSlots()` 那道門，ADR-0083）。
- 她從此看不到「這一筆現在有幾句提醒」直到按下送出。這是刻意的取捨：
  那一張常駐的卡是她說的「太雜亂了、會視覺疲勞」的一部分。
