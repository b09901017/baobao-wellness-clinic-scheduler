# 壓表的卡片組是一層，不是一位客戶一層

ADR-0048 定了「畫面上多出來一層東西，就多一筆返回鍵退得掉的紀錄」，然後在
代價那一段把壓表**排除在外**：

> `pushState` 有頻率上限（Safari 每 30 秒有一個數量限制）。她壓表時一個晚上
> 開關面板幾百次，所以壓表那一頁的記錄面板暫時沒有接上去，而且左右滑換客戶
> 絕對不能一位推一筆。

那個「暫時」現在收掉了。2026-08-25 她確認要修 —— 而例外剛好落在她用最多的
那一頁：日曆的抽屜、客戶詳情的編輯、二次確認全都退得掉，唯獨壓表的卡片面板
開著按返回鍵是跳走整頁。**那正是 ADR-0048 一開始要修的症狀。**

## 排除的理由只對其中一半成立

那一段其實講了兩件事，而它們的答案不一樣：

| | 一個晚上幾次 | 接不接 |
|---|---|---|
| 開關卡片組 | **幾十次**（一位客戶開一次，中間換人不關） | 接 |
| 換人、點丸子、換日子 | 幾百次 | 不接 |

會撞到頻率上限的是第二列，而第二列本來就不該推紀錄 —— 換人不是「多一層東西」，
是同一層裡換內容。**它們是同一層。**

所以：`openDeck()` 推一層、`closeDeck()` 收掉，`goTo()` 與 `openDeckAt()`
一筆都不推。她在卡片組裡滑過二十三位再按返回鍵，回的是卡片牆，不是第二十二位。

## 為什麼不是「一位客戶一層」

那是 ADR-0048 已經寫下的第二個理由，這裡只是把它變成實作：一位推一筆的話，
按返回鍵會**倒著走過她剛剛處理完的每一位**。她按那顆鍵的意思從來不是
「回到上一位」（那是左右滑與抬頭上那兩顆鈕在做的事），是「關掉這個東西」。

## 返回鍵關掉的那一層不可以再 `pop()` 一次

`pushLayer(onPop)` 的 `onPop` 只在返回鍵那條路上被呼叫，那時候紀錄已經退掉了；
自己按叉叉關掉的那條路要自己 `pop()`。兩條路都走 `closeDeck()`，所以它多一個
`fromBack` 參數分辨 —— 兩條路各寫一份關閉邏輯是 `ui/nav.js` 檔頭那個 race
的來源，這裡不要再造一個。

## Consequences

**`mount()` 要把 `deckLayer` 清掉。** 整頁重畫（換一批、批次在別的裝置上被結束）
之後，上一次那一層的節點與紀錄都不在了，留著那個 handle 只會在下一次關閉時
對著空氣退一筆。

**沒有動 ADR-0038。** 推一筆紀錄不重畫任何東西（`pushState(state, '', location.hash)`
不觸發 `hashchange`），所以那一頁「只重畫真的變了的那一塊」的規矩一個字都沒改。

**二次確認疊在卡片組上面時是兩層。** 那是對的：按返回鍵先收掉確認框，
再按一次才關掉卡片組。`ui/nav.js` 的堆疊本來就是這樣對帳的。
