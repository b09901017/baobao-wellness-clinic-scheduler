# ADR-0136：資料健檢那一頁只回答「有沒有事、要做什麼」

日期：2026-10-07
狀態：已接受
延伸：[ADR-0007](./0007-health-check-reads-only.md)（只算不寫，正解不需要判斷的才給修正）。舊的一個字都不改。

## 背景

那一頁是一項一項加出來的：33 項，每一項畫兩次（上面一排數字磚、底下一張卡）。用她的資料，33 項裡 31 項是「沒問題」，
手機上整頁七千多像素；一項很多列時一位客戶好幾行。字也是寫給寫程式的人看的：ADR 編號、原封不動的 `**` 與反引號、
「你」「她」「妳」混用，還有一句叫她「改一個做得到的死線」而 app 裡沒有地方改得了死線。

她講過三次同一件事（2026-09-10「非常占版面，一眼看下去非常雜亂，會視覺疲勞」、2026-10-05「資訊太多太複雜了，我認知疲勞了」、
2026-10-07「資料健檢太長可以處理一下，確實會有點資訊疲勞」）。先畫了一張模擬圖給她看，她回：

> 可以，照這樣做

## 決定

**她開這一頁要回答的只有兩件事：有沒有事、有事的話我要做什麼。** 沒事的那幾項不是資訊。

1. 最上面一塊結論：全部沒事寫「33 項都沒問題」；有事寫「有 N 項要你看」＋「其餘 M 項沒問題」。重新掃描與掃描時間縮小放在底下。
2. 數字磚那一排拿掉（它跟底下的卡是同一份資訊）。
3. 有事的排最上面，分兩組：「資料對不起來」在前、「要處理」在後。一項一張卡：名字、幾筆、一句白話、列、一次修正。
4. 同一位客戶的好幾筆收成一列（點了才展開）；一項很多列時先列前五列，其餘收進「還有 N」。
5. 沒問題的收成最底下一行，點開是名字清單 —— **收起來不是藏起來**，她要能確認「那一項有在檢查」。

**每一項給不給「修正」「一次修正」跟以前一模一樣**：檢查邏輯、`fix` 的形狀、`CHECKS` 的 id 一個都沒動。
收起來的列裡的按鈕照樣在，只是要點開。分組靠 finding 上一格選填的 `who`（那一筆講的是哪一位客戶）。

字一句一句過：不寫 ADR 編號、不留 `**` 與反引號、對她一律寫「你」；這一頁照舊可以寫「筆」（ADR-0087 的例外）。

## 沒有選的

- **每一項的說明照舊收進 `?`**：有事的那幾項，那一句就是「這是什麼事」，她要看；沒事的那幾項連名字都收起來了，不需要說明。
- **同一位客戶的那幾筆預設展開**：一項幾十列時又回到一長串。上面那一顆「一次修正」是主要的按鈕，逐筆修正是點開之後的事。
