# 隨手記可以掛一個日期，掛了就上日曆

她要的兩件事其實是同一件（2026-08-23）：

> 隨手記可以多一個日期的選擇（不一定要選）⋯⋯然後就會紀錄到日曆的 todo 類別

> todo 就是從隨手記那邊記過來的，或是我在這邊新增的，**也必須要同步到隨手記那邊**

## 沒有第二份資料

日曆上那一類**就是 `notes` 這個集合裡有日期的那幾筆**，不是 `events` 底下新開的
一種類別，也不是另一個集合。

「必須要同步」最可靠的實作是**根本沒有東西要同步**：

```
notes
├── date == null  → 只在待辦首頁與 #/todo/notes
└── date != null  → 上面兩個地方照樣有，而且出現在日曆那一天
```

在日曆上新增待辦 ＝ 建一筆 `date` 已經填好的隨手記。在日曆上勾掉 ＝
`notes.setDone()`。兩邊讀的是同一份文件，所以不可能不一致。

這跟 ADR-0015 把「來訪」與「個人行程」刻意分成兩個集合不衝突，理由剛好相反：
那兩者要分開是因為**合起來會讓「這筆要不要扣次數」變成到處都要判斷的分支**；
這裡要合起來是因為它們本來就是同一件事，分開只會產生一個沒有人維護得了的同步。

## 日期不是死線

`CONTEXT.md` 對兩者的界線寫得很死：**任務要有死線且由來訪產生，隨手記是她
自己打的、沒有死線的**。加一個日期看起來像是在打破這條界線，但沒有：

| | 任務的死線 | 隨手記的日期 |
|---|---|---|
| 誰決定 | 系統（來訪日的前一天） | 她 |
| 過了會怎樣 | 逾期，變紅字，進「逾期」那顆大數字 | 字變色，沒有紅底，不進任何數字 |
| 意思 | 「這件事再不做就來不及了」 | 「我想在這一天處理」 |

畫面上也照這條界線走：日期標籤過期只有**字**變色，沒有紅底。紅底在這個 app 裡
一直只有一個意思，「這件事該做了」，而隨手記從來不是那種東西。

## 兩顆丸子，不是一個攤開的日曆

`domain/notes.js` 的檔頭寫死了這件事的標準：「它要能在三秒內記完，多一個必填
欄位就會變成『算了我等一下再記』」。所以：

- **預設是沒有日期。** 兩顆丸子都沒按 ＝ 不掛日期，跟這一支之前一模一樣。
- **「今天」一次點擊就完成**，而那是最常見的那一種 —— 客人當著她的面講的話，
  通常就是今天記、今天處理。
- 「挑日期」才展開系統原生的 `<input type="date">`。自己畫一個小日曆是壓表
  那一頁才需要的（那裡要標紅、標休假、標半天），這裡不需要。

## 一支元件，四個地方

`ui/components/note.js`：一列（`row`）與那個日期欄（`field`／`read`／`wire`）。

待辦首頁底下那張卡、右下角那顆泡泡、`#/todo/notes`、客戶詳情頁 —— 這四個地方
在這一支之前**各有一份自己的寫法**。加一個欄位就是四個地方都要記得改，
而其中一份遲早會把空字串當成有值。

空字串與 `null` 在這裡是兩件事：日曆是用 `where('date', '>=', from)` 撈的，
`null` 不會被撈到（Firestore 的型別排序把 null 排在字串前面），空字串會排在
所有日期前面而且看起來像有值。`normalize()` 一律轉成 `null`。

## Consequences

**`notes` 多一個複合索引**（`deletedAt` + `date`）與 Rules 上的一條型別檢查。
舊資料沒有 `date` 欄位，那就是「沒掛日期」—— 不需要任何搬移。

**日曆多讀一次。** `listBetween()` 跟現有那四份一起放進同一個 `Promise.all`，
不多一輪往返。

**沒有「編輯隨手記」這條路，除了日曆上那一張卡。** 現在的隨手記只能勾掉與
取消勾。掛了日期的那幾筆從此有了編輯入口（日曆上點一筆 → 鉛筆），沒掛日期的
還是沒有。這被接受：那種東西的壽命通常是幾小時，改它不如重記一筆。
