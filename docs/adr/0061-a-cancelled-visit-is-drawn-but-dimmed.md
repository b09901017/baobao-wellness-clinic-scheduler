# 取消的來訪在日曆上畫出來，暗掉，但不算數

`domain/visits.js` 的 `STATUS_VIEW` 檔頭曾經寫著：

> 取消是灰的，而且日曆上根本不畫（`isActive()` 濾掉了）。

**那句話從月檢視加上色條那一天起就只有一半是真的。** 月檢視的 `visitAsBar()`
沒有濾，所以取消的那一筆畫得出來（灰色的一條）；抽屜、日檢視、週檢視走的是
`agendaFor()`，那裡 `isActive()` 把它整筆濾掉。

同一份資料，三個檢視兩種畫法。她 2026-09-01 講出來的症狀正是這個：

> 「已取消」的來訪目前在日曆視圖上會暗掉，但點開該日的抽屜後，
> 裡面卻沒有顯示為暗掉/已取消狀態。

而且那一天的抽屜還會印出「這天還沒有東西 —— 但同事在 Abovee 壓的看不到」。
那句話在說謊。

## 決定

**三個檢視一律畫出來，整列暗掉加刪除線，右邊掛「已取消」的徽章。
但它不算進任何一個數字。**

### 為什麼要看得見

「那一格本來有人、後來取消了」是**她會想再排一個人進去**的訊號。
那正是她在時段反查那一頁要找的東西（`CONTEXT.md`：從一個空出來的時段回頭找誰可以補）。
把它藏起來等於把一個機會藏起來。

### 為什麼不算進數字

日曆頂端那一行與週檢視格子上的「N 筆」回答的是**「那段時間有幾件事要做」**，
而取消的那一筆已經沒事要做了。算進去會讓她以為那幾天排滿了。

所以 `summaryByDate()` 一個字都不改（它本來就濾掉），
`countLine()` 反而要**補上**濾掉 —— 它以前沒濾，是同一個 bug 的另一半。

### 為什麼取消的不參加撞期判斷

那個時段已經還回去了，標成撞期是**假警報**。而假警報的代價是她學會忽略
真的那幾個（SPEC 第 4.7 節：這裡看不到同事在 Abovee 上壓的東西，
找到的一定是她自己撞的 —— 所以每一個都該是真的）。

## 不吃新的色相

色相在 ADR-0039、0045 就已經用完了（來訪的四個狀態 ＋ 待辦 ＋ 行事備註 ＋ 休假）。
所以這裡用的是**既有的畫法**：`--visit-cancelled` 那一組顏色照舊，
再加上降透明度與刪除線 —— 跟 `.kind-todo--done`（勾掉的待辦）**同一種手法**。

`opacity` 與 `text-decoration` 都不是顏色，所以 `tokens.css` 的淺色深色兩份
一個字都不用動（ADR-0055）。

## 開關收在 `agendaFor()`，而且**預設是不收**

```js
agendaFor(visits, date, { roomsById, staffById, includeCancelled })
```

只有日曆的三個檢視傳 `true`。壓表問的是「這一天還排得下嗎」，
進度追蹤問的是「這個月做了多少」—— 兩個都不該看到取消的。
預設值選錯的代價不對稱：多看到一筆只是雜訊，少看到一筆是排錯班。

**軟刪除的一律不收**，`includeCancelled` 也救不回來。刪掉不是一種狀態，
是那一筆不存在 —— 所以那兩件事在程式碼裡要分開判斷，不可以只把 `isActive()` 放寬。

## Consequences

- `agendaFor()` 多一個選項；`views/calendar.js` 的空狀態判斷要拿
  **還算數的那幾筆**去問（一天只剩取消的來訪時，那幾列照樣要畫，
  但「這天還沒有東西」不可以同時印出來）。
- `STATUS_VIEW` 檔頭那句話跟著改掉 —— 它現在是錯的。
- 取消的那一列上長按會拿到一張空的快捷選單（`nextStatuses('cancelled')` 是空的，
  ADR-0060），所以那時候要**講一句話**而不是跳一張空選單。
