# ADR-0140：改了課程「壓哪幾個系統／寫紀錄」，已經談定的來訪回頭重算待辦

日期：2026-10-08
狀態：已接受
推翻：[ADR-0119](./0119-a-course-ticks-its-own-systems.md)「改了一門課的勾法之後」那一段
（「已經長出來的任務不追溯。下一次那一筆來訪被存時照新規則比對」）。
延伸：[ADR-0027](./0027-registration-tasks-wait-for-the-customer.md)（確認之後才長）、
[ADR-0097](./0097-confirming-is-per-slot-too.md)與 [ADR-0107](./0107-a-registration-task-knows-which-slots.md)（掛號逐段）、

## 背景

2026-10-08 上線前健檢的那一張卡（`f-course-systems`）：

> 改了「設定 → 課程」要壓哪幾個系統，已經談定的來訪不會跟著補長或收掉
>
> 有六門課標著「設定暫定」，預期你上線後會調整。改完之後，只有之後才談定的來訪會照新設定長待辦。……例如替羊膜多勾「耀聖」：已經約好的那幾天，耀聖一張都不會長，畫面也沒有提示。反過來取消勾選，已經長出來的會一直留著。

她對這 18 件的回答：

> ・「上線前要先修」那 18 件，要怎麼出貨？ → 全部一起修完、一起上 staging，你點一次驗收清單

ADR-0119 寫的是「下一次那一筆來訪被存時照新規則比對」。實際上那句話只對**收**成立：
已經談定的那幾筆下一次被存通常就是簽療程單，那時那一段已經不是「已確認」，掛號那一族的閘門
（`acceptsNewTasks()`）不放行 —— 所以多勾的那一個系統**一張都不會長**，而且沒有任何地方講。

## 決定

**存課程的那一下，「壓哪幾個系統」或「寫紀錄」變了，就替用到這門課的來訪回頭算一次待辦。先講再寫。**

### 只有這兩格

待辦是從這兩格推出來的（`tasksForCourse()` 與 `needsRecord`），而且推出來的東西**存成了任務** ——
改了之後有人手上拿的是舊的推導結果。其餘的格子不是這個形狀：

| 這一格 | 改了之後誰拿著舊的 | 現在怎麼辦 |
|---|---|---|
| 壓哪幾個系統、寫紀錄 | 已經長出來／還沒長出來的待辦 | **這一支：存的時候回頭重算** |
| 只改了「壓在哪」（Abovee → Examine） | 沒有 —— 它只在取消那一刻讀，已經長的「取消 X」記的是當初 | 不動 |
| 要不要簽療程單 | 沒有 —— 簽療程單那一頁每次現算 | 不用做 |
| 哪一科的醫師、指派診間／治療師 | 既有時段上選好的人與診間 | 刻意不動（那是她當時選的）；下次改那一段時驗證會講 |
| 時長 | 既有時段的結束時間、額度上抄的時長 | 資料健檢兩列列出來，只列不修 |
| 做完還要再約一次（二返） | 既有客戶身上沒有成對的二返額度 | 資料健檢補（ADR-0023） |
| 名字 | 時段上的快照 | 畫面讀主檔；快照刻意不改 |

### 只寫任務，不存來訪

不走存來訪那一條路。那一條會換 `updatedAt`（別台開著的抽屜全部變舊）、補段落狀態、重算次數、
每筆多跑一次健檢鏈、每筆一則稽核 —— 而來訪本身一個字都沒變。`syncTasksForVisit()` 是純函式，
餵它「還沒存的那一份課程」就算得出來。因為來訪不寫，沒有搶寫的問題，重跑幾次結果一樣。

### 哪幾筆

- **用到這門課**＝`slot.courseId` 是它。任務的規則從頭到尾讀的就是這一格，不另外推一次。
- **長的那一側從還開著的來訪出發**（整筆是已確認或待確認；沒有日期上界）。
- **收的那一側從還沒勾的任務出發**（→ 它們的來訪）：「寫紀錄」是那一段做完才長的，
  開著的那幾張多半掛在已經結案的來訪上，只看還開著的來訪收不到它們。

### 只留這次變了的那幾種

`syncTasksForVisit()` 的結果裡只留「這次改動讓它變了」的種類（`changedTaskKinds()`）：

- **取消類一張都不長。** 「壓在哪」變了時，`cancelTasksFor()` 的去重是照種類比的，已經取消、
  收過「取消 Abovee」的段重算會多長一張「取消 Examine」—— 那一段當初壓的是 Abovee。
- **新長的只給還開著的來訪。** 「寫紀錄」打開時，一年份已經結案的來訪不回頭各長一張
  （她第一件事是全部勾掉）。還開著的那一天裡已經做完的段照長 —— 它下一次存檔本來也會長。
- 同一筆上別的還沒對齊的東西（死線、名字、別種待辦）不順手改 —— 改了的話確認框上的數字對不上。
- 既有的規則照舊：那一天過了的不長（ADR-0113）、還沒談定的不長（ADR-0027）、勾過的不動（ADR-0106）、
  三個都不勾＝全收而且不長「取消 X」（ADR-0126）。

### 先講再寫

存之前算一次，有東西要動才問：

> 儲存「羊膜」？
> ・會影響 3 天的待辦
> ・多 3 張「耀聖」

數字是試算出來的（`courseTaskPlan()`），存下去跑的是同一段（ADR-0070）。一天都不影響就不問 ——
改名字、時長、診間跟以前一樣一按就存。讀不到（離線）就不存：這一格存下去之後「這門課變了沒」就是否，
沒有人會再回頭補那幾天。

### 寫的順序

待辦的操作與課程本身放在同一個 commit（放得下的時候：一起成功、一起失敗、復原退得回整組）。
放不下要分批時**課程放在最後一批**：先寫課程、待辦寫到一半失敗的話，她再存一次時課程已經是新的、
看起來什麼都沒變，剩下的那幾天就再也沒有人去補。寫的那一刻重算一次，不拿確認框那一份來寫，
所以按兩次、或失敗後重按，結果跟按一次一樣。

## 沒做的

- **資料健檢的「課程做完要不要寫紀錄」那一顆不回頭算。** 它只會把從來沒設過的那一格打開（她自己關掉的不報），
  而打開的那一側本來就是「那一段做完時才長」；差別只有「還開著的那一天裡已經做完的段」要等那一天下次存檔。
- **停用、刪除一門課不重算**：照舊。主檔把課程刪掉，不代表已經排出去的來訪就不用去掛號了。
- 改了設定之後，**已經長出來的「取消 X」不改種類**：它記的是當初在哪裡壓的。

## 後果

- 設定暫定的那六門她上線後調整時，已經談定的那幾天會跟著補長或收掉，而且存之前看得到幾天、幾張。
- 存課程多一輪讀取（只在那兩格變了的時候）：兩種整筆狀態的來訪、有東西要收時再加還沒勾的任務，
  用到這門課的每一筆各讀一次它的任務。設定頁一年改不到幾次。
- 被收掉的那幾張在「設定 → 已刪除項目」裡，理由寫著「『某某』的設定改了，這一張不用做了」。
  她改回去時，還沒勾的那幾張會照新設定再長一次（新的一張，不是把舊的救回來）。
