# 底部面板只用 transform 拖，而且整張都拖得動

ADR-0020 把底部面板做成拖得動的，但只做對了一半。使用者的原話：
「往上拉的時候，抽屜不會跟著往上，而且是整塊斷裂的往上，下面沒有接續，
反而會閃一下才往上」「往下滑也一樣，會閃一下」。

## 為什麼會卡

那一版有三個各自獨立的毛病，湊起來就是「卡卡的」：

**用 `height` 做過場。** 面板從貼著內容的高度長到滿高，是靠 `transition: height`。
瀏覽器每一幀都得把面板裡所有東西重新排版一次 —— 那是主執行緒的工作，
掉幀就是「斷一下」。而且面板是靠底邊固定的，長高的過程中上緣往上跑、
內容也跟著往上跑，中間那一段沒有東西可以露出來，看起來就是「下面沒有接續」。

**往上拖時面板根本沒跟著手指。** 那一版往上只讓它跟三分之一、最多 40px，
真正的長高等到放開手才發生 —— 所以是「閃一下才往上」。

**收起來沒有動畫。** 拖到底之後節點直接被拿掉，畫面上就是消失。

## 改成什麼

**只動 `transform`，一次都不重排。** 手勢一開始就把面板換成滿高（瞬間換，
同時用 `translateY` 把它推回原本的位置，所以那一瞬間畫面上完全沒有變化），
之後純粹靠 `translateY` 跟著手指走。底下的內容在手指動之前就已經排好了 ——
拉多少就露多少，這正是「下面有接續」的來源。放開手之後彈到最近的那一格，
一樣是 transform。

代價是**底部那排按鈕要反向位移**（`--sheet-y`）：面板變成滿高之後，
按鈕本來會待在滿高的那個底部，也就是螢幕外面。反向位移把它黏回螢幕底。
往下拖過原本那一格之後就不再黏，改成跟著面板一起走 —— 不然它會自己浮在灰底上。

**三個停的位置**：貼著內容的那一格、拉到頂、收起來。從頂上往下甩一次
**只回到前一格**，不會一路關掉 —— 那一下太容易誤觸，而她可能只是想把面板
縮小一點看看底下的日曆。再甩一次才收。

## 整張面板都拖得動

使用者要的第二件事：「不要只能按著上面的橫桿才能拖曳……那個名單之外的地方
希望都可以拖曳整個抽屜，然後當那個名單上滑到底或下滑到底的時候一樣可以變成
整個抽屜在滑」。

會捲的那一塊（`.drawer__body`）維持瀏覽器原生的捲動 —— 慣性與邊緣回彈只有它
給得出來，跟 ADR-0017 選 `scroll-snap` 而不自己接 touch 是同一個判準。
手勢落在那裡時分三種：

- 往下拖，而且它已經捲到最上面 → 交給面板（往下收）
- 往上拖，而且面板還沒到頂 → 交給面板（往上長）
- 其餘 → 讓它自己捲

落在其他任何地方（把手、抬頭、留白、按鈕之間）一律拖面板。

## 三個踩到的坑

**判斷要在第一次 `touchmove` 就做完，不能等手指移超過幾個 px。**
內容那一塊是 `touch-action: pan-y`，瀏覽器在第一次 `touchmove` 決定要不要開始捲；
那一下沒有 `preventDefault`，整個手勢就被它拿走了，之後再擋也沒有用。
症狀是「有時候拖不動」—— 而且會依當下的畫面內容時好時壞，最難查的那一種。
「移動超過 5px」現在只用來決定要不要送出那個 `click`，跟接不接手無關。

**補償要量「上緣位移」，不是算「兩個高度的差」。** 手機上面板貼著底邊，
長高時只有上緣往上跑，兩者剛好相等；但 ≥900px 時它是**置中的對話框**，
長高是上下各長一半 —— 用高度差會補過頭，一開始拖就往上跳 157px。
改成量 `getBoundingClientRect().top` 換 class 前後的差，兩種版型共用同一段程式。

**速度不能只看最後一下。** 兩個事件擠在同一毫秒裡送達時，
`(dy / dt)` 會算出十倍的速度，把「輕輕推一下」判成「用力甩」，
面板就在她只是想挪一點的時候整個關掉。改成取最近 90 毫秒的位移，
取樣時間不足 25 毫秒就當作沒有甩。

## Consequences

ADR-0020 的結論沒有被推翻，只是實作換掉了：面板照樣拖得動、拉得到頂、
關得掉，把手照樣是關閉鈕，右上角照樣有叉叉。SPEC 第 8.0 節的「無拖拉」
仍然成立 —— 這些手勢全部都有按鈕做得到。

`.drawer` 從此永遠帶著一個 `transform`（就算是 `translateY(0px)`），
所以它是裡面任何 `position: fixed` 的定位基準。目前全站的浮層
（懸浮鈕、卡片組、資訊卡片、二次確認、toast）都掛在面板外面，沒有人受影響；
之後要在面板裡放固定定位的東西時要記得這件事。

首頁的確認動線自己畫了一張 `.drawer`（它要跟著整頁重畫），沒走 `openSheet()`，
所以 `wireDrag()` 是 export 的，那一張接同一支 —— 全站的抽屜手勢只有一套，
只有一張拖不動的話，她會以為那張壞了。
