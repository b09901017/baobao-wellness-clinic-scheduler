# app 是記錄者，不是判斷者

實際的工作流程是：使用者看著 app 上的客戶狀況（可用時間、剩餘次數、喜好程度）與公司的 Abovee 系統，**自己判斷**要排誰排哪天，填進 Abovee，然後回 app 記錄。app 從頭到尾沒有決定權。因此除了醫療禁忌之外，**所有檢查一律只提示、不阻擋**：診間衝突、治療師衝突、診間限制、頻率限制（每季一次），發現了就顯示在旁邊，但永遠不擋下儲存。

會這樣決定是因為 app 看不到同事在 Abovee 上壓的東西，手上的資料本來就不完整；用不完整的資料去擋一個看得到完整畫面的人，只會擋錯。

## Consequences

醫療禁忌是唯一的例外，維持硬性阻擋——它不需要推算，只是比對客戶身上有沒有那個標記，不存在資料不完整的問題，而且錯了會造成實際傷害。

第一版也不做「建議時段」。SPEC 第 8.2 節原本要系統算好時段讓使用者照抄，但使用者選擇自己判斷，那個功能就失去了對象。壓表模式改為「一位一位把客戶資訊攤開 + 快速記錄」。

未來若要恢復自動推薦，方向是讓使用者拍一張 Abovee 畫面的照片來補足缺少的佔用資訊，而不是靠 app 自己推算。
