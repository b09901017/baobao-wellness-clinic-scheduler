# ADR-0143：切換那天正式站連主檔一起刪掉，用 firebase-tools 一類一類刪

日期：2026-10-09
狀態：已接受
延伸：[ADR-0118](./0118-staging-holds-a-rehearsal-of-real-data.md)（切換那天正式站重新匯一次合併檔）、
[ADR-0141](./0141-staff-show-full-names-with-a-short-name.md)（人員全名跟著合併檔 v6 進來）。
`scripts/reset-staging.mjs` 檔頭那一句（「正式站沒有任何理由需要被整份清空」）**不改**：那一支照舊拒絕正式專案。

## 背景

ADR-0118 定了切換那天正式站重新匯一次合併檔，沒講主檔。正式站的主檔是舊一代的種子，而 `loadSeed()` 只建不覆蓋 ——
只清客戶與來訪的話主檔還是舊的，合併檔照新種子的名字認課程與人員，會有一批對不到
（10/9 用 8/20 那一代的種子量過：SIS 還叫舊名字，51 處對不到）。資料健檢補得上大部分，但要逐列按、而且有幾格補不到。

她 2026-10-09：

> 正式站是哪一代的種子？有關係嗎 ? 反正最後我會清空正式的重匯一次

接著選了怎麼刪（三條路：firebase-tools 的指令、主控台手動刪、替 `reset-staging.mjs` 開一個正式站模式）、
稽核紀錄要不要一起刪、她自己在正式站寫的東西怎麼處理：

> firebase-tools 指令
> 稽核紀錄：刪掉
> 備忘錄留著、其餘照刪

## 決定

1. **切換那天正式站連主檔一起刪掉、重新載入現在的種子**，再匯帶人員名單的合併檔。
2. **用 firebase-tools 的 `firestore:delete --recursive`，一類一類點名**，不用 `--all-collections`、不加 `--force`。
   點名的那一份名單寫在 `docs/STAGING.md`「切換那天」。
3. **不刪三類**：`allowedUsers`（白名單）、`aiUsage`（Function 的帳本）、`playbooks`（備忘錄）。**稽核紀錄刪掉**，刪之前的備份勾「含稽核紀錄」。
4. 刪之前抄下來、切換之後重填：設定（`config/app` 的排序權重、時段間隔、天數、試算表網址與密鑰、LINE 模板）、`config/ai` 的每月上限、她自己加的主檔。

## 為什麼

- **不開正式站模式**：那一支是「每一次預演之前都會跑」的工具，拒絕正式專案是它的護欄。替一年一次的事開一條放行的路，
  護欄就從「做不到」變成「記得加旗標」。firebase-tools 已經裝好、本來就要她本人的登入，每一類問一次「確定嗎」，
  而且不用多寫一行要測試的程式。
- **點名、不用 `--all-collections`**：後者會連白名單一起刪，刪完就登不進去。點名的代價是名單打錯會漏刪 —— 那一類照樣在、
  資料健檢與匯入頁的數字看得出來；多刪的方向（白名單）才是收不回來的那一邊。
- **主控台手動刪**：子集合要一層一層點進去，漏刪了畫面上看不出來。
- **備忘錄留著**：合併檔不帶它；它掛的是課程 id，種子那幾門的 id 重新載入之後不變，掛得上。
- **AI 帳本留著**：每月上限照它算，刪掉等於這個月的用量歸零（ADR-0100 的防護）。
- **稽核刪掉**：她選的。切換之前的紀錄指的是刪掉的資料，留在備份裡。

## 後果

- 載入種子之後資料健檢的主檔那幾列應該都是 0；不是 0 就是種子與資料健檢對不上，要先停下來。
- 她自己在正式站加的主檔與設定要手動重填。沒填的那一格是預設值，畫面上看不出來 —— 所以檢查表把每一格列出來。
- 正式站的療程單照片（Storage）不在 Firestore 裡，這個指令刪不到；正式站還沒開通照片之前不會有。
