# ADR-0163：備註沒排過的預設順序 —— 病歷號最前面、電話最後面

日期：2026-10-20
狀態：已接受
推翻：[ADR-0156](./0156-long-notes-and-the-notes-order.md) 第二節「沒排過：電話、LINE、長備註、短備註」那一句、
「不在順序裡的電話、LINE（排的時候還沒填）→ 放最前面」那一句，以及 [ADR-0160](./0160-chart-number-is-a-field.md)「病歷號接在 LINE 後面」。
舊的兩支一個字都不改。

## 背景

她 2026-10-20 要上線、重產切換用的合併檔時說：

> 還有一個希望注意的點是，我希望每個人的備註都應該預設是病歷號最前面，然後有line的line第二個，然後電話是在最後面

10/18 她說的是「最上面一行電話，長備註，原本的短備註」（ADR-0156），10/19 病歷號變成一格時接在 LINE 後面（ADR-0160）。
匯進來的每一位都沒有排過順序（合併檔不寫 `noteOrder`），所以預設順序就是切換那天她看到的每一位客戶的樣子。

## 決定

- 沒排過（沒有 `noteOrder`）：**病歷號 → LINE → 長備註 → 短備註 → 電話**（`domain/customerNotes.js` 的 `noteItems()`）
- 排過的照她排的，一格都不動
- 排過、但那一格排的時候還沒填（不在順序裡）：病歷號、LINE 放最前面（同以前）；**電話放整串的最後** ——
  接在沒排進去的長備註、短備註後面（別的入口加的，例如拍訂購單的「尾款」，變成倒數第二）
- `chartNoMove()` 照舊：沒排過的不寫順序（搬完就照預設排在最前面）；排過的照它算出來的那一串寫

## 後果

- 客戶清單的卡片只畫前四則（ADR-0160 的 `notesPreview()`）：大部分人的卡片上**看不到電話了**。她要的是電話在最後面，
  卡片照同一串畫 —— 第一段過目時講過這一條，她沒有要卡片另外排
- 客戶詳情的撥號照舊是那一顆丸子（在整串的最後）；按住複製照舊
- E2E `74`、`77` 照舊的預設位置拖曳、斷言順序的那幾條跟著改
