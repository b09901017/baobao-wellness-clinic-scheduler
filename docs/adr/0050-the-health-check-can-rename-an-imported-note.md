# 資料健檢也改得掉匯入寫錯的那個字

2026-08-24 她說：

> 「備註幾乎都會寫一個姓名欄的編號：…其實那個是病歷號，
> 我希望之後匯入，不要寫『姓名欄的編號：』而是寫『病歷號』。」

匯入端改字是一行的事。問題是**已經匯進去的二十幾位身上還掛著舊的說法**，
而那是她天天在客戶詳情上看到的字。

## 決定

在資料健檢上加一項「備註寫著舊的說法」，一鍵改掉。

**這是資料健檢第三個會寫入的動作。** ADR-0007 定的是「資料健檢只讀不寫」，
ADR-0023 開了第二個口（補二返額度）。這一支符合同樣的條件：

- **有明確正解。** 「姓名欄的編號：1234」與「病歷號 1234」指的是同一件事，
  不需要她判斷。
- **沒有第二種可能的意思。** 不像「次數對不上」那種要她決定信哪一邊。
- **沒有別的地方做得了。** 這個 app 沒有後台，她只有畫面；
  一支跑一次就丟的腳本她跑不了。

寫入時**兩個欄位一起改**：`marks`（彩色小丸）與 `notes`（那幾則接起來的
純文字，試算表報表與壓表卡片讀的是它）。只改一邊會讓兩處從此對不起來。

## Consequences

**這一項是一次性的。** 她按過一次之後永遠是 0 筆，而 CHECKS 上會多一列
永遠沒事的檢查。可以接受：那一列不佔畫面（沒有 finding 的檢查在
`views/health.js` 上收起來），而留著它的好處是萬一有一份沒被掃到的舊資料
之後才冒出來，它照樣抓得到。

真的想刪的話，刪掉 `checkChartNo` 與 `renameChartNo` 那兩段就好，
`domain/legacyImport.js` 的 `OLD_CHART_NO_PREFIX` 也可以跟著走。
