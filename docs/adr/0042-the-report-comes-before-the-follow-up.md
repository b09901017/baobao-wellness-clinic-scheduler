# 二返前面還有一站：報告還沒拿到

`SPEC.md` 第 7 節規則 8 從第一版就寫著：健檢那一筆標成已完成 → 長出「約二返」，
死線是**健檢日 + `followupDueDays`**（預設 7 天）。ADR-0022 把那條規則實作出來。

真的用起來之後她講了現實：**報告通常兩三週才出來。**

所以那張待辦的形狀一直是錯的：

- 它在第 8 天變紅
- 而它紅著的那兩週，她**做不了任何事** —— 報告還沒到，沒有東西可以跟客人約
- 一張永遠紅著、而且紅得沒有道理的待辦，最後的下場是她不再看那個顏色

紅色在待辦中心的意思是「這件事該做了」。一個系統只要製造出一批
「紅了但做不了」的東西，紅色就不再是訊號。

## 中間真的少了一個動作

不是「把死線調長」就好 —— 那樣會蓋掉一件她真的要做的事：**去問報告出來了沒**。

健檢做完到約二返之間有兩個動作，而它們的觸發條件不一樣：

| | 追蹤健檢報告 | 約二返 |
|---|---|---|
| 什麼時候該做 | 健檢做完之後兩三週 | **拿到報告之後**，越快越好 |
| 死線從哪天算 | 健檢日 + 21 天 | **勾掉追蹤報告那一天** + 7 天 |
| 跟客人講什麼 | 沒有，是她去問實驗室／診所 | 約時間 |

把它們壓成一張，等於用一個死線同時描述兩件觸發條件不同的事。

## 為什麼「約二返」的死線要從勾掉那天算

這是這一支真正的重點，也是唯一一個**鏈式**的地方（其餘的待辦一律在客人確認
的那一刻一次長齊，各有各的死線）。

從健檢日算的話，「約二返」一出生就是逾期的 —— 我們只是把紅字從第 8 天
推遲到第 22 天，問題一模一樣。從勾掉那天算，它出生時是乾淨的，而它變紅
就真的代表「報告拿到兩週了還沒約」，那時候紅色是對的。

代價是死線依賴另一張任務的 `doneAt`。讀不出來時（舊資料、手動改過）退回
**健檢日 + 報告天數 + 約的天數**，而不是「今天 + 7」—— 用今天算的話，
死線會在每次讀取時往後跑一天，那是一張永遠不會逾期的待辦。

## 為什麼只有這一段鏈式

反過來的例子是簽療程單。如果它要等 Examine 與耀聖勾完才出現，那麼
**掛號忘了做的那幾筆，來訪當天就連提醒都沒有** —— 而那正是最需要提醒的一筆。
鏈式會把「前一步沒做」變成「後一步不存在」，那在多數情況下是災難。

報告這一段是例外，因為它的前後不是「兩件都要做」，是**前一件的結果決定
後一件能不能開始**。報告沒到，「約二返」在現實裡不可能發生。

## 既有的「約二返」不收掉

上線的那一刻，Firestore 裡就有未完成的「約二返」（她已經在用了）。
新的鏈條跑到它們時會找不到對應的追蹤報告任務，照規則會判成「不該存在」
而收掉 —— **那等於把一件她真的還沒做的事默默刪掉。**

所以規則多一條：**那一筆健檢已經有一張未完成的「約二返」時，就當作報告
那一段已經走過了** —— 不補產生追蹤報告，也不動那張約二返（連死線都不改）。

這跟 ADR-0027 的 Consequences 是同一個判斷：替她刪待辦比留著更糟。

## ADR-0022 哪一半還活著

| | 狀態 |
|---|---|
| 額度成對展開（買 N 次健檢就有 N 次二返） | **活著**，一個字沒改 |
| 「約二返」由額度推導、不由來訪類別推導 | **活著** |
| 它不能塞進 `syncTasksForVisit()` | **活著**，而且現在有兩種待辦要擋（`CHAIN_KINDS`） |
| 死線是健檢日 + `followupDueDays` | **被這一支推翻** |
| 系統不會自動幫她約 | **活著**（ADR-0002）。「去問報告」也一樣不會自動做 |

## Consequences

**`settings` 多一個 `reportDueDays`（預設 21）。** 兩個間隔各自可調，
因為它們講的是兩件不同的事：一個是實驗室出報告要多久，一個是她拿到之後
多快該約。

**待辦中心多一個種類。** 它落在「來訪之後」那一段（ADR-0043），
跟「約二返」相鄰。

**沒有第二個地方記「報告拿到了沒」。** 那張任務的 `done` 就是那個狀態。
存成健檢來訪上的一個欄位會變成兩個地方講同一件事，而兩個地方遲早會不一致。
代價是：她如果把那張任務刪掉，鏈條會退回上一站重新長一張。這被接受 ——
軟刪除的任務在「已刪除項目」裡還原得回來（SPEC 第 6.1 節）。
