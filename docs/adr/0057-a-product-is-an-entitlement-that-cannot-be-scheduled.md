# 營養品也是一筆額度，只是排不進來訪

`CONTEXT.md` 一直寫著：

> **營養品**：賣給客戶的實體商品，例：夜態美、速膳淨。
> 只記錄與顯示，**不佔時段、不排班、不產生任務**。

「只記錄與顯示」在 2026-08-25 以前的實作是：**沒有地方記**。舊試算表匯進來的
那幾筆變成一則備註（`domain/legacyImport.js`），而她自己賣掉一罐夜態美之後，
加購那一排丸子上根本沒有這個選項。

她的原話：「少了營養品可以加選……加營養品也要能選那些多少」。

## 三個做法

| | 怎麼存 | 代價 |
|---|---|---|
| A | 主檔多開幾個「課程」 | **那就排得進來訪了** —— 正是 CONTEXT 說不可以的事 |
| B | 客戶文件上一個 `products` 陣列（像 `marks`） | 稽核紀錄、軟刪除、已刪除項目還原全部要再做一份 |
| C | **額度多一個型態 `product`** | 它會流進「還要排幾次」的計算，要擋 |

**2026-08-25 選 C。**

A 是最快的一條路，也是最危險的：一個叫「夜態美」的課程會出現在壓表的課程
清單上、出現在時段反查的結果裡、出現在來訪編輯器的「這一段做什麼」丸子上。
那不是多了一個選項，是**把一件不會發生的事放進她每天要掃過的清單裡**。

B 是乾淨的，但它要重造一整套 `data/repo.js` 已經給的東西。而且那一份資料
會是唯一一種「買了但不在稽核紀錄裡」的東西 —— 出事的那天它是唯一查不回去的。

## 決定

`entitlements` 的 `type` 多一個 `'product'`，外加一個 `productId`。

換來的是：同一顆「加購」按鈕、同一張表、同一份稽核紀錄、同一個垃圾桶、
同一條還原路徑。要付的代價只有一個，而且付得起：

**它不可以流進任何「還要排幾次」的計算。**

閘門收在 `domain/entitlements.js` 的兩支上，呼叫端不要自己再判斷一次：

```js
export const isProduct = (e) => e?.type === 'product';
export const schedulable = (rows = []) => rows.filter((e) => !isProduct(e));
```

擋在三個地方，而這三個是**全部**：

| 在哪 | 不擋會怎樣 |
|---|---|
| `domain/scheduling.js` 的 `customerPools()` | 壓表卡片牆、待辦中心的「壓表登記」與「問這輪的時間」三條路都走它。她的待辦上會冒出「王小明還有 2 次沒壓表」，而那 2 是兩罐夜態美 |
| `domain/entitlements.js` 的 `summarize()` / `lowRemaining()` | 客戶總覽那一列的「剩 N 次」會把罐數加進去 |
| `ui/views/visitEditor.js` 讀額度的那一行 | 「這一段扣哪一筆」的丸子上會出現夜態美 |

**`domain/sheetReport.js` 刻意不擋。** 她的舊試算表第 12 列就是營養品
（ADR-0024：那份報表要照著她原本那一張），少掉那一列反而對不起來。

## 畫在哪

客戶詳情上**自己一小段「營養品」，接在額度下面**（她 2026-08-25 決定的），
一筆都沒有就整段不畫。

不塞進那一排額度卡，是因為那張卡的主體是「已完成／已排未上／剩餘」三段式
進度條，而營養品**永遠是滿的** —— 沒有任何一筆來訪扣得掉它。一條永遠滿格的
進度條在講一件不會發生的事，那正是同一天 ADR-0056 拿掉一句說明的理由。

同理，「調整」那一張表對營養品只留「幾份」與刪除：時長、頻率限制、器材、
課程、到期日對一罐夜態美通通沒有意義。單位也不一樣 —— **營養品論份，其餘論次**。

## 順帶：營養點滴終於選得到品項

同一輪修掉的另一半。`CONTEXT.md`：營養點滴品項「各自有各自的次數，
**不合併計算**」，所以一位客戶身上會有好幾筆營養點滴額度，靠名字分辨
（`營養點滴 - 護肝排毒`、`營養點滴 - 雪顏亮彩`）。

舊資料匯進來的時候一直是對的（`domain/legacyImport.js` 把 B 欄拆開），
**只有她手動加購這條路做不到** —— 同一件事有兩份實作，而其中一份是錯的。
接法收進 `itemisedLabel()`，匯入與加購共用同一支：兩邊各接一次的話，
同一位客戶身上一筆匯進來的、一筆手動加的，長得不一樣她會以為是兩種東西。

品項存成 `ivProductId`，跟 `tier`（ADR-0054）同一種東西：**存下來，
但流程與任務都不看它**。存 id 而不是只留在名字裡，是因為主檔上的名字
她隨時改得了，而字串比對正是舊 Apps Script 靜默失效的原因。

## Consequences

- `firestore.rules` 的 `validEntitlement()` 只驗形狀（`type` 三選一、兩個
  選填的 id 是字串或 null）。「product 一定要有 `productId`」那一條在
  `validateEntitlement()` 擋 —— 同 `followupForEntitlementId` 的判斷：
  在 Rules 裡查一筆主檔存不存在，代價是每次寫入多一次讀取。
- 之後真的要記價格時，`productId` 會是那張對照表的 key，不是再多一個並排欄位。
