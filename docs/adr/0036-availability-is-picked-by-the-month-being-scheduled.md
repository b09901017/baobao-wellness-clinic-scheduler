# 本輪可用性照「壓哪個月」挑，不照「今天」挑

`domain/scheduling.js` 的 `rowFor()` 一直是用 `currentCollection(availability, today)`
拿那位客戶的本輪可用性 —— 也就是「今天還算數的那一份」。壓表批次卻是按月開的，
而她的流程是**這個月坐下來壓下個月的表**。兩件事對不起來。

使用者問的是這個：

> 我填了不方便的時間，就算我是填 9 月不方便的時間，我壓 8 月的表他也會出現限制？
> 為什麼不是我壓那個月，他只呈現我那個月問的？

## 錯在哪裡，而且錯得看不出來

`currentCollection()` 不排除還沒生效的那一份（`state === 'upcoming'`），
所以八月底壓八月的表時，它拿到的是剛收到的**九月**那一份。接著 `rowFor()`
把可用日算在「收集的有效期」與「這個月」的交集上：

```
九月那一份 2026-09-01 – 2026-09-30
壓的月份   2026-08-01 – 2026-08-31
交集       空的  →  可用 0 天
```

而排序的第一項是「可用天數越少越優先」，**0 天等於限制最滿分**。
於是一位其實只是「八月還沒問」的客戶，會用一個假的「可用 0 天」
排到卡片牆的第一位 —— 而那一列正是她最信任的一列。

更小但更常見的另一半：九月那一份裡的「每個禮拜一不行」會被拿去劃掉八月的每個禮拜一。
她會照著避開，而客戶其實那幾天可以。

## 決定

新增 `domain/availability.js` 的 `collectionFor(collections, from, to)`：
**涵蓋這段期間的那一份**（有交集就算，交集最多的優先，一樣多才比收集日期）。
壓表（`rowFor()`）與時段反查（`candidatesFor()`，那裡的期間就是空出來的那一天）
都改用它。

**沒有涵蓋到那段期間就是 `needsAvailability`**，不是「可用 0 天」。
兩者在畫面上長得完全不一樣：一個是黃色的「還沒問 8 月的時間」，
一個是紅色的「哪天都不行」，而她會對這兩件事做出相反的動作。

## 為什麼不是把 `currentCollection()` 改掉

因為另外兩個地方問的是真的「現在」：

- 待辦中心的「問這輪的時間」（ADR-0028）—— 現在該打電話給誰
- 資料健檢的「可用性過期了」—— 現在手上這份還算不算數

那兩頁沒有「哪個月」這個參數，也不該有。兩支各自回答一個問題，
比一支帶旗標的函式好懂，而且旗標傳錯不會有人在畫面上發現。

## Consequences

`ADR-0001` 沒有被推翻：待壓表仍然是推導的。改的是推導時**讀哪一份可用性**。

`ADR-0028` 與 `ADR-0033` 一個字都沒動 —— `customersToAsk()` 仍然走
`currentCollection()`，因為它問的還是「現在還沒問到誰」。

row 上多了 `askedFrom` / `askedTo`，UI 才講得出「問的是哪個月」。
壓表那一頁的三句文案跟著改成帶月份的（「還沒問 8 月的時間」
「不知道他 8 月哪幾天可以」「去記 8 月問到的時間」）—— 少了月份，
「還沒問」與「問過但那是別的月份」在畫面上長得一樣。

代價是她如果只在八月中問了一份跨到九月中的可用性（例如 8/15–9/15），
壓九月時可用天數只會算那半個月。這是對的：另外半個月她本來就沒問。
