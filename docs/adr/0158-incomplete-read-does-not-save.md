# ADR-0158：讀不完整時，會動到次數或健檢那一串待辦的存檔先不存

日期：2026-10-19
狀態：已接受
推翻：SPEC「形態」那一格「讀取用快取，寫入排隊重試」裡**寫入**那一半，只對「會動到次數或待辦」的那一種寫入。
其餘的寫入（隨手記、備註、客戶資料、主檔）照舊離線寫進本機快取、連上自己補送。
延伸：[ADR-0004](./0004-counts-are-derived-in-detail-cached-in-lists.md)（次數是快取，真相是來訪）、
[ADR-0070](./0070-a-warning-may-only-say-what-really-happens.md)、

[ADR-0140](./0140-changing-a-course-recomputes-the-tasks-of-agreed-visits.md)（設定 → 課程 離線不存的先例）、

## 背景

她 2026-10-19 逐條回答上線前那份清單：

> 3. 沒網路的時候存檔，會收掉健檢那條鏈的待辦，而且剩幾次會少算。 好 修

接著問她要擋還是要「先存、連上再補算」：

> 3. 離線，我手機就有網路吃到飽，所以除非是短暫的網路不好，不然我一直都是有網路的

Firestore 開著本機快取（`data/firebase.js`）。離線、或網路不穩到 SDK 判定離線時，`getDocs()` **不會失敗**，
回的是快取裡剛好有的那幾筆（她只看過那幾個月的日曆時，快取裡就只有那幾個月）。存一筆來訪拿那一份當
「這位客人的全部」：

- 額度身上的次數照那一份重算 —— **少算**，寫下去
- 健檢那一次不在手上 → 當成「不是已完成」→ 開著的「追蹤健檢報告」「約二返」「寄報告給醫師」被收掉；
  二返不在手上 → 長一張假的「約二返」

同一支 `followups.js` 裡 `owed()` 對「不在手上」是「不知道就不改」，收待辦那一圈卻是「不在＝收」。
10/12 只查不改時在 domain 層重現過；這一次在瀏覽器裡走過（E2E `76`）。

## 決定

**算這一筆要用的那幾份讀回來，只要有一份是本機快取的、或這台裝置確定離線，就不寫、講一句、畫面上她打的留著。**

### 擋哪幾種

會吃「這位客人的全部來訪」的寫入：

| 寫入 | 在哪裡擋 |
|---|---|
| 存一筆來訪（壓表、日曆長按、來訪編輯器、待辦兩張抽屜、批次取消、拍 Abovee、另約健檢順便接二返） | `data/visits.js` 的 `save()` |
| 還原一筆刪掉的來訪、軟刪除一筆來訪（現在沒有呼叫端） | `restore()`、`remove()` |
| 勾／拿回健檢鏈上那兩種待辦（追蹤健檢報告、約二返） | `followupOpsAfterTaskChange()`（`tasks.setDone()` 經過它）；預覽那一支也丟，`confirmUntick()` 讀不到就放行、寫的那一下擋 |
| 拍 Abovee 存完收掉中途長出來的鏈上待辦 | `dropChainLeftovers()`：一張都不收（多一張可以勾掉） |
| 客戶詳情的「修正」次數 | 按下去那一刻重讀全部（`listWhole()`） |
| 資料健檢的「重算次數」 | 快照是快取來的就不寫（`applyFixes()`） |

確認框讀的那兩份（`chainInputs()`）讀到快取時當讀不到：**少講幾句，不講錯的**。

**不擋**：隨手記、備註、客戶資料、主檔、勾鏈以外的待辦 —— 它們不吃這位客人的全部來訪。

### 怎麼知道「不完整」

- `repo.list()` 每一次讀回來是快取（`snapshot.metadata.fromCache`）就記一筆（`cacheReads()`）；寫入在開始時記下那個數，
  commit 之前再看一次 —— 中間自己讀的課程、任務、額度有一份是快取就擋
- **這位客人的全部來訪記在 data 層，不掛在陣列上**：呼叫端傳進來的常常是 `.filter()`、spread 過的，陣列上的旗標一抄就掉，
  掉了等於「完整」放行 —— 錯的方向。`listByCustomer()` 每讀一次就記下來源（`visitsRead`），寫入問「這一台最近一次讀到的是不是伺服器的」；
  **還沒讀過也算不完整**
- `navigator.onLine === false` 也算（確定離線）—— 那時候一進來就擋，不等 SDK 那十秒

擋不擋只有一支純函式（`domain/incompleteRead.js` 的 `readsIncomplete()`）。

### 按下去那一刻重讀

打開時讀一次就沿用的話，那一次是快取的就**永遠存不進去**（她連上之後按幾次都一樣）。所以要拿去存的那幾條路
在按下去那一刻讀（`listWhole()`：讀不完整就丟），而且**擋在確認框之前** —— 不要讓她答完幾道框才說存不了。
來訪編輯器以前打開時讀一次就沿用，現在存與取消一段之前都重讀。

### 那一句

「網路不穩，讀不到 客戶A 的全部紀錄 —— 這一筆先不存，連上之後再按一次」。

- **不給重試鈕**（同 `StaleWriteError`）：重試跑同一個閉包，拿的還是快取那一份
- **不可以說「已經存在這台裝置上了」**：那是真的排進佇列的那一種。網路不穩時讀取要十秒左右才退回快取，
  而 toast 的 `PENDING_MS` 是 8 秒 —— 以前那幾秒會先講「已經存在這台裝置上了」再講「沒存」。
  現在那一句要**真的送出過一次寫入**才講（`repo.commitsSent()`、`ui/saveFailure.js` 的 `slowSayNow()`）；
  傳照片的那幾條自己給一句（`slow`），照舊時間到就講

## 為什麼不做「先存、連上再補算」

她說了：網路吃到飽，斷線只是短暫的。補算要記住「哪幾筆是照不完整的資料存的」、連上之後重算、而且中間她可能在別台改過 ——
那是另一套同步機制，為了幾秒鐘的空檔不值得。擋下來的代價是她等一下再按一次。

## 後果

- 網路不穩的那幾秒，壓表、日曆、待辦抽屜按下去會講那一句；連上之後再按一次就存得進去
- SDK 剛回到線上那一下可能還讀到快取（照樣擋），她會多按一次
- 全站共用一個「讀到快取」的數：同一段時間別的畫面讀到快取也算 —— 那代表 SDK 那時候認為自己離線，寧可多擋
- 同一個形狀還有三處沒收（刪客戶的「還掛著什麼」、推試算表的次數、舊資料匯入判同名），記在 `before-golive-2026-10-19/HANDOFF.md` 的「中途發現」
