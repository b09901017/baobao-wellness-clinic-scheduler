# 備忘錄是一個大框框，一疊卡

2026-09-04 她把 ADR-0067 那一版點過一遍之後：

> 備忘錄要是像卡牌一樣可以左右滑動的，然後也有所有的清單可以快速選，
> 就顯示標題。然後我覺得不用特地幫我分什麼事前事後，那些全部都給我一個大框框，
> 像是一般的備忘錄 app 一樣，只要有標題、掛那個課程，以及很大的輸入框就好。
> ……不需要章節，不需要分類，也不需要多餘的說明，就是簡潔直觀就好。
> 然後我希望「加一個備忘錄」會是以浮動小泡泡的形式出現在這頁的右下角。
> 原本「寫一份」那個按鈕我覺得可以做成放大鏡的圖示。

## 決定

**三個欄位：標題、掛哪些課程、一大塊字。**

```js
{
  title,      // 必填，≤ 40
  courseIds,  // 選填
  body,       // 必填，≤ 5000。換行她自己打
}
```

畫面是**一疊左右滑的卡牌**：上面一排標題丸子直接跳到某一張，
卡片右上角一顆鉛筆就地編輯，右下角一顆泡泡加一份，抬頭一顆放大鏡展開搜尋。

## ADR-0067 哪一半還活著

| | 狀態 |
|---|---|
| 它不勾、不上日曆、不產生任何任務 | **活著**，這是整件事的地基 |
| 綁課程不綁人 | **活著** |
| 頂層集合 `playbooks`，不是 `config/` 底下的主檔 | **活著** |
| `data/playbooks.js` 的行程內快取 | **活著** |
| 入口在待辦那一頁的右上角，導覽列一個字都不動 | **活著** |
| `visitReadHtml()` 一個字都不改 | **活著** |
| 一節可以標「時機」，標了的會自己浮出來 | **被這一支推翻** |
| 分類（`tag`）與釘選（`pinned`） | **被這一支推翻** |
| 閱讀頁的簽名是那條脊線 | **被這一支推翻**（沒有節了，線沒有東西可以串） |

## 「自己浮出來」沒有被砍掉，改的是浮什麼

她那句「點開該筆預約或日曆卡片時，自動浮現的操作小撇步」還在，而她擔心的
洗版也還在（「好像也不用特別獨立開一個『提醒吃飯』的任務，避免洗版」）。

改的是**用什麼擋洗版**：

| | 第一版 | 現在 |
|---|---|---|
| 浮什麼 | 對得上時機的那一節 | 整份的**前四行**（`PREVIEW_LINES`） |
| 擋洗版靠 | 時機（`whenForVisit()`） | 行數 |
| 她要怎麼控制 | 幫每一節標事前／當天／結束後 | 把最重要的寫在前面 |

**行數比時機好懂。** 她看得到自己寫的第幾行會出現在日曆的卡片上；
時機要她先在腦袋裡跑一次「這一筆現在算事前還是當天」。而她自己說的是
「不用特地幫我分什麼事前事後」—— 那個分段是我們替她發明的結構，
不是她筆記裡本來就有的（第一版把它當成她的，那是讀錯了）。

## 為什麼不留一個「進階：分節」

因為那會讓兩種形狀同時存在，而**每一個讀的地方都要處理兩種**。
她要的是「像一般的備忘錄 app」，而一般的備忘錄 app 沒有進階模式。

## 為什麼一疊卡的順序是「她寫下來的順序」

不用「最近改過的在最前面」（一般備忘錄 app 的作法）：那一疊會在她編輯完之後
自己重排，而卡牌的全部價值就是**「我正在看第三張」這件事站得住**。
也不用標題排序 —— 那個順序對她沒有意義。新的加在最後面，永遠不會自己動。

## 為什麼左右滑用原生捲動

`scroll-snap-type: x mandatory` + 每張 `scroll-snap-align: center`。
自己接 touchmove 永遠差一截慣性、回彈與橡皮筋，而她那句「絲滑」講的就是那一截。

現在停在第幾張用 `IntersectionObserver` 認，**不用 scroll 事件**：
scroll 在 iOS 上捲動時會被節流，圓點與丸子跟不上手指的話，那一排看起來就是壞的。

## 舊資料

`playbooks` 這個集合是 PR #52 帶進來的，那一版只活過一天，**正式與 staging 上
一筆都沒有**。所以沒有搬家程式。

讀的那一側留了四行退路（`bodyOf()`）：`body` 是空的而 `sections` 有東西時，
把每一節接起來，節標題自成一行。**只在讀的時候接，不自動改寫資料** ——
她一存檔就自然變成新的形狀。`firestore.rules` 反過來只收新形狀，
所以舊形狀寫不回去，不會有半新半舊的文件。

## Consequences

- **這一頁上沒有一句解說文字。** 第一版有兩句，那種話她讀過一次就夠了。
  只有一份都沒有的時候留一句。
- **`#/playbook/:id` 不是另一頁**，是「這一疊，開在那一張」。
  少一頁就少一個回不去的地方，日曆卡片上的「看整份」也還通得到。
- **一張卡的裝飾只有上緣那一道茶色**（便條紙的黏邊）。一疊便條紙的樣子由
  「白卡 + 黏邊 + 露出下一張」三件事講完，再多一件就變成貼圖。
- 卡片高度固定、內文在卡片裡面捲：一張很長的備忘錄不該把整疊撐高。
- `MAX_BODY` 從 2000 拉到 5000。第一版一份可以有 20 節 × 2000 字，
  現在只有一格，上限不跟著放大就變成另一種「存不下去」
  （`tests/number-fields.test.js` 的同一句話）。
- 刪掉那一份的入口在編輯狀態裡（跟隨手記同一條：要刪就先進編輯）。
  **不做長按選單** —— ADR-0060 要求每一顆都要另外有一條點得到的路，
  而這一頁只有一顆，那條路本身就夠短了。
