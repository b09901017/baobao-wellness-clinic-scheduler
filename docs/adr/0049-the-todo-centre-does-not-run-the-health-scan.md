# 待辦中心不再跑背景的資料健檢

2026-08-24 她說：

> 「我希望資料健檢的那個提醒可以移除，如果我要看健檢結果，我去設定看就好。」

拿掉的不只是那顆徽章，**背景掃描本身也一起拿掉了**。

## 為什麼不能只拿掉徽章

`runIfDue()` 與 `lastBadge()` 的唯一呼叫端就是首頁那顆徽章。留著掃描的話，
它每天會把客戶、額度、來訪、任務、可用性整個讀一遍，把一個字串寫進
`localStorage`，然後沒有任何人讀它 —— 一段**每天付一次成本、沒有出口**的程式。

那比「沒有背景掃描」更糟：它看起來還在保護什麼。

## 這推翻 ADR-0008，也修改 SPEC 第 6.6 節

ADR-0008 記的是「啟動時的背景掃描每天最多跑一次」，那支仍然是對的推論 ——
它的前提（畫面上有一個地方會顯示結果）現在不成立了。

SPEC 第 6.6 節寫的「也在 app 啟動時背景跑」不再成立。手動那一半完全不動：
`#/settings/health` 打開就是一次即時的全庫掃描，入口在設定頁上。

## Consequences

**對不起來的資料要等她自己去看才會發現。** 這被接受，理由跟 ADR-0008 的
Consequences 是同一條，而且更強：資料健檢抓的是慢性的不一致（計數欄位歪掉、
狀態沒結案），不是需要當下攔截的錯誤。真的不能錯的地方 —— 客戶詳情的次數、
壓表面板的剩餘次數 —— 一律現算，本來就不靠資料健檢把關。

真正改變的是**提醒的節奏**：以前是「app 會告訴你」，現在是「你想看的時候去看」。
那是她要的，而且她是唯一的使用者。
