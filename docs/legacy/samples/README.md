# 舊試算表樣本（去識別化）

`domain/legacyImport.js` 原本是照著 `../README.md` 的「舊表應該長這樣」寫出來的，
從來沒有看過真的檔案。這裡是**真的那 21 張工作表**去識別化之後的樣子，
用來驗收解析器 —— 改了解析器就重跑一次，看看 21 張各自讀出了什麼。

原檔（`.xlsx`）**不在 repo 裡，也不會進來**。SPEC 第 10 節：含真實客戶資料的
匯出檔進了 git 歷史就拿不掉。

## 去識別化做了什麼

轉檔的規則寫在 `scripts/legacy-xlsx-to-tsv.py`，判準是「留下結構、拿掉人」：

| | |
|---|---|
| 留下 | 療程名稱、應有／實際次數、日期表頭、勾選格、營養點滴品項明細、器材簡寫、TODO 區塊 |
| 換掉 | 客戶姓名 → `客戶A`…；病歷號 → `9001`…；同事與家屬姓名 → `治A` 或整段拿掉 |
| 抹掉 | 所有手寫註記 → `（手寫註記，已移除）`。健康狀況與生活細節都寫在那裡 |

日期表頭刻意保留成 `6月15日` 這種**沒有年份**的寫法，因為那就是從畫面複製出來的樣子 ——
匯入時要補哪一年是解析器要處理的事，樣本不該先幫它補好。

儲存格裡原本的換行寫成字面的 `\n`，這樣一列還是一列，但「A2 有兩行」這件事留得住。

## 怎麼重跑

```
node scripts/legacy-dry-run.mjs docs/legacy/samples 2026 > docs/legacy/samples/dry-run-report.txt
```

`dry-run-report.txt` 是上面那行的輸出，跟 app 裡「開始匯入」前看到的是同一份報告
（`.claude/skills/calendar-sheet-merge/scripts/merge.mjs` 的 `reportText()`），差別只在它連 Firestore 都沒有。
這份樣本產出時報告還在 `domain/legacyImport.js`，那一支隨著貼試算表那條路一起拿掉了（ADR-0047）。
主檔用 `domain/seed.js` 的種子資料，所以報告講的是「用種子主檔會怎樣」，
不是「在她自己的資料庫裡會怎樣」。

## 這批樣本測不到的一件事

去識別化把手寫註記與購買名稱裡的自由文字抹掉了，而**醫療禁忌的字眼就寫在那裡面**
（真的舊表上有一位的 B2 是 `0604 顧客會-手有金屬，只能INDIBA`）。所以拿這批樣本
跑 dry-run，`‼ 醫療禁忌` 那一段永遠不會亮。

守著那條路的是 `tests/legacy-import.test.js` 裡自己編的 fixture，不是這批樣本。
改到 `contraindicationHints()` 的時候不要拿樣本的輸出當通過標準。
