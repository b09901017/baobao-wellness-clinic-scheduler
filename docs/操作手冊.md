# 操作手冊

給沒看過這個系統的人。從頭走一遍：客戶進來 → 問時間 → 壓表 → 掛號 → 到院 →
健檢的後續 → 收工前檢查。

> **這份文件只講「按哪裡」。** 為什麼這樣設計在 `SPEC.md` 與 `docs/adr/`，
> 詞的定義在 `CONTEXT.md`。同一件事只寫在一個地方，這裡看到的連結都是指過去的。

## 零、先認得五個畫面

底部有五個分頁，每一個回答一個問題：

```
┌──────────────────────────────────────────────┐
│                                              │
│               （內容區）                      │
│                                              │
├────┬────┬────┬────┬────────────────────────┤
│待辦│客戶│壓表│日曆│設定                     │
└────┴────┴────┴────┴────────────────────────┘
```

| 分頁 | 你在這裡問的問題 |
|---|---|
| **待辦** | 現在有幾件事、哪一件最急 |
| **客戶** | 這個人還剩幾次、這個月哪天來 |
| **壓表** | 這個月還有誰沒排、先排誰 |
| **日曆** | 這一天塞不塞得下、那一筆要改 |
| **設定** | 主檔、資料健檢、備份、已刪除的東西 |

兩條要先記住的規矩：

1. **改一筆來訪只有日曆一個入口。** 待辦中心、客戶詳情、進度追蹤上點開的
   卡片都是**唯讀**的，沒有鉛筆。要改就回日曆找那一天。見
   [ADR-0056](./adr/0056-only-the-calendar-can-change-a-visit.md)。
2. **系統只記錄決定，不替你做決定。** 除了醫療禁忌，所有的檢查都是提醒 ——
   它會講出「這樣排會超過總次數」，但不會擋住你。見
   [ADR-0002](./adr/0002-app-records-decisions-it-does-not-make-them.md)。

## 一、核心作業路徑

### 步驟 1　新增客戶

**客戶 → 右下角的加號**

填名字（其餘都可以之後補）。同一張表單底下有一塊「她買了什麼」：

- 買**方案**（例：筋骨強身）→ 選方案 + 數量，底下的項目會自動展開成**額度**
- 買**單項** → 一項一項加

> **加購那張表全站只有一份**（`ui/components/buy.js`），三個入口
> （客戶詳情的「加購」、新增客戶的「加一項」、批次建立的「微調」）
> 長得一模一樣。

買**健檢**的時候多一格「金額等級」（0.75 萬、8 萬、12 萬…），
它只影響顯示名稱，不影響流程。

### 步驟 2　健檢一買，二返自動跟著出現

存檔之後回客戶詳情看那一排額度卡，你會看到**多了一張「二返（8 萬健檢）」**，
次數跟健檢一樣多。

那是自動的：買幾次健檢就有幾次二返
（[ADR-0022](./adr/0022-followup-entitlements-are-expanded-in-pairs.md)）。
**不要自己再加一筆** —— 加了會變成兩筆，而次數會對不起來。

舊客戶身上如果沒有配到，健檢那張卡底下會出現一句
「⚠ 這筆健檢還沒有對應的二返額度」加一顆「補一筆二返額度」，按它就好。

### 步驟 3　問這一輪的時間

**待辦 →「問這輪的時間」**

```
問這輪的時間
   ‹   9 月   ›            ← 上一月 / 下一月，往前往後都走得到
   25 位客戶

[ 還沒發連結 8 ]  [ 已經發出 5 ]

還沒發連結
  客戶A   從來沒問過・還剩 4 次        [ 產生 9 月的連結 ]
  客戶B   還沒問 9 月・上次 7/28 問的   [ 產生 9 月的連結 ]

已經發出
  客戶C   9/1 發出           ⏳ 等待回覆     [重發]
  客戶D   9/1 填好           ✍ 已填寫時段    [ 去收下 ]
  客戶E   9/1 收下           ✓ 已確認排定

▸ 9月已經問到了 3 位
```

三件事要知道：

- **月份切得動**，而且**產生的連結帶的就是你選的那個月**（按鈕上印著）。
- **「還剩幾次」不是門檻。** 身上 0 次的人照樣列得出來 ——
  你可能就是要先把時間問起來，再談加購。
- **已經發出那一格不會有人消失。** 客戶填完、你收下之後，那一列還在，
  只是徽章換成「已確認排定」。

兩條路可以問：

| 路 | 怎麼做 |
|---|---|
| **發連結** | 按「產生 X 月的連結」→ 底下出現一則可以直接貼到 LINE 的訊息 → 按「複製 LINE 訊息」 |
| **自己問** | 在 LINE 上問完，去那位客戶的詳情頁，「不能的時間」那一段按「記一次」 |

### 步驟 4　收下客戶填的

**待辦 →「客戶填好的時間」**

客戶填完**不會自動生效**。你看過、按「收下」，它才變成那位客戶的
**本輪可用性**（[ADR-0032](./adr/0032-what-the-customer-fills-in-waits-in-an-inbox.md)）。
收下之後系統會給你一則回覆客戶的訊息。

### 步驟 5　壓表

**先去 Abovee 把時段佔住，再回這個系統記。**
這個系統看不到同事在 Abovee 上壓了什麼，它不取代 Abovee。

**壓表 → 選月份 → 開始這一批**

```
9 月　已壓 5 / 23
┌─────────────────────────────────┐
│  客戶A                      ‹ › │   ← 左右滑換下一位
│  復能 剩 11 ・ 8萬健檢 剩 1      │
│  9月不能的時間  ［禮拜一］［9/17］│
│  可用 21 天                      │
│  ────────────────────────────── │
│  9 月小日曆（點一天）             │
│  做什麼  [復能 剩11] [＋ n返]    │
│  幾點開始 [09:00][09:30]…        │
│  器材    [INDIBA][超磁場][雷射]  │
│  治療師  [治療師甲][治療師乙]     │
│                                  │
│         [ 加這一筆 ]             │
└─────────────────────────────────┘
```

按下「加這一筆」會跳一個確認框，問「已經在 Abovee 壓好表了嗎？」
並且**把接下來會發生的事列出來**。那不是廢話 —— 那是你唯一一次
看得到「這一下會產生哪幾張待辦」的地方。

存進去的來訪狀態是**待確認**（琥珀色）。

### 步驟 6　跟客人確認時間

**待辦 →「跟客人確認時間」**

用 LINE 問完客人，回來按那一列的打勾 → 跳出確認畫面，把這個人所有的時段
攤開 → 三條路：

| 客人說 | 你按 |
|---|---|
| 都可以 | 確認 → 那幾筆變成**已確認**（靛藍），**掛號的待辦這時候才長出來** |
| 這兩天可以、那天不行 | 逐筆標「客人說不行」，其餘照樣成立 |
| 還沒回 | 在那一列寫一句（例：「禮拜一再問問」），那一列**留著**，只是看得出問過了 |

> **掛號的待辦要等客人說可以才長。** 壓完一晚上二十幾位就立刻多出幾十件待辦，
> 而其中一部分等客人說不行就會被收掉。見
> [ADR-0027](./adr/0027-registration-tasks-wait-for-the-customer.md)。

### 步驟 7　去掛號

**待辦 → Examine／耀聖**

- Examine：預約作業 → 查核 → 已報到
- 耀聖：右下角 → 未報到 → V

在系統這一側：勾起來 → 按「把勾起來的標成完成」→ 確認。
勾掉的**不會消失**，它移到「已完成」那一格，點回來就拿得回來。

也可以走**待辦 →「依客戶」**：點一位客戶，從底部滑出一張抽屜，
那個人身上的事全部在裡面，勾完往下甩掉就換下一位。

### 步驟 8　客人來了 → 簽療程單

**待辦 →「簽療程單」**

點那一筆 → 逐段勾「這一段做了」→ 送出。

**次數是這一刻才扣的。**（[SPEC 第 4.2 節](../SPEC.md)）
客人做了兩段、第三段就走了是會發生的，所以是逐段勾，不是整筆。

二返（與加約的三返、四返）**不用簽療程單** —— 那一次是回院聽報告，
沒有療程可以扣。但**那一筆照樣要在這裡結案**，卡片上會寫明。

## 二、健檢那一條鏈

這是整個系統唯一的**鏈式**待辦，也是最容易漏的一段。

```
健檢結案
   │
   ├─ 21 天後死線 ──▶ ① 追蹤健檢報告      「報告出來了沒」
   │                        │
   │                     勾掉它
   │                        ▼
   └─ 勾掉那天 +7 ──▶ ② 約二返            「回去跟客人約聽報告的時間」
                            │
                        去壓表（按那一列的「去壓表」，項目會先選好）
                            ▼
                      那一筆健檢從此不再出現在待辦上
```

兩個常見的誤會：

- **「約二返」勾得掉，但勾掉不等於真的約了。** 那一列右邊有一顆徽章寫著
  「已約 9/3 14:00」或「還沒約」。還沒約就勾掉的話，確認框會多問你一次。
- **報告那一張可以拿回來。** 在「已完成」那一格點一下就退回上一站，
  「約二返」會跟著收起來 —— 這是對的，不是壞掉。

### 加約三返、四返……

客人聽不懂、想再聽一遍時才會有。**不需要先加購**，只要他名下有一次
**已完成的健檢**就約得了，也**沒有次數上限**。

從**壓表**或**日曆**加：

```
做什麼  [復能 剩11] [8萬健檢 剩1] │加約│ [＋ n返 不扣次數]
                                            ↓ 點下去
第幾返   [三返][四返][五返]…              ← 預設是下一個沒用過的
這是哪一次健檢的　一定要選
         [7/13  二返]  [8/20  二返・三返]  ← 已經有幾返會標出來
```

三件要知道的事：

1. **它不扣任何次數。** 存檔前的確認框會講出這一句。客戶身上的數字一個都不會變。
2. **一定要選是哪一次健檢的。** 沒有它，試算表上那一場沒有位置可以印。
3. **掛號的待辦、要不要簽單、選不選醫師，全部跟二返一模一樣。**

> 一位**什麼次數都用完**的客戶不會出現在壓表的卡片牆上（那面牆答的是
> 「這個月還有誰要排」）。那種情況從**日曆**加：點那一天 →
> 抬頭的「＋」→ 新增來訪 → 選那個人。

試算表上會長這樣，接在那一次健檢的欄位底下：

```
                        │ 7/13 │ 8/20 │
8萬健檢       1  1  0  0 │  ✓  │      │
二返（8萬健檢）1  1  0  0 │      │  ✓  │
                        │8/8 二返(醫師甲) │
                        │9/20 三返(醫師乙)│
```

## 三、日曆上的七種顏色

日曆上會出現七種東西，**顏色已經用完了**，所以有兩種靠形狀分：

| 看到什麼 | 是什麼 |
|---|---|
| 琥珀色 | 來訪・**待確認**（壓好了，還沒問過客人） |
| 靛藍色 | 來訪・**已確認**（客人說可以了） |
| 墨綠色 | 來訪・**已完成**（來了、簽了單、次數扣掉了） |
| 硃紅色 | 來訪・**未到** |
| 淡紫色（可以自己挑顏色） | **行事備註**（你自己的事，例：公出、演講） |
| **斜線紋** | **休假**（那幾天整片排不進去） |
| **方框勾勾** | **待辦**（就是掛了日期的隨手記） |

灰掉又劃線的是**已取消**的來訪 —— 它畫在那裡是為了讓你看得出
「那個時段本來有人」。

顏色與符號只寫在一個地方（`domain/visits.js` 的 `STATUS_VIEW`），
所以日曆、客戶詳情、試算表三個地方永遠一樣。見
[ADR-0039](./adr/0039-six-things-on-the-calendar-need-six-colours.md)、
[ADR-0045](./adr/0045-the-calendar-has-four-kinds.md)。

## 四、待辦、任務、隨手記差在哪

三個詞很像，但它們是三種東西。分清楚才知道「這件事會不會有人提醒我」。

| | 誰產生的 | 有死線嗎 | 上日曆嗎 | 例子 |
|---|---|---|---|---|
| **任務** | 系統（來訪產生的） | **有**（來訪日的前一天） | **不** | 到 Examine 掛號 |
| **隨手記** | 你自己打的 | 沒有 | **掛了日期就會** | 下次記得帶健保卡 |
| **待辦** | —— | —— | —— | 是一個範圍更大的詞，見下 |

**「待辦」要看上下文，而且刻意保留兩個意思**（因為你本來就這樣講）：

- **待辦中心（首頁）上的一列** —— 那一頁列的不只任務：「問這輪的時間」
  「壓表登記」「跟客人確認時間」「簽療程單」都是**推導出來的**，
  它們沒有死線、也不存在資料庫裡。
- **日曆上的一類** —— 那一類**只有掛了日期的隨手記**。

要指某一種的時候講得具體一點：「任務」「日曆上的待辦」「待辦中心那一列」。
完整定義在 [CONTEXT.md](../CONTEXT.md)。

### 隨手記怎麼記

三秒內要記完，所以有三個入口：

- 首頁最底下那一塊（直接打一行字）
- **右下角那顆鉛筆泡泡**（點下去鍵盤自己上來，送出之後不關掉 ——
  你一次常常記三件事）
- 日曆上點一天 → 新增待辦

掛日期是**選填**的。掛了就出現在日曆的「待辦」那一類，勾掉了在日曆上畫成刪除線。
**那個日期不是死線**：過了只有字變色，不會變紅字、也不進「逾期」那顆數字。

## 五、刪掉的東西去哪裡了

**這個系統永不硬刪除。**（[SPEC 第 6.1 節](../SPEC.md)）

刪掉只是標記，**設定 → 已刪除項目**裡還原得回來。破壞性的操作一律走
二次確認，而且會把後果列出來（刪幾筆、會影響什麼）。

另外兩個工具在設定裡：

- **資料健檢** —— 把整個資料庫掃一次，把對不起來的列出來。
  它**只顯示不亂改**：正解不需要判斷的那幾項才有「修正」可以按。
  （注意：這裡的「資料健檢」跟課程的「健檢」完全無關，不可以簡稱。）
- **變更紀錄（稽核）** —— 每一次寫入的前後值，改不掉也刪不掉。
  出事的時候唯一能回溯的東西。

還有一個每天會用到的：**待辦中心最底下的「看今天做了什麼」**。
它是稽核紀錄的白話版，回答「有沒有漏掉登記」，往前最多翻七天。
