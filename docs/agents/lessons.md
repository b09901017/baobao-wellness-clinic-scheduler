## 一、同一件事有好幾個入口，只改到其中一個

這個 repo 最常見的 bug 形狀。同一個概念通常有三個入口（壓表、來訪編輯器、拍 Abovee），
或兩條路（試算表自動推送／手動貼上），或兩份實作（app 與 `.gs`、產檔與接收端）。

10/8 抓到的例子：
- 試算表手動貼上讀主檔帶 `includeDeleted`，自動推送沒帶 → 刪掉治療師後只有自動那份名字消失
- 給 `taskBlocks()` 的 master 少了 `ivProducts` → 試算表寫「營養點滴」、app 寫品項
- 日曆列表的撞期 `markClashes()` 自己寫一份，存檔前的 `conflictWarnings()` 走 `roomCapacityOf()` → 兩邊判斷不一樣
- 讀取卡片沒畫警示，壓表／編輯器／拍 Abovee 都有畫
- toast 讓位只寫了 `.drawer-backdrop`，壓表那一疊卡片（`[data-deck]`）沒算進去 → 「復原」蓋住「下一位」

> 我改的這個規則／畫法，還有哪幾個地方在講同一件事？（`grep` 函式名，也 `grep` 畫面上的字）

## 二、拿「部分資料」算次數

畫面為了快只讀一段期間（壓表讀 180 天、試算表往後讀 400 天），
接著有人拿這一份去算「還剩幾次」或做驗證 —— 早於那段期間的使用就看不到了。
例：拍 Abovee 確認層用壓表那一頁讀的 180 天來訪 → 預選一筆其實用完的額度、不提醒超用、扣錯筆。
壓表自己存檔前會重讀全部，確認層沒有。

> 這一段算次數／驗證用的來訪是全部嗎？是誰讀的、讀了多少天？

## 三、會建很多筆的按鈕，按兩次、重試一次

`withSaveState(key)` 擋得住大部分連按，但**一次寫很多筆、跑很久**的那種要另外想：
- 匯入頁 `run()` 沒有「正在匯」的記號，跑到一半再按一次 → 全部客戶多一份，而且來訪刪不掉
- 一位失敗後重按，前一次已經寫進去的雜事（行事備註、待辦）不檢查就再寫一次
- `tests/save-guards.test.js` 只掃 `withSaveState()` 的呼叫，沒走它的那一頁**根本不在它的視野裡**

> 這個動作按兩次、或失敗後重按，結果會一樣嗎？（只能做一次的，例如切換那天的匯入，要特別怕）

## 四、比對與去重：用原字、只測一次

拍照、合併檔、療程單都在做「這一筆跟那一筆是不是同一件事」。三種一再出錯的情況：
- **拿原字當鑰匙**：名字被 AI 抄錯一個字就配不上；同一張照片裡本來就不同的兩列（同人同時兩門課）被當成重複。有病歷號、id 就用它們
- **再做一次**：已經記過的再拍一次。合併扣課在 app 上是一段、照片上是兩列；合併檔匯進來的舊段沒有開始時間 —— 「app 上已經有了」的判斷要認得這些**不同形狀**
- **一列錯、整串錯**：療程單年份從上一列往下推，一列讀錯後面全部跨年。每一列各自對錨點（表頭、拍照那天）推

> 這個比對拿什麼當鑰匙？同一份資料送兩次會怎樣？另一個來源存的形狀跟這裡一樣嗎？

## 七、時間：UTC 切字、匯入當天、過夜

- `new Date().toISOString().slice(0, 10)` 是 **UTC 的日期**，台灣 00:00–08:00 會早一天。日期一律走 `dates.js` 的 `todayISO()`／`dayOf()`；腳本也一樣（`merge.mjs` 沒給 `--today` 時踩過）
- 「今天以前＝已完成」在匯入當天不成立：當天還沒來的客人會被直接記成已完成、收不回來
- app 開著過夜，畫面上的「今天」不會自己換

> 這個日期是誰的時區？跨午夜、跨月、跨年、匯入當天各會怎樣？

## 八、公開 repo：app 自己產生的檔案也算

- 設定頁匯出的 `排課系統備份-日期.json`（全部客戶＋健康資訊＋密鑰）放在 repo 根目錄**不會被 `.gitignore` 擋**，而文件的範例正好放根目錄

## 九、部署：看起來成功不等於成功

- Firebase Hosting 預設 `Cache-Control: max-age=3600`（`/js/**`、`/css/**`、連 `/`）。service worker 是網路優先，但它抓檔也經過瀏覽器快取 → **「明明改好了卻沒變」可能是這個**，不一定是 `sw.js` 版號
- firebase-tools 只在互動模式補 Storage 跨服務 Rules 要的 IAM 角色；CI 與 agent 的 shell 都是非互動，**一聲不響地跳過** → 療程單照片 403
- deploy job 三個步驟要全綠；Hosting 綠、Storage 紅看起來像部署好了（9/17）
- 拍照的 Function 不歸 CI 部署；`.firebaserc` 預設是正式站，本機部署漏打 `--project` 就上正式（10/8 預設改成 staging；要上正式的指令自己帶 `--project prod`）
- 本機模擬器**在 Windows 上不回 `firebase.json` 的 `headers`**（`glob-slasher` 把規則的 `/` 換成 `\`，一條都對不上）—— 她的機器上 `curl -sI 127.0.0.1:5000/…` 看不到 Cache-Control 不代表規則寫錯；CI（Linux）與真的 Hosting 才看得到

> 這一步在非互動模式下會不會被跳過？部署完我是怎麼確認新版真的在跑的？

## 查的方法（給之後做健檢或驗證的 session）

- **測試全綠不代表沒事**：掃原始碼的測試只看得到它認得的寫法（save-guards 只掃 `withSaveState`；E2E U8 量按鈕外框，量不到被 `overflow` 裁掉的感應範圍 —— 要用 `elementFromPoint` 量）
- **零成本的真資料語料**：`.local/references/abovee-m5-m10/擷取/abovee-m5-m10.json`（Abovee 353 列，逐像素驗證過）、`.local/references/ai-exam/result-*.json`（模型真的吐出來的抄字）。拿來餵翻譯層，不用再叫模型。腳本只印數字
- **正式站的主檔是舊一代的種子**：要測「上線那天」就用 `git show <舊 commit>:public/js/domain/seed.js` 造主檔，不要拿現在的種子
- **每一條都重現一次再寫**：腳本放 `.local/`、從 repo 根目錄跑、印出實際輸出；畫面的用本機模擬器＋單一個無頭 Chromium 截圖（見 `CLAUDE.md` 的測試那一節）。「設計如此」先翻 ADR
- **自己寫的隨機情境，先量亂數的週期**：`seed = (seed * 1103515245 + 12345) & 0x7fffffff` 在 JS 裡超過 2^53 會掉精度，**一萬多個數就繞回同一圈** ——
  ADR-0139 的「20,000 組」實際上只有幾百組不同的情境在重複（10/9 發現：換了種子，答案一模一樣）。用 `Math.imul(seed, 1103515245) + 12345 >>> 0`（週期 2^32）。
  換種子結果完全不變，就是這個症狀
- **平行的 subagent**：這個環境的 subagent 寫不了 `.md` 報告檔（主控代存）；撞到用量上限會中斷，用 SendMessage 接回去；同時只准一組模擬器＋一個瀏覽器（她的筆電會過熱）
