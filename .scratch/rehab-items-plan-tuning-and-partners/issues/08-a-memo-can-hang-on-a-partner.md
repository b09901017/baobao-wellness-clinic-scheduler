# 備忘錄也可以掛合作機構

Status: 已完成
Blocked by: 07

## 她說的

> 備忘錄那邊希望也有自然美的標籤(他不是課程，但是如果這個客戶有標記是自然美，
> 那他也可以出現在和現在備忘錄sop會出現的地方一樣出現備忘錄)

2026-09-06 確認浮出來的位置：**日曆點開那一筆來訪**、**待辦的「跟客人確認時間」**
—— 就是掛課程的備忘錄現在浮的那兩個地方，一個都不多。

## 這件事碰到 ADR-0067

ADR-0067 的標題就是「備忘錄綁課程不綁人」，理由是「綁客戶的東西已經有三種了，
第四種只會讓她每次都要想一下該記在哪裡」。

這一輪不推翻它，是**把邊界講清楚**：備忘錄仍然不綁**某一位客戶**，
它綁的是一家**合作機構**（跟課程一樣是一份主檔上的東西）。
差別只有一個：它是**透過客戶**浮出來的，而課程是透過那一段時段浮出來的。

那個差別要寫進 ADR（`12`），因為看到程式碼的人會問「為什麼這一支要收 customer」。

## 要做什麼

### 一、`playbooks` 加一個欄位

```js
{
  title,
  courseIds,      // ['course-iv-drip']，存 id（不變）
  partnerNames,   // ['自然美']，**存字串**
  body,
}
```

**一個存 id 一個存字串，是刻意的**，要寫在欄位旁邊：

- 課程是排班的骨架，時段上就存著 `courseId`，比對的兩邊都是 id。
- 合作機構貼在客戶身上而且**存的是字串**（`07`，同永久限制的慣例）。
  這裡存 id 的話每次都要多一跳去主檔翻名字，而主檔改名之後兩邊還是會對不上
  —— 一致地承擔同一個代價，比兩種作法各壞一半好。

`firestore.rules` 的 `validPlaybook()` 補
`(!('partnerNames' in d) || d.partnerNames is list)`，跟 `courseIds` 同一個深度。

### 二、`domain/playbook.js`

```js
/**
 * 這一筆來訪、這一位客戶，掛得到哪幾份備忘錄。
 * 課程配 + 合作機構配，同一份只回一次，順序照 playbooks 進來的順序。
 */
export function playbooksFor({ playbooks, visit, customer }) { … }
```

**`playbooksForVisit()` 留著**，改成 `playbooksFor()` 的一個薄殼
（`customer: null`）—— 它有測試，也還有呼叫端。

### 三、`ui/components/playbookHint.js`

`hintHtml()` 與 `hintForVisits()` 各多收一個 `customer`。
**兩個入口共用一支**這件事不變 —— 那正是這一支存在的理由（它的檔頭寫著
「第三個入口以後接上去只要一行」）。

呼叫端：

| 入口 | 檔案 | 客戶從哪來 |
|---|---|---|
| 日曆點開那一筆來訪 | `ui/views/calendar.js` | `visit.customerId` → 那一頁已經有的客戶清單 |
| 待辦的「跟客人確認時間」 | `ui/views/home.js` | 那一列本來就是一位客戶一組 |

拿不到客戶時**只掛課程的那幾份**，不要整塊不畫 —— 少一份提醒比整塊消失好。

### 四、備忘錄編輯那一頁

`ui/views/playbook.js`：「掛哪些課程」那一排丸子底下多一排「掛哪些合作機構」。

**版面要小心**：`.pbcard--edit > *` 除了內文那一格每一項都要 `flex: none`
（CLAUDE.md）。多一排就是多一個 `> *`，漏了那一條它會被壓成 2px ——
而症狀是「東西在那裡但看不到也捲不到」。

## 不做的

- **不讓備忘錄綁某一位客戶。** ADR-0067 的主體成立。
- **不做「時機」「分類」。** ADR-0069 把那些拿掉了，這一輪不加回來。
- **不改 `PREVIEW_LINES`。** 洗版由行數擋，多一份來源不改這條規則。

## 測試

- `tests/playbook.test.js`：`playbooksFor()` 課程配、機構配、兩邊都配到只回一次、
  客戶是 null 時只回課程配到的。
- `tests-e2e/specs/15-playbook.spec.js` 延伸：一份掛自然美的備忘錄，
  在一位帶自然美標記的客戶的來訪卡片上浮得出來；沒有標記的客戶不浮。
