# 輸入框底下一排點得到的 emoji

Status: done
來源：她的第二項 c（`../spec.md`）
動工前先讀：issue 03（共用 `insertAtCursor()`）、ADR-0038（不重畫整頁）

## 她要的

> 我會有可愛的小表情貼以及標記 1 2 3 4 的表情貼，不知道能不能寫備忘錄的時候
> 也可以有？
>
> 在備忘錄編輯框下方或工具列提供一排常用／可愛的 Emoji 快捷鍵，點擊即可在
> 游標處插入。

**只裝在備忘錄的大輸入框**（她 2026-09-04 選的）。隨手記、來訪的「記的話」、
客戶備註都不裝 —— 那三個是單行、短、而且不是她會排版的地方。

## 有哪幾顆

從她自己那份筆記反推的，不是憑感覺挑的：

| 這一組 | 顆數 | 從她哪一句來的 |
|---|---|---|
| 數字 `1️⃣2️⃣3️⃣4️⃣5️⃣` | 5 | 「標記 1 2 3 4 的表情貼」 |
| 段落 `🐻🔸▪️` | 3 | 每一段抬頭那顆熊；另外兩顆是不想用熊的時候 |
| 提醒 `⏰⚠️📌✅` | 4 | 她信裡點名的「提醒 ⏰、注意事項 ⚠️」 |
| 這一行的事 `💊💉🩺📋🏥` | 5 | 她的內容本身：打針、療程單、房間、檢查 |

**十七顆，不給第十八顆，也不做搜尋。** 一排 emoji 一旦做成「全部的 emoji」
就變成一個選擇器，而她要的是「一點就有」。

清單寫成 `domain/lineText.js` 的 `const EMOJI_ROW`（跟 `EMOJI_PLACEHOLDER`
放一起，因為 `(emoji)` 換成的那一顆就在這一排裡 —— 兩份清單遲早會分岔）。

## 長什麼樣

```
┌─────────────────────────────┐
│ 一行一件事就好              │
│                             │   ← .pbedit__body
│                             │
└─────────────────────────────┘
 1️⃣ 2️⃣ 3️⃣ 4️⃣ 5️⃣ 🐻 🔸 ▪️ ⏰ ⚠️ …   ← .emojirow（橫著捲）
 [存起來] [取消]         [🗑 刪掉]
```

- 一排橫著捲（`.chiprow` + `noscroll-bar` 已經有這個手法，備忘錄的丸子清單
  就是），**不折行** —— 折成兩行會把存檔鈕再推下去一次，那正是 issue 02 在修的事
- 每一顆是 `<button type="button" data-emoji="⏰">`，最小 44×44 的觸控面積
  （這一頁其他按鈕都是這個尺寸）
- 一直看得到，**不做展開／收起**。她信裡寫「Emoji 快捷列展開」的動畫，但一顆
  「打開 emoji」的按鈕等於每次都要多點一下，而這一排只有 17 顆、佔一行
- 點下去：`insertAtCursor(body, emoji)` → `grow()` → **焦點留在 textarea**，
  游標在插入的字後面。焦點跑掉的話她點完一顆就得再點一次輸入框
- 過場：`:active` 縮到 0.9（`--motion-fast`），跟 `.pbcard__edit` 同一組。
  沒有出現／消失的動畫，因為它不出現也不消失

## CSS

`.emojirow` 新增在 `app.css` 的備忘錄那一區。顏色全部用現成的 token
（`--surface`、`--border-soft`、`--text`），**不加新的 token** ——
`tokens.css` 要動就是淺色深色兩份都要動（ADR-0055），而這一排沒有一個顏色是
新的。

## 這一排會不會弄壞別的地方

不會，但要親手確認三處（issue 09 有測試）：

- **`.pbcard--edit` 的高度**：多一行 44px，所以 issue 02 的 `46dvh` 是**含這一排**
  算出來的，兩支要一起看
- **`tests-e2e/specs/15-playbook.spec.js` 的 P6**「這一頁上一個勾選框都沒有」：
  emoji 是 `<button>` 不是 `<input type=checkbox>`，照樣綠
- **搜尋**：`matches()` 比的是標題與內文的原字串，emoji 是普通字元，不用改

## 驗收

- E2E：點 `1️⃣` → 內文出現它 → 存起來 → 重新整理後還在
- E2E：游標放在第一行中間 → 點一顆 → 它插在**游標那裡**，不是接在最後
- E2E：點完之後焦點還在 textarea 上
