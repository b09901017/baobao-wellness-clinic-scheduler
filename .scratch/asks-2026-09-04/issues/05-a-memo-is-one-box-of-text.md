# 備忘錄砍成三個欄位：標題、掛哪些課程、一大塊字

Status: proposed
來源：她實測回報第三項，2026-09-04（`../spec.md`）
動工前先讀：ADR-0067（備忘錄是拿來讀的，不是拿來勾的）、`domain/playbook.js`

## 她要的

> 我覺得不用特地幫我分什麼事前事後，那些全部都給我一個大框框，像是一般的
> 備忘錄 app 一樣，只要有標題、掛那個課程，以及很大的輸入框就好。
> 不需要章節，不需要分類，也不需要多餘的說明，就是簡潔直觀就好。

## 現在有什麼、要拿掉什麼

```js
{
  title,        // 留
  tag,          // ✂ 拿掉
  courseIds,    // 留
  sections: [{ heading, when, body }],  // ✂ 變成一個 body
  pinned,       // ✂ 拿掉
}
```

改成：

```js
{
  title,      // 必填，≤ 40
  courseIds,  // 選填
  body,       // 必填，≤ 5000。**一大塊字，換行她自己打**
  }
```

## 這樣做會失去什麼，以及為什麼可以

ADR-0067 為「時機」寫了一整段理由，它現在被推翻了一半，要誠實記下來：

| 拿掉的 | 它本來在做什麼 | 沒有它之後 |
|---|---|---|
| `sections[].when` | 標了時機的那一節會在日曆點開來訪時**自己浮出來** | 浮出來的變成**整份的前幾行 + 「看全部」**，見下面 |
| `sections[].heading` | 分段的小標 | 她自己在內文裡打一行就是了 |
| `tag` | 依科別分組 | 卡牌只有幾張，丸子清單就是導覽（issue 06） |
| `pinned` | 常看的排最前面 | 順序＝她寫下來的順序，永遠不會自己動 |

**「自己浮出來」那件事沒有被砍掉**，她那句話還在（「點開該筆預約或日曆卡片
時，自動浮現的操作小撇步」）。改的只是浮什麼：以前浮「對得上時機的那一節」，
現在浮「整份的前幾行」。她擔心的洗版由**行數上限**擋，不由時機擋 ——
而行數上限比時機好懂：她看得到自己寫的第幾行會出現在卡片上。

`MAX_BODY` 從 2000 拉到 5000：以前一份可以有 20 節 × 2000 字，
現在只有一格，上限跟著放大才不會變成另一種「存不下去」（issue 02 的同一句話）。

## 舊資料

`playbooks` 這個集合是 PR #52 帶進來的，而 **#52 還沒有合併進 `develop`**，
所以正式與 staging 上一筆都沒有。理論上不需要搬家。

但她自己在本機點過（那是她發現這些問題的方式），而 #52 有可能先被合併。
所以讀的那一側留一道**四行的退路**：`body` 是空的而 `sections` 有東西時，
把每一節接起來當成 `body`（節標題自成一行）。**只在讀的時候做，不自動改寫
資料** —— 她一存檔就自然變成新的形狀。

## 為什麼不留一個「進階：分節」

因為那會讓兩種形狀同時存在，而**每一個讀的地方都要處理兩種**。她要的是
「像一般的備忘錄 app」，而一般的備忘錄 app 沒有進階模式。
