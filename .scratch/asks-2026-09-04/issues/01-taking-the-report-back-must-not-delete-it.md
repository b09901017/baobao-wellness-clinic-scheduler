# 把「追蹤健檢報告」拿回來，那一張自己會被靜默刪掉

Status: proposed
來源：她實測回報第一項，2026-09-04（`../spec.md`）
動工前先讀：ADR-0042（報告先於二返）、ADR-0065（第二站是兩張）、
`domain/followups.js` 的 `syncFollowupTasks()`、`data/tasks.js` 的 `setDone()`

## 她看到的

> 我把追蹤健檢報告勾掉，已經生出寄報告以及約二返，然後我再回去把追蹤健檢報告
> 勾回去，雖然那兩張都會收起來，但是健檢報告好像沒有放回未完成，
> 幫我檢查看看對不對，有可能是我測試錯了？

**她沒有測試錯。** 那一張不是「沒有放回未完成」，是**被軟刪除了** ——
它不在未完成、不在已完成，只在「設定 → 已刪除項目」裡。

## 重現

跑 `syncFollowupTasks()`，輸入是「報告剛剛被拿回來（`done: false`）、
約二返與寄報告都還在」的那一刻：

| 情境 | 結果 |
|---|---|
| A 二返還沒壓表 | ✅ 報告留著，另外兩張收掉 |
| B 二返已經壓好（待確認／已確認／已完成） | ❌ **三張全部軟刪除** |
| C 「約二返」那一張已經勾掉了 | ❌ **報告與寄報告被軟刪除** |

她會走到 B 或 C，是因為完整的動線就是「勾掉報告 → 去壓二返 → 發現按錯了 →
回來把報告拿回來」。A 那一條（勾完立刻反悔、中間什麼都沒做）才是少見的。

## 為什麼

`syncFollowupTasks()` 的收尾只有一句話：

```js
for (const t of openTasks) {
  const keep = t.kind === SEND_REPORT_TASK_KIND
    ? wantedSend.has(t.visitId)
    : wanted.get(t.visitId)?.kind === t.kind;
  if (keep) continue;
  remove.push({ id: t.id, reason: ... });
}
```

而 `wanted` 是**第一圈**算出來的，第一圈的第一道閘門是：

```js
const want = owed(pair, visits);
if (!want) continue;
```

`owed()` 數的是**還欠幾次二返**。二返一旦壓好（`booked`）或勾掉（`settled`），
`owed` 就掉到 0，那一次健檢整個退出候選 —— 於是掛在它身上的**每一張**
未完成待辦都不在 `wanted` 裡，包含她剛剛才拿回來的那一張報告。

ADR-0065 已經替「寄報告」走過同一段推論了（那一張被擠進第一圈的話，
她一約好二返就會被靜默收掉）。**同一個閘門對「追蹤健檢報告」也是錯的，
只是上一輪沒有一起看。**

## 決定：長出來與收掉不是同一條規則

「這一次健檢還欠不欠二返」決定的是**要不要長一張新的**，
不是**已經在那裡的那一張還算不算數**。

```
追蹤健檢報告
  長出來   還在第一圈裡（要 owed > 0）—— 沒買二返額度就不該長這一張
  收掉     只有一個理由：那一筆健檢不再是已完成的

約二返
  兩件都照舊，它本來就是 owed 在數的東西

寄報告給醫師
  照舊（ADR-0065 已經處理過）
```

三種待辦三條規則，寫進 `syncFollowupTasks()` 的 `keep` 那一段。

### 為什麼不是「拿回來的時候讓它復活就好」

因為那要在 `data/tasks.js` 判斷「她剛剛是不是在做取消勾選」，而那一層不該
知道鏈條的規則。規則只有一份，在 `domain/followups.js`（`CLAUDE.md` 的連動表）。

### 為什麼不改成「一律不刪，只留著」

那會讓健檢被取消時，掛在上面的待辦全部留在清單上叫她去追一場不存在的健檢。
`reasonFor()` 的第一句 `if (!stillDone) return '那一筆健檢不是已完成了'`
是對的，要留著。

### 收掉的理由要跟著改

`reasonFor(REPORT_TASK_KIND, ...)` 現在會印「報告拿到了」。改完之後，
一張**未完成**的報告不可能因為「報告拿到了」被收掉（拿到了 = 它是已完成的，
而已完成的根本不在 `openTasks` 裡）。所以那一行是一句**從來沒有成立過的話**，
拿掉。

## 連動

| 會動到 | 為什麼 |
|---|---|
| `domain/followups.js` | 規則本身。只改 `keep` 與 `reasonFor()` 兩處 |
| `tests/followups.test.js` | 現有的「報告那一張被拿回來」三支要留著，補 B 與 C |
| `tests-e2e/specs/02-examine-chain.spec.js` | 補一支走完整動線的（見 issue 08） |
| ADR | 補一支：**收掉的規則跟長出來的規則不是同一條**。它是 ADR-0065 的延伸，也是 ADR-0066 那張表的第三個例子 |

`data/visits.js` 的 `followupOpsAfterTaskChange()` **一個字都不用改** ——
它已經正確地把「寫進去之後的世界」餵給 domain 了，錯的一直是 domain 那一層。

## 驗收

- 單元：B 與 C 兩個情境，`remove` 裡不可以有那張報告的 id
- 單元：健檢被改成已取消時，那張報告**還是要**被收掉，理由是「那一筆健檢不是已完成了」
- E2E：勾掉 → 兩張長出來 → 壓一場二返 → 把報告勾回來 → 報告回到未完成清單上，
  另外兩張不見了
