# 六種東西要分辨，其中兩種是同一個顏色

Status: done
來源：使用者，2026-08-23（spec.md 的 b 與 d 的前半）

## 原話

> 「顏色多一點 鮮豔一點」
> 「個人行程以及休假的顏色不要和來訪的〔待確認／已確認／已完成／未到〕衝突，
> 要很明顯的區別」

## 這不只是感覺的問題，是真的撞在一起

`public/css/tokens.css`：

```css
--slate: #5b7a8c;              /* 註解寫著：個人行程裡的休假那一類 */
--visit-confirmed: var(--slate);   /* 已確認 */
```

`public/css/app.css`：

```css
.kind-leave     { --kind-fg: var(--slate); }   /* 休假 */
.status-confirmed { --kind-fg: var(--visit-confirmed); }  /* 已確認 */
```

**「休假」與「已確認的來訪」是同一個 `#5b7a8c`，一個像素都不差。**
月檢視上一條霧藍的色條，可能是「這天客人確認要來」，也可能是
「這天我不在」—— 兩件事的意思完全相反，而畫面上長得一模一樣。

同一組還有第二次撞：`--visit-done: var(--accent)`，而 `.kind-visit` 也是 `--accent`。
這一次撞得比較沒事（`.kind-visit` 只用在篩選丸上，而那顆已經改成中性色了），
但它說明了同一件事：**這一組顏色是靠別名疊出來的，沒有人數過總共要幾種。**

數一次：待確認、已確認、已完成、未到、個人行程、休假 —— **六種**，
現在只有五個顏色，而且其中兩個一樣。

## 為什麼會這樣

`tokens.css` 上那段註解說得很誠實：

> 刻意做成別名指到既有的語意色 —— 深色模式那邊已經幫它們換過一輪，
> 這裡再抄一份就會有一份忘了改。

當時的判斷是對的：狀態色少的時候，借用語意色（逾期紅、今明黃）省掉一份維護。
代價是**狀態色不能有自己的想法** —— 它只能長成某個既有語意色的樣子，
而既有語意色一共就那幾個。六種東西要分辨的時候，這個省法就付不起了。

## 要做什麼

### 1. 六種各給一個自己的顏色

`public/css/tokens.css`。淺色與深色都要寫，不再用別名。

| | 淺色字 | 淺色底 | 深色字 | 深色底 |
|---|---|---|---|---|
| 待確認（琥珀） | `#995400` | `#fbeacd` | `#e8a94a` | `#3a2c14` |
| 已確認（靛藍） | `#1c5fa8` | `#dde9f8` | `#7fb3e8` | `#16283a` |
| 已完成（墨綠） | `#17714b` | `#d5efe2` | `#6fc79a` | `#123024` |
| 未到（硃紅） | `#c0271a` | `#fbdedb` | `#f08a7c` | `#3a1e1a` |
| 個人行程（紫） | `#6b3fa0` | `#eae0f8` | `#b899ec` | `#251c3a` |
| 休假（灰青） | `#4f6b7d` | `#e4ebf0` | `#9db4c4` | `#1e2a33` |

字對底的對比度全部 ≥ 4.5（深色 ≥ 6）。色條上的字是 11px 的中文，
所以這個門檻不是形式 —— 算過再改，不要憑眼睛挑。

已取消維持灰（`--text-mute`），而且日曆本來就不畫取消的時段。

### 2. 休假不靠顏色，靠紋路

上面那張表把休假放在灰青，是**刻意不給它一個鮮豔的色相**：

- 色相輪上塞六個彼此分得開的顏色，最後兩個一定會擠在一起。
- 而且休假講的不是「這裡有一件事」，是「這幾天我不在」——
  它跟其他五種本來就不是同一類東西。

所以休假的色條再加一層**斜線紋**（`repeating-linear-gradient`），
一眼就看得出「這一段是被劃掉的，不是一筆行程」。這比第六個色相有用得多，
而且在色弱的情況下照樣成立。

### 3. 為什麼做不到「只有日曆這一頁」

她要的是「只有日曆這一頁」變鮮豔。**四個來訪狀態色做不到。**

`CLAUDE.md` 的連動表：

> 來訪狀態的顏色、標籤或符號｜只改 `domain/visits.js` 的 `STATUS_VIEW`，
> 日曆、客戶詳情、試算表全部讀它。顏色在 `app.css` 的 `.status-*`

理由（README 與 SPEC 第 8.5 節都寫過）是「同一位客戶在兩個畫面顯示成不同顏色，
她不會知道哪個算數」。所以四個狀態色一動，客戶詳情的日期卡、進度追蹤那一頁、
壓表卡片上的徽章會一起變。

**這是對的。** 一個代表「未到」的顏色本來就該在每一頁都長一樣。
而且不會跟著變的東西比會變的多：米白的頁底、墨綠的主要按鈕、
茶色的次要強調、備註的六色小丸全部不動 —— 「全站換色系」沒有發生。

動工前**先補一支 ADR**，把「狀態色從別名改成自己的一組」與
「這一組是全站共用的，不可能只鮮豔一頁」寫下來。
不要改掉 `tokens.css` 上那段解釋別名的註解，改寫它 ——
它記的是一個當時正確的判斷，要記的是它為什麼失效了。
