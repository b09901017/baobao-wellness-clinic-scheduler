## 一、🔴 上線或匯入之前

### 1.1 匯入會長出 18 張逾期的「寫紀錄」，確認框講反了

**看到什麼**

拿 `import-2026-09-16.json` 模擬匯入：`countNewTasks()` 回 18。確認框那一句會印

> 還沒發生的那幾筆會產生 18 筆登記待辦；已經發生的一筆都不會長

實際上那 18 張**全部是「寫紀錄」、全部掛在已經發生的來訪上**（二返、營養師諮詢這種
勾了「做完要寫紀錄」的課程），死線是來訪那一天 —— 六月到九月，匯進去的那一刻就全部逾期。
還沒發生的 22 筆來訪一張登記待辦都不會長（它們都是不用另外掛號的課程）。

**為什麼**

- `data/legacyImport.js:97-99` 對每一筆來訪跑 `syncTasksForVisit(visit, [])`
- `domain/taskRules.js:370`：`if (t.kind === RECORD_TASK_KIND || acceptsNewTasks(visit.status))` ——
  紀錄那一族**刻意不走** `acceptsNewTasks()`（ADR-0066），而匯入的過去來訪是 `done`，
  `recordTasksForVisit()` 的閘門（`acceptsRecordTasks('done')`）是開的
- SPEC 第 6.10 節與 `data/legacyImport.js` 的檔頭都寫著「已經發生的那些一筆都不長」。
  那一條是 ADR-0066（2026-09-04 加「寫紀錄」）**之前**寫的，匯入這條路沒有跟上
- 畫面上那兩句（`ui/views/mergeImport.js:491-500`、`:513-514`、`:535-539`）假設「會長的一定是還沒發生的登記」，
  於是把數字套進一句錯的話 —— ADR-0070「一句警告只能講真的會發生的事」
- 測試沒抓到：`tests/merge-import.test.js:440-441` 那筆「過去的來訪」用的課程沒有 `needsRecord`

**影響**

待辦中心頂端的「逾期」一匯完就是 18（加上她之前本來就有的），而那 18 件在耀聖上早就寫過了。
如果她先按了資料健檢「課程的做完要不要寫紀錄」那一列（復健科醫師門診補上勾），數字會更大。

1. 拿 `.local/references/staging-假資料-v3.json`，在 `entitlements` 加一筆、在 9/2 那一筆來訪的 `slots` 加一段（全部是假的）：

   ```json
     "courseName": "營養師諮詢", "optionEquipmentNames": [], "productName": null,
     "purchasedAt": "2026-09-01", "sourcePlanName": null, "sourcePlanSets": null, "sourcePlanQty": null, "purchaseKey": "extras" }
   ```
   ```json
   { "entitlementKey": "nc", "courseName": "營養師諮詢", "startsAt": "15:30", "endsAt": "15:50",
     "roomName": null, "therapistName": null, "equipmentName": null, "ivProductName": null,
   ```

2. 設定 → 舊資料匯入 → 貼上 → 看那張卡最底下那一句，再按「開始匯入」看確認框倒數第二行

### 1.2 日曆「新增來訪」併進同一天既有那一筆時，日期欄還在

**看到什麼**

日曆 → 點某一天 → ＋ → 新增來訪 → 選一位**那一天已經有一段還沒結案**的客戶。
編輯器照 ADR-0083 接著編輯那一筆、只畫新的那一段 —— 但**最上面的「來訪日期」照樣畫出來**。
改成別天再存，**那一天原本那幾段（可能已經跟客人談定了）會一起搬到新的日期**，
而存檔前那道 Abovee 確認只列新的那一段，所以她看不出來。

**為什麼**

- `ui/views/visitEditor.js:152`：`isNew: !existing` —— 併進來的那一筆不是從 `visitId` 進來的，所以算「新」
- `:313`：`wholeVisit || isNew` 就畫日期欄
- `:888`：`readDraft()` 把表單的日期寫回**整筆**
- `:1014`：確認框只列 `storedSlotCount` 之後的段

ADR-0085 寫「只改一段時日期不給改」、ADR-0089 寫「改整天的日期一條路都沒有」。
這一條路是兩者都沒想到的那一種：她按的是「新增」。

**影響**：Abovee 上那幾格沒動、app 裡搬走了，任務的死線跟著移。安靜的錯。

**你可以怎麼點（staging）**：日曆 → 點一位客戶已經有一段「待確認」的那一天 → ＋ → 新增來訪 → 選他 →
最上面「來訪日期」改成隔天 → 新的一段填好 → 記錄這次來訪 → 回日曆看原本那一天，那一段不見了、跑到隔天。

#### 1.2b（🟠）同一條路的另一個方向：改日期會長出「同一天第二筆」

反過來：從一個他**沒排**的日子新增，把日期改到他**已經有一段**的那一天。併不併是 `boot()`
開表單那一刻決定的（`:137`），改日期只重讀了撞期用的 `sameDayVisits`（`:376-383`），
沒有重問 `sameDayState()` —— 於是同一位客戶同一天兩筆，ADR-0083 破功。

資料健檢的「同一天有兩筆來訪」會列出來，但那一列的說明寫著「**這是舊資料**」（`domain/health.js:66`），而它是新的。

## 二、🟠 上線後很快會碰到

### 2.1 壓表「這個月壓好的」與資料健檢「去看看」都通到整天的編輯器

**看到什麼**

- 壓表 → 開一位 → 底下「這個月壓好的」每一列是 `<a href="#/visits/:id">`（`ui/views/schedule.js:1018-1025`）
- 設定 → 資料健檢 → 每一列的「去看看」（`ui/views/health.js:152`），來訪相關的那幾種全部指 `#/visits/:id`
  （`domain/health.js:400、439、495、509、524、606、625、778`）

那條路由是 `visitEditor.renderEdit()`（`ui/views.js:81-84`）：**整天全部的段、日期欄、每一段的 ×**。
`.scratch/slot-first-and-fewer-words/spec.md:87` 與 CLAUDE.md 那張表寫著「`renderEdit()` 那條網址留著，
**沒有任何畫面上的連結**，不算一條路」—— 實際上有兩個入口，其中一個在她最常用的那一頁。

**三個後果**

1. 改得到整天的日期（同 §1.2 的效果）、改得到她沒點的那幾段 —— ADR-0056／0085／0089 那一串決定在這裡都不成立
2. 那張編輯器存完或按「取消」都是 `go('/customers/:id')`（`visitEditor.js:247-250`、`:356-358`）——
   **她從壓表點進去看一眼、按取消，就被帶離壓表**，卡片組那一層沒了
3. 資料健檢「狀態異常：日期已過但還是已確認，該標已完成或未到了」→ 去看看 → 那一頁**做不到那件事**
   （整天的狀態卡 2026-09-12 拿掉了）。那一列真正的出口是待辦中心的「簽療程單」

**你可以怎麼點**：壓表 → 開一位有壓過的客戶 → 「這個月壓好的」點任一列 → 看到「來訪日期」與那一天每一段 → 按「取消」→ 落在客戶詳情。

### 2.2 清掉已完成的待辦之後，同一筆來訪再存一次，那幾張會重新長出來

**看到什麼**（拿 `syncTasksForVisit()` 跑過）

| 情境 | 清掉之前再存一次 | 清掉之後再存一次 |
|---|---|---|
| 只取消一段 → 「取消 Abovee」勾掉 → 清掉 → 那一天去簽療程單結案 | 不長 | **又一張「取消 Abovee」，死線已經過了** |
| A 類已確認 → Examine、耀聖勾掉 → 清掉 → 在日曆改那一段的時間 | 不長 | **Examine、耀聖又各一張** |

**為什麼**

- 「清掉這 N 筆」與已完成那一列的垃圾桶都是軟刪除（`ui/views/home.js:2323`、`:2340-2368`）
- `data/tasks.js:45-47` 的 `listByVisit()` 走 `repo.list()`，一律濾掉 `deletedAt`
- 所以 `syncTasksForVisit()` 看到的「這筆來訪現有的任務」裡沒有那幾張：
  掛號那一族走 `:306-311` 的比對 → 以為從來沒有 → 已確認就長；
  取消那一族走 `cancelTasksFor()` 的 `covered`（`:438-472`）→ 那一段沒被蓋到 → 長新的一張
- 清掉的畫面上寫著「做過的事本身沒有被改掉 —— 清掉的只是這一列」，而那句話在這裡不成立

**影響**：假的待辦會叫她**再去 Examine 掛一次號**，或回 Abovee 放掉一個可能已經被別人排進去的時段。

**你可以怎麼點（staging）**：日曆 → 一位同一天有兩段的客戶 → 長按其中一段 → 取消這一段 →
待辦中心「改時間／取消」勾掉那一張 → 已完成 → 清掉這 1 筆 → 回日曆長按另一段 → 改這一段 → 改個時間存 →
待辦中心又出現一張「取消 Abovee」。

**方向**：比對「現有任務」時把軟刪除的也算進去；或「清掉」只清掉那一筆來訪已經結案的。這一條要她選。

## 四、❓ 跟她的真實資料對照出來，要她決定

### 4.1 EECP 到底壓 30 分還是 60 分

- 主檔：EECP `durationMin: 30`（`domain/seed.js:243`）
- **她的 9 月壓表白紙**：EECP 三次都是一小時（15:30–16:30、14:00–15:00、15:15–16:15）
- import 裡 20 段 EECP 全部是 30 分 —— 那不是行事曆上的時間，是 skill 拿**主檔的時長**補的結束時間（`merge.mjs:1045-1046`）
  （行事曆在這一題不能當證據：TimeTree 匯出的 467 筆裡 437 筆是一小時，看起來是它的預設值，EECP 那 25 筆也全是一小時）

主檔如果少了一半：月曆畫短、治5／治8 的撞期判斷少算一半、匯入的結束時間也跟著錯。

### 4.2 營養點滴壓幾分鐘

- 主檔 60 分
- **她自己的 SOP**（`備忘錄_SOP們.txt`）：「壓時間：一般針劑 120 分、護心抗老 180 分」，「第一針比較久，後續可能 60 分就能打完」
- 行事曆上有 8 筆是兩小時，**8 筆全部寫著點滴室**（其餘幾乎都是預設的一小時）—— 那是她特地拉長的

時長是跟著**品項**與**第幾針**變的，app 目前只有課程一個數字。另外同一份 SOP 的「護心抗老 TG>266 不能打」
是**品項層級**的禁忌，app 的提醒只掛在器材上。要不要做、做到哪一層，是她的判斷。

### 4.3 點滴8 其實是兩床嗎
