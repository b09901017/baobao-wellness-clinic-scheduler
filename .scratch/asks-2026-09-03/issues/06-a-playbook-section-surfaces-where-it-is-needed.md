# 備忘錄要在她正在做那件事的時候自己出現

Status: done
Blocked by: 04
來源：她的三件事，2026-09-03（`../spec.md`）
動工前先讀：ADR-0020（日曆上的任何操作都不換頁）、ADR-0018（同一筆來訪在四個地方
長得一樣）、ADR-0056（只有日曆改得了一筆來訪）、ADR-0028（提醒不是佇列）

## 她要的

> 我也希望能夠在點開該筆預約或日曆卡片時，自動浮現的操作小撇步，或是我記的 memo。
> 像是？當日曆上顯示「點滴」預約時，卡片詳情提供「檢視 SOP」快捷按鈕，點擊直接
> 展開對應備忘錄章節之類的。
>
> 然後像是點滴的「飯後打針」該何時提醒？怎麼提醒你也可以幫我設計，通常客人預約
> 前一天或當天早上會發確認訊息，但好像也不用特別獨立開一個「提醒吃飯」的任務，
> 避免洗版。

**她選的是「不開任務」。** 所以這一支就是「飯後打針」那個問題的完整答案：
它是點滴那份備忘錄 `before` 那一節的第一行，而那一節會在**她正在發確認訊息的
那一刻**出現在畫面上。

## 挑哪一節：`whenForVisit()`，只有一份

`domain/playbook.js` 的 `whenForVisit(visit, today)`（issue 04）：

| 那一筆來訪 | 浮出哪一節 |
|---|---|
| 日期在今天之後 | `before`（事前） |
| 日期就是今天 | `onday`（當天）—— **不管狀態還是不是待確認**，人已經要來了 |
| 日期過了，或已完成／未到 | `after`（結束後） |

判斷寫在 domain 而不是各自的畫面裡：兩個入口問的是同一句話，
而同一筆來訪在兩個畫面浮出不同的一節，她不會知道哪個算數
（同 ADR-0028、ADR-0043 的理由）。

## 共用一支 `ui/components/playbookHint.js`

兩個入口共用，第三個入口以後接上去只要一行。**不共用的代價已經在這個專案付過
兩次**（`buy.js` 的「其他…」漏了兩次、`note.js` 的 `.notemeta` 兩邊裸放）。

```
┌────────────────────────────────────────┐
│ 營養點滴 · 事前                      ⌄ │   ← 整列可點，收合／展開
│   · 飯後打針（通知客人）                │
│   · 預約系統註記（第一針或血管難打）      │
│   看整份備忘錄 ›                          │
└────────────────────────────────────────┘
```

- **預設展開。** 她要的是「自動浮現」，收起來等於還是要點一下。
- 一筆來訪掛到兩份備忘錄時（一天兩個時段、兩個課程）就畫兩塊，各自一個抬頭。
- 那一節是空的、或那幾個課程沒有掛備忘錄 → **整塊不畫**，不留一個空殼。
- 「看整份備忘錄 ›」連到 `#/playbook/:id`。**這是這一塊唯一會換頁的動作**，
  而且它換到的是「讀那份備忘錄的地方」。
- 行的畫法走 `linesOf()`（issue 04），跟閱讀頁同一支 ——
  兩份寫法遲早有一份會把空行畫成一個空的項目符號。

## 入口一：日曆上點那一筆來訪

`views/calendar.js` 的 `openDetail()`，接在 `visitReadHtml(visit, data)` 後面：

```js
body: visitReadHtml(visit, data) + playbookHint({ visit, playbooks: data.playbooks, today }),
```

**不改 `visitReadHtml()` 本身。** 那一支是四個畫面共用的（ADR-0018、0056），
把備忘錄塞進去等於客戶詳情、待辦中心、進度追蹤三頁也要有備忘錄名單，
而那三頁問的問題（他還剩幾次、今天要掛哪幾個、這個月做了多少）都不是
「這一場我該怎麼做」。

`load()` 多讀一份 `playbooksData.list()`，併進現有的 `Promise.all` ——
`data/playbooks.js` 有行程內快取（issue 04），所以實際上一個 session 只打一次。

**讀失敗不擋日曆。** 備忘錄讀不到就是那一塊不畫，跟待辦中心那兩列「讀不到就當它
不存在」同一個判斷 —— 它是提醒，不是這一頁的主體。

## 入口二：跟客人確認時間（`#/todo/confirm`）

這是「飯後打針」真正該出現的地方：**她按下那一列的時候，正在打那則訊息。**

那一頁是一位客戶一組（`byCustomer(visitsToConfirm(...))`），所以備忘錄那一塊掛在
每一組底下，**固定取 `before` 那一節**（不走 `whenForVisit()`）——
這一頁的定義就是「還沒發生、要去問本人」，那一節永遠是事前。

一位客戶好幾天的來訪：把那幾筆的課程併起來去對備忘錄，**同一份只畫一次**。

## 刻意不接的三個地方

| 哪裡 | 為什麼不接 |
|---|---|
| 來訪編輯器 | 她在那裡是在**改資料**，不是在執行流程。那一頁已經有額度丸子、器材、治療師、醫師、診間五排東西，再多一塊字會讓真正要填的東西更難找 |
| 客戶詳情 | 那一頁問的是「他還剩幾次、這個月哪天來」（ADR-0056 的那張表）。備忘錄綁課程不綁人，掛在那裡是掛錯地方 |
| 壓表的記錄面板 | 壓表那一刻要看到的是**這位客人的**臨床提醒（issue 01 已經接上了），不是這個課程的流程 |

三個都留著一條路：`#/playbook` 一直都在待辦頁的右上角。
**備忘錄是隨時查得到的東西，自動浮出來是加分不是唯一的路** ——
同 ADR-0060 對長按的判準（手勢是捷徑，不是唯一的路）。
