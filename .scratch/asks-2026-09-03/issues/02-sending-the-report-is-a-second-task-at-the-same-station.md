# 拿到健檢報告之後，除了約二返還要寄給醫師 —— 而現在沒有人記得這件事

Status: done
來源：她的三件事，2026-09-03（`../spec.md`）
動工前先讀：ADR-0022（二返額度成對展開）、ADR-0042（報告在二返前面，唯一的鏈式待辦）、
ADR-0043（待辦中心照流程分段）、ADR-0027（任務等客人確認才長）、
`CONTEXT.md` 的「二返」「n返」「醫師」

## 她要的

> 二返，目前只有事前去壓兩個系統，事後簽療程單，其實還需要有事前要把報告寄給
> 醫生（也就是當我拿到健檢報告的時候），除了要約二返，還要寄健檢報告給醫生
> （這是之前沒有加到的）。

她自己的筆記寫得更清楚：

```
二返
  前  (1) 寄報告給醫生
      (2) 三系統
  後  曜聖寫二返紀錄        ← 這一件在 issue 03
```

**「(1)」是她自己標的順序** —— 寄報告排在三系統前面。

## 名字用「醫師」不是「醫生」

`CONTEXT.md` 的詞條是 **醫師**，`_Avoid_` 明列「醫生」。所以任務種類是
**`寄報告給醫師`**，不是她口語裡的那個詞。她的原話照抄進 issue 可以，
進到畫面上的字要用詞彙表的詞（`docs/agents/domain.md`）。

## 它掛在鏈條的哪裡

ADR-0042 的那條鏈現在是一條線：

```
健檢結案 ──▶ 追蹤健檢報告 ──勾掉──▶ 約二返 ──約好了──▶ 這一次健檢從此不再出現
             死線 健檢日+21          死線 勾掉那天+7
```

「寄報告給醫師」的觸發條件跟「約二返」**一模一樣**（報告到手的那一刻），
所以它不是第三站，是**第二站的第二張**：

```
健檢結案 ──▶ 追蹤健檢報告 ──勾掉──┬─▶ 寄報告給醫師   死線 勾掉那天+7
                                  └─▶ 約二返         死線 勾掉那天+7
```

死線兩張一樣，共用既有的 `followupDueDays`（預設 7）。**不開第三個設定值**：
它們是同一個動作的兩半，給兩個可調的天數只會讓她某天發現兩張的紅字時間不一樣
而想不起來為什麼。

## 最危險的一段：`owed()` 那道閘門會把它默默收掉

`syncFollowupTasks()` 現在的形狀是：

```js
const want = owed(pair, visits);
if (!want) continue;                       // ← 這裡
...
for (const visit of ordered.slice(0, want)) wanted.set(visit.id, stationFor(...));
...
for (const t of openTasks) {
  if (wanted.get(t.visitId)?.kind === t.kind) continue;
  remove.push({ id: t.id, reason: ... });  // ← 沒有在 wanted 裡的一律收掉
}
```

`owed()` 算的是「**做完的健檢**比**約掉的二返**多幾次」。她一去把二返約好，
那一場二返就變成 `booked`，`owed` 掉到 0，`continue` 一跑 —— 那一次健檢
整個退出候選名單，於是**還沒寄出去的報告那一張會被 `remove` 掃掉，而畫面上
什麼都不會說**。

這正是 ADR-0042 那句「替她刪待辦比留著更糟」講的同一件事，只是換了一個入口。

### 做法：寄報告那一張走在 `owed` 閘門外面

`syncFollowupTasks()` 拆成兩圈，順序不能換：

```
第一圈（現有的，一個字都不動）
  照 owed 決定哪幾次健檢該有「追蹤健檢報告 / 約二返」

第二圈（新的）
  凡是「追蹤健檢報告已經勾掉」的那幾次健檢，就該有一張「寄報告給醫師」，
  而且它不受 owed 管 —— 報告寄出去了沒，跟二返約了沒是兩件事。
```

第二圈的收掉條件只有三個，全部要能講出人話的理由：

| 收掉 | 理由字串 |
|---|---|
| 那一筆健檢不再是已完成的來訪 | `那一筆健檢不是已完成了` |
| 「追蹤健檢報告」被拿回來了（取消勾選） | `報告那一張被拿回來了` |
| 這一張自己被勾掉了 | 不收 —— 已完成的任務一律不刪（SPEC 第 6.1 節） |

第三條是既有的規矩，寫在這裡是因為 `openTasks` 那一圈只掃未完成的，
新的第二圈也要照做。

## 舊資料不補產生

ADR-0042 已經處理過同一種情況：上線那一刻 Firestore 裡就有一批
「有未完成的約二返、但從來沒有過追蹤報告」的健檢（`stationFor()` 的第 2 條路）。
那一批**不補「寄報告給醫師」**。

理由跟那一支一樣，但方向相反：ADR-0042 是「不要刪掉她真的還沒做的事」，
這裡是「不要無中生有一批她其實早就做完的事」。報告如果已經走到「在約二返」
那一站，她多半早就寄出去了 —— 補一批紅字出來，她第一件事是把它們全部勾掉，
而那讓稽核紀錄多了一批假的「做完了」。

**判斷用 `hasReport`**（`stationFor()` 已經在算了：勾掉的與還沒勾的都算），
不要另外寫一次。

## 待辦中心的分段

`domain/todoFlow.js` 的 `FLOW` 是一個**有序陣列**，段裡的順序就是她做事的順序
（ADR-0043）。所以：

```js
[REPORT_TASK_KIND,    'after'],   // 追蹤健檢報告
[SEND_REPORT_KIND,    'after'],   // 寄報告給醫師   ← 新的，插在中間
[FOLLOWUP_TASK_KIND,  'after'],   // 約二返
```

**插在中間，不是接在最後** —— 她自己標的順序是「(1) 寄報告 (2) 三系統」，
而約二返比三系統更前面。照死線排會讓兩張並列（死線一樣），所以順序只能由這一份決定。

## 要改的地方

| 檔案 | 改什麼 |
|---|---|
| `domain/followups.js` | 多一個 `SEND_REPORT_TASK_KIND = '寄報告給醫師'`；`syncFollowupTasks()` 多第二圈；**`stationFor()` 不動**（它回答的仍然是「第一圈那條線走到哪一站」） |
| `domain/taskRules.js` | `CHAIN_KINDS` 加一個 —— 少加的話，健檢那一筆一存檔 `syncTasksForVisit()` 就會因為「來訪裡沒有需要這個任務的課程」而把它刪掉（那一行的註解已經寫著為什麼要擋） |
| `domain/todoFlow.js` | `FLOW` 插一列 |
| `data/visits.js` | `followupOpsAfterTaskChange()` 的 `chainKinds` 加一個 —— 勾掉「追蹤健檢報告」的那一下要在**同一個 commit** 裡把兩張都長出來（`data/tasks.js` 的 `setDone()` 檔頭寫著為什麼） |
| `ui/views/home.js` | 待辦列的說明字。`KIND_NOTES` 加一句：「報告拿到了，寄一份給看報告的那位醫師」 |

## 測試

`tests/followups.test.js` 至少要有這四支：

1. 勾掉追蹤報告 → 同時長出「約二返」與「寄報告給醫師」，兩張死線相同
2. **約二返勾掉了、寄報告還沒 → 寄報告那一張還在**（就是上面那個 `owed` 陷阱）
3. 追蹤報告被拿回來 → 寄報告那一張被收掉，理由是「報告那一張被拿回來了」
4. 舊資料（有未完成的約二返、從來沒有過追蹤報告）→ **不補產生**寄報告

第 2 支是這一整支 issue 的重點，寫測試的時候先寫它。
