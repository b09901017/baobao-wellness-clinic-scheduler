# 候選清單照「來源」分，不照時間分；`ambiguous` 沒有任何地方看得到

Status: 待動工
回報者：使用者，2026-08-21
動工前先讀：`ui/views/mergeImport.js` 的 `candidateCards()`、
`domain/mergeImport.js` 的 `validateFile()` 與 `eventDocs()`

## 症狀

她的原話：

> 日曆那邊，匯入的時候希望能區分兩個區塊，一個是以前一個是未來，讓我可以自己勾選要不要匯入
> （目前有勾選匯入，但是我要一個一個看日期，希望直接分成兩個區塊，一樣勾選）

## 為什麼

`candidateCards()` 現在的三張卡是照**這筆資料哪裡來的**分的：

| 卡片 | 來源 | 她那份檔案裡有幾筆 |
|---|---|---|
| 行事曆上有，試算表沒勾 | `missingFromSheet` | 27 |
| 未來的預約 | `futureVisits` | **1** |
| 對不到客戶的行事曆事件 | `eventCandidates` | **198** |

問題有三個：

1. **198 筆混在一起，過去和未來交錯排列。** 她要一筆一筆看日期才知道哪些還沒發生。
2. **「未來的預約」那張卡名字騙人。** 它只有 1 筆，但真正在未來的來訪有 11 筆 ——
   另外 10 筆藏在 `customers[].visits` 裡（見 `issues/03`）。
   一張叫「未來的預約」的卡只列出十一分之一，比沒有這張卡還糟。
3. **`customers[].visits` 那 67 筆根本沒有勾選介面**，是直接寫進去的。
   她說「一樣勾選」，指的很可能包含這一塊。

## 另一件沒人看得到的事

合併檔裡有 `ambiguous` —— 同一筆行事曆事件配得上兩位客戶，skill 不敢猜，
所以列出來讓她判斷。她那份裡有 1 筆（6/30 的靜脈，兩位客戶都可能）。

**`ambiguous` 在整個 `public/js/` 底下出現 0 次。** `validateFile()` 不看它，
`candidateCards()` 不列它，摘要卡不數它。skill 那側花力氣不猜，
結果 app 這側連提都沒提 —— 那一筆來訪就這樣消失了，兩邊都沒有錯，但東西不見了。

## 想要的樣子

### 候選清單改成先分時間，再分來源

```
▸ 還沒發生的（N 筆）           ← 預設全部勾起來
    來訪（會建成「已確認」，會長出登記待辦）
    個人行程
▸ 已經發生的（N 筆）           ← 預設一筆都不勾
    行事曆上有、試算表沒勾的來訪
    個人行程
```

兩個區塊各自一顆「全選 / 全不選」。

### 預設值要反過來（2026-08-21 使用者拍板）

**未來的預設勾起來、已經發生的預設不勾。** 她 2026-08-21 直接確認了這一條。

現在是「三份清單一律 `include: false`，她說要自己一筆一筆決定」。
那條規則對**過去**的資料是對的（補歷史要謹慎）。

但她 2026-08-21 說的是：

> 未來的就算不是客人相關也都要匯入，因為是現在紀錄的

**未來的東西預設勾起來。** 那些是她現在正在管理的事，不是考古。
她還是可以取消勾選，只是不用勾 198 次。

### `ambiguous` 要有地方看

不做成可勾選的（勾了也不知道要算給誰）。做成一張**唯讀的提醒卡**：
「有 N 筆行事曆事件對得上兩位以上的客戶，沒有匯入。匯完到日曆上自己補。」
列出日期、原文、可能是哪幾位。

`validateFile()` 也該把它算進 warnings，理由和現在那條
「有 N 筆候選的客戶名字不在這份檔案裡」一樣。

## 不要順手做的事

- **不要把「未來 / 過去」的界線寫進檔案。** 理由見 `issues/03` ——
  界線在匯入的那一刻。UI 這一層用 `todayISO()` 分組就好。
- **不要因為 `ambiguous` 沒地方放就讓 skill 自己挑一個。**
  不猜是對的，缺的是轉述。
