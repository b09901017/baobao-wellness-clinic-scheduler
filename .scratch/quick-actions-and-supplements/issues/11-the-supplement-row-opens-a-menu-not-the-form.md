# 客戶詳情點營養品直接落進「調整」表單

Status: todo
來源：使用者，2026-09-01（需求 6.4）
Blocked by: 05, 08, 10
動工前先讀：`public/js/ui/views/customerDetail.js` 的 `productsBlock()`、
`issues/05`、`public/js/domain/products.js`、ADR-0020、0057、0059

## 原話

> 目前在客戶詳情點擊營養品會直接進入「修改」。請改成點擊或長按後彈出選單，
> 提供三個選項：「約時間」、「已經給了」、「編輯」等等。
>
> *約時間*：選擇日期後，產生對應的日曆 Todo 提醒。
> *已經給了*：選擇日期（預設今天）後，將營養品標註為已完成，同步勾掉關聯的 Todo，
> 並有 Toast 提醒。

## 為什麼現在是錯的

`productsBlock()` 那一列是 `data-ent`，跟額度卡上那顆「調整」共用同一個處理器 ——
點下去直接 `paintEntitlement()`，也就是一張表單。

ADR-0020 對日曆定的規矩是「先給看的，不先給改的」，而這一列比日曆那一筆更該守：
她點營養品那一列，十次有九次要問的是**「這一包給了沒、什麼時候給」**，
不是「改幾個月」。直接落進表單等於每次都冒著改到東西的風險。

## 決定：點一下開快捷選單

跟 issue 05 的長按共用同一支 `openActions()`，但**這一列是「點一下」就開** ——
它不是一份清單裡的一列（那種要保留「點＝看」），它是一個入口。
長按也開同一張（兩種手勢同一個結果，不會有人按錯）。

```
┌──────────────────────────────┐
│  營養品 5,050（夜態美＋速體淨） │
│  2 個月・還沒給                │
├──────────────────────────────┤
│  📅  約時間　　9/3 有預約       │  ← 有提醒且有日期時寫「改時間　現在 9/3」
│  ✓   已經給了                  │
│  ✎   編輯這一包                │
├──────────────────────────────┤
│         先不要，回去           │
└──────────────────────────────┘
```

規則寫成純函式（畫面不判斷）：

```js
/**
 * 長按／點一列營養品，快捷選單上有哪幾顆，各自要講什麼。
 *
 * 「約時間」那一顆的字要跟著提醒現在的狀態走：沒有提醒是「約時間」，
 * 有提醒沒日期是「約時間」，有日期是「改時間」加上現在是哪一天 ——
 * 她按下去之前要知道自己在改什麼還是在建什麼。
 *
 * @param {object} entitlement
 * @param {object|null} note 那一包配的提醒（`note.entitlementId === e.id`）
 */
export function productActions(entitlement, note)
```

## 三顆各自做什麼

### 約時間 / 改時間

1. 開系統原生的 `<input type="date">`（`note.field()` 的「挑日期」同一招：
   `showPicker()` 要在點擊的手勢堆疊裡才叫得動）。
   **預設值**是 `nextDeliveryDate(ctx.visits, todayISO())`，找不到就空白
   （不要退回今天，`nextDeliveryDate()` 的檔頭寫了為什麼）。
2. 已經有提醒 → `notesData.update(note.id, { date })`
   還沒有提醒 → `notesData.create(deliveryNoteFor({ entitlement, customer, date }))`
3. Toast：「9/3 提醒你給客戶A」。

**日曆的那一件是自己長出來的**，不用寫任何同步：日曆的「待辦」那一類
**就是有日期的隨手記本人**（ADR-0044、0045）。這是這一件唯一要記住的事。

### 已經給了

1. 一張小面板挑日期，**預設今天**（她的原話）。
2. 那一天的交付要記哪幾款：**預設全部還沒給的**，跟 `askDelivery()` 同一個判斷
   （十次有九次是整包給完）。**直接借 `askDelivery()`** —— 不要在這裡再寫一張
   逐項面板，`components/note.js` 的檔頭寫過四個入口共用一份的理由，
   這是第五個。
3. 寫入走 `notesData.recordDelivery(note, entitlement, { at, productIds })` ——
   **額度的 `deliveries[]` 與提醒的勾選寫在同一個 commit 裡**（ADR-0059）。
4. Toast：全給完是「都給了，記起來了」，只給一部分是「記起來了」——
   跟 `prepareToggle()` 回的 `success` 同一句話。

**沒有提醒那一筆的時候**（她從來沒約過時間就直接給了）：
`recordDelivery()` 要的第一個參數是那筆提醒。這一件要處理這個情況 ——
最小的作法是讓 `recordDelivery()` 收 `note` 為 `null`，那時只寫額度那一半：

```js
/**
 * @param {object|null} note 那一筆提醒。**沒有也可以** —— 她可能從來沒約過
 *   時間就直接給了。那時只寫額度那一半（交付紀錄是要進試算表的那一份，
 *   提醒只是提醒，ADR-0059）。
 */
export async function recordDelivery(note, entitlement, delivery)
```

`repo.commit()` 的陣列少一筆，其餘一個字都不改。

### 編輯這一包

走既有的 `paintEntitlement(ctx, record)` —— 一模一樣，只是多一步。

## 順帶：那一列要多講一句

`productsBlock()` 現在印的是 `deliveryState()` 那一句（還沒給／給了 N/M／都給了）。
再補一句**提醒的狀態**，因為那正是「約時間」那一顆要回答的問題：

| 情況 | 那一列右邊寫什麼 |
|---|---|
| 提醒有日期 | `9/3 給` |
| 提醒沒有日期 | `還沒排哪天給` |
| 沒有提醒、也還沒給完 | `還沒排哪天給` |
| 都給了 | 不寫（`deliveryState()` 那一句已經講完了） |

所以 `paint()` 要多讀一份：這位客戶的隨手記。**客戶詳情已經在讀了**
（隨手記那一段），把它傳進 `productsBlock(bought, notes)` 就好，不多一次 IO。

## 連動

- `SPEC.md` 第 8.5 節「營養品」那一段要補這三顆與那一句。
- ADR-0059 的 Consequences 補一句：交付有兩個入口（勾掉提醒、客戶詳情的
  「已經給了」），**而且它們走同一支 `recordDelivery()`**。
- `data/notes.js` 的 `recordDelivery()` 簽名放寬（`note` 可以是 `null`）。
- 客戶詳情的營養品那一列**不再是 `data-ent`** —— 額度卡上那顆「調整」還是。

## 不做

- 不在快捷選單裡改「幾個月」或「哪幾款」。那是編輯那一張表的事。
- 不做「取消交付」。記錯了走編輯（`deliveries[]` 在那裡看得到）。
  ——（如果她之後要，那是另一支 issue：交付紀錄是要進試算表的，
  刪一筆要留稽核。）
