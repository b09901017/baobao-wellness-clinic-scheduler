# 資料健檢新增的七列沒有一支 E2E

Status: 不做（2026-09-10，她說不需要）
來源：2026-09-10 的覆蓋率盤點（見 `spec.md`）
動工前先讀：`public/js/domain/health.js` 的 `CHECKS`、`tests-e2e/specs/03-health-and-counts.spec.js`

## 症狀

PR #71 / #76 / #80 一共替資料健檢加了七列，**每一列都有單元測試、一列都沒有
E2E**：

| 列 | 單元測試 |
|---|---|
| 器材沒有指到課程 | `health.test.js:1259` |
| 課程的名字跟建議的不一樣 | `:1352` |
| 器材的名字跟建議的不一樣 | `:1064` |
| 課程的指派跟建議的不一樣 | `:992` |
| 診間清單跟建議的不一樣 | `:1121` |
| 來訪上還記著床位 | `:1184` |
| 課程的「做完要不要寫紀錄」跟建議的不一樣 | `:1317` |

而這七列**正是她被交代要先按的那幾顆修正鈕**（手動清單第 0 組）——
PR #76 查出來「選 ILIB 沒變成選診間」「有課程叫靜脈」兩件事的根因是資料不是
程式，`loadSeed()` 只建不覆蓋，所以這幾顆是唯一的補救路徑。

「按下去真的改對了」在瀏覽器層只有計數那一列（`03` 的 H2）驗證過。

## 為什麼值得單獨決定

補齊要 seed 七種「還停在舊種子那一代」的主檔、按七次修、再讀七次回來 ——
`03-health-and-counts` 現在是 8 支 / 約 1.5 分鐘，這會讓它變兩倍。
而全量現在 18.5 分鐘（`.scratch/e2e-speed/issues/06`）。

所以先決定：**七列一支一支寫，還是寫一支「七列一起修、一次讀回來」的？**
後者快很多，但一列壞掉時錯誤訊息指不出是哪一列。

## 建議

寫成一支參數化的 `test.describe.for(...)`：seed 一份「七種都停在舊種子」的
主檔，逐列進健檢頁按修、讀回來比對。共用同一份 seed 與同一次 `signIn()`，
每一列自己是一個 test，所以壞掉時指得出來。

## Comments

2026-09-10：**她說不需要，這一支關掉。**

不是因為它不重要，是因為代價與風險不成比例：那七列**單元測試每一列都有**
（`health.test.js` 各一個 describe），而它們是「認得出還停在舊種子那一代的」
純比對，沒有跨模組的接線 —— 也就是 issue 01 那種「掃描綠、行為錯」的形狀
在這裡長不出來。補 E2E 會讓 `03-health-and-counts` 變兩倍，而全量現在 18.5 分鐘。

**要重開的訊號**：哪一列的「一鍵修」開始動到不只主檔那一格（例如順手改
既有來訪、或連著重推狀態）。那時候接線就出現了，掃描與單元都擋不住。
