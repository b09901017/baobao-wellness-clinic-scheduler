# 客戶詳情：七段裡有四段不對

Status: todo
來源：使用者，2026-08-24
動工前先讀：`SPEC.md` 第 8.5 節、`docs/adr/0018`、`0019`、`0025`、`0035`、`0036`

這一頁的骨架不動：**順序照她問問題的順序排，不是一疊白卡**（ADR-0018）。
名字 → 備註 → 這個月 → 不能的時間 → 額度 → 來訪紀錄 → 隨手記 → 任務，
這個順序她沒有意見。有意見的是其中四段各自長什麼樣，加上一個匯入留下來的錯字。

## 她說的六件事（原話）

| # | 原話重點 | issue |
|---|---|---|
| a | 「備註幾乎都會寫一個姓名欄的編號：…其實那個是病歷號…我希望之後匯入，不要寫『姓名欄的編號：』而是寫『病歷號』」 | `01` |
| b | 「這個月的呈現方式，目前是用卡牌，我希望改用清單，就像客戶那頁『看這個月的進度』那邊呈現的一樣…而且他說這個月，為什麼會有下個月的預約資訊跑進來？我希望這邊呈現可以切換不同月份」 | `02` |
| c | 「不能的時間，我希望呈現方式可以像是壓表客戶牆那邊呈現的一樣，並且一樣可以〔看得出〕甚麼時候問的」 | `03` |
| d | 「我點選不能的時間的記一次，我希望呈現的介面是一個日曆，而不是選單…就和我給客戶填的不方便的時間的那個表單一樣簡單明瞭就好，一樣可以有備註啦」 | `04` |
| e | 「額度…我希望這邊的呈現方式，可以一樣是像現在這樣的卡牌，但是我希望是可以左右滑的，就如同現在的『這個月』的那欄呈現的一樣」 | `05` |
| f | 「來訪紀錄，我希望可以收合，我需要看的時候才展開…並且不需要『紀錄一次來訪』這個按鈕，所有來訪都不應該從這裡加入（目前啦，之後不一定）」 | `06` |

## 確認過的事（2026-08-24）

- **`b`：只看選中的那個月**，不要再混「今天之後的全部」進來。
- **`d`：日曆為主，原文欄留著但只是純備註** —— 系統不再去解析它。

## 一個好玩的對稱

`b` 說「卡牌改清單」，`e` 說「清單改卡牌，而且要左右滑」—— 看起來矛盾，其實不是：

- **這個月**回答的是「他哪幾天要來、每一段做什麼、到哪一步了」。那是**一份有
  順序的紀錄**，一列一段掃得完，橫著捲會讓她看不出「這個月總共幾次」。
- **額度**回答的是「復能還剩幾次」。那是**一堆彼此獨立的數字**，她一次只看一個，
  而直著疊十二種課程會佔掉半頁。

判斷的依據是「這一段回答的問題是一個列表還是一組獨立的數字」，不是「卡牌好看
還是清單好看」。這件事要寫進 ADR，不然下一輪又會被翻過來。

## 不在這一輪範圍內

- 段落的順序、`LINE 訊息／變更紀錄／停用刪除`三個小標籤（ADR-0018）。
- 額度本身的加購與調整表單 —— 那在 `.scratch/form-legibility/issues/02`。
- 客戶總覽（`#/customers`）那一頁。
