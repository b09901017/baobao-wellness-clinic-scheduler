# 「不能的時間」要長成壓表卡片牆上的樣子

Status: done
來源：使用者，2026-08-24（spec.md 的 c）
動工前先讀：`docs/adr/0035`、`0036`、`SPEC.md` 第 4.3、8.5 節

## 原話

> 「不能的時間，我希望呈現方式可以像是壓表客戶牆那邊呈現的一樣，
> 並且一樣可以〔看得出〕甚麼時候問的」

## 兩邊現在長什麼樣

**壓表那一邊**（`ui/views/schedule.js` 的 `banBlock()`，`.ban` 那組 CSS）：

```
不能的時間                          2026-08-22 收集
⟨每週二⟩ ⟨每週三上午⟩ ⟨09/10–09/11⟩ ⟨09/24–09/26⟩ ⟨09/07⟩
⟨可用 19 天⟩
他原本是怎麼說的  ›
```

一排丸子，收集日期在右上角，原文收在一摺裡。ADR-0035 講的就是這件事：
**牆上放規則不放原文**，因為原文現在幾乎都是系統照客戶的答案產生的，
講第二次只是佔位置。

**客戶詳情這一邊**（`ui/views/availability.js` 的 `collectionCard()`）：
原文用正常字級擺在最上面（`.ban__raw`），規則變成底下一串**項目符號清單**，
再加兩行說明文字（「上面那幾條是系統從原文讀出來的」「讀錯了以原文為準」）。

她要的是前者。

## 要做什麼

### 1. `banBlock()` 抽成共用元件

搬進 `ui/components/` 或 `ui/views/availability.js` 並匯出，兩個畫面共用一份。
**不要複製一份到客戶詳情** —— `CLAUDE.md` 的原則是同一件事只寫在一個地方，
而這一塊已經在兩個畫面上了（壓表卡片牆、壓表記錄面板），現在要變成三個。

它現在讀的是壓表那邊算好的 `row`（`rules` / `collectedAt` / `availableDays` /
`rawText` / `needsAvailability`）。客戶詳情要餵同一個形狀進去 ——
從 `collection` 記錄轉成那個形狀是一小段對應，寫在 domain 裡。

### 2. 哪一份算數：這一段問的是「現在」

`CLAUDE.md` 的連動表寫得很清楚：綁月份的畫面用 `collectionFor()`，
**問「現在」的畫面用 `currentCollection()`**。客戶詳情屬於後者
（她臨時被問「他最近哪天可以」），現在的程式也是這樣寫的 —— **不要改**。

但 ADR-0036 的那句話仍然要看得見：「這個月沒問過就寫『還沒問 8 月的時間』，
不要拿別的月份那一份硬算」。`banBlock()` 的 `needsAvailability` 分支已經
會講月份，沿用。

### 3. 「以前問過的 N 次」

現在是一個 `<details>`，裡面每一份都是一張完整的 `collectionCard()`。
改成同一套丸子的樣子，但**淡一級**。保留摺疊。

### 4. 原文

照 `banBlock({ raw: true })` 收在「他原本是怎麼說的」那一摺裡。
**原文不能拿掉**（SPEC 第 4.3 節：原文永遠比解析結果大），只是不再佔第一位置。

`issues/04` 之後她自己記的那一份，原文會變成純備註 —— 那一摺的標題到時候
要跟著換一個講得通的字（「她記的備註」之類），兩條一起做的時候一併處理。

## 一起要檢查的

- `.ban` / `.ban__chip` / `.ban__head` 那組 CSS 現在寫在壓表那一段裡（`app.css`），
  搬到共用的位置去。
- 客戶詳情這一段底下的「記一次」與每一份的「編輯」按鈕留著（`issues/04` 會改
  它們點下去長什麼樣，位置不變）。
