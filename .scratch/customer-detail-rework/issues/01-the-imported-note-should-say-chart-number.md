# 匯入寫的「姓名欄的編號」其實是病歷號

Status: todo
來源：使用者，2026-08-24（spec.md 的 a）
動工前先讀：`docs/legacy/README.md`、`docs/adr/0047`

## 原話

> 「備註幾乎都會寫一個姓名欄的編號：…那應該是一開始匯入時從名稱那邊解析出來的，
> 其實那個是病歷號，可以幫我去解析那邊看看，我希望之後匯入，不要寫
> 『姓名欄的編號：』而是寫『病歷號』」

## 在哪裡

`public/js/domain/legacyImport.js:795`：

```js
const out = (text.match(/\d{3,}/g) ?? []).map((d) => `姓名欄的編號：${d}`);
```

舊試算表的 A2 是像 `王小明 (高能/sis)3157` 這種寫法，解析器把三位以上的數字
抓出來當備註。那串數字**就是病歷號**，當初不知道所以取了一個描述性的名字。

## 要做什麼

### 1. 改字

`姓名欄的編號：3157` → `病歷號 3157`

冒號也拿掉 —— 「病歷號 3157」讀起來就是一件事，不需要標點。

### 2. 已經匯進去的舊資料

她說「我希望**之後**匯入」不要那樣寫，但畫面上現在那二十幾位身上掛的
還是舊的字。**兩件事都要做**，不然她還是天天看到它。

寫一支一次性的修正，掛在**資料健檢那一頁**（`#/health`）—— 那一頁本來就是
「把對不起來的東西列出來並修掉」的地方，而且它的每一個修正都走稽核紀錄。
列出「有 N 位客戶的備註寫著舊的說法」，一顆按鈕改掉。

**不要寫成一支跑一次就丟的腳本** —— 這個 app 沒有後台，她只有畫面。

### 3. 詞彙表

`CONTEXT.md` 要不要補「病歷號」這個詞？**要**。它是一個會出現在畫面上的名詞，
而且跟「客戶」「來訪」一樣是她講的話。一句話就好：客戶在醫院系統裡的編號，
只顯示、不參與任何計算。

## 一起要檢查的

- `tests/legacy-import.test.js:359` 與 `tests/merge-import.test.js:32` 都寫死了
  舊字串，跟著改。
- **那個正規表示式抓的是「三位以上的數字」，會不會抓錯？** 舊表的 B2 是
  購買通路（`0522 顧客會-8`），如果解析器也吃那一欄就會把 `0522` 當成病歷號。
  動工時看清楚它只吃 A2；如果會吃到別欄，那是另一個 bug，**開一支新 issue**，
  不要順手改。
- 稽核紀錄（SPEC 第 6.2 節）：批次修改備註要留 before/after。
