# 「禮拜一再問問」沒進隨手記；加進日曆之後沒有確認

Status: done
來源：她的十二件事，2026-08-25（`../spec.md`）
動工前先讀：`docs/adr/0044`、`CONTEXT.md` 的「隨手記」與「備註」

## 症狀（兩件事，同一張卡片）

**一、在卡片上打「禮拜一再問問」按「記」**

她的原話：「我期待隨手記上面會多出一個誰，禮拜一再問問，然後按下記的時候
會提醒已記錄到隨手記了。」

現在那一句只寫進 `visit.followupNote`（`domain/confirmations.js` 的檔頭解釋了
為什麼不是任務也不是備註，那個判斷是對的），可是**隨手記上什麼都沒有**，
而隨手記正是她「還沒做完的雜事」的那一份清單。訊息也只說「記下了，這一列還留著」。

**二、按打勾 → 確認 N 段，加進日曆**

她的原話：「我希望加入日曆後可以跳出畫面中央的提醒，簡潔的說，誰，幾月幾號
幾點做什麼，加入日曆。」

現在只有右下角一條 toast 寫「確認了，已排進日曆」—— 她剛剛逐段點掉了兩段、
留下三段，而畫面沒有把「最後成立的是哪三段」講出來。那是這條動線唯一一次
不可逆的寫入（狀態轉 confirmed、登記任務長出來）。

## 要做成什麼

**一、那一句同時落在隨手記上**

`visit.followupNote` 照舊（它決定那一列長什麼樣：卡片換底、天數從問的那天算），
**另外**建一筆隨手記：掛這位客戶、文字就是她打的那一句、沒有日期。
訊息改成「記下了，也放進隨手記」。

不是「搬過去」而是「兩份」的理由，跟日曆上的待辦那一題（ADR-0044）剛好相反：

| | 日曆上的待辦 | 這一句 |
|---|---|---|
| 兩邊是什麼 | 同一件事的兩個畫法 | **兩件事**：一個是「這一列的狀態」，一個是「我要記得去做」 |
| 所以 | 只能有一份資料 | 各存各的 |

把 `followupNote` 搬進隨手記的話，「跟客人確認時間」那一列會退回
「長得跟從來沒問過的一模一樣」—— 那正是 2026-08-20 加這個欄位要解決的問題。

**不重複建**：同一位客戶身上已經有一筆一模一樣、還沒勾掉的隨手記就不再建
（她改字、改回原本那句、按兩次「記」都不該長出第二筆）。清掉那一句時
**不動隨手記** —— 她可能已經在隨手記上處理到一半了。

**二、加進日曆之後出一張置中的卡片**

走既有的 `components/card.js`（`openCard()`，抬頭 + 內容 + 底部按鈕），
不新開一種浮層 —— 這個 app 的浮層已經有三種了（抽屜、卡片、對話框，ADR-0048）。

```
        王小明・加進日曆
   ─────────────────────────
    9/14(一) 10:30  復能
    9/14(一) 11:30  營養點滴
    9/23(三) 14:00  復能
   ─────────────────────────
    退掉 2 段（客人說不行）
              [ 好 ]
```

有被退掉的段落就多一行，沒有就不出現。

## 做了什麼

- `ui/views/home.js` 的 `saveFollowupNote()`：寫完 `followupNote` 之後
  建那一筆隨手記（`notesData.create`），去重的判斷走
  `domain/notes.js` 新增的 `sameOpenNote(notes, {customerId, text})`
- `ui/views/home.js` 的 `applyConfirm()`：成功之後 `openCard()`，
  內容由 `domain/visits.js` 新增的 `describeConfirmed(visits, rejectedKeys)` 產生
  —— 「誰、幾月幾號幾點、做什麼」是規則不是排版，不寫在事件處理器裡
