# 抽屜底下那三顆看起來像切換，不像新增

Status: done
來源：使用者，2026-08-24（spec.md 的 b）
動工前先讀：`SPEC.md` 第 8.6 節、`docs/adr/0020`

## 原話

> 「我覺得抽屜最下面寫行事代辦，備註，來訪，不像是新增的樣子，感覺像是切換而已，
> 我希望可以…不要在下面呈現，而是這個抽屜最右上角可以有一個新增的圖示，
> 點了之後有點像漂浮泡泡那樣可以選要新增甚麼」

## 她是對的

現在那一排是 `openDay()` 傳給 `openSheet()` 的 `actions`：

```
[ 待辦 ]  [ 行事備註 ]  [ 來訪 ]
```

三顆等寬、並排、釘在底部、其中一顆是主色 —— 那是**分段切換**的長相
（`app.css` 的 `.seg`，待辦中心的「總覽／依客戶」就長這樣）。畫面上兩個東西
長得一樣就會被讀成同一種東西，而這三顆做的事是新增，不是換一個看法。

而且它們佔掉抽屜底部一整條 —— 那一格是她**看那一天**時最不需要的東西。

## 要做什麼

### 1. 抽屜的抬頭多一顆「＋」

`ui/components/sheet.js` 的 `.drawer__head` 現在是「標題　＋　叉叉」。
中間加一個給呼叫端放東西的位置：

```html
<div class="drawer__head">
  <h2 class="drawer__title" data-sheet-title>…</h2>
  <div class="drawer__tools" data-sheet-tools></div>   ← 新的
  <button class="drawer__x" …>✕</button>
</div>
```

配一支 `setTools(html)`（跟 `setActions()` 同一個形狀：空的就 `hidden`）。
**這是給所有抽屜用的一般能力，不是日曆專用的** —— 客戶詳情的「全部來訪」、
壓表的面板之後都可能要在抬頭放一顆東西。

叉叉留在最右邊：關掉是每一張抽屜都有的動作，位置不能因為某一張多了一顆＋就換。
所以順序是 `標題 …… ＋ ✕`。

### 2. 點「＋」長出一張小選單

照懸浮泡泡那一組（`app.css` 的 `.fab__menu` / `.fab__item` / `.fab__dot`）的
長相與行為，但從抬頭那一顆往**下**長，不是往上：

```
                              [＋] [✕]
                        ┌──────────────────┐
                        │ 新增來訪      👤 │
                        │ 新增待辦      ✏️ │
                        │ 新增行事備註  📅 │
                        └──────────────────┘
```

- 順序照她按的頻率：來訪最常按，放最上面（最靠近手指）。日曆懸浮鈕現在是
  「行事備註／待辦／來訪」由上而下，**兩邊要一致** —— 同一組三選一在同一頁
  出現兩次卻順序相反，比順序不好更糟。挑一個順序，兩邊都改。
- 點外面收起來、按 Esc 收起來、選一個就收起來並直接接進原本那條路
  （`mountNoteEditor` / `mountEditor` / `pickCustomer`），**一步都不多**。
- 44px 感應範圍照 SPEC 第 8.0 節，視覺上那顆＋可以小一點。

### 3. 底下那一排拿掉

`openDay()` 不再傳 `actions`。抽屜底部那一條在看某一天時就整條消失，
一天的清單多拿到一整行的高度。

**編輯器掛進來時底下那排還是要有**（存起來／取消）—— 那是真的動作列，
不是這一條要拿掉的東西。

## 一起要檢查的

- `openDay()` 目前用 `sheet.el.querySelector('[data-add-note]')` 之類直接抓，
  改成掛在工具列上；`mountNoteEditor()` / `mountEditor()` / `pickCustomer()`
  進來時會 `setActions()`，那幾支要跟著 `setTools('')` 把＋收掉 ——
  **在編輯器上面留一顆「新增」是講不通的**。
- `.drawer__head` 目前是 flex，多一個小孩要確認長標題（「8/14（五）」不長，
  但客戶詳情的「全部來訪」比較長）不會把叉叉擠出去。
- 空的那一天（沒有任何東西）也要有＋ —— 那正是她最想新增的時候。

## 驗證

- `npm test`（`tests/shell-cache.test.js` 若動到 `public/` 的檔案清單）
- 瀏覽器：點一天 → 抬頭有＋、底下沒有那一排 → 點＋ → 三條路都走得通，
  存完回到那一天
- 瀏覽器：點＋ → 點外面 → 選單收起來，抽屜還在那一天
- 瀏覽器：進了編輯器之後抬頭的＋不見了
- 手機寬度（375px）與 iPad 橫式（≥900px，抽屜變置中對話框）兩種都看

## Comments

**2026-08-24 —— done。**

`openSheet()` 多了第三個插槽 `tools`（抬頭上、叉叉左邊）與 `setTools()`，
跟 `setActions()` 同一個形狀。**這是給所有抽屜的一般能力，不是日曆專用的。**

三個會換掉面板內容的地方（`mountNoteEditor` / `mountEditor` / `pickCustomer`）
現在除了 `setActions('')` 也一起 `setTools('')` —— 在一張正在填的表單上面
留一顆「新增」是講不通的。

**順序的決定跟 issue 寫的不一樣，要記一下。** issue 說「兩邊要一致」，
我照做了，但一致的定義不是閱讀順序，是**離觸發點的距離**：

- 懸浮泡泡往上長 → 來訪在最下面（最靠近那顆泡泡）
- 抽屜的＋往下長 → 來訪在最上面（最靠近那顆＋）

兩邊的規矩是同一條「手指從觸發點出發，第一個碰到的是最常按的那一個」，
只是方向相反。硬要讓兩邊的閱讀順序一樣，就得讓其中一邊把最常按的放到最遠。
