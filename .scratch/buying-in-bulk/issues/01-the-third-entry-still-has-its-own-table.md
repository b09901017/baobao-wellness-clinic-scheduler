# 批次建立的「微調」還在用自己的那一張加購表

Status: todo
來源：使用者，2026-08-26（`../spec.md`）
動工前先讀：`CONTEXT.md` 的「營養品」「營養點滴品項」「健檢」、
`docs/adr/0054`、`docs/adr/0057`、`docs/adr/0038`、
`ui/components/buy.js` 的檔頭、`../bulk-customer-create/issues/01` 的「微調那一張面板」

## 症狀

她的原話：

> 批量新增那邊的微調，好像沒有營養品，也沒有加健檢要選幾萬的方案
> 加營養品也要選
> 加營養針也要選
> 可以不要用下拉選單而是用小丸
> 像是其他加購一樣

`#/customers/bulk` → 某一列的「微調」→ 底下那一段「加購」現在是：

```
加購　方案之外多買的
  [ 健檢          ▾ ] [ 1 ] [ 加 ]
```

一個 `<select>` 列著課程主檔的每一個課程，一格數字，一顆「加」。所以：

1. **營養品不在那個下拉裡** —— 它們是主檔 `products` 的東西，不是課程。
2. **選了健檢沒有「幾萬的」那一排**（ADR-0054）。加出來的那一筆就叫「健檢」，
   而她一批八位裡有人買 8 萬有人買 12 萬 —— 建完之後兩張卡片長得一模一樣。
3. **選了營養點滴沒有「哪一種」那一排**（ADR-0057）。加出來是一筆叫
   「營養點滴」的額度，而 `CONTEXT.md` 說品項「各自有各自的次數，不合併計算」。
4. **它是下拉不是丸子。** 她 2026-08-25 就講過一次了（`../buying-and-read-only/`）。

## 為什麼是「接上去」而不是「再做一次」

`ui/components/buy.js` 的檔頭寫的是「兩個入口」，而入口有三個。第三個比它
早兩天寫，所以它沒有被算進去 —— 這一輪只是把第三個接上同一張表。

**不要在微調面板裡再實作一次那四件事**：一排丸子、選了健檢多一排等級、
選了營養點滴多一排品項、營養品論份不論次。同一件事有兩份實作、而其中一份是錯的
——那正是上一輪 `../buying-and-read-only/issues/04` 修掉的形狀。

## 要做成什麼

### 一、微調面板裡的「加購」換成那一張表

```
微調 · 王小明
  ☑ 套用「筋骨強身」
  購買數量　整批是 1   [    ]

  加購　方案之外多買的
    · 8萬健檢 1 次                         ✕
    · 夜態美 2 份                          ✕
    [ ＋ 加一項 ]
```

按下「＋ 加一項」在**同一張面板裡就地展開**那一張表，不另外開一張面板：
`components/sheet.js` 同一時間只留一張（開第二張會把第一張關掉），
而微調面板上那兩個還沒按「好了」的欄位是會被關掉一起丟掉的。

展開之後：

```
    ┌ 加一項 ─────────────────────────────────────
    │ 買了什麼  [復能][靜脈][健檢][營養點滴][復能（三選一池）] ｜商品 [營養品]
    │ 幾萬的    [0.75萬][8萬][12萬][其他…]
    │           會變成「8萬健檢」
    │ 幾次      [ 1 ]  +1 +5 +10
    │ [ 加進來 ]  [ 取消 ]
    └─────────────────────────────────────────────
```

欄位一個字都不要自己寫，全部是 `buy.fields(draft, master)`。

### 二、`row.extras` 的形狀跟著換

現在是 `[{ courseId, qty }]`，那個形狀表達不出「哪一款營養品」「幾萬的」
「哪一個品項」。換成**一筆已經整理好的額度**（`buy.toEntitlement()` 的結果，
購買日先留 `null`）：

- **不要存 `buy.blank()` 那種草稿。** 草稿上有 `tierOther` 這種只有畫面在用的
  欄位，它會一路跟著 `createWithPlan()` 寫進 Firestore —— `validEntitlement()`
  只驗形狀不擋多餘欄位，所以沒有人會攔下來。
- **購買日在 `extrasFor()` 那一刻才蓋上去。** 她可能先加了三筆加購才回頭去改
  整批的購買日，早早烤進去就會對不起來。

於是 `domain/bulkCustomers.js` 的 `extraToEntitlement()` 沒有呼叫端了 ——
它做的事（課程 → 一筆額度）現在是 `components/buy.js` 在做，而那一支同時
知道等級、品項與營養品。刪掉它，不要留一支「還可以用但沒有人用」的
第二種接法。

### 三、順帶對齊的兩件事

- **`validateRoster()` 要拿得到營養品主檔。** 少了它，一筆營養品加購會被
  `validateEntitlement()` 判成「指定的營養品不存在或已刪除」而擋住整批建立。
- **那一列的小字用 `buy.summaryLine()`**（`8萬健檢 1 次` / `夜態美 2 份`），
  不要自己再接一次字串 —— 營養品論份、其餘論次只寫在 `buy.unitOf()`。

### 四、時長與頻率限制會變成 `null`

`extraToEntitlement()` 以前把課程主檔上的 `durationMin` 與 `frequencyRule`
抄到額度上，`buy.toEntitlement()` 留 `null`。**這是對的**，而且是往
另外兩個加購入口對齊：

- 時長：`visitEditor.js` 與 `schedule.js` 兩邊都是
  `ent.durationMin ?? course.durationMin ?? 60` —— `null` 就是「用課程的」，
  行為一模一樣，而且課程之後改了時長它會跟著改。
- 頻率限制：只在客戶詳情的「進階設定」顯示，沒有任何計算讀它。

## 不做什麼

- **加購那一列不給改，只能加與刪。** 跟新增客戶那一頁一樣。要改一筆額度的
  七個欄位是客戶建好之後進詳情頁的事（`../bulk-customer-create/issues/01`）。
- **微調面板不接 `pushLayer()` 的第二層。** 展開「加一項」不是多一層東西，
  是同一張面板裡換內容（同 ADR-0052 對壓表卡片組的判斷）。

## 驗證

- `npm test`（`tests/bulk-customers.test.js`：extras 是額度、購買日蓋得上、
  營養品不會被驗證擋掉）
- 瀏覽器：客戶 → 快速建立一群 → 打兩個名字 → 其中一位「微調」→「＋ 加一項」
  → 點「健檢」→ 出現「幾萬的」→ 選 8萬 → 會變成「8萬健檢」→「加進來」→
  那一列寫著「8萬健檢 1 次」→ 再加一筆「營養品／夜態美／2」→ 那一列寫著
  「夜態美 2 份」→「好了」→ 名單那一列的小字寫得出這兩筆 →「建立 2 位」→
  進那位客戶的詳情：額度多一張「8萬健檢」、底下自動配出「二返（8萬健檢）」、
  **營養品那一段**多一列「夜態美 ×2」，而且它沒有進「剩 N 次」
