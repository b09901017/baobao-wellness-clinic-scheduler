# 「幾萬的」選了「其他…」，自己打的字不進顯示名稱

Status: done
來源：使用者，2026-08-26（`../spec.md`）
動工前先讀：`docs/adr/0054`、`ui/components/buy.js` 的檔頭

## 症狀

她的原話：

> 然後加購那邊我發現如果是幾萬建檢選其他，名稱不會自動改?

客戶詳情 → 額度 → 加購 → 點「健檢」→「幾萬的」那一排點「其他…」→
底下展開的那一格打「5萬(心臟)」→ 加購。

那一筆存進去叫 **「健檢」**，不是「5萬(心臟)健檢」。等級本身有存對
（`tier` 欄位是 `'5萬(心臟)'`），錯的只有顯示名稱 —— 而顯示名稱正是
ADR-0054 這整件事唯一的目的：

> 加購時她要選得到，而選了之後那一筆要叫「8萬健檢」——兩筆都叫「健檢」的話
> 她在客戶詳情頁分不出哪一筆對哪一筆。

三顆常用的等級（0.75萬／8萬／12萬）是好的。**只有她自己打的那一種是壞的**，
而那正是 ADR-0054 說「她選的就是『可以自己加』」的那一半。

## 原因：那一格沒有人在聽

「換了等級要改名」這條規則本身是對的，而且只有一份實作
（`components/buy.js` 的 `retitle()`）。斷點在**接線**：

```js
// ui/views/customerDetail.js / ui/views/customers.js，兩邊都一樣
const detail = ev.target.closest('[data-chip="tier"], [data-chip="ivProductId"], …');
if (detail) { …retitle… }
```

兩個入口都只聽了**點丸子**。「其他…」是一顆丸子沒錯，但它展開的那一格
`tierText` 是一個 `<input>` —— 打字不是點擊，所以那條路上沒有任何人被叫到。
點「其他…」的那一下確實有 retitle，只是那時候那一格還是空的
（等級是 `null`），所以算出來的名字就是「健檢」，然後就停在那裡了。

同一頁上那句預告（「會變成『8萬健檢』」）也是同一個原因不見的。

## 為什麼修法不是「再加一個監聽」

再加一個監聽是三行的事，但它要加**三次**（客戶詳情、新增客戶，
加上 issue 01 要接上去的批次建立），而這個 bug 的成因就是同一件事接了兩次、
兩次都漏掉同一格。第四個入口出現的那一天會漏第三次。

而且打字**不可以重畫**：重畫會把游標與輸入法的組字狀態一起洗掉
（`views/customersBulk.js` 的檔頭已經為了同一件事寫過一次）。所以這條路
還多一個「不重畫要怎麼把名字改掉」的細節，那更不該有三份。

## 要做成什麼

### 一、把「動了一下之後草稿變成什麼」收成純函式

`components/buy.js` 現在有 `pick()` 與 `retitle()` 兩支純規則，但**合成那一版
草稿的那幾行留在三個呼叫端各寫一次**。收成兩支：

```js
/** 點了「買了什麼」的某一顆之後的整張草稿。 */
export function afterPick(value, draft, typed, master)

/** 換了「幾萬的」「哪一種」、或在「自己打」那一格打字之後的整張草稿。 */
export function afterDetail(draft, typed, master)
```

`typed` 是**表單現在說的話**（她打進去的字、丸子剛剛換掉的值）。
兩支都是純函式，測得到。

`afterDetail()` 有一個一定要寫成測試的不變量：**連續打字時，
「她自己改過名稱嗎」要拿上一個字那一版去問。** 拿更早的那一版去問，
第二個字開始就會把 app 自己填的名字誤判成「她改過的」，然後停住不再跟。

### 二、三個入口共用同一份接線

`components/buy.js` 多一支 `wire(root, …)`，把四種動作接在一起：
換「買了什麼」、換「幾萬的／哪一種」、`+1/+5/+10`、**在「自己打」那一格打字**。
呼叫端只給「畫面上哪一塊要重畫」。

這一支會碰 DOM，而這個檔案到今天為止一行都沒碰過 —— 檔頭與
`tests/buy.test.js` 的檔頭都要跟著改，不要留一句已經不成立的話。

### 三、打字那一下就地改，不重畫

- 顯示名稱那一格（只有客戶詳情的「進階設定」裡有）直接寫進去。
- 那句預告（「會變成『5萬(心臟)健檢』」）就地換字。所以 `nameHint()`
  要**一直印那個節點**（沒有東西講的時候 `hidden`），不然第一個字打下去時
  沒有節點可以改。

## 驗證

- `npm test`（`tests/buy.test.js`：`afterDetail()` 連打兩個字之後名字還在跟）
- 瀏覽器：
  - 客戶詳情 → 加購 → 健檢 → 其他… → 打「5萬(心臟)」→ **邊打邊看到**
    「會變成『5萬(心臟)健檢』」→ 展開「進階設定」，顯示名稱也是那一句 →
    加購 → 卡片上寫著「5萬(心臟)健檢」，底下配出「二返（5萬(心臟)健檢）」
  - 同一張表：先在「進階設定」自己打一個名字，再回去換等級 →
    **她打的字不會被蓋掉**
  - 新增客戶 → 加一項 → 同上

## 做了什麼

- `ui/components/buy.js`：多 `afterPick()` / `afterDetail()`（純規則）、
  `values()`（讀表單）、`wire()`（接線）。`nameHint()` 改成一直印那個節點。
  檔頭多一段「規則在上半段，接線在下半段」。
- `ui/views/customerDetail.js` 的 `wireEntitlement()`、
  `ui/views/customers.js` 的 `openBuySheet()`：兩邊的三段 `if` 換成 `buy.wire()`，
  各自只留「哪一塊要重畫」。
- `tests/buy.test.js`：多一段「動了一下之後的整張草稿」，其中兩支是回歸測試
  （「其他…」那一格打字要跟、連著打第二個字也要跟）。
