# 方案範本沒辦法「複製一份改名成新範本」

Status: done
回報者：ADR-0003 寫進去時就講好的作法，但一直沒開票，2026-08-18
動工前先讀：`docs/adr/0003-plan-templates-have-no-version.md` 與 `SPEC.md` 第 4.5、5.3、6.4 節

## 症狀

`docs/adr/0003-plan-templates-have-no-version.md` 明講範本的三種操作是
**「可就地修改、可複製一份改名成為新範本、可停用」**。

現在做得到的只有兩種：

| 操作 | 現況 |
|---|---|
| 就地修改 | ✅ 設定 → 方案範本 → 編輯（含項目編輯器） |
| 停用 | ✅ 編輯畫面最下方的危險區 |
| **複製一份改名** | ❌ **沒有任何入口** |

所以「9 月的方案跟 8 月的只差兩個項目」這件事，現在唯一的做法是**從零手打一次**
—— 種子資料的筋骨強身有 7 個項目，實際的方案只會更多。

這不是藏在別處的功能，是缺的。ADR-0003 的整個立論就建立在「不做版本、改用複製」上，
複製沒做等於那支 ADR 只實現了一半。

## 根因

**`public/js/ui/views/masterList.js`**

- `paintList()` 的每一列只有一顆「編輯」按鈕
- `paintForm()` 只有兩條路：`isNew`（`record?.id` 是空的）就 `config.create()`，
  否則 `config.update()`

也就是說「帶著既有內容開一張新表單」這件事**機制上已經成立**（`paintForm` 收 `draft`
參數，而且 `isNew` 看的是 `record?.id` 而不是 `record`），只是沒有人去呼叫它。
第 2 步那張 issue 修 `isNew` 的時候就順手把地基鋪好了。

## 要做什麼

在方案範本的清單列與編輯畫面各加一個「複製一份」，按下去**開一張帶著內容的新表單**，
不是直接寫一筆進資料庫。

### 為什麼是「開表單」而不是「直接建立」

直接建立會在清單上長出一筆「筋骨強身（複本）」，她還沒改名就已經存在了 ——
萬一那當下被打斷，資料庫裡就留著一筆半成品，而方案範本是拿來展開額度的東西，
半成品混在裡面很危險。開表單則是「按了儲存才算數」，跟現有的新增流程一致。

### 複製過去什麼

| 欄位 | 怎麼處理 |
|---|---|
| `name` | 預設 `原名（複本）`，讓她直接改 |
| `membershipMonths`、`note` | 原樣帶過去 |
| `items` | **深拷貝**。項目是物件陣列，淺拷貝會讓兩張範本共用同一批項目物件，改了新的連舊的一起變 |
| `active` | 一律 `true` —— 從停用的範本複製一份出來，本意就是要用它 |
| `id`、`deletedAt`、`createdAt`、`createdBy`、`updatedAt` | **一律不要帶**。新的一筆由 `repo` 自己產 |

### 驗證與寫入

- 驗證走既有的 `validate('plans', candidate, { existing, courses, equipment })`，
  不要另寫一套。**同名檢查會擋下來**（`duplicateName()`），所以預設名字一定要加後綴，
  否則她一按複製就看到「已經有同名的」而不知道為什麼。
- 寫入走 `data/config.js` → `data/repo.js`，才會有稽核與軟刪除。

## 不能違反的既有決定

- **`docs/adr/0003-plan-templates-have-no-version.md`：範本沒有版本。**
  複製出來的是一張**完全獨立**的新範本，**不可以**加 `version`、`copiedFromId`、
  `sourcePlanId` 之類的欄位指回原本那張。使用者口中「5 月的範本」與「8 月的範本」
  是兩個各自有名字的範本，不是同一個範本的兩個版本。
- **不需要任何「這會影響 N 位客戶」的警告。** 額度在展開當下就整份複製到客戶身上了，
  新增一張範本影響不到任何人。也不要因此走 `confirmAction` ——
  複製不是破壞性操作（SPEC 第 6.5 節講的是取消、刪除那一類）。
- **分層守衛**（`tests/layering.test.js`）：深拷貝與欄位取捨是「一張範本長什麼樣」的規則，
  放 `/domain`（`domain/masterData.js`，跟 `planItem()` 放一起）才測得到，
  不要寫在 UI 的事件處理器裡。
- 其他 editors（rooms / staff / equipment / ivProducts / products / courses）
  不可以因為這次改動而改變 —— 複製只有方案需要。

## 驗收

1. 清單上按「複製一份」，跳出的表單名稱是「筋骨強身（複本）」，7 個項目都在，
   按儲存後清單多一張，原本那張一個字都沒變。
2. 複製出來的那張改一個項目的次數，**原本那張不受影響**（深拷貝的驗收）。
3. 從**停用**的範本複製，新的那張是啟用的。
4. 複製之後不改名直接儲存，出現同名錯誤而不是無聲蓋掉 ——
   前提是預設名稱已經加了後綴，所以這一項應該不會發生，測試要蓋住。
5. 複製出來的範本展開給一位新客戶，額度與原範本展開的結果逐欄相同。
6. 存下來的文件裡**沒有** `version` / `copiedFromId` / `sourcePlanId` 之類的欄位。
7. `npm test` 全綠，深拷貝與欄位取捨在 `tests/master-data.test.js` 有測試。
8. 375px 寬度下清單列上的兩顆按鈕（編輯、複製）都摸得到（44px）且不會擠成一團。

## 不在範圍內

- 客戶端的「換方案」或「重新展開額度」（額度展開後與範本脫鉤，那是另一件事）
- 方案範本的匯入匯出
- 其他主檔的複製（診間、課程之類的欄位少，手打比較快）
