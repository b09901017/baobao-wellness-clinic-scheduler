# 今天做了什麼：以人分組，照流程留成另一種看法

Status: todo

Blocked by: 01
動工前先讀：`public/js/domain/dayReview.js`、`public/js/ui/views/home.js`

## 原話

> 在今天做了什麼那邊也許可以以「人」為群組分類呈現?：
> 用客戶姓名作為大標題，底下條列式列出對他做了什麼事 ? 之類的請你幫我設計

問過她之後定的：**以人為主（預設），保留「照流程」切換。**

## 為什麼不是二選一

兩種看法回答的是兩個不同的問題，而她兩個都會問：

| 看法 | 回答 |
|---|---|
| 照人 | 「客戶A今天處理完了沒」—— 壓了表、確認了、掛號了、還缺什麼 |
| 照流程 | 「哪一類整個漏了」—— 例如整天一張療程單都沒簽 |

**ADR-0062 的分段不推翻**（那一支的段落順序與「最後一段永遠收得下剩下的」
一個字都不動），它變成兩種看法的其中一種。所以這一件不新增 ADR，
只在 ADR-0062 底下補一段 Consequences。

## `domain/dayReview.js` 要做什麼

`reviewOf()` 多回一個 `people`，`groups` 原封不動：

```js
/**
 * @param {object[]} events 那一天的稽核，**新的在前**
 * @param {{limit?: number|null, nameOf?: (id: string) => string|null}} [o]
 * @returns {{groups, people, tiles, total, truncated}}
 *   people：照人分組，一位一組。**沒有掛客戶的收成最後一組**
 */
export function reviewOf(events = [], { limit = null, nameOf = null } = {})
```

### 一組人長什麼樣

```js
{
  who: '客戶A' | null,        // null = 沒有掛客戶（設定、行事備註、休假）
  whoId: 'abc123' | null,
  rows: [{ at, text, stage, times }],  // stage 是那一段的 label，例：'壓表'
  n: 4,
}
```

- **`text` 不含名字。** 抬頭已經寫了，每一列再印一次是雜訊 ——
  這正是 issue 01 把 `describeParts()` 拆成兩半的理由。
- **每一列帶一個 `stage`**（用 `STAGES` 那一份的 `label`，不另外定義一組）。
  照人看的時候還是看得出「這是壓表還是掛號」。
- 一位客戶身上的 `rows` **照時間由早到晚**：那是一條線
  （壓表 → 確認 → 掛號），照她做的順序讀才連得起來。
  照流程那一格維持**新的在前**（那一格問的是「我剛剛做了什麼」）。
  兩邊的方向不一樣是刻意的，而每一列都印著時間，看得出來。
- 收合（`collapse()`）在兩種分組裡各做一次，規則同一支 ——
  **只收連著的，不是全天去重**（ADR-0062 那一條不動）。

### 人的順序

**照那一位客戶今天最後一次被碰到的時間，新的在前。** 她剛剛在處理的人排最上面。
`who` 是 null 的那一組永遠排最後（那些不是「一個人」）。

### 沒有掛客戶的那一組

設定、行事備註、休假、以及任何 `customerIdOf()` 答不出來的。
抬頭寫「**沒有掛客戶**」——不要寫「其他」，那個字已經是流程分段的最後一段，
兩個「其他」在同一塊畫面上會讓人以為是同一件事。

**一則都不可以被丟掉**（ADR-0062 的那一條規矩對兩種分組都成立）：
測試要斷言 `people` 的列數總和 === `groups` 的列數總和 === 進去的筆數。

## `ui/views/home.js` 要做什麼

### 一顆切換

```html
<div class="seg" role="group">
  <button class="seg__item" aria-pressed="true"  data-review-by="person">照人</button>
  <button class="seg__item" aria-pressed="false" data-review-by="stage">照流程</button>
</div>
```

- 存在模組裡（`let reviewBy = 'person'`），**不進網址** —— 它是看法不是位置
  （同這一頁的「總覽／依客戶」與 `reviewDay`）。
- 切換**只換那一塊，而且不重新讀資料**：那一天的稽核已經在手上了。
  接法照 ADR-0038：委派、只改 `aria-pressed`、只重畫列表那一塊。
  → 所以 `paintReview()` 要拆成「載入」與「畫」兩支，載回來的 `events`
  存在模組裡（跟 `taskVisits` 同一個作法）。

### 客戶名單

`paintReview()` 讀稽核的時候**平行**讀一次 `customersData.list()`，
建成 `nameOf`。**只在這一塊展開時才讀**（這一塊本來就是展開才載入），
而且讀回來之後存在模組裡，翻日子與換看法都不再讀第二次。

**讀不到名單不可以擋住這一塊**：各自 catch，沒有名字就退回「沒有掛客戶」那一組。

### 照人那一格的版面

```
今天 9/1                      [照人] [照流程]   ‹ 前一天  後一天 ›
壓了 6 筆　簽了 3 張單　登記 8 筆　記了 4 件

客戶A                                        4 件
  14:22  壓表    9/14(日)・復能、營養針
  15:03  確認    9/14(日)・復能、營養針・改成已確認
  16:40  掛號    勾掉・Examine
  18:02  額度    二返（12萬健檢）・已排未上 1 → 2 次

客戶B                                        2 件
  09:11  待辦    新增待辦・9/3・「帶健保卡」
  09:12  待辦    勾掉待辦・「帶健保卡」

沒有掛客戶                                    1 件
  20:15  日曆    新增休假・「宜蘭休假」・9/5–9/8
```

- 名字那一行用 `.reviewwho`，右邊一個淡的件數。
- 中間那一欄是 `stage`，固定寬度，**淡一級** —— 它是分類不是內容。
  用 `STAGES` 的 `label` 直接印（不印編號：編號講的是流程的第幾步，
  在照人的排法裡沒有意義）。
- 頂端那一排摘要數字與底下的試算表那一行**兩種看法共用**，不跟著切換動。

### 過場

切換與翻日子時那一塊會整個換掉。**只給一個很輕的淡入**
（沿用既有的 `deck-in`，0.14s），不要逐列延遲 —— 一天有一百多列的話
那會變成一串閃爍。長按與抽屜那些既有的動畫一個字都不動。

## 不做

- 不做「照客戶篩選」的搜尋框。她一天碰到的客戶不到二十位，捲得完。
- 不把切換寫進網址。
- 不因為分組而多讀一次稽核。
- 不動 `STAGES` 的順序與內容。
