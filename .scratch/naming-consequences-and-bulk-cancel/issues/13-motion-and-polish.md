# 動畫與版面的收尾

Status: done
來源：使用者，2026-09-08（「有動到 UI 介面或互動的地方請務必精心設計」）

## 她的三條原則

1. 流暢的視覺回饋（長按的按壓回饋、抽屜過渡、選單展開、狀態切換的顏色漸變）
2. 排版直觀流暢舒服閱讀
3. **簡潔直觀，點到為止，絕不能過度設計**

## 先確認既有的 token

動工第一件事：把 `public/css/tokens.css` 裡現有的 `--motion-*` 與 `--ease-*`
列出來，**全部用既有的**（現在有三個：`--motion-fast` 120ms、`--motion-base` 180ms、
`--motion-slow` 300ms，加一條 `--ease-out`）。這一輪**不新增任何 motion token** ——
新增一個就要淺色深色兩份都改（CLAUDE.md 那一列），而且第二個人會不知道
該用哪一個。

## 這一輪動到的地方，各一句

| 哪裡 | 做什麼 | 不做什麼 |
|---|---|---|
| 名稱怎麼寫（`02`） | 那一列展開：~~`grid-template-rows` 0fr→1fr~~ → 入場淡入＋位移 | 不要整頁重排 |
| 備忘錄分段切換（`09`） | 丸子那一排 `opacity` 淡入 | **不要橫向滑入**（會跟丸子自己的橫捲打架） |
| 抽屜收合（`10`） | 修好起點就好 | 不要順手改時長 |
| 批次取消（`11`） | 展開當日、長按彈一下、勾選漸變 | 不要整列閃 |
| 壓表返回（`12`） | 走既有的 `pushLayer()` | 不要另外做換頁動畫 |
| 逐段取消（地基） | 那一段暗掉走既有的 `.status-*` | **不要開第八種顏色**（ADR-0039） |

## 做出來之後才發現的第三條（2026-09-08）

**`transition` 在整段重畫出來的節點上不會跑。** 上面那兩條寫「0fr→1fr」的
時候假設了那一列會留在原地改 class，但名稱怎麼寫、批次取消攤開的那一天都是
`innerHTML` 整段換掉的 —— 節點是新的，瀏覽器沒有起點可以動。

所以那幾處改成 **`animation`（入場）**，跟 repo 既有的 `chip-in` /
`nth-in` / `pbcard-in` 同一家。收合那一下沒有動畫（節點已經不在了），
那是這個做法的代價，而它比「寫了但不會跑」誠實。

**高度動畫刻意不做**：一格與兩格（器材那幾列沒有 LINE）、一天一段與一天四段
會是兩種速度，抖給她看不如不做。同 `.nthfields` 當初的理由。

**真的會跑的那一種**在批次取消的勾選上：`repaintPick()` 只換那一列、那一天
的格子與底下那一條，節點留著，所以 `.bulkrow__box` 上那條 `transition` 這次
是真的（順帶把 ADR-0038 那條「她要點五六下」也一起做了）。

## 兩條硬規矩

- **`prefers-reduced-motion` 已經是全域的**（`app.css:5559`，對 `*` 生效），
  所以新加的過場**自動被蓋到**，不用逐條再寫一次。要做的只有一件事：
  不要在任何一條新規則上寫 `transition: ... !important`，那會蓋掉它
- **不要用 JS 撐高度。** 備忘錄那張卡付過帳（CLAUDE.md 那一列）

## 44px

新加的每一顆可以點的東西（鉛筆、分段鈕、月曆上的日期格、勾選）
都要有 44px 的感應範圍。視覺上可以小，`::after` 撐出來 ——
`.drawer__grip` 就是這樣做的。

## 測試

- E2E 在 `phone` project 下量新按鈕的可點範圍
