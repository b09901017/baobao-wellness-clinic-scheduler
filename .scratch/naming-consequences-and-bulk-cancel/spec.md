## 動工前先講一件事：**三項需求的根因是資料，不是程式**

`data/config.js` 的 `loadSeed()` **只建不覆蓋**（`existingIds.has(row.id)` 就跳過，
連欄位都不合併）。所以 2026-09-06 以後改的種子，對她**現有的**資料庫一點作用
都沒有。她這一輪回報的三件事全部是這個形狀：

| 她看到的 | 真正的原因 | 程式對不對 |
|---|---|---|
| 選 ILIB 沒變成選診間，固定卡在治療師 | 她資料庫上的器材**身上沒有 `courseId`**（2026-09-06 才加的欄位） | 程式是對的 |
| 有課程叫「靜脈」 | `course-iv-laser` 在她庫上還是 2026-09-06 之前的名字 | 種子已經是 `ILIB` |
| 提醒不會跟著課程設定變 | 三個畫面**漏傳 `coursesById`**（見下） | 這一個是真的 bug |

**前兩件不能靠改程式修**，要靠資料健檢多兩列讓她按一下。少了那兩列，
她重新部署一百次也還是同一個症狀 —— 而畫面上看起來跟「程式沒改」一模一樣。

   額度仍然是 `ILIB(60)`、月曆仍然是 `IL(60)`。

## 我找到的、她還沒看到的三個真 bug

### 一、`coursesById` 在三個畫面漏傳（需求 6 的真正原因）

`visitReadHtml()` 是四個畫面共用的，而 `coursesById` 只有客戶詳情與日曆傳了：

| 畫面 | 傳了嗎 |
|---|---|
| 日曆 `calendar.js:1447` | ✓ |
| 客戶詳情 `customerDetail.js:1764` | ✓ |
| 待辦中心「跟客人確認時間」`home.js:1188` | **✗** |
| 待辦中心 任務詳情 `home.js:2091` | **✗** |
| 進度追蹤 `progress.js:289` | **✗** |

沒傳 → `formSlotIndexes(visit, {})` → 每一個課程都是 `undefined` →
`needsForm(undefined)` 回 `true`（沒有欄位就是要簽）→ **那三頁一律寫
「簽療程單」**，就算她已經把那個課程的「要不要簽療程單」關掉了。

這就是她說的「我改了課程設定，這個提醒不會更新」。

### 二、抽屜收合前會先往上跳一下（需求 9）

`components/sheet.js` 的 `dismiss()`：

```js
goTall();                                   // ← 這一步把面板換成滿高，上緣往上跑 peekY
backdrop?.classList.add('...--out');
settleAt(fullH + 40, ...);                  // ← 同一輪就開始過場
```

`goTall()` 裡面有兩次 `getBoundingClientRect()`，**強制瀏覽器算一次樣式**——
而那時 `--sheet-y` 還是舊值。於是過場的起點被定在「已經變高、但還沒補位移」
的那個位置，也就是比她看到的高 `peekY`。**先往上跳，再往下滑。**

`expand()` 沒有這個問題，因為它多包了一層 `requestAnimationFrame()` ——
兩支對照著看就知道差在哪。
