# 從客戶詳情點一筆來訪或任務，落點都不太對

Status: todo
來源：使用者，2026-08-24（spec.md 的 3）
動工前先讀：`docs/adr/0018`、`0020`、`SPEC.md` 第 8.1、8.5 節

## 原話

> 「客戶詳細資料那頁的來訪紀錄點進去，客戶詳細資料那頁的任務那邊的選項點進去
> （不是應該是跳到 todo 那邊嗎？不知道為甚麼點進去是那個？你如果解釋得通的話
> 也可以）…或是有些其實也應該是呈現資訊而不是點進去就是修改畫面？」

## 先回答「為什麼點任務會跑到那裡」

`customerDetail.js` 的 `taskRow()`：

```js
return t.visitId
  ? `<li><a href="#/visits/${t.visitId}">…`
  : `<li><span …>`   // 手動加的獨立任務沒有來訪可以點
```

任務連到的是**產生它的那一筆來訪**。設計上的意思是「這張 Examine 是哪一天
哪一筆產生的」，那個資訊確實有用 —— **但她點下去的當下心裡想的不是那個**，
而且落點是一個**可以改東西的編輯器**。

**她的直覺是對的，但『跳到 todo』也不完全對**：待辦中心那一頁列的是
「所有客戶的所有任務」，從一位客戶身上點一張任務跳到那裡，她還要在裡面找回
這個人。兩邊都不對。

## 要做什麼

### 1. 來訪：先給看的，鉛筆才給改的

`visitRow()` 現在直接連到 `#/visits/:id`（整頁編輯器）。改成**點一筆浮出
讀取模式的卡片**，跟日曆一模一樣（`views/calendar.js` 已經匯出 `visitReadHtml()`
可以共用），右上角鉛筆才進編輯器。

理由是 ADR-0020 已經寫過的那一條：「她點一筆的十次有九次只是要確認
那天幾點、誰、做什麼。直接落進表單等於每次都冒著改到東西的風險，
而這一站最不能出錯的就是次數。」**那條規矩本來就該適用於整個 app，
不是只有日曆。**

`.scratch/customer-detail-rework/issues/02`（這個月改清單）也要走同一條路，
兩條一起做。

### 2. 任務：那一列自己就講得完

一張任務身上的資訊只有四樣：哪一種（Examine／耀聖／追蹤健檢報告／約二返）、
死線、做完了沒、哪一筆來訪產生的。**這四樣一列就寫得下**，
不需要跳到任何地方：

```
☐ Examine        死線 8/13        8/14 的來訪 ›
☑ 耀聖           已完成
```

- **勾掉就在這一列做。** 現在那一頁寫著「要勾完成請到待辦中心，那裡可以
  一次勾一批」—— 那句話是在解釋一個限制，而不是限制本身。
  在這裡勾掉一筆沒有任何壞處（跟日曆上勾待辦是同一個判斷，ADR-0045）。
  勾完那一句說明也可以拿掉。
- **右邊那個「8/14 的來訪 ›」才是連結**，點它才去看那一筆（而且是讀取卡片，
  照上面第 1 點）。這樣「勾掉」與「去看來訪」是兩個分得開的動作，
  不會手滑。

### 3. 那一段要不要收起來

`.scratch/customer-detail-rework/issues/06` 把來訪紀錄收起來了。
任務這一段**在她身上還有沒做完的任務時要展開**（那是她要看到的），
全部做完了就收起來只留一個數字。

## 一起要檢查的

- 勾掉任務要走 `toast.withSaveState()`（可復原）。待辦中心那一頁的
  `markDone()` 已經有一份，看能不能共用。
- 二返那種「不用簽療程單但仍然要結案」的補述（`app.css` 有一個掛在徽章
  右邊的樣式）要留著。
- 手動加的獨立任務（沒有 `visitId`）在新版裡就是右邊沒有那個連結，其餘一樣。
