# `{slots}` 每一行寫完整的時間，不是只有開始

Status: done
來源：使用者，2026-09-05（spec.md 的第三）
動工前先讀：`domain/messages.js` 的 `slotLines()`、`domain/visitTime.js` 的 `timeLabel()`

## 原話

> 設定那邊 LINE 回覆模板的「問壓好的時間」的那個模板中的 `{slots}` 這個參數，
> 我希望時間可以寫完整，就是不是只寫幾點開始，而是幾點 - 幾點。

## 現在她貼給客戶的長這樣

```
王小姐您好，9 月為您安排了：
9/3(四) 14:00 復能
9/17(四) 10:00 營養點滴
9/17(四) 11:00 復能
請問可以嗎？
```

客戶看到「9/17 10:00 營養點滴、9/17 11:00 復能」會以為兩件事各要一個小時，
或者根本不知道 11:00 那一段做完是幾點。**而她的客戶要的正是「那天要待多久」**
—— 2026-09-04 那一輪把「一次來訪只講第一段」改成逐段一行，用的就是這個理由
（`domain/messages.js` 的 `slotLines()` 檔頭）。這一支是同一句話的下半段。

## 要做什麼

`domain/messages.js` 的 `slotLines()`，那一行 `.map()`：

```js
// 現在
.map((r) => [shortDate(r.date), r.startsAt, r.courseName].filter(Boolean).join(' '))
```

改成印一段時間。**不要直接用 `timeLabel()`** —— 它在兩頭都沒有時間時回
「時間不詳」，而那三個字**不可以進貼給客戶的訊息**：既有的測試就叫
〈沒有時間的那一段不印時間 ——「時間不詳」貼給客戶只會被打電話問〉。
所以要一支只給這裡用的小函式：

```js
/**
 * 這一段在訊息裡寫成什麼。
 *
 * 兩頭都有就寫完整的一段（她 2026-09-05 的原話：「不是只寫幾點開始，
 * 而是幾點 - 幾點」）—— 客戶要知道的是那天待多久，不是幾點報到。
 *
 * **`timeLabel()` 借不得**：它在沒有時間時回「時間不詳」，而那三個字貼給
 * 客戶只會換來一通電話（`slotLines()` 的既有規矩）。這裡沒有時間就整段不印。
 */
function slotTime({ startsAt, endsAt }) {
  if (isValidTime(startsAt) && isValidTime(endsAt)) return `${startsAt}–${endsAt}`;
  return isValidTime(startsAt) ? startsAt : '';
}
```

`slotLines()` 的 `flatMap` 要多帶一個 `endsAt: s?.endsAt ?? ''`，
`.sort()` 那一段一個字都不動（照 `date` 再照 `startsAt`，沒有時間的排那一天最後）。

改完之後：

```
王小姐您好，9 月為您安排了：
9/3(四) 14:00–15:00 復能
9/17(四) 10:00–11:00 營養點滴
9/17(四) 11:15–12:15 復能
請問可以嗎？
```

## 那個橫槓用哪一個字

**建議用 `–`（en dash, U+2013），不是她打的那個 `-`。**
理由是這個 app 裡「一段時間」已經有一種寫法，而且都在她看得到的地方：

| 哪裡 | 現在印的 |
|---|---|
| `domain/visitTime.js` 的 `timeLabel()` | `14:00–15:00` |
| 「臨時空出一格」那一則訊息的 `{range}`（`offerSlotMessage`） | `9/18(五) 14:00–15:00 臨時空出…` |
| 日曆抽屜每一列左邊那一欄、來訪編輯器、試算表 | 同上 |

**「臨時空出一格」那一則已經是貼給客戶的訊息了**，兩則用不同的橫槓會是她自己
看得出來的不一致。要用半形 `-` 也可以，但那時候 `offerSlotMessage` 要一起改，
而那是一個沒有人要求的改動。→ **這一顆要她點頭**（見底下）。

## 一併修掉一句過期的註解

`domain/messageTemplates.js` 第 15 行還寫著：

> `{slots}` 要先排序、每一筆只取第一個時段的開始時間（她問客戶的是「那天幾點
> 來」，不是把三個療程的時刻表念一遍）

那句話 2026-09-04 就被推翻了（`slotLines()` 的檔頭寫著推翻的理由），只是那一支
的檔頭沒跟著改。這一輪之後它會**錯兩次**（既不是「只取第一個時段」，也不是
「只有開始時間」），順手改掉。

## 不動的

- **`reminderMessage()` 的 `{time}` 不改。** 那一則問的是「幾點到」，
  她只在前一天發它，`earliestStart()` 給的就是那個答案。改了會變成
  「提醒您明天 9/3 14:00–15:00 有復能的課程」，那句話在講一件她沒有要講的事。
- **模板的字不改。** `{slots}` 的內容是變數，算變數留在 `messages.js`
  （`messageTemplates.js` 的檔頭寫死了這一刀切在哪）。她在設定頁改過的模板
  自動吃到新的內容，一則都不用重存。
- **`docs/操作手冊.md` 第 532–535 行的例子要跟著改**（見 `04`）。

## 這會不會弄壞既有的測試

不會，而**那正好是要注意的地方**：`tests/messages.test.js` 與 `tests/tasks.test.js`
裡 `confirmMessage()` 的每一個例子，slot 都只給 `startsAt` 沒給 `endsAt`
（`{ startsAt: '14:00', courseName: '復能' }`）—— 它們照樣會綠，但**真的資料
兩頭都有**（`domain/visits.js` 第 599 行擋著：不是匯入的來訪，`startsAt` 與
`endsAt` 兩個都要是合法時間）。所以測試綠不代表這一支做完了，要另外補
帶 `endsAt` 的例子（見 `04`）。

## 驗證

**手動**（兩個入口）：
1. 待辦中心 →「跟客人確認時間」→ 一位有壓好時段的客戶 → 展開 LINE 訊息
   → 每一行都是 `9/3(四) 14:00–15:00 復能`
2. 客戶詳情 →「LINE 訊息」→「問壓好的時間可不可以」→ 同上
3. 設定 → LINE 回覆模板 → 把 `confirm` 那一則改成 `{name}：{slots}` → 存 →
   回到 1，仍然是完整的時間區間（模板不管內容）
4. 一筆匯入的舊來訪（沒有時間）→ 那一行是 `9/3(四) 復能`，
   **沒有「時間不詳」四個字，也沒有多出來的空格或半截橫槓**

**自動**：`tests/tasks.test.js` 的 describe「LINE 確認訊息」（見 `04`）。
