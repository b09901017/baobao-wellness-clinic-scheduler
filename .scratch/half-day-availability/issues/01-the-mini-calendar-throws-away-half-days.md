# 壓表的小日曆把半天丟掉了

Status: done
來源：使用者，2026-08-23
動工前先讀：`SPEC.md` 第 4.3、8.2、8.9 節、`CONTEXT.md` 的「本輪可用性」、
`docs/adr/0002`、`0035`、`0036`

## 原話

> 「我發現壓表客戶卡片牆的小日曆挑日子是不是沒有檔上下午？我希望呈現的方式一樣可以
> 像我給客戶填的不行的表單，在點選的日曆上，上半部或下半部紅色 劃掉之類的」

## 這不是缺功能，是資料在最後一哩掉了

半天**整條路都已經做好了**，只有畫面沒有讀它：

| 那一段 | 現況 |
|---|---|
| 客戶在表單上點「只有上午不行」 | `public/js/form/page.js` 的三選一，已經有 |
| 存成規則 | `domain/availabilityForm.js` 的 `picksToRules()` 帶 `partOfDay` |
| 她自己打字「禮拜一下午不行」 | `domain/availability.js` 的 `partOfDayOf()` 解析得出來 |
| 算某一天的狀態 | `dayStatus()` 回 `{ available, blockedPart: 'am'\|'pm'\|null, reasons }` |
| **壓表的小日曆畫它** | **`schedule.js` 的 `miniCal()` 只讀 `.available`，`blockedPart` 沒有人接** |

所以「他說 9/15 下午不行」這件事，客戶打了字、系統讀懂了、存下來了，
然後在她唯一要用到它的那一格上**長得跟一天都沒事的日子一模一樣** ——
連 `title` 都沒有，因為那一行只在 `kind` 有值的時候才寫。

`availableDates()` 把只擋半天的日子算成可用是**對的**（那天真的排得進去），
所以這不是要把它變成不能點，是要讓它看得出來「這天只剩一半」。

## 要做什麼

### 1. `miniCal()` 接住 `blockedPart`

`public/js/ui/views/schedule.js`：

- `kind` 那一串維持原樣（`past` › `ban` › `away` 的優先序不動）。
- 多一個**不互斥**的標記：`status.blockedPart` 有值時加上
  `minical__cell--half` 與 `minical__cell--half-am` / `--half-pm`。
- **格子照樣點得下去**，`disabled` 不加 —— 那天排得進去，只是要挑另外半天。
- `title` 改成一律寫得出理由：現在只有點不下去的日子有 `title`，
  半天的那幾天要寫 `status.reasons`（例：`9/15 下午不行`）。
- 格子裡多一個小字標籤（`上午` / `下午`），跟客戶表單上那一格寫的字一樣。
  **不可以只靠顏色** —— 她在窗邊反光的地方看這一格（見 `--ban` 那段註解的理由）。

### 2. CSS 照抄客戶表單那一招

`public/css/app.css` 的 `.minical__cell` 那一區。客戶表單（`public/css/form.css`）
已經解過這題，用同一個做法，不要另外發明一種：

```css
.cell--am { background: linear-gradient(to bottom, var(--overdue-bg) 52%, var(--surface) 52%); }
.cell--pm { background: linear-gradient(to bottom, var(--surface) 48%, var(--overdue-bg) 48%); }
```

小日曆的格子比表單小（38px vs 56px），所以：

- 半邊塗色 + **只在那半邊劃線**（`--ban` 是整格劃掉，半天不可以整格劃 ——
  整格劃掉的意思是整天不行）。用 `::before` 疊一條線在被擋的那一半上。
- 兩處的 52% / 48% 是為了讓中線壓在數字上看起來不歪，抄過來的時候一起抄，
  不要改成 50%。

### 3. 選中那一天之後也要講

點下去展開的 `dayPanel()`：那一天只擋半天時，抬頭那一列要有一句
「他說這天下午不行」。她點進去是要挑時間的，而**時間丸子就在下面** ——
在挑時間的那一刻不講，等於沒講。

`timeChoices()` 產生的時間丸子，落在被擋的那半天的**標一個記號**（淡掉 + 一個小點），
但 **不 disable**：ADR-0002，app 記錄決定不做決定，而原文永遠比解析結果大
（SPEC 第 4.3 節）—— 解析錯的時候她要有辦法照樣排下去。

### 4. 圖例

`minical__legend` 現在四格（可以排／已經記了／他不行／你休假），加第五格「半天不行」。

## 不做

- **不動 `availableDates()` 與排序。** 半天算可用是對的，改了會讓「可用 N 天」
  變成另一種意思，而那個數字是排序的第一權重（SPEC 第 9 節）。
- **不擋。** 唯一的硬性阻擋是醫療禁忌（SPEC 第 4.7 節）。
- **不動客戶表單那一頁。** 它已經對了。

## 驗證

- `tests/availability.test.js`：`dayStatus()` 的 `blockedPart` 已經有測試，確認還在。
- 新增：只擋半天的日子，`availableDates()` 仍然含它（守住「不做」的第一條）。
- 瀏覽器：壓表 → 找一位有半天限制的客戶 → 那一格看得出上半／下半被劃掉、
  點得下去、點下去之後面板上有那一句話。

## Comments

**2026-08-23 —— done。**

`partOfTime()` 與 `partLabel()` 放進 `domain/availability.js`：
「10:30 算不算上午」是規則不是排版。順手併掉一份重複 ——
`schedule.js` 本來自己有一支 `partLabel()`，吃的是規則物件而不是 `'am'`/`'pm'`。

**在瀏覽器裡畫出來才發現第一版是錯的**，三件事截圖之前全都「看起來會動」：

- 劃掉的線壓在數字上，跟 `--ban`（整天不行，劃掉數字）長得一樣。
  半天與整天在畫面上分不出來，等於這一支白做
- 「上午」兩個字印在下半格 —— flex 把數字、字、點三個當成一組置中，
  那個字就落在中線附近，剛好是最看不出它屬於哪半邊的位置。**那個字在講反話**
- 選中一顆落在被擋半天的時間丸子時，`.chip[aria-pressed='true']` 已經把字
  改成白的了，而我只覆蓋了 background —— 白字配淡粉底完全看不見

定案的畫法：被擋的那半邊塗色、那兩個字放進那半邊並且劃掉它們，
**數字擠進還可以排的那半邊** —— 數字站的位置本身就講得出他還有空的是哪半天，
不必先讀那兩個字。選中的紅丸改成實心（淺色白字 6.44:1、深色深字 6.35:1）。
