# 改一筆來訪 = 只改那一段

Status: done
來源：使用者，2026-09-08（需求三 e）＋ 2026-09-09 再次確認
動工前先讀：`docs/adr/0080`、`0056`

## 她要的

> 如果我要修改某一筆來訪，就請讓我只能修改這一個時段的東西
> 而不是讓我還可以新增還可以修其他時段的東西

## 好消息：每一條路都已經知道是哪一段了

清查過**所有**進得了編輯器的路：

| 入口 | 帶得到 slotIndex？ |
|---|---|
| 日／週那一列點一下 → 讀取卡片 → 鉛筆 | ✅ `visit:<id>:<第幾段>`（ADR-0080） |
| 抽屜那一列點一下 → 讀取卡片 → 鉛筆 | ✅ 同上 |
| 長按 → 「改這一筆」 | ✅ `runVisitAction()` 收得到 |
| 月檢視的色條 | 不可點（點的是那一天，開抽屜） |
| 客戶詳情／待辦中心／進度追蹤 | **沒有鉛筆**（ADR-0056） |

**只是進去之後把那個數字丟掉了**：`openEditor()`（`calendar.js:1562`）
與 `mountEdit()` 都沒有傳 `slotIndex`。

## 決定

**一、`mountEdit()` 收一個選填的 `slotIndex`。**

有帶 → 只畫那一段、沒有「＋新增一個時段」、沒有那一段以外的東西。
沒帶 → 照舊全部（**留這條退路**：`renderEdit()` 那條網址路由沒有段落資訊，
畫成空的比畫太多糟，同 `slotsToShow()` 的兩條退路）。

**二、哪幾段畫得出來走既有的 `slotsToShow()`，不要新寫一支。**
那一支的兩條退路（沒指定就全部、指到不存在也全部）本來就是對的。

**三、`readDraft()` 只能改那一段，別段原封不動帶回去。**
這是最危險的一點：現在 `readDraft()` 是 `draft.slots.map(...)`，
表單上沒有的欄位讀回來是 `undefined`，靠 `key()` 保留原值。
**只畫一段時其餘每一段都要走「原封不動」那條路，不是走 `key()`** ——
少一個欄位就是靜默清掉一段別人的資料。

**四、新增那條路不受影響。** 日曆的「＋新增一個時段」留著、壓表記完一段
接著記下一段也留著（她 2026-09-09：「新增的時候…我希望一樣可以一次新增多筆多個時段」）。

**五、那顆 × 在只畫一段時不出現。** 它現在的規矩是「只有一段時不給」
（`slotXButton()`），而只畫一段時她看到的就是一段 —— 取消走底下的狀態卡，
那裡問得比較清楚。

## 測試

- `mountEdit({ slotIndex: 1 })`：畫面上只有第 2 段、沒有 `data-add-slot`
- 存檔之後第 1、3 段**逐欄位**跟存檔前一模一樣（deepEqual，不是抽查）
- `mountEdit()` 不帶 slotIndex → 照舊全部
- `slotIndex` 指到不存在的段落 → 退回全部
- E2E：日／週點第二列 → 鉛筆 → 只有那一段 → 改時間 → 另外兩段沒動
