# 一人一天一筆：日曆新增也要併進同一天

Status: todo
來源：使用者，2026-09-08（需求二 a/b/c/d）＋ 2026-09-09 的共識（Option B）
動工前先讀：`docs/adr/0081`、`SPEC.md` 第 4.4 節、`domain/visits.js` 的 `withExtraSlot()`

## 她要的

> 為什麼同一個人可以來訪一次裡面有兩項 然後又可以同一天再來訪一次然後一項？
> 不是應該是這個人 今天有三個時段嗎？

## 根因：「一天一筆」現在是假的

`firestore.rules` 沒擋，`validateVisit()` 也沒擋（ADR-0081 已經寫過）。
真正發生的是**兩條路行為不一樣**：

| 入口 | 行為 |
|---|---|
| 壓表 | `sameDayVisit()` 找同一天**收得下**的那一筆併進去（`schedule.js:1698`） |
| 日曆新增 | `blankVisit()`（`visitEditor.js:130`）**完全不查**，一律開新的一筆 |

所以她從日曆排的每一段都變成獨立的一筆，而從壓表排的會併起來。
**同一件事有兩種樣子，而規則她看不出來** —— 這就是她說的「不合理」。

## 決定

**一、`mountNew()` 進來時先找同一天收得下的那一筆，找到就接著編輯它。**

不是「存檔時才合併」—— 那樣她在表單上看到的是一段、存完變五段，
中間發生了什麼畫面上沒講。進來就接著編輯那一筆，她看到的就是真相。

**二、判斷只有一支，寫在 domain。**

`domain/visits.js` 多一支 `sameDayVisitFor(visits, customerId, date)`：

```
撈 date 相同、沒刪掉、isActive()、acceptsMoreSlots() 的第一筆
```

壓表的 `sameDayVisit()` 改成呼叫它 —— 兩份判斷遲早有一份會漏掉一個狀態。

**三、收不下的時候（那一天已經結案／已取消）照樣開新的一筆，但要講一句。**

「9/15 那一天已經結案了，這是新的一筆。」**只有這一種情況會出現第二筆**，
而那是對的：已完成的那一天不該被再加一段進去（`acceptsMoreSlots()` 的檔頭寫過）。

**四、既有的重複資料由資料健檢列出來，不自動合併。**

`domain/health.js` 多一列「同一位客戶同一天有兩筆來訪」，一鍵合併。
跟「不能的時間」那一條同一個做法（ADR-0053）：自動合併會把她刻意分開的那幾筆
黏起來，而那一下沒有人按過。

## 為什麼不是別的做法

**改 `firestore.rules` 擋第二筆。** Rules 查不到「同一天有沒有別的來訪」
（沒有 query），而且擋下來的症狀是一句看不懂的權限錯誤。

**存檔時合併。** 見上：畫面講的跟發生的不是同一件事。

## 後果

- 日曆上「這一天要幫誰排」選完人之後，如果那天已經有一筆，她會直接看到既有那幾段
  —— 而 issue 07（只改那一段）**只管「改」那條路，新增這條路照樣看得到全部**。
  兩件事不要混：新增時她要知道那天已經排了什麼。
- `sameDayVisits`（衝突檢查用的）不受影響，那一支問的是**別人**的來訪。

## 測試

- `sameDayVisitFor()`：待確認／已確認的找得到；已完成／未到／已取消／已刪除的找不到
- 同一位客戶同一天兩筆都收得下時，回的是第一筆（穩定）
- 日曆新增 → 那天已有一筆 → 進去看到的是既有那幾段 + 一段新的
- 日曆新增 → 那天那一筆已完成 → 開新的一筆，而且畫面上講了那一句
- 資料健檢那一列列得出既有的重複，且**不自動改**
- E2E：從日曆同一天排兩次，日曆上是一位客戶、五段，不是兩塊
