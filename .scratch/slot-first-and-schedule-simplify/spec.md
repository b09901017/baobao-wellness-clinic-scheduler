# 時段優先：壓表精簡、來訪退化成那一天、日曆表單修 bug

來源：使用者，2026-09-08 ～ 09-09 的三輪對話
基底分支：`develop`
動工前先讀：`docs/adr/0081`（時段帶狀態）、`0080`（讀取卡片只畫那一段）、
`0079`（器材決定要指派誰）、`0001`（佇列是推導的）、`SPEC.md` 第 4.4 / 5.2 / 5.3 節

---

## 一句話

**她要的是「這個人那天有哪些時段」，而每一段自己有狀態、自己有一句話、
改的時候只改那一段。** 這一輪不動資料庫的形狀，把「來訪」從她眼前拿掉。

---

## 她問的三個架構問題，與定案

### 「為什麼要有來訪這一層？我當時是怎麼想的？」

翻到源頭了：`SPEC.md` 是 2026-08-17 的 commit `9cc6b2d` 一次寫成的，
第 4.4 節當時只有一句「UI 是幫某人某天建立一次來訪，裡面加多個時段…
**不要做成一格一格分開建立預約**」。

**她當初講的是建立的動線**，不是資料模型。這件事 ADR-0081 已經承認過。

後來另外長出四個理由，逐一驗過今天還成不成立：

| 理由 | 今天 |
|---|---|
| 單次原子寫入（SPEC 5.2） | **不成立**。`data/repo.js` 的 `commit()` 用 `writeBatch`，本來就跨文件原子 |
| 掛號待辦一天一張（她一天去 Examine 一次） | 成立 |
| 確認動線是客人一次回一整天 | 成立 |
| 療程單一天簽一張、LINE 一次講第一段 | 成立 |

### 「扁平化（每段一筆）會怎樣？」

清查過：`visitId` / `visit.slots` 相依 **35 支原始碼 + 15 支測試 + 4 個非 JS
的地方**（`firestore.rules`、`firestore.indexes.json`、`sheets/readonly-report.gs`、
`scripts/restore-backup.mjs`）。

**結論：容器不會消失，只會從資料庫搬到八個地方的 `groupBy(customerId, date)`。**
掛號、確認、療程單、LINE、試算表那一欄本來就是「一天一次」的事實。
代價是全部正式資料的遷移 + 稽核紀錄斷鏈（`audit.targetPath` 指 `visits/{id}`，
那是歷史，遷不了）+ 試算表要跳 `SYNC_FORMAT` 並請她回 Google 重貼。

**她選了 Option B。**

### Option B：一人一天一筆，詞從畫面上消失

- 資料維持 `visits` 內嵌 `slots`
- **「一人一天一筆」變成程式擋得住的規則**（今天是假的，見 issue 04）
- 畫面上一律講日期與時段，不出現「來訪」
- 狀態、次數、記一句、修改範圍全部逐段

**這條路把之後真要扁平化的門留著**：有了「一人一天一筆」的不變量，
遷移會變成機械式的一對多展開。

## 她明確答過的邊界（不要再問一次）

- **掛號待辦是一天一張**，會同時出現在那幾段的詳情裡 → 標一句「這一天共用」。**她說可以。**
- **「取消一整天（N 段）」那個數字留著**當煞車。**她說可以。**
- 留下三句「不講會出錯」的話：擇一池的「先選上面那一台」、「主檔裡還沒有醫師…」、
  確認框裡的後果句。**她說留著。**
- 舊資料那一句話走 **A 方案**：下次存那一筆時搬到第一段。
- 待辦中心那一列「問過了、客人還沒回」（`visit.followupNote`）**維持一天一句，不動**。
  但入口也要收成 icon（同 issue 05 的元件）。
- **試算表這一輪不動，`SYNC_FORMAT` 不跳版** —— 她還在想同一天多句要怎麼標，
  之後單獨開一輪。她不用回 Google 重貼。

## 不做

- 完整扁平化（每段一筆文件）。理由見上。
- 動 `SYNC_FORMAT` 或 `sheets/readonly-report.gs`。
- 改 `firestore.indexes.json`（這一輪沒有新的排序查詢）。
- 動 `visit.followupNote` 的資料形狀。
