## 為什麼會這樣

她現在是看著紙本打進新增客戶那一頁。「怎麼讀一次購買」這件事 repo 裡**已經寫過一次**，
只是給舊試算表用的（`legacyImport.js`，skill 那一側在跑）：

- `rowShape()`：`任選(30)`、`SIS(60min)`、`ILIB 30` → 擇一池或單一課程＋時長
- `parsePurchaseCell()`：`0617 顧客會-8+5` → 日期、通路、方案套數、健檢金額
- `flagsFromText()`／`partnersFromText()`：備註裡的字 → 警示、合作機構
- 有「尾款」兩個字的備註預設紅色（`:1314`）

訂購單是**同一件事的另一種寫法**，所以翻譯要重用這幾支，不是另寫一套。
而寫入一定要走 `createWithPlan()`／`addEntitlements()` —— 少走 `expandPlan()` 的話抬頭上的套數會掉（ADR-0090），
健檢不在同一個 commit 的話配不到二返（ADR-0022）。

### 翻譯（`domain/orderForm.js`，純函式）

- `customerName` → 姓名；**跟既有客戶同名**時兩顆（「加購到 客戶A」「新增一位」）**都不預選**，她點一顆才存得下去
- `formMonth` ＋ `handwrittenDates` → 購買日（手寫日期在表頭月份前後一個月內才採用，不然空著）
- 購買通路 → 「顧客會」＋日期，形狀照 `purchaseHeadline()` 要的（ADR-0090 動工時讀）
- `packages[].printedName`（「8萬筋骨強身」）→ 方案範本比對名稱（去掉價格字頭）；對不上 → 空著讓她選，附一句「沒有這個方案？拍文宣建一個」（07）
- `quantity` → 套數
- `checkupTicked` → 健檢加購，金額等級帶在額度上（ADR-0054）
- `handwrittenRows` → `rowShape()`／課程名稱 → `buy.js` 的一項；`EECP 40堂` → EECP ×40；認不出 → 留原字那一列讓她選或拿掉
- `unpaid`：`0` 或空 → 什麼都不做；其餘 → 一則**紅色**備註「尾款 ＋原字」
- `obNote`、`stickyNotes` → 灰色備註照原文（保留原始文字優先，SPEC 第 14 節）；
  同時走 `flagsFromText()`／`partnersFromText()`：對上的警示、合作機構**預先按下**，她看得到、點得掉；
  `contraindicationHints()` 有東西 → 卡片最上面一張紅卡（ADR-0047 搬過去的那個安全網）
- **各項金額與總計不記**（她 9/17）
- 電話不抄（spec「暫定」），所以新客戶會帶電話欄的 ⚠

## 判準

- 模擬器用「筋骨強身 ×1 ＋ 手寫 `任選(30)` ×10、尚欠尾款 0」的假抄字走一次：
  建出一位客戶，額度是筋骨強身展開的七筆 ＋ 一筆 `復能-任選(30)` ×10；**沒有尾款備註**；抬頭是 `MMDD 顧客會 筋骨強身+…`

- 便利貼寫「自然美」→ 合作機構那顆預先按下；寫「體內金屬」→ 警示按下＋最上面紅卡
