# 「今天做了什麼」不是流水帳：加一道份量閘門

Status: done
來源：使用者，2026-09-04（spec.md 的第二）
動工前先讀：`docs/adr/0062`、`SPEC.md` 第 8.1 節的「看今天做了什麼」

## 原話

> 有關看今天做了什麼，客戶與額度那個類別其實沒什麼必要（在今天做了什麼這邊
> 沒必要，但是一樣可以留在稽核那邊），像是對帳過了、已排未上 0->1 這種都沒必要，
> 這類別只需要留「新增客戶、新增額度」這兩個就好。
> 還有像是其他：新增備忘錄、修改備忘錄，其實也不需要。
> 這邊需要呈現的就只要重要的那些就好，**不是流水帳**。

## 她說對了什麼

那一頁的問題不是「翻譯得不好」，是**它把兩種東西畫成一樣大**：

- 她**做的事**：壓了誰的表、跟誰確認了、勾掉了哪幾張掛號。
- 系統**跟著寫的東西**：來訪一存檔額度的 `bookedCount` 就 0→1、對帳跑過就
  留一則、備忘錄改一個字也留一則。

第二種**每一則都是真的**，所以它從來不會被當成 bug；它只是把第一種淹掉。
她一天壓十筆表，那十筆會拖出十則額度計數的變化 —— 畫面上就是二十列，
而其中十列是同一件事的副作用。

## ADR-0062 的那條規矩要改，但只改一半

ADR-0062 寫著：

> 最後一段是「其他」，而且它 `match` 永遠是 true。**一則都不可以被丟掉** ——
> 她開這一頁是為了確認沒有漏掉東西，而一個安靜消失的項目正好是最該被看到的
> 那一種。

**理由沒有錯，結論要換一個。** 那條規矩真正在防的是「安靜地」三個字，
不是「不可以不列」。所以新的規矩是：

> **一則都不可以安靜地消失。** 濾掉的不列出來，但要**數出來**，
> 而且**點得開**。

`total` 仍然等於進去的筆數，畫面上永遠算得回去。要補一支 ADR（見 issue 05）。

## 閘門長什麼樣

**寫在 `domain/dayReview.js`，不寫進 `domain/audit.js`。** 稽核那一頁一個字都不
改（她指名「一樣可以留在稽核那邊」），而 `domain/audit.js` 是兩頁共用的翻譯層。
份量是「這一頁要不要印」的判斷，它屬於這一支。

閘門**掛在段上**，不是一張獨立的規則表 —— 段已經是「這是流程的哪一步」的
分類，再開第二套分類法等於同一件事有兩個答案（同 ADR-0028 的理由）。

| 段 | 留什麼 | 為什麼 |
|---|---|---|
| ① 問到時間 | 全部 | 發連結、收下他填的、自己記一筆，三種都是她做的 |
| ② 壓表 | 全部 | |
| ③ 跟客人確認 | 全部 | |
| ④ 登記掛號 | 全部 | 她指名要，而且要講得更清楚（issue 03） |
| ⑤ 簽療程單 | 全部 | |
| ⑥ 寫紀錄 | 全部 | |
| ⑦ 取消與改期 | 全部 | 取消與改期是她做的，而且最該被看到 |
| ⑧ 日曆與待辦 | 全部 | 「勾掉了什麼隨手記」她指名要 |
| ⑨ 客戶與額度 | **只留五種**（見下） | |
| ⑩ 設定 | **一則都不留** | 見下 |
| ⑪ 其他 | **一則都不留** | 備忘錄、壓表批次的游標、拿回來一張待辦 |

### ⑨ 客戶與額度（2026-09-04 她決定的）

留這五種，其餘全部濾掉：

| 留 | 為什麼 |
|---|---|
| 新增客戶 | 她點名的 |
| 新增額度（含營養品） | 她點名的 |
| **刪掉客戶／刪掉額度** | 刪掉一份額度是這個系統裡最貴的動作之一，而它跟「新增」是同一個手勢的反面。一天零到一則 |
| **給了哪幾款營養品**（額度的 `deliveries`） | 那是一筆**要進試算表的紀錄**（ADR-0059、CLAUDE.md 的連動表），而這一頁的用途正是「確認有沒有漏掉登記」。濾掉它等於濾掉這一頁最該抓的一種漏 |
| **改客戶的永久限制／特殊狀況**（`flags`、`notes`） | 那兩欄會改變她之後每一次壓表能不能用哪一台器材（ADR-0064）。改了一次，往後每一場都跟著變 |

**濾掉的**：`bookedCount` / `doneCount` / `totalQty` 的變化（那是來訪的副作用，
來訪本人就在上面幾列）、「對帳過了」、改電話／LINE／購買通路／喜好程度／
會籍到期日、改額度的到期日與頻率限制。

判斷寫成**欄位的白名單**（`flags`、`notes`），不是黑名單 —— 之後客戶身上多一個
欄位時，黑名單會讓它預設冒出來，而白名單會讓它預設安靜。這一頁的預設應該是安靜。

### ⑩ 設定 —— 一則都不留（2026-09-04 她決定的）

新增一個課程、改一台器材的規則、改方案範本，全部收進「另外 N 則」。
**那一段仍然留在 `STAGES` 裡**（`keep: () => false`）—— 那一則還是有它的段，
只是這一頁不印。段落表要是完整的，不然下一個人會以為設定沒有被歸類過。

### ⑪ 其他 —— 一則都不留

現在落在這裡的有三種，三種都符合她說的「不需要」：

- **備忘錄**（`playbooks`）—— 她指名的「新增備忘錄、修改備忘錄」。
- **壓表批次**（`batches` 的 `cursor`）—— 純機器的東西。
- **拿回來一張待辦**（`done: true → false`）—— 這一則的意思是「我剛剛按錯了」。
  它跟著「其他」一起走。**如果她想看到「我剛剛拿回來什麼」，那要另外開一段**，
  不是留在其他 —— 這一輪先不做。

濾掉之後 `STAGES` 的最後一段 `other` 的 `match` **照樣永遠是 true**：
它還是那個收得下任何東西的段，只是這一頁不印它。認不得的東西仍然有家可歸，
而且會被數進「另外 N 則」。

## 要做什麼

### 1. `domain/dayReview.js`

`STAGES` 每一段多一支 `keep(event, fields)`（沒寫就是整段都留）。
`reviewOf()` 跑完歸類之後分兩堆：

```js
{
  groups, people, tiles,   // 只有留下來的
  total,                   // 進去的筆數，不變
  hidden: 12,              // 濾掉幾則
  hiddenRows: [...],       // 濾掉的那幾則（收合過、新的在前），給「攤開」用
  truncated,
}
```

三條不變量，測試各盯一條：

- `shown + hidden === total`（兩種分組都成立）
- **一個人身上的事全部被濾掉時，那個人整組不出現** —— 空的抬頭比多一列糟
- **`tiles` 數的是留下來的**：畫面上寫 6 筆就要數得出 6 列

### 2. `ui/views/home.js`

清單底下一行（`review.hidden > 0` 才畫）：

```
另外 12 則沒列出來 —— 改欄位、對帳這種            攤開
```

（2026-09-04 她選的：**底下一行、點得開**。）

- 點「攤開」就地展開那幾列，畫得比一般的列**再淡一級**，
  不重畫整塊、不重讀資料（那幾則已經在手上了）。
- 展開的狀態跟 `reviewBy` 一樣**存在模組裡**（換一天要收回去，換看法不要）。
- **不要叫它「其他」** —— 那三個字是流程分段的最後一段的名字，
  同一塊畫面上兩個「其他」會被當成同一件事（`NOBODY` 那一條同樣的理由）。
- 最底下那一句「這裡是稽核紀錄的白話版 —— 要看某一筆到底改了哪個欄位，
  去稽核紀錄」照舊，它就是這一支的退路。

### 3. 過場

展開／收合走 `grid-template-rows: 0fr → 1fr`，0.18s，
`@media (prefers-reduced-motion: reduce)` 關掉。細節在 issue 04。

## 一起要檢查的

- **`#/settings/audit` 與客戶詳情的「變更紀錄」一個字都不改。**
  閘門只在 `domain/dayReview.js`，兩頁走的是 `describeEvent()`。
- `reviewOf()` 的 `limit` 與 `truncated` 算的仍然是**撈回來的筆數**，
  不是留下來的 —— 那一句講的是「這一天太多了，稽核只撈得到 300 則」。
- `tests/day-review.test.js` 裡「一則都不可以被丟掉」那一整組要改寫成
  「一則都不可以安靜地消失」（`shown + hidden === total`），
  **不是刪掉**（見 issue 05）。
