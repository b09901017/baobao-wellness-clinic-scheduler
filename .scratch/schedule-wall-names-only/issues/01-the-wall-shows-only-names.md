# 卡片牆先只給名字，其餘等點進去才攤開

Status: 待動工
來源：使用者，2026-08-23
動工前先讀：`SPEC.md` 第 4.3、8.2 節、`CONTEXT.md` 的「永久限制」「醫療禁忌」、
`docs/adr/0002`、`0017`、`0035`、`0037`

## 原話

> 「有關壓表那邊的客戶名稱呈現，就是在進入客戶卡片牆之前不是會有很多客戶，
> 然後每個客戶都會呈現很多資訊嗎，我覺得就不用呈現那麼多資訊了，就只需要寫名字，
> 然後我點名字後才會進入客戶卡片牆看到那些資訊。
> 然後搜尋以及排序那些不用動⋯⋯
> 對了！**體內有金屬這是很重要的資訊，希望他的標籤小丸可以更明顯，是紅色的，
> 寫體內金屬 或是 Only INDIBA**」

問過、定案的：**「還沒壓／已壓好／壓了 N 天」那一顆狀態徽章留著。**

## 現況

`views/schedule.js` 的 `custCard()` 一張卡上有七塊：姓名 ＋ 星星 ＋ 永久限制、
最強的排序理由、狀態徽章、**不能的時間（整塊，最大的一塊）**、
剩餘次數泡泡（最多六顆）、這個月／上個月／距上次、備註（最多三則）。

二十幾位排下來，一頁看得到兩三張。她要找的那一位在第三次捲動的地方。

**這件事推翻 SPEC 第 8.2 節現在寫的一句話**：

> 卡片上最大的一塊是「不能的時間」—— 那是她在公司系統上挑格子時唯一需要
> 一直對照的東西。

那句話是對的，只是它講的是**記錄面板**那一層，不是卡片牆那一層。她真的用起來
之後才顯出來：**在卡片牆上她做的唯一決定是「下一個處理誰」**，而那個決定
只需要名字（照著預設順序或搜尋跳過去）。「不能的時間」是她**點進去之後**
一直要對照的東西 —— 而記錄面板上本來就有一份（`banBlock(row, { raw: true })`）。

## 要做什麼

### 卡片牆上一張卡只剩三樣

```
┌──────────────────────────────────────────┐
│ 王小明  [體內金屬] [只能 INDIBA]   還沒壓 │
└──────────────────────────────────────────┘
```

1. **姓名**（維持現在的字級，那是她在掃的東西）
2. **醫療禁忌的紅丸**（見下）
3. **狀態徽章**（`還沒壓` / `已壓好` / `壓了 N 天` / `跳過`）

拿掉：星星、排序理由標籤、不能的時間整塊、剩餘次數泡泡、
這個月／上個月／距上次、備註。**那七塊在記錄面板上一塊都不會少。**

一張卡從六七行變成一行，一頁看得到十幾位 —— 二十幾人的名單一眼掃得完。

### 醫療禁忌的紅丸

現在 `row.flags` 是客戶的**全部**永久限制，一律用同一顆灰色 `.flag` 印出來
（「固定禮拜五不行」跟「體內金屬」長得一模一樣）。要分成兩種：

- **會擋掉器材的那幾個**（`contraindications.contraindicationTerms(equipment)`
  裡有的字）→ **紅丸**，字就是那個限制本身（`體內金屬`）。
  `loadAll()` 已經把器材主檔讀進來了，不用多讀。
- **剩下的那幾個** → 卡片牆上**不畫**。它們不擋任何東西，
  而這一支的整個重點是把牆收乾淨。記錄面板上照舊全部都有。

紅丸旁邊再補一顆**「只能 INDIBA」**：由 `annotateOptions()` 算出這位客戶的
擇一池還剩哪幾台，只剩一台時就寫「只能 ⟨那一台⟩」，剩兩台寫「不能用 ⟨那幾台⟩」，
全被擋住時寫「三台都不能用」並用最重的樣式 —— 那種情況壓不下去，
她要在點進去之前就知道。

**這一顆是算出來的，不是打字打的。** 器材主檔上的禁忌一改，它跟著改。
`domain/contraindications.js` 加一支純函式：

```js
/** 這位客戶的擇一池還剩哪幾台、要怎麼講。給卡片牆上那顆丸子用。 */
export function equipmentLimitLabel(customer, equipmentOptions)
```

### 顏色

紅丸走 `--overdue` 那一系（`tokens.css` 已經有），**不新增顏色**。
它是這一頁上唯一的紅色 —— 那正是重點：這一頁紅色只有一個意思，
「這個人有東西被硬性擋住」。

小日曆上「他說不行」也是紅色，但那在記錄面板裡，跟卡片牆不同頁，不會打架。

## 不動的

- **搜尋、排序、篩選一個字都不動**（她講的）。`QUEUE_SORTS`、`matchesSearch()`、
  三顆篩選丸照舊。
- 記錄面板（`recordPanel()`）一塊都不減。
- 旁邊那兩張半露的卡（`peekCardHtml()`）本來就只有姓名與剩餘次數泡泡 ——
  現在改成跟卡片牆一致：姓名 ＋ 紅丸。
- `buildCustomerQueue()` 回傳的欄位一個都不刪。牆上不畫不等於算出來的東西沒用 ——
  排序仍然吃它們，記錄面板也吃。

## 一起要檢查的

- `SPEC.md` 第 8.2 節「客戶卡片牆」那張表要重寫（那一段現在描述的是記錄面板）
- 補一支 ADR：**卡片牆只回答「下一個是誰」**（推翻 SPEC 第 8.2 節原本那句
  「卡片上最大的一塊是不能的時間」在卡片牆這一層的適用）
- `tests/scheduling.test.js`（新的純函式）
- `public/css/app.css` 的 `.queue-row`、`.flag`

## 不做

- **不隱藏醫療禁忌。** SPEC 第 4.3 節：「永久限制（尤其是醫療禁忌）在任何畫面
  都必須跟著客戶名字顯示，不可被摺疊隱藏。」這一支是把它變得**更**明顯，
  不是相反。
- 不做「展開這張卡看更多」。那等於把記錄面板做兩份 —— 點進去就有了，
  而點進去只要一下。
- 不改預設排序。
