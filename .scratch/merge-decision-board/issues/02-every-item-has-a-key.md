# 每一項有鑰匙：報告攤成一項一項，筆數一樣多

Status: todo
Blocked by: 01
來源：`../spec.md` 做法 1、2
動工前先讀：`merge.mjs` 的 `reconcile()`（`decisionLog`）、`reportText()` 每一段怎麼算的

## 她要的

> 必須一樣完整不能遺漏或簡化各種問題

> 之前我做過的決定就不要再問了

## 為什麼會這樣

報告是一大段文字，問卷是模型讀報告手挑的。沒有任何東西保證「報告上的每一筆都變成一題」，
也沒有任何東西認得「這一題上次答過了」—— 決定檔的每一條都沒有題號。

## 做法

新的 `scripts/board.mjs` 的 `boardItems(r, { today, decisions, plans })`：

| 報告那一段 | 變成 | 要她決定嗎 |
|---|---|---|
| ② 行事曆有、舊表沒勾 | 沒做（不匯）／有做（補一段） | 要 |
| ① 兩邊講的不是同一件事 | 舊表對／行事曆對 | 要 |
| ③ 舊表有、行事曆沒有 | 有 ⇄ 的要；沒有的是資訊（照舊表匯、時間不詳） | 看情況 |
| ④ 推測的時間（low） | 對／不對（時間不詳） | 要 |
| ④b 兩個人都可能 | 是誰 | 要 |
| ⑤ 未來的預約 | 建成來訪／不匯 | 要 |
| ⓪b 舊表本身的問題 | 年份、同一天兩欄、營養品不排班是資訊；其餘要 | 看情況 |
| ⓪c 購買名稱對不上 | 照應有次數（維持）／其他 | 要 |
| ⓪d 找不到對象的決定 | 照這一次讀到的／這一條不用了／其他 | 要 |
| app 主檔對不到（`planForCustomer()` 的 problems） | 我去設定加／其實是別的 | 要 |
| ⑥ 以後的雜事 | 匯／不匯、哪一類（預設照建議、看一眼就好） | 不用 |
| ⑥ 今天以前、兩週內的待辦 | 丟掉／留著 | 要 |
| ⑥ 其餘今天以前的 | 照她的規則丟掉（列出來） | 不用 |
| 決定檔裡保留中、但這一次沒產生的 | 用存下來的那一份題目再問 | 要 |

每一項：`key`（固定）、種類、日期、誰、一句話的題目、證據（行事曆原文、舊表那一格）、「這次先照什麼做」、
選項（每一個帶要寫進決定檔的那幾條 `ops`，或是 `free: true`）、急不急（會匯成已完成的是「上線前要定」）。

`reconcile()` 的 `decisionLog` 多記一份結構化的 `stale`（哪一位、哪一段、原本那一條長怎樣），
⓪d 的選項才寫得出「拿掉舊的那一條、換成這一次讀到的」。同一段同時有 ⓪d 與推測時間的，只出一項。

## 判準

- 報告每一段的筆數＝那一種的項數？（測試；少一筆就紅）
- 同樣的輸入跑兩次，鑰匙一模一樣？
- 決定檔 `answers` 裡答過（沒保留）的那一把鑰匙，這一次標成「已決定」、不算在要決定的數字裡？
- 保留的標成「保留中」、帶著她上次的答案？
- 保留中、但這一次報告已經沒有那一筆的（例：9/16 那 20 題），照樣出現？
