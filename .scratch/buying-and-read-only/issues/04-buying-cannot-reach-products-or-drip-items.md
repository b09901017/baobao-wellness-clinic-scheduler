# 加購買不到營養品，營養點滴也選不了品項

Status: done
來源：她的三件事，2026-08-25（`../spec.md`）
動工前先讀：`CONTEXT.md` 的「營養品」「營養點滴品項」「額度」、`docs/adr/0054`、
`docs/adr/0003`、`domain/legacyImport.js` 的營養點滴那一段

## 症狀

她的原話：

> 少了營養品可以加選
> 加健檢要能選幾萬的方案
> 加營養品也要能選那些多少
> 加營養針也要選那些(雪亮/護肝)多少
> 可以不要用下拉選單而是用小丸

客戶詳情 → 額度 → 加購。「買了什麼」那一排丸子列的是**課程主檔裡的每一個課程**
外加一顆「復能（三選一池）」。所以：

1. **營養品根本不在那一排上**（夜態美、速膳淨、粒能康、GABA）。
   它們是主檔 `products` 裡的東西，不是課程 —— 而課程才畫得出丸子。
2. **選了「營養點滴」之後沒有第二排。** 存下去就是一筆叫「營養點滴」的額度，
   而 `CONTEXT.md` 寫得很清楚：

   > **營養點滴品項**：營養點滴實際施打的內容，例：護肝排毒、雪顏亮彩。
   > **各自有各自的次數，不合併計算。**

   舊資料匯進來的時候是對的（`domain/legacyImport.js` 把 B 欄拆成
   `營養點滴 - 護肝排毒`、`營養點滴 - 雪顏亮彩` 各一筆），**只有她自己手動加購
   這條路做不到**。同一件事有兩份實作，而其中一份是錯的。
3. 健檢的金額等級是在的（ADR-0054），她提到它是因為新增客戶那一頁沒有加購
   （見 `05-new-customer-has-no-buying.md`）。

## 決定：營養品也是一筆額度，只是排不進來訪

`CONTEXT.md`：「營養品：賣給客戶的實體商品……只記錄與顯示，**不佔時段、不排班、
不產生任務**。」

存法有三種，選第三種（寫成 ADR-0056）：

| | 怎麼存 | 為什麼不 |
|---|---|---|
| A | 主檔多開幾個「課程」 | 那就排得進來訪了，正是 CONTEXT 說不可以的事 |
| B | 客戶身上一個 `products` 陣列（像 `marks`） | 稽核、軟刪除、已刪除項目還原全部要重做一份 |
| C | **額度多一個型態 `product`** | 選這個 |

C 換來的是：同一顆「加購」按鈕、同一張表、同一份稽核紀錄、同一個垃圾桶。
要付的代價只有一個 —— **它不可以流進任何「還要排幾次」的計算**，
所以加一道閘門：

```js
// domain/entitlements.js
export const isProduct = (e) => e?.type === 'product';
```

擋在**一個地方**：`domain/scheduling.js` 的 `customerPools()`。壓表卡片牆、
待辦中心的「壓表登記」「問這輪的時間」，三條路全部走它，所以擋一次就夠了。
另外兩支 `summarize()` 與 `lowRemaining()`（客戶總覽那一列的合計與「快用完」）
也要擋 —— 「王小明 剩 12 次」裡面混著兩罐夜態美是錯的。

**`domain/sheetReport.js` 刻意不擋**：她的舊試算表第 12 列就是營養品（ADR-0024：
試算表要照著她原本那一張），少掉那一列反而對不起來。

## 要做成什麼

### 一、把「買了什麼」那一張表抽成共用的元件

新增 `ui/components/buy.js`。現在住在 `ui/views/customerDetail.js` 裡的
`buyFields()`、`tierFields()`、`keptLabel()`、`readTier()`、`POOL_PICK`、
`TIER_OTHER` 全部搬過去，因為新增客戶那一頁要用同一張（issue 05）。

抽出來的介面（草稿是額度形狀，不是另一種形狀 —— 兩種形狀就要有人翻譯）：

```js
buy.fields(draft, master)          // 「買了什麼／哪一種／幾萬的／幾次」那幾排
buy.pick(value, draft, master)     // 點了「買了什麼」的某一顆 → 下一版草稿
buy.retitle(draft, master)         // 換了等級／品項 → 顯示名稱跟著換
buy.read(form, draft)              // 從表單讀回那幾個只有它管的欄位
buy.payload(draft)                 // → 一筆可以寫進 entitlements 的文件
```

`master` = `{ courses, equipment, ivProducts, products }`。

### 二、那一排丸子

```
買了什麼   [ 復健科醫師門診 ] … [ 健檢 ] [ 營養點滴 ] … [ 復能（三選一池）] [ 營養品 ]
```

「營養品」放最後一顆 —— 它不是課程，跟課程之間隔著那顆擇一池，
順序本身就在講「這一顆是別的東西」。

### 三、選了之後多出來的那一排

| 選了 | 多一排 | 顯示名稱自動變成 | 數量的說法 |
|---|---|---|---|
| 有配二返的課程（健檢） | 幾萬的（`TIER_PRESETS` + 其他…） | `8萬健檢` | 幾次 |
| `requiresIvProduct` 的課程（營養點滴） | 哪一種（主檔 `ivProducts`） | `營養點滴 - 雪顏亮彩` | 幾次 |
| 營養品 | 哪一種（主檔 `products`） | `夜態美` | 幾份 |
| 其餘 | 沒有 | 課程名 | 幾次 |

三排都是丸子，一個下拉選單都不留（她的原話：「可以不要用下拉選單而是用小丸」）。

`營養點滴 - 雪顏亮彩` 這個接法**照抄 `domain/legacyImport.js` 現在產生的字**
（`` `營養點滴 - ${p.name}` ``），不要自己另外發明一種 —— 同一位客戶身上
一筆匯進來的、一筆手動加的，長得不一樣她會以為是兩種東西。

### 四、額度上多兩個選填欄位

```js
ivProductId,   // 這一筆營養點滴額度是哪一個品項的。選填
productId,     // type === 'product' 才有：哪一個營養品
```

兩個都跟 `tier` 同一種東西（ADR-0054）：**存下來，但流程與任務都不看它**。
存 id 而不是只留在名字裡，是因為主檔上的品項她隨時改得了名字，
而字串比對正是舊 Apps Script 靜默失效的原因（`domain/followups.js` 的檔頭）。

`domain/legacyImport.js` 那一段**這一輪不動**：它現在只寫 label，補寫
`ivProductId` 是另一件事（匯入是唯讀參考路徑，改它要重跑一次驗證匯入）。
記在 `06` 的清單裡。

### 五、驗證與 Rules

- `validateEntitlement()`：`type` 多認一個 `'product'`。product 型態
  **必須有 `productId`**、不可以有 `courseId` 或 `optionEquipmentIds`；
  `single` / `pool` 的規則一個字都不改。
- `firestore.rules` 的 `validEntitlement()`：`d.type in ['single', 'pool', 'product']`，
  外加選填的 `productId` / `ivProductId`（`null` 或 string）。

### 六、客戶詳情上畫在哪

**營養品自己一小段，接在額度下面**（她 2026-08-25 決定的）：

```
額度  4                                          加購
[ 復能 ▓▓▓░ ] [ 8萬健檢 ▓░ ] …

營養品  2
夜態美 ×2                                          ›
GABA ×1                                            ›
```

不塞進那一排額度卡，因為那張卡的主體是「已完成／已排未上／剩餘」三段進度條，
而營養品**永遠是滿的**（沒有來訪扣得掉它）—— 一條永遠滿格的進度條在講一件
不會發生的事。點一列進「調整」那一張表，那裡也只有「幾份」與刪除，
沒有那三個對不上的數字。
