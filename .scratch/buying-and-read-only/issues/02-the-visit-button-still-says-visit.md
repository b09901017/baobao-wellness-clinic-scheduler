# 客戶詳情的「來訪」按鈕與來訪紀錄那一列還是直接跳編輯器

Status: todo
來源：她的三件事，2026-08-25（`../spec.md`）
動工前先讀：`01-the-detail-card-still-has-a-pencil.md`、`docs/adr/0018`

## 症狀

她的原話：

> 還有像是客戶詳細資料那邊的任務，來訪還是寫來訪，他其實和已改成詳情的按鈕
> 一樣 ? 我希望改成寫詳情，和todo那邊一樣，然後也可以幫我找找有沒有類似的地方
> 寫的是來訪但其實可以寫成詳情 並且唯讀?

兩個地方：

1. **客戶詳情 → 任務 → 右邊那顆按鈕寫「來訪 ›」**
   （`ui/views/customerDetail.js` 的 `taskRow()`）。它的行為跟待辦中心那顆
   「詳情」一模一樣（都是 `openVisitCard()`），只有字不一樣。
   同一個動作在兩頁叫兩個名字，她會以為是兩件事。

2. **客戶詳情 → 來訪紀錄 → 展開 → 那一列**
   （同一支的 `visitRow()`）。那是一個 `<a href="#/visits/:id">`，
   點下去**直接落在整頁的來訪編輯器上** —— 正是 `../asks-2026-08-25/issues/06`
   在待辦中心修掉的那一種。「看全部 N 筆」那張面板裡是同一支，所以同樣的問題。

掃過全站，寫著「來訪」而其實是「詳情」的就只有這兩處。其餘的「來訪」都是
名詞用得對的地方（`新增來訪`、`來訪紀錄`、已刪除項目的分類名、稽核紀錄的集合名）。

## 要做成什麼

- `taskRow()` 那顆按鈕的字：`來訪 ›` → **`詳情 ›`**。
- `visitRow()` 從 `<a href>` 改成 `<button data-visit>`，點下去走
  `openVisitCard()`（唯讀，見 issue 01）。**長相不要變** —— 她認的是
  「日期＋課程＋狀態徽章」那一列，不是那是不是一條連結。
- 「看全部 N 筆」那張面板要自己接一次事件（同一支裡的 `[data-all-tasks]`
  已經是這個作法）：面板不在 `pageRoot(el)` 底下，委派監聽吃不到。

## 為什麼不是「讓那一列還是連到編輯器」

因為 issue 01 已經把「改」收成只有日曆一個入口（ADR-0056）。留一條連結
繞過去，等於那個決定只做了一半 —— 而半個決定比沒有決定糟：她會發現
「有時候點得進去有時候點不進去」，然後開始每一列都試一次。

## 驗證

- `npm test`
- 瀏覽器：客戶詳情 → 任務那一段 → 右邊按鈕寫「詳情」→ 點了浮出唯讀卡片
- 客戶詳情 → 來訪紀錄 → 展開 → 點一列 → 浮出唯讀卡片（不是編輯器）
- 「看全部 N 筆」→ 點一列 → 一樣浮得出來
