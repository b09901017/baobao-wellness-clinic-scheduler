## 選的做法（`spec.md`「決定 1」有理由）

全名只活在 `.local/references/staff-names.json`。`merge.mjs` 把它帶進合併檔，匯入頁用 app 自己的寫入路改主檔。
她要的「先看不寫」＝匯入頁的摘要卡，在按「開始匯入」之前就列出會改哪幾位。staging 與正式站是同一個動作。

**19 做完之後，「把全名填進 Abovee 上的寫法」這件事不需要了** —— 全名就是顯示名，`staffFrom()` 直接認。所以這一支只搬兩格：全名與簡寫。

## 要做的

### 名單（`.local/`，不進版控）

- `tests/no-secrets.test.js` 的 `realNames()` 多讀這一份的**值**（全名）。

### 產檔那一側

- `merge.mjs --staff-names <檔>`：合併檔多一段 `staff: [{ match: '<現在的顯示名>', name: '<全名>', shortName: '<現在的顯示名>' }]`。
- 格式升 `baobao-merge/v6`，**一律寫 v6**（版本講的是格式，不是內容）。所以「沒帶旗標一個位元都不變」那條測試改成
  「沒帶這個旗標時，**除了 `format` 那一行**，合併檔跟以前逐位元一樣」。
- 終端機只印數字（幾位、幾位對不到種子），不印名字。
- `SKILL.md` 補這個旗標與那一段的格式。**`SKILL.md:112-113` 現在寫著相反的建議**（「全名填在 Abovee 上的寫法，顯示名不要改」）——
  那一句要改掉，不然下一個做合併的 session 會照舊建議做。

### app 那一側

- `FORMATS` 收 v6（舊的五版照收）；`validateFile()` 認得 `staff` 那一段（選填；形狀不對整份拒收 —— 「匯入了一半」比整個拒絕糟）。
- **`resolveAssignments()` 對人員多比一格簡寫**：名字對不到時比 `shortName`。這樣「先改名再匯」「先匯再改名」「匯到一半重試」三種順序都對得到。
  其餘主檔（器材、品項、診間）照舊只比名字。**簡寫要「剛好一位」才算**：`byName()`（`:60-64`）是 `.find()`、拿第一個，
  而角色是從比到的那一位讀的（`:366-368`）—— 簡寫對到兩位時留空並講出來，不可以拿第一位。
- 算出「要改哪幾位」只在 `domain/mergeImport.js`。`match`（＝她原本叫他的那個名字）照這個順序認：
  1. 主檔上的**名字**等於 `match` → 改成 `name`（全名）、`shortName`＝`match`
  2. 主檔上的**簡寫**等於 `match`、全名也等於檔案裡的 → 已經是那個樣子，不算（重貼一次是 0 位）
  3. 主檔上的**名字已經是檔案裡的全名**、沒有簡寫（她自己先手打過全名）→ 只補簡寫
  4. 簡寫對到了、但全名跟檔案不一樣（她自己改過）→ **不蓋**、列出來
  5. 對不到、或對到兩位 → 不改、列出來
- **驗證要自己叫。** `data/config.js:28` 的 `update` 就是 `repo.update()`，不驗證 —— 驗證是設定頁自己叫的（`masterList.js:1413`）。
  所以算「要改哪幾位」那一支對每一位候選叫 `validate('staff', 候選, { existing })`；過不了的（全名跟另一位既有的人同名…）不改、列出來，其餘照改。
- 摘要卡多一行「人員：N 位會改成全名，原本的名字變成簡寫」，點開看得到每一位的「原本 → 全名（簡寫）」與不改的那幾位各自的理由；確認框多一句。**0 位時一個字都不多。**
- 寫入用**一個 `repo.commit()`**（21 位一起，不會只改一半；稽核照 `repo` 的規矩記）。**人員先寫、客戶後寫**；寫過的那幾位重試時是 0 位。
- 客戶全部同名跳過、只剩人員要改時，「開始匯入」照樣按得下去（staging 上她不想重來一次預演時就是這個情況）。

## 判準

- 沒帶 `--staff-names`：產出來的檔除了 `format` 那一行，跟以前逐位元一樣嗎？
- 上面五種認法各有一條測試嗎？第 3、4 種（她自己先動過主檔）會不會被列成「主檔上沒有這一位」或被蓋掉？
- 21 位是不是在同一個 commit 裡？寫到一半斷線會不會只改了幾位？
- 同一份檔貼兩次：第二次「人員 0 位」嗎？
- 主檔還是種子的名字時匯：58 段的治療師／醫師都對得到嗎？**已經改成全名之後**再匯呢？（重跑 `r02-renamed-master.mjs` 的那幾種，數字寫進「做完時留下的」）
- `match` 同時對到兩位（一位的名字、另一位的簡寫）怎麼辦？（不改、列出來）
- 全名跟另一位既有的人同名（validator 會擋）：那一位不改、講出來，其餘照改 —— 不可以整批失敗。
- 舊版 app 收到 v6 會怎樣？（拒收，講「格式不認得」—— 不可以安靜地吃掉 `staff`）
- 稽核紀錄上那 21 筆改名講的是什麼？（「誰」是她，不是系統；句子讀得懂）
- **repo 裡有沒有任何一個全名**：`git grep` 名單上的每一個值（腳本放 `.local/`，只印命中幾處）要是 0；`staff-scan.mjs` 也跑一次。
- 契約兩邊的版本字串一樣嗎？（`tests/calendar-merge.test.js`）
