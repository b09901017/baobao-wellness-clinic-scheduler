## 為什麼會這樣

一、失敗那一位以外，其他客戶和行事曆上的雜事（行事備註、休假、待辦）都已經寫進去了。雜事那一批（`looseDocs`）
不問系統裡有沒有，重按一次就再寫一次。10/6 那份：14 筆行事備註／休假、6 筆待辦各多一份。

二、對不到主檔的東西不是留空就是整筆不匯（一筆額度對不到課程，它底下每一段都不匯）。之後補不回來 ——
再貼一次時每一位都同名跳過。實測：器材還叫舊名時少 51 處，其中 3 筆額度整筆沒進來。

## 要做的

- 雜事寫完就把它們的勾清掉，重試只剩還沒寫進去的。**行事備註／休假與待辦共用同一個 `picks.events`**（`:58-59`），而它們分兩批寫（`importEvents()`、`importNotes()`）：
  前一批寫完、後一批失敗時**只清已經寫的那一類**，整個 `clear()` 會把沒寫的也清掉（變成安靜地少匯）。
  01 做的「放開前重算」如果已經讓雜事不會再寫，確認一次、寫進「做完時留下的」，不要做兩道。
- 確認框與完成提示講出來：**對不到主檔 N 處**、**同名跳過 N 位**。句子在 `domain/mergeImport.js` 算（跟摘要卡同一支數字），畫面只印。
  兩個數字都是 0 時**一個字都不多**。
- 對不到主檔 > 0 時，確認框那一句要講後果：「匯完之後補不回來，先到資料健檢把主檔補齊」—— 她看得懂的話，不寫函式名。

## 判準

- 一位失敗 → 重按：雜事的筆數跟只按一次一樣嗎？
- 行事備註寫完、待辦那一批失敗 → 重按：待辦還寫得進去嗎、行事備註有沒有多一份？
- 確認框上的兩個數字跟摘要卡是同一支算的嗎？（各算一次遲早一邊漏）
- 兩個都是 0 的那一份（正常的切換日）確認框有沒有變長？（不可以）
- 這一句後果講的是真的會發生的事嗎？（lessons 五：補不回來是因為同名跳過，不是因為別的）
