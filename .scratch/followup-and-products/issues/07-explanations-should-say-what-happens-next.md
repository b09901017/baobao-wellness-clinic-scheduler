# 說明要寫「按下去之後會發生什麼」，不要寫系統詞

Status: done
回報者：使用者，2026-08-27（「我希望與其寫一些我看不太懂得系統說明，我希望也許可以簡單直白的寫接者會產生甚麼?」）
動工前先讀：`docs/adr/0056`（ADR-0056 的刪減判準）、`CONTEXT.md`（用詞）

## 判準

ADR-0056 問的是「這句話該不該留」。這一張問的是**留下來的那幾句該怎麼寫**：

> 每一句後果說明都要回答四件事：**記到哪、狀態變什麼、產生哪張待辦、試算表會不會動。**
> 沒有的那幾項就不寫，有的一定要寫。用她的詞（`CONTEXT.md`），不要用系統詞。

「系統登記等客人確認之後才產生」是典型的反例：`系統登記` 不是她的詞，
而且它講的是**不會發生**的事，不是會發生的事。

## 她逐句點出來的（健檢那條動線）

### 1. 壓表 →「加這一筆」的確認框

現在（`ui/views/schedule.js` 第 1478 行附近）：

```
已經在 Abovee 壓好表了嗎？
測試健檢二返・8/27(四) 11:30–13:30 健檢
這一段會併進同一天已經有的來訪裡
會記成「已壓表，等客戶回覆」—— 系統登記等客人確認之後才產生
```

三個問題：

- **抬頭寫死 Abovee。** 健檢壓的是 Examine —— `domain/taskRules.js` 的
  `bookingSystemFor(category)` 早就答得出來（B 類回 `'Examine'`），這裡沒有用它。
  `ui/views/visitEditor.js` 第 531 行有同一句寫死的，一起改。
- 第一行是額度名稱不是客戶名稱（`selected.customerName` 在測試資料裡剛好是那個字串，
  但那一行該長成「誰・什麼時候・做什麼」）
- 最後一行講的是不會發生的事

要變成：

```
已經在 Examine 壓好表了嗎？
王小明・8/27(四) 11:30–13:30 健檢
會記到日曆上，標成「待確認」
待辦會多一張「跟客人確認時間」
十秒後自動同步到試算表
```

### 2. 勾掉「跟客人確認時間」之後那張卡

現在（`showConfirmed()`）抬頭是「加進日曆」。但那一筆**本來就已經在日曆上了**
（壓表那一刻就進去了），這一步改的是顏色不是有沒有。

要變成：抬頭「已確認」，內容寫

```
日曆上這幾段從「待確認」變成「已確認」
來訪當天會多一張「簽療程單」
試算表跟著更新
```

（`tasksForCategory('B')` 是空的，所以健檢**不會**多出 Examine／耀聖那兩張。
A 類才會 —— 那時要多寫一行「待辦會多一張 Examine、一張耀聖」。
這一句要照類別算出來，不要寫死。）

### 3. 收尾「這 N 段做了，結案」

現在按鈕上只有那一句，按下去 toast 說「結案了，次數扣掉了」。沒有講後續。

要變成（按鈕不動，底下多一句預告）：

```
日曆上改成「已完成」，次數扣掉
待辦會多一張「追蹤健檢報告」（健檢做完要等報告）
試算表跟著更新
```

「追蹤健檢報告」那一句只有這一筆真的含健檢時，才寫得出來 ——
判斷走 `domain/followups.js` 的 `pairsOf()`，不要在這一頁認課程名字。

### 4. 「約二返」那張待辦

見 issue 04（連到壓表、勾之前先確認、壓完自動勾掉）。文案的部分：

勾掉的確認框要寫

```
已約 9/3(三) 14:00 · 王醫師
這是 8/27 那次 8萬健檢 的二返
勾掉之後這一次健檢就不會再出現在待辦上
```

### 5. 「試算表會跟著動」全站都沒講過

`data/sheetSync.js` 每次寫入成功後十秒自動推一次整包，
但**畫面上沒有任何一個地方講過這件事**。她問「對了剛剛都沒說到修試算表」。

→ 凡是會改到來訪、額度、任務的確認框，最後一行都補一句
「十秒後自動同步到試算表」。沒開同步（`isConfigured()` 是 false）就不寫。

## 其他要一起掃的

同一個毛病散在別處，一起改：

| 檔案 | 現在寫什麼 | 問題 |
|---|---|---|
| `ui/views/schedule.js:1101` | 「系統登記等客人說可以之後才長出來」 | 講不會發生的事 |
| `ui/views/visitEditor.js:531` | 「已經在 Abovee 壓好表了嗎？」 | 寫死 Abovee |
| `ui/views/visitEditor.js:534` | 「這筆會記成『已壓表，等客戶回覆』」 | 沒講產生什麼待辦 |
| `ui/views/home.js:311` | 「壓好了、還沒問過本人」 | 這一句是對的，不動 |

**不要順手把所有說明都改掉。** ADR-0056 那三條判準還算數：
在解釋「畫面上根本沒有的動作」→ 刪；在解釋「看得到卻按不動的東西」→ 留。
這一張只管**後果句**。

## 附帶發現：同一天兩次健檢只長得出一張「追蹤健檢報告」

她自己提到的：

> 然後追蹤健檢報告如果同一天有兩個，是不是直覺上應該分開呈現

現在是**做不到**的，不只是沒分開呈現。`syncFollowupTasks()` 的 `wanted`
是一張 `visitId → 站別` 的 Map，一筆來訪只放得下一個值。
同一天兩段健檢併在同一筆來訪裡（排班單位是「某人某天來一次」），
所以 `owed()` 算出欠 2 次，也只長得出 1 張待辦。

要修的話得把待辦的鍵從 `visitId` 換成「哪一次健檢」（`visitId` + 時段序號）,
而 `task.visitId` 全站都在用。**她自己說「理論上我也不會同一天約兩個健檢」，
所以這一條先記著不做** —— 等她說要再動。

## 做了什麼（2026-08-27）

規則收進 `domain/consequences.js`（新，`tests/consequences.test.js` 31 條）——
以前這幾句在兩個入口各寫死一次，所以「Abovee」在健檢上錯了兩次。

| 哪一句 | 現在講什麼 |
|---|---|
| 壓表「加這一筆」 | 抬頭照類別算（健檢是 Examine）。記到日曆、標成什麼、產生哪張待辦、試算表 |
| 併進已確認的那一筆 | **多一句「會退回等客戶回覆」** —— 不講的話她會以為新加的那一段也是談定的 |
| 來訪編輯器的「已壓表」 | 同上，走同一支 |
| 勾掉「跟客人確認時間」 | 抬頭從「加進日曆」改成「已確認」（那一筆本來就在日曆上了），底下列出後果 |
| 收尾「這 N 段做了，結案」 | 抽屜底下多一段預告：改成已完成／未到、扣不扣次數、會不會多一張「追蹤健檢報告」 |
| 「約二返」勾掉 | 見 issue 04 |
| 客戶詳情「還沒有任務」 | 不寫「系統登記」了，直接寫「要去 Examine、耀聖掛號的那幾張」 |

**「試算表會跟著動」全站第一次講出來** —— `data/sheetSync.js` 每次寫入成功後
十秒自動推一次整包，但畫面上一個字都沒說過。沒開同步就不寫（`isConfigured()`）。

判準：**只講這一筆真的會發生的事**。健檢的 `onConfirm` 是空的，所以不預告
登記待辦；整批沒做就不說「次數扣掉」；沒有健檢就不說「會多一張追蹤健檢報告」。

`二返()` 的空括號**保留** —— ADR-0026 定的，那在她的寫法裡就是「還沒約」的意思。
