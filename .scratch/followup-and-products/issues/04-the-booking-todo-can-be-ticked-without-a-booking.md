# 「約二返」勾得掉，但沒有人檢查真的約了沒

Status: 待動工
回報者：使用者，2026-08-27（「我發現這個預約二返我可以直接勾掉但是其實沒有還沒預約」）
動工前先讀：`docs/adr/0042-the-report-comes-before-the-follow-up.md`、
`docs/adr/0002-app-records-decisions-it-does-not-make-them.md`

## 症狀

待辦中心的「約二返」那一張，點一下就勾掉了。**沒有任何地方確認她真的去約了。**

勾掉之後 `syncFollowupTasks()` 把那一筆健檢放進 `settled`，整條鏈就結束了 ——
那一次健檢從此不再出現在任何待辦上。如果她其實還沒約，這件事就這樣消失了，
而那正是這個 app 要消滅的東西。

## 為什麼會這樣

`data/tasks.js` 的 `setDone()` 收的是任務本身，不看世界上有沒有對應的來訪。
它沒有錯 —— 那一支的職責是「勾起來，順便把鏈條的下一站算出來」。
缺的是**勾之前那一句話**。

## 想要的樣子

她的原話：

> 然後勾選的時候要確認這個二返真的有被記錄，就是這邊要檢查是不是真的有幫這個
> 連結到的健檢做二返預約，是不是真的有壓表，是不是在日曆上有，然後確認時可以寫說，
> 是不是預約幾月幾號幾點這樣

還有兩句是關於動線的：

> 約二返的todo，希望這邊有可以點了直接連結到壓表，像是說去預約等等，
> 就連結到這個人的壓表，然後會自動選好二返

> 所以期待我在壓表壓二返的時候，可以顯示這是聯結幾號的健檢，可以多提醒記得去把todo給勾掉，
> 或是點完這個todo可以自動勾掉

## 三段要一起做

### 1. 待辦上寫出「約了沒」

那一列要能自己回答。有約到就寫出來：

```
約二返 · 客戶A          已約 9/3(三) 14:00
約二返 · 客戶B          還沒約
```

判斷走 issue 02 的 `slot.followupForVisitId`：那一筆健檢有沒有被任何一段二返認領。
**這是一個推導值，不是新欄位** —— 存第二份一定會對不起來（同 ADR-0004 的判斷）。

### 2. 勾掉之前先問

還沒約就勾 → 確認對話框講清楚後果：

> 還沒看到這一次的二返預約
> 客戶A · 8/27 的 8萬健檢
> 勾掉之後這一次健檢就不會再出現在待辦上了
> 如果只是還沒回來記，先去壓表比較安全

按鈕給兩顆：「去壓表」與「還是勾掉」。**不擋**（ADR-0002：app 記錄決定，不做決定）——
她可能在別的地方約好了還沒記，或者客人當場就約了下一次。

已經約到的就不要問，直接勾掉。多問一次她會學會閉著眼睛按。

### 3. 壓完二返自動把待辦勾掉

壓表存下二返、而且那一段指到某一次健檢時，把那一次健檢的「約二返」待辦一起勾掉，
**寫在同一個 commit 裡** —— 跟 `data/tasks.js` 的 `setDone()` 帶出健檢鏈下一站
是同一個道理（一個動作一個 commit 才給得出復原，見 `repo.withUndo`）。

存完那句 toast 要說出來：「記好了，『約二返』那張待辦一起勾掉了」。

### 4. 待辦點得進壓表

「約二返」那一列點下去 → 壓表那一頁、那位客戶、二返那一筆額度已經選好、
而且「哪一次健檢的」也已經選好（就是這張待辦掛的那一筆）。

`ui/views/schedule.js` 已經被 `home.js` import 了（`import * as scheduleView`），
路由帶參數的作法照現有的 `data-goto` 那條路走。

## 驗收

- 「約二返」那一列寫得出「已約 9/3(三) 14:00」或「還沒約」
- 還沒約就勾 → 跳確認，可以選「去壓表」
- 已經約了就勾 → 不跳確認，直接勾掉
- 壓表壓完二返 → 那張待辦自己勾掉了，toast 有講
- 點那一列 → 落在壓表、人與項目都選好了
