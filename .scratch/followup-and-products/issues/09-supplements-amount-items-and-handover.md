# 營養品：金額、一次好幾種、哪天順便給（提案，等她確認）

Status: done
來源：使用者，2026-08-27（「營養品其實也算是額度，然後會有金額……但其實我也沒有想得很清楚可以怎麼做，你可以先說說你的想法問我確認」）
動工前先讀：`docs/adr/0057-a-product-is-an-entitlement-that-cannot-be-scheduled.md`、
`docs/adr/0044-a-dated-note-goes-on-the-calendar.md`、`docs/adr/0045-the-calendar-has-four-kinds.md`

## 她說了什麼

> 營養品其實也算是額度，然後會有金額，次數1就是一個月2就是兩個月的，我都會一次給，
> 然後同一次裡面會有很多種類例如 營養品(5000) : 夜態美+速體淨+粒能康+GABA 7/6 順便給，
> 我都是等客人哪天有預約來，我就順便給，需要記上日曆成為todo然後也可以改期，
> 假設我當天忘記給了，然後可以記我給了那些多少，或是我全部給了，一樣要記到試算表上

> 就是加購營養品的時候要能標注金額，然後選他買了那些，然後有些可能沒有事先設定好的這邊可以新增

## 現在的樣子跟她的說法差在哪

| 她的說法 | 現在 |
|---|---|
| 一筆營養品 = 一次購買，裡面好幾種 | 一筆額度 = **一種**（`productId` 是單數） |
| 有金額（5000） | **沒有金額欄位** |
| 次數 = 幾個月 | `totalQty`，畫面上叫「幾份」 |
| 哪天順便給、可以改期 | **完全沒有這件事** |
| 給了哪些、或全部給了 | **完全沒有這件事** |

所以她寫的 `營養品(5000) : 夜態美+速體淨+粒能康+GABA` 現在會變成**四筆**額度，
而 5000 是那一整包的價錢，拆成四筆之後就沒有地方放了。

## 提案

### 一、一筆營養品 = 一次購買

額度上多三個欄位：

```js
{
  type: 'product',
  amountTwd: 5000,                    // 這一整包多少錢
  items: [                            // 這一包裡有哪幾種
    { productId: 'p-1', name: '夜態美' },
    { productId: 'p-2', name: '速體淨' },
    …
  ],
  totalQty: 2,                        // 幾個月
  label: '營養品（夜態美＋速體淨＋粒能康＋GABA）',
}
```

`items` 上同時存 id 與名字：id 是為了主檔改名時跟得上，名字是為了那一款
被刪掉之後畫面上還印得出來（同 `payload()` 現在對 `productId` 的理由）。

**舊資料**：只有 `productId` 沒有 `items` 的那幾筆，讀的時候當成
`items: [{ productId }]`。不寫回去、不自動搬 —— 她下次編輯那一筆時才會換成新的形狀。

「幾份」改成「**幾個月**」（`unitOf()` 那一支）。

### 二、加購那一張表加兩排

`ui/components/buy.js`（三個入口共用一份）在選了「營養品」之後多兩排：

```
金額        [ 5000 ]

哪幾種      (夜態美) (速體淨) (粒能康) (GABA) (Q10) … (新增…)
            ← 可以複選，不是擇一

幾個月      [ 2 ]  +1 +5 +10
```

- 「哪幾種」從擇一改成**複選**。`f.chips()` 現在是單選的，要加一個 `multi` 模式
- 「新增…」那一顆：當場打一個名字 → 寫進 `config/products` 主檔 → 直接選起來。
  （跟「其他…」那一格同一種作法，但這一顆會真的建一筆主檔）
- 顯示名稱自動帶：`營養品（夜態美＋速體淨＋粒能康＋GABA）`，她改過就不覆蓋
  （`keptLabel()` 那條規則不變）

### 三、「哪天順便給」＝ 一筆有日期的隨手記

**不開日曆的第八種顏色。** 色相已經用完了（ADR-0039、0045），
而「有日期的隨手記」本來就會出現在日曆的「待辦」那一類（ADR-0044）——
**它就是她要的那個東西**：有日期、可以改期、勾得掉、勾掉畫成刪除線。

加購營養品存下去的時候，順手建一筆隨手記：

```
text:         給營養品：夜態美＋速體淨＋粒能康＋GABA
customerId:   （那位客戶）
date:         那位客戶下一筆已排的來訪日期，沒有就留空白
entitlementId: （那一筆營養品額度）   ← 新欄位
```

改期＝改那筆隨手記的日期，已經做得到了，一行程式都不用寫。

### 四、勾掉的時候問「給了哪些」

隨手記勾掉的動線現在是「點一下就勾」。掛了 `entitlementId` 的那幾筆改成
先開一張小面板，**照收尾那一張的作法**（`home.js` 的 `closeDrawerHtml()`）：

```
給了什麼？                    王小明・8/27

  夜態美                      給了
  速體淨                      給了
  粒能康                      給了
  GABA                        給了      ← 點一下切成「沒給」

  [ 四種都給了，記起來 ]
  [ 先不要，回去 ]
```

**預設全部打勾**，跟收尾那一張同一個判斷（十次有九次是整包給完）。
按鈕上的字跟著勾選數變（「三種給了，記起來」）。

沒給完的那幾種：**那筆隨手記留著不勾掉**，日期往後推到她挑的下一天，
文字換成剩下的那幾種。這樣「還沒給完」這件事不會消失。

給的結果寫在額度上：

```js
deliveries: [
  { at: '2026-08-27', productIds: ['p-1','p-2','p-3'], note: null },
]
```

### 五、試算表

那一列現在印的是 `營養品　應有 2　已完成 0　已排未上 0　剩餘 2`，
而 2 是月數，四個數字沒有一個看得懂。

改成一列白話的：

```
營養品 5,000（夜態美＋速體淨＋粒能康＋GABA）　2 個月　8/27 給了
```

**要她決定的**：這一列要怎麼進試算表，有兩條路 ——

- **A：塞進 `label` 字串。** `sheets/readonly-report.gs` 一行都不用改，
  她也不用回去重新部署那份指令碼。代價是那四個數字欄還是印著月數。
- **B：`SYNC_FORMAT` 升到 3，多一個 `products` 區塊。** 排版乾淨，
  但**她必須回 Google 試算表把 `.gs` 重新貼一次、重新部署**
  （`.gs` 收到不認得的版本會整份拒收，見那支的 `SUPPORTED_FORMAT`）。

## 還沒決定的（問她）

1. 一筆營養品 = 一次購買（好幾種），還是照舊一種一筆？
2. 交付走「有日期的隨手記」可以嗎？
3. 沒給完的時候，剩下的要自動推到下一次，還是就留在原地？
4. 試算表走 A（不用重新部署）還是 B（排版乾淨）？
5. 金額要不要進試算表？（她的舊表是寫在名稱裡的）

## 她的回答（2026-08-27）

1. 一次購買 = 一筆 ✅
2. 交付走「有日期的隨手記」✅（沒有異議）
3. 沒給完 → **留在原地**，只換文字。日期不動 —— 隨手記的日期不是死線，
   自己往後跳一天會讓她以為是系統排的
4. 試算表走 **B**：升版、營養品自己一區。**她要回 Google 試算表把 `.gs`
   重新貼一次並重新部署**
5. 金額進試算表 ✅（她的舊表本來就寫在名稱裡）

## 做了什麼

`domain/products.js`（新）+ `tests/products.test.js`（31 條）。
`docs/adr/0059`、`CONTEXT.md` 多了「交付」、`CLAUDE.md` 的連動表多兩列。

| | |
|---|---|
| 形狀 | `items[]`＋`amountTwd`＋`totalQty`（幾個月）。舊資料**讀的時候**相容，不自動搬 |
| 加購那一張表 | 金額那一格、「哪一種」改複選、「＋ 新增…」當場加一款（三個入口共用 `commitNewProduct()`）|
| 提醒 | 建立額度時同一個 commit 配一筆隨手記。日期：客戶詳情算得出下一次來訪就填，批次建立新客戶留空白（**不猜今天**）|
| 勾掉 | 逐款確認面板（預設全打勾，同收尾那一張）。四個入口共用 `note.toggleWithDelivery()` |
| 沒給完 | 提醒留著、文字換成剩下的那幾款、日期不動 |
| 客戶詳情 | 那一小段寫出「都給了・8/27」或「給了 2/4 種，還差 粒能康、GABA」|
| 試算表 | `SYNC_FORMAT` 3，營養品自己一區（品名／金額／幾個月／哪幾種／給了沒），還沒給完的那幾列標琥珀色 |

`f.chips()` 多一個 `multi` 模式，值用換行串在同一個 hidden input 裡。
