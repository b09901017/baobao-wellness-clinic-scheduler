# 刪掉客戶後，他未來的來訪與待辦都還在

Status: todo（先問她選哪一個方向）
來源：`../spec.md`
動工前先讀：`ui/views/customerDetail.js` 的 `openDanger()`（刪除那一道確認）、`docs/adr/0041`（來訪存在就代表壓過了）、
`boundary-checklist` 那一輪記的「壓表批次裡已刪除客戶的卡片」

## 現在壞在哪

一位客戶今天有一段已確認的門診、一張還沒做的 Examine → 客戶詳情 → 停用與刪除 → 刪除：

| 地方 | 刪除之後 |
|---|---|
| 日曆那一天 | 那一段**還在** |
| 待辦 → Examine | 還叫她去**替他掛號** |
| 待辦 → 簽療程單 | 還叫她去**替他結案** |
| 長按那一段 → 改這一段 | 「找不到這位客戶」 |
| 客戶清單 | 不見了（對的） |

刪除確認框只寫「他底下的 N 筆額度與 N 筆來訪都不會被修改」「客戶清單上不再顯示，壓表時也不會出現」，
沒有講上面那幾件。那些時段在 Abovee 上**還被佔著**，撞期判斷也照樣算他。

## 怎麼重現

種子一位客戶＋今天一段 confirmed 的 `course-rehab`＋一張未勾的 `Examine` → `#/customers/<id>` →
`[data-danger]` → `[data-delete]` → 確認 → 看日曆那一天、`#/todo/Examine`、`#/todo/close`、長按 → 改這一段。

## 為什麼

刪除只寫客戶本人那一份（`data/customers.js` 的 `remove()`），來訪、任務、隨手記都是頂層集合，
它們讀的時候不問客戶還在不在。

## 要她選的

| | 做法 | 代價 |
|---|---|---|
| A | **刪除之前先擋**：他還有今天以後的來訪或還沒做的待辦時，確認框列出來，請她先去壓表的批次取消 | 多一步；但批次取消那一頁要先確認刪除前還進得去 |
| B | **刪除時一起收**：今天以後還沒結案的每一段照「取消這一段」處理（會長「取消 Abovee」叫她回去放時段），沒做的掛號收掉；確認框逐條講 | 一次動很多筆，要分好幾個 commit、給不出復原 |
| C | 只把確認框講清楚，其餘不動 | 日曆與待辦上會留著一個點不進去的人 |

建議 **A 或 B**：那幾個時段真的還在 Abovee 上佔著，C 會讓她忘記去放。
選完照 ADR 的慣例補一支（「刪客戶不收來訪」是這一次才被說清楚的決定）。

## 判準（照她選的那一條補）

- 刪除確認框講的每一句都是真的會發生的事（ADR-0070）
- 刪除之後日曆、待辦、簽療程單上**不會**留著一個點進去是「找不到這位客戶」的人
- 還原（設定 → 已刪除項目）之後行為講得通
