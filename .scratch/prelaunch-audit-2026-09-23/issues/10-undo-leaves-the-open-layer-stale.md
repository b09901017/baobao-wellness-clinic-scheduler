# 按「復原」之後，開著的那一層還是舊資料

Status: done
來源：`../spec.md`
動工前先讀：`ui/toast.js` 的 `saved()`（復原成功後叫 `reload()`）、`ui/router.js` 的 `reload()`、
`ui/views/calendar.js` 的 `openDay()`（那一天的抽屜）與 `visitQuickActions()`
相關：04（舊資料被拿去寫）

## 現在壞在哪

日曆 → 點今天 → 長按一段待確認 → 客戶說可以 → 按 toast 上的「復原」→「已復原」：

- 資料庫：那一段退回**待確認**（對的）
- 那一天的抽屜還開著，長按同一段：選單上有「客人來了，去簽療程單」「改這一段」「取消這一段」，
  **沒有「客戶說可以」**——它還以為那一段是已確認
- 要關掉抽屜或重新整理才會回來。她會以為復原沒生效，或者照著舊的畫面再按下去（那就是 04）

## 怎麼重現

種子一段今天 `pending_confirm` 的 Inbody → 日曆打開那一天 → 長按 → 客戶說可以 → `#toast [data-undo]` →
等「已復原」→ 再長按同一列 → 選單上沒有「客戶說可以」。

## 為什麼

`toast.js` 復原成功後會叫 `router.reload()`，那只重畫**底下那一頁**。日曆那一天的抽屜是另外疊上去的一層
（`openDay()`），它手上的 `data` 是打開那一刻傳進去的，復原之後沒有人更新它；長按選單讀的正是那一份。

其他「開著一層、手上抓著資料」的地方可能也一樣（待辦的確認抽屜、簽療程單抽屜、客戶詳情的讀取卡片），一起看。

## 做法（方向）

- 最小：復原成功之後**把開著的抽屜／卡片一起收掉**再重畫（日曆那一頁的 `refreshAfterAction()` 就是「收掉 → 重讀 → 把同一天開回來」，可以照用）
- 或者：讓 `router.reload()` 通知目前的頁面，由頁面自己決定要不要把那一層開回來
- 不要為了這件事在每一層各寫一份重讀

## 判準

- 上面那個情境：按了復原之後，長按同一段選單上**有**「客戶說可以」
- 復原之後她停在同一天（不要把她丟回月曆最上面）
- 04 的防線做了的話，這裡不會再撞到「剛剛在別的地方被改過」

## 做了什麼（2026-09-23）

- 日曆的 `render()` 畫完之後，那一天的抽屜還開著就**就地換掉它手上的 `data`、就地重畫**（`openDay()` 的 `refresh()`）；
  抽屜被編輯器接走時（點一筆 → 鉛筆）只換資料不重畫
- 第一版是「收掉、開一張同一天的」，全量 E2E 抓到它錯在哪：`render()` 重畫時抽屜開著**不只**復原這一條路 ——
  隨手記的讀取卡片收掉時也會（`onClose: () => render(el)`），於是鉛筆剛接上的編輯器被換掉（08 U13、U14），
  勾一筆之後抽屜捲回最上面（19 U19）。改成就地重畫之後三支都綠
- 其他幾層看過：待辦的確認抽屜與簽療程單抽屜存完就收掉（`drawer = null`）而且確認抽屜給不出復原；
  讀取卡片沒有寫入的按鈕 —— 不必各寫一份重讀
- E2E：`44-stale-copies` 的 S4
