# 確認抽屜的「全部退回未確認」其實是取消

Status: done
來源：`../spec.md`
動工前先讀：`ui/views/home.js` 的 `drawerHtml()`（`:2906-2907` 那三種字）與 `applyConfirm()`、
`domain/visits.js` 的 `applyConfirmation()`、`domain/consequences.js`、`docs/adr/0070`、`CONTEXT.md`（用詞）

## 現在壞在哪

待辦 → 跟客人確認時間 → 點一位客戶 → 抽屜上每一段預設是「可以」，點一下變「客人說不行」。
**全部都點成「客人說不行」**（而且那幾天沒有別的已談定的段）時，底下那顆按鈕寫：

> 全部退回未確認

按下去**沒有再問一次**，結果是：

- 那幾段變成**已取消**（不是退回待確認）
- 整筆取消、理由「客人說這個時間不行」、`released: true`（時段放出去給人遞補）
- 長出「取消 Abovee」

「退回未確認」讀起來像「先放回去、之後再問」，實際上是取消。

**不會誤傷的情況**：只要有任何一段是「可以」，按鈕就是「確認 N 段，加進日曆」，按下去是「可以的確認、不行的取消」——
那是對的。已經談定、不在這張抽屜上的段也不會被動到。只有「全部都不行」那一種字不對。

## 怎麼重現

種子一段 4 天後 `pending_confirm` → `#/todo/confirm` → `[data-open="<客戶>"]` → `[data-slot="<visit>:0"]` →
按鈕字是「全部退回未確認」→ 按下去 → 讀那一筆：`status: cancelled`、`released: true`，多一張「取消 Abovee」。

## 做法（方向）

- 按鈕字講實話，例如「客人都不行，取消這 N 段」（字請照 `CONTEXT.md` 的詞，給她挑）
- 全部取消這一下是不可逆的（`undoable: false`），**要一道確認框**，後果照 `cancelConsequences()` 算
  （會長哪幾張取消、時段會放出去）—— 不要在畫面上另寫一份
- 順手：`applyConfirm()` 的檔頭還寫「只退掉其中幾段 → 把那幾段移出來訪」，那是 ADR-0081 之前的說法（現在是標成取消），改掉
- 「退掉這 N 段」那一種（有別的已談定的段時）也一起看要不要同一道確認

## 判準

- 全部點成不行時，按鈕的字不會讓人以為是「退回待確認」
- 按下去先跳一道確認，講得出會長「取消 Abovee」、時段會放出去
- 有任何一段是「可以」時，行為與字都不變

## 做了什麼（2026-09-23）

抽屜上每一段都是「客人說不行」時，按鈕改成「客人都不行，取消這 N 段」，按下去先跳確認框；後果走 `cancelConsequences()`
（會長哪幾張取消、剩下的段不受影響）。檔頭那句「移出來訪」改成 ADR-0081 之後的「標成取消」。測試：E2E `34` 的 C7、C8。
