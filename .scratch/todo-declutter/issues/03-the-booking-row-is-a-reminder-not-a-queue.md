# 壓表那一列是提醒，不要給它一個永遠歸不了零的數字

Status: todo
來源：使用者，2026-08-24（spec.md 的 c）
動工前先讀：`docs/adr/0028`、`0041`、`0043`、`SPEC.md` 第 8.1 節

## 原話

> 「我想問壓表的那個 todo 你是怎麼判斷需要壓的健檢人數的？然後為什麼會寫
> 『還有 9 位沒排。壓好了回來按「這位壓完了」，他就會出現在「跟客人確認時間」。』
> 我壓好後應該在壓表那邊就可以直接紀錄，而不是要回到 todo 這邊吧，
> todo 這邊只是提醒，其實應該沒有這個月一定要壓所有人的限制，只是可以提醒，
> 因為我有很多客戶，所以一定會有沒壓到的，那這樣 todo 這邊顯示了好多數字，
> 看了就會很煩，他不像其他 todo 是真的要做的」

## 先回答「怎麼判斷的」

`domain/scheduling.js` 的 `customersToBook()`：每一位在服務中的客戶，
看他身上還有剩餘次數的額度，把每一份對應到「要去哪個系統壓」
（健檢類 → Examine，其餘 → Abovee，`taskRules.js` 的 `bookingSystemFor()`）；
如果他這個月**已經有一筆來訪動到那個系統**，那一區就不算他。所以
「其中 N 位是健檢」＝ 身上還有健檢次數、而且這個月還沒排過健檢的人數。

**算法是對的，不用改。** 錯的是它在畫面上長得跟真任務一樣。

## 她說對了什麼

ADR-0028 與 ADR-0041 早就寫了這一列「是提醒不是任務、沒有死線也不計分」，
但畫面沒有照著做 —— 它跟 Examine、耀聖那幾列**用同一支 `groupRow()`、
同一個大數字、同一個紅字位置**。一個永遠不會歸零的數字擺在一堆會歸零的數字
中間，結果是整頁的數字都貶值。

那句「壓好了回來按『這位壓完了』」也是錯的：那顆按鈕在壓表那一頁的記錄面板上，
不在這裡。文案把她往回導。

## 要做什麼

### 1. 那一列不給數字

```
壓表登記                              去看還有誰 ›
八月還沒排到的人
```

- **右邊的大數字拿掉。** 換成一句「去看還有誰」或直接就是那顆箭頭。
- 說明改成一句不帶數字的話。「還有 9 位沒排」要拿掉 ——
  她的原話是「一定會有沒壓到的」，那個數字每個月都會是一個大數字。
- **健檢那個分項也拿掉**（「其中 N 位是健檢」）。想知道有誰就點進去，
  那一頁本來就分成 Examine 與 Abovee 兩區。

### 2. 那一列在視覺上要看得出是另一種東西

它跟「問這輪的時間」同屬提醒（ADR-0028），所以**兩列要長得一樣**。
先把壓表這一列做成提醒的樣子（沒有數字、字級與顏色淡一級），
「問這輪的時間」**這一輪先不動** —— 她沒有反映它煩，而且它有明確的完成動作。
做完給她看兩列並排的樣子，她要一致再一起改。

`groupRow()` 多一個 `kind: 'reminder'` 之類的參數，不要複製一支新的。

### 3. 空的時候整列不畫（不變）

`bookRows.length === 0` 時 `bookGroupRow()` 已經回空字串，維持。

### 4. 「這位壓完了」那句文案

從這一列與 `#/todo/book` 那一頁的說明裡拿掉。她壓完是在壓表那一頁按的，
這裡不需要教她流程。

## 一起要檢查的

- **`CLAUDE.md` 的連動表有一條**：「任務什麼時候產生 → UI 上講這件事的四句文案
  要跟著改」。這一條動到的是「壓表登記」那一列的說明，確認改完之後
  那四句仍然彼此一致（壓表那一頁兩句、確認動線的提示、客戶詳情沒有任務時那一句）。
- `markNext()` 標「流程上最前面那個還有東西的段」—— 壓表那一段變成提醒之後，
  **它還算不算「下一步」？** 我的判斷是**不算**：她的下一步不會是一件永遠做不完的事。
  改成 `markNext()` 跳過提醒類的列。這一點要在 Comments 裡寫清楚。
