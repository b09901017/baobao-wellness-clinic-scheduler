# 首頁那一格隨手記掛得了日期，掛不了客戶

Status: todo
來源：使用者，2026-08-24（spec.md 的 e）
動工前先讀：`CONTEXT.md`（隨手記）、`docs/adr/0044`、`.scratch/quick-capture/`

## 原話

> 「有關滑到最下面的那個隨手記一筆，我發現他可以掛日期但不能掛客戶？」

## 現況

隨手記現在有四個入口，而它們的欄位不一樣：

| 入口 | 文字 | 日期 | 掛客戶 |
|---|---|---|---|
| 首頁底下那張卡（`notesCard()`） | ✓ | ✓ | **✗** |
| 右下角泡泡（`quickBody()`） | ✓ | ✓ | ✓ |
| `#/todo/notes`（`paintNotes()`） | ✓ | ✓ | ✓（下拉選單） |
| 客戶詳情（`notesBlock()`） | ✓ | ✓ | 不用選，就是那個人 |

首頁那一格漏掉了。當初的註解寫著「掛客戶在點進去那一頁做」，但**日期後來
補上去了**（ADR-0044），於是變成一個「掛得了日期、掛不了人」的奇怪組合 ——
而掛人比掛日期常用。

## 要做什麼

首頁那一格補上「掛給誰」，**而且要跟泡泡長一樣**：`CLAUDE.md` 的連動表寫著
四個地方共用 `ui/components/note.js`，這一條就是那條規矩在講的事。

具體來說：把泡泡裡那一組「掛給誰」的丸子（`issues/06` 會重新設計它）
抽進 `ui/components/note.js`，變成 `note.who()` / `note.readWho()` 之類，
然後**首頁那一格與泡泡用同一支**。`#/todo/notes` 那一頁的新增表單在
`issues/07` 會整個拿掉，客戶詳情那一格不需要（就是那個人）。

抽出來的那一支要自己管「點開才讀客戶名單」這件事 —— 那是泡泡上刻意的設計
（十次有九次不掛人，不該為了那一次每次都多一趟往返），首頁一樣適用。

## 一起要檢查的

- 首頁那一格現在是一行輸入框加一顆「記」，右邊很擠。加了「掛給誰」之後
  版面要重排 —— 輸入框一行，底下一排丸子（日期、掛給誰）。
- `notesData.create()` 要 `customerId` 與 `customerName` 成對（`validateNote()`
  會擋只有 id 沒有名字的），共用的元件要一起回傳兩個。

- 瀏覽器：首頁那一格與泡泡的欄位長一樣
