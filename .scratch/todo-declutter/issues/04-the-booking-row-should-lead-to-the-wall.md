# 壓表清單上點一個人，應該去壓他的表

Status: todo
來源：使用者，2026-08-24（spec.md 的 d）
動工前先讀：`SPEC.md` 第 8.2 節、`docs/adr/0014`、`0028`、`0037`、`0046`

## 原話

> 「壓表 todo 點進去不是會有很多人名嗎，理論上我期待的是點人名進去後會讓我
> 選要押這個月還是下個月的然後跳到壓表她的那個卡片牆，而不是跳到客戶資訊那邊
> 很怪，然後這頁最下面寫去壓 8 月的表不一定是 8 月吧？應該寫去壓表」

## 現在是什麼樣

`ui/views/home.js` 的 `bookRow()`：

```js
<a class="grouprow" href="#/customers/${row.customerId}">
```

點一個人名 → 客戶詳情頁。她在那一頁要做的下一件事是「去壓這個人的表」，
而客戶詳情上沒有任何一條路通到壓表。

底下那顆按鈕是 `開始壓${monthLabel(today)}的表` → `#/schedule`，
月份寫死成今天所在的月。**她八月底在排的是九月的表**，所以那個「8 月」
十次有九次是錯的。

## 要做什麼

### 1. 點人名 → 先問月份 → 進壓表的卡片牆，並停在那一位身上

點下去從底部滑出一張小面板（`openSheet()`），只有兩顆：

```
      要壓哪個月的表？

   [  八月  ]   [  九月（下個月）  ]
```

- 兩顆就好，不做月份選擇器 —— 她壓的永遠是這個月或下個月。
- 選完直接進 `#/schedule`，並且**帶著「要打開誰」**。

### 2. 壓表那一頁要收得下「直接打開某一位」

`#/schedule` 現在是卡片牆，點一位才浮出記錄面板（ADR-0017）。
需要一條路讓外面指定「進去就打開這一位」。做法擇一，動工時看程式碼決定：

- 路由加一層：`#/schedule/:customerId`（router 支援一層參數）。月份怎麼帶要想 ——
  也許 `#/schedule/2026-09/:customerId`，但那是兩層，router 現在只支援一層。
- 或者用模組層的一個「下一次 render 要打開誰」變數（`views/schedule.js` 已經有
  類似的模組層狀態）。**簡單、不改 router，但換頁重整就沒了** ——
  對這個動線來說可以接受（她不會在中間重整）。

**傾向後者**，但要在 Comments 裡寫清楚取捨。

### 3. 那個批次的月份

壓表是**批次**的（`batches`，跨裝置續作，SPEC 第 1 節）。如果她選的月份跟
目前這一批的月份不同，不能默默換掉 —— 要問一次，或者照現有「開新批次」的
動線走。**動工前先讀 `views/schedule.js` 現在怎麼決定月份的**，不要在這裡發明
第二套。

### 4. 底下那顆按鈕的字

`開始壓 8 月的表` → **`去壓表`**。月份由上面那張面板決定，按鈕不要先講一個
可能是錯的月份。

### 5. 那一頁抬頭的月份

`#/todo/book` 抬頭現在是「八月壓表登記」，而那一頁列的是**這個月**還沒排的人
（`loadBookRows(today)` 用的是 `today.slice(0,7)`）。抬頭與資料是一致的，
所以**抬頭留著**。但要確認她理解那一頁講的是這個月 —— 如果她其實想看下個月
還有誰沒排，那是另一件事（那一頁也要能換月份），**先問她再做**。

## 一起要檢查的

- 一位客戶可能同時出現在 Examine 與 Abovee 兩區（那是對的，ADR-0041）。
  兩區點下去都走同一條路。
- `bookRow()` 上的醫療禁忌紅字與剩餘次數泡泡留著，那是她決定「先壓誰」的依據。
- 客戶詳情那條路不要完全消失 —— 名字右邊留一個小小的「看資料」入口，
  或者長按。**先做成「點名字去壓表」，不補第二個入口**，她有需要再說。

## 驗證

- 瀏覽器：`#/todo/book` 點一個人 → 選月份 → 落在壓表卡片牆上，而且那一位
  的記錄面板是打開的
- 瀏覽器：底下那顆按鈕寫「去壓表」
- 瀏覽器：選了跟現有批次不同的月份，行為講得通（不會默默把批次換掉）
