# 合併檔 v9：舊表的備註分到該去的地方＋備註的預設順序（2026-10-20）

切換（上線）用的合併檔要再產一次。她這一次的舊表補了很多備註，而 v8 只帶得了「客戶的短備註」一種：
日期欄底下那一格（那一天那一段的事）、沒勾的那一欄底下的取消理由、A 欄一大段的整體備註，全部會擠成短備註
（拿她的檔案跑：一位 17 則，app 一位最多 12 則）。

> 我給你新的ics以及xlsx主要是給你參考行程以及待辦以及試算表的備註我有多新增一些，值得注意的是，通常我試算表，A B 底下放的都是這個客戶的整體備註，然後F 之後的療程內容最底下的在往下一排都是當天的那個時段的備註，如果那一整排有日期單是沒勾最下面寫得像是她忘記，就是她取消的理由，請不要全部都放入這個客戶的備註之中，如果有你判斷是長備註，也可以幫我變成長備註

> 還有一個希望注意的點是，我希望每個人的備註都應該預設是病歷號最前面，然後有line的line第二個，然後電話是在最後面

> 如果遇到資料雌不進去的問題，或是要動到app的部分，可以和我說後直接kickoff修改

> 禮拜六以及禮拜醫的客戶應該有但是我明天去確認看看，可以保留他們的簽診療單的待辦，逾期沒關係

## 第一段談定的（她 10/20 選的）

| 題目 | 她選的 |
|---|---|
| 沒勾、底下寫理由的那幾格 | **建成那一天已取消的段＋取消理由**（課程與時間從 Abovee 那天取消的那一列拿）；客戶失約的建成**未到**、理由記在那一段的「記一句」。不扣次數、不長任何待辦 |
| 這一輪怎麼做 | 這個 session 一路做完（issue → subagent 過目 → 改 app → PR 合進 develop → 重產合併檔、模擬器整份匯一次） |

我照建議做、她沒反對的（她可以推翻）：

- 只寫器材／課程簡寫的那幾格（`IN`、`IL`、`in`、`功醫門診`、治療師的名字）不記 —— Abovee 已經記了那一段是什麼
- 超過 40 字或有換行的整體備註 → 長備註、標題用第一句；其餘照舊短備註
- 電話排最後的副作用：客戶清單卡片只畫前四則（ADR-0160 的 `notesPreview()`），大部分人的卡片上就看不到電話了

## 策略

**app（repo，這一輪的 PR）只做「收得下」**：

1. 備註預設順序（`customerNotes.js` 的 `noteItems()`）—— issue 01，新 ADR 推翻 ADR-0156「沒排過：電話、LINE、長備註、短備註」那一句
2. 合併檔 v9（`domain/mergeImport.js`）：每一段多三格選填的 `note`、`status`（只收 `cancelled`／`no_show`）、`cancelReason`；
   客戶多一格選填的 `longNotes` —— issue 02、03、04
3. skill 那側只升版本字串與格式說明（`merge.mjs` 的 `importJson()` 那一行、`SKILL.md`）—— 契約兩邊同一個字串（`tests/calendar-merge.test.js`）

**產檔（`.local/` 的切換腳本，一次性，不進 repo）** 讀新舊表的日期欄底下那幾格與 A／B 欄，掛到最後那一份上：
有勾的那一欄 → 那一段的 `note`；沒勾、Abovee 那天有取消／失約的列 → 已取消／未到的段；其餘 → 照舊短備註。

**不改 `domain/legacyImport.js` 的讀表版面**（固定第 13 列二返、第 14 列品項簡寫）。她這一次在幾張分頁插了一列
（點滴拆成肝／腸），固定列號讀歪了 —— 但切換之後永不重匯（記憶 go-live-cutover-advice），改它要動一串測試、換一次性的好處。
讀歪的那幾張由切換腳本照她 10/17 講的數字修。

## 連動清查（第一段）

| 動到的 | 會怎麼受影響 |
|---|---|
| `mergeImport.js` 的 `validateFile()` | 新的四格要驗形狀（不對整份拒收，同 v7 的 `phone`／`giftKind`） |
| `planForCustomer()` 組時段 | 帶 `note`、`status`、`cancelReason`；`attended` 照段算；整筆的 `status` 照段推（`visitStatusFrom()`，ADR-0081） |
| `data/legacyImport.js` 的 `importPlan()` | `withSlotStatuses()` 只補沒有狀態的段 —— 已取消／未到的段要在 domain 那一側先寫好；`recount()` 照 `slotOutcome()`（取消 null、未到 noShow）；`importedTasksFor()` 不可以替取消的段長「取消 Abovee」 |
| `slotsMissingEntitlement()` | 取消／未到的段沒有額度時怎麼辦（產檔那側從 Abovee 拿得到課程，額度不一定配得上） |
| `summarize()`／匯入頁的摘要卡、確認框 | 「N 個時段」要講其中幾段已取消／未到、幾段帶記一句、幾則長備註 —— 不講的話她對不了數字 |
| `customerNotes.js` 的 `noteItems()` | 預設順序；`chartNoMove()` 沒排過的不寫順序（照預設）；客戶清單卡片 `notesPreview()` 讀前四則 |
| 長備註 | `readLongNotes()` 認 `id`；`validateLongNotes()`、`MAX_LONG_NOTES`（Rules R14.3 也是 20） |
| 試算表 | 記一句會印上去（格式 7 的兩個落點）—— 匯進來的那幾句也會，這是對的 |
| 文件 | `CLAUDE.md`「舊表 B2…合併檔」與「備註那一段的順序」兩列、`SKILL.md` 的格式、`SPEC.md` 匯入那一節 |

## 過目（10/20，唯讀 subagent；主控自己對過最重的兩條）

- 只有取消段的那一筆會長「取消 Abovee」、一段做完一段取消的那一筆之後一存就**補長** → 匯入時長一張勾好的（issue 03，新 ADR）
- `validateVisit()` 每一段都要額度 → 取消的段跟一般的段同一套額度規則，產檔那側配；app 不放寬（issue 03）
- `merge.mjs` 沒有 `FORMAT` 常數；寫死 v8 的測試五支；E2E 74、77 照預設順序拖曳；`SPEC.md`、`docs/STAGING.md` 各有一句（issue 01、02、05）
- 匯入頁「其餘的標成已完成」「全部標成已完成」有取消／未到的段時是假話（issue 03）
- 真名：六個檔掃過 0 命中（還沒進版控，commit 之後 `npm test` 再掃一次）
