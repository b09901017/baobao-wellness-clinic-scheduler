## 先量，再改

**不要一進去就開始換等待。** 先跑一次 `npx playwright test 07-chaos --reporter=list`
把**每一個 test 的秒數**印出來，看是「一支特別慢」還是「每支都慢」：

- 一支特別慢（例如 C12 連點五次那一支，2026-09-09 那次量到 1.1 分鐘）
  → 問題在那一支的作法，不是整支 spec
- 每支都慢 → 那是塞 5000 字的長字串、六種髒輸入逐一試的成本，
  那是這支 spec 存在的理由，**不要為了快而刪掉輸入樣本**

## 這支 spec 特別難改的地方

它的判準是 SPEC 第 6.9 節：**不可以靜默失敗，也不可以假裝成功。** 而「證明某件事
**沒有**發生」天生需要等一段時間 —— 這正是 issue 02 裡列的兩種「不要換掉」的其中一種。

換的時候要找得到一個「該發生的事」可以等。`19-untick` 的 U9 是可以照抄的範本：
等 `app.saved()`（沒有確認框就是直接寫下去），**然後**才斷言 `dialog()` 是 0。
找不到可以等的東西就**留著那個固定等待**，並在那一行寫出理由。

C12（連點五次「加這一筆」→ 只寫進去一筆）那一支特別要小心：它測的是防重複提交，
而「連點」跟「等」本來就是它的主體。

## 做完了（2026-09-09）：284s → **120s**（本機 5.5m → 2.0m，-64%）

比 issue 樂觀估的 180s 還多砍 60s。**而且一支輸入樣本都沒有刪。**

### 先量：不是「每支都慢」，是三支在等逾時

照 issue 說的先跑 `--reporter=list` 印每個 test 的秒數，再用一份加了計時的
複本量到每一行。**時間不在「塞 5000 字」上，在三個等逾時的地方**：

| test | 前 | 後 | 時間原本花在哪 |
|---|---|---|---|
| C1+C2+C3+C4 髒字串 | **78s** | **19.2s** | 每一輪 8.5s 等一顆點不到的送出鈕 × 6 |
| C12 連點五次 | **78s** | **14.9s** | 第 2～5 下各等滿 15s 的 `actionTimeout` |
| C13 連點五次 | **72s** | **12.8s** | 同上 |
| C23 遍歷每一頁 | 50.3s | 29.5s | 40 頁 × 1100ms 固定等待 |
| C26 不存在的網址 | 10.5s | 6.9s | 5 × 1200ms |
| C3c 姓名髒字串 | 10.2s | 8.3s | |
| C25 快速開關抽屜 | 9.3s | 7.9s | |
| C11 跳過必填 | 5.8s | 4.3s | |
| C24 返回鍵 | 6.1s | 4.4s | |
| C3b 顯示回來 | 4.5s | 4.1s | |
| **合計** | **330s** | **120s** | |

### 三個根因

1. **C12／C13 的第 2～5 下點擊各燒掉 15 秒。** 第一下之後確認框就關了，
   剩下四下**點不到東西才是對的** —— 但它們用的是預設的 `actionTimeout`
   （15 秒），而 `.catch(() => {})` 把逾時整個吞掉。量到的是
   `click#2 = 15031ms`、`#3 = 15030ms`、`#4 = 15020ms`、`#5 = 15041ms`，
   兩支合起來 **120 秒**。改成 `timeout: 1_000`。
   **測試的力道沒有少**：防重複提交壞掉的話那顆鈕還在，四下照樣點得到。

2. **C1 每一輪等 8.5 秒等一顆不需要點的鈕。** Enter 本來就是送出
   （`ui/views/home.js` 的 keydown 直接喊 `save()`），後面那顆「保險起見」的
   送出鈕是多的。存完之後「復原」那個 toast（`ui/toast.js` 的 `UNDO_MS = 8000`）
   **壓在鈕上面**，所以 Playwright 要等它自己消失才點得到 —— 元素在、
   點擊最後也成功，只是每一輪白等 8.5 秒。拿掉那一行，改等 `app.saved()`。

3. **C23 的 40 頁各等 1100ms。** 換成 `app.go()`（＝設 hash ＋ `settled()`）。

### 固定等待 17 → **1**

`tests/e2e-waits.test.js` 的 `PENDING` 跟著改成 1（沒有整列刪掉）。

**留著的那一個是刻意的**，在 C25 的結尾：那一步要證明的是「**沒有**一層殘留的
抽屜冒出來」，而證明某件事沒有發生天生需要等一段時間 —— 沒有「該發生的事」
可以等。理由寫在那一行上面。順手在它後面補了一句 `toHaveCount(0)` 的斷言，
原本那裡只有 `console.log`。
