# 舊的「打電話」「Abovee」任務還躺在待辦上

Status: done
來源：`issues/01` 的連帶
動工前先讀：本資料夾的 `spec.md`、`issues/01`、`SPEC.md` 第 6.1 節

## 問題

`issues/01` 拿掉的是**以後不再產生**。Firestore 裡已經有的那些不會消失：

- 已完成的：**留著，那是紀錄**（SPEC 第 6.1 節，永不硬刪除）。
- 未完成的：照樣出現在待辦首頁上，各自一列（`overviewHtml()` 是從現有任務的
  `kind` 動態列出來的）。

而「打電話」那幾張，她已經不做那件事了 —— 留在那裡就是每天看到一列做不掉的東西。

## 要做什麼

**不自動刪，給她一次收掉的路。**

- `domain/todoFlow.js` 加一份 `RETIRED_KINDS = ['打電話', 'Abovee']`，
  並提供 `isRetired(kind)`。
- 待辦首頁：這幾列照樣出現（在 `before` 那一段），但說明改成
  **「這個類別已經取消了 —— 這是舊資料」**。
- `#/todo/打電話` 那一頁的導言講同一件事，並多一顆**「全部勾完成」**。
  走現有的 `tasksData.setDone(ids, true)`，一批一個 commit，所以復原退得回去。
- **不做一鍵刪除。** 勾完成是「這件事處理掉了」，刪除是「這件事不存在」——
  她真的打過的那幾通電話屬於前者。

## 不做

- 不在資料健檢加一項。ADR-0007 定的是「一鍵修正只有兩項有」，
  而這件事沒有「不需要判斷的正解」——「這張還要不要做」只有她知道。
- 不寫一次性的搬移腳本。這個 repo 沒有 migration 這個東西，
  而且能不碰既有資料就不碰。

## 驗證

- `npm test`
- 瀏覽器：造一筆 `kind: '打電話'` 的未完成任務 → 首頁看得到那一列、
  說明講出它已經取消了 → 點進去 → 全部勾完成 → 那一列消失 → 復原退得回去
