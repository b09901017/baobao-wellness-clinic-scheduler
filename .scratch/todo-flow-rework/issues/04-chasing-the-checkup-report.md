# 二返之前還有一站：健檢報告還沒拿到

Status: 待動工
來源：使用者，2026-08-23
動工前先讀：本資料夾的 `spec.md`、`SPEC.md` 第 7 節規則 8、
`CONTEXT.md` 的「健檢」「二返」、`docs/adr/0022`、`0023`

## 原話

> 「一個是記得追蹤健檢報告（通常是兩三周會出來）（完成這個追蹤報告的 todo，
> 也就是拿到報告後會產生下面那個記得約二返的 todo）」

死線問過了：追蹤報告是**健檢結案那天 ＋ 21 天**（設定頁可調）；
約二返是**勾掉追蹤報告那天 ＋ 7 天**。

## 現況

`domain/followups.js`：健檢那一筆標成已完成 → 直接長出「約二返」，
死線是**健檢日 ＋ 7 天**（`DEFAULT_FOLLOWUP_DUE_DAYS`）。

現實裡報告要兩三週才出來，所以那張待辦**一出生就會在第 8 天變紅**，
而且紅著也做不了 —— 報告還沒到，沒有東西可以跟客人約。
一張永遠紅著的待辦最後的下場是她不再看那個顏色。

中間真的少了一站：**去問報告出來了沒。**

## 要做什麼

### 新的任務種類

`domain/followups.js`：

```js
export const REPORT_TASK_KIND = '追蹤健檢報告';
export const DEFAULT_REPORT_DUE_DAYS = 21;
```

放在 `followups.js` 而不是 `taskRules.js`，理由跟 `FOLLOWUP_TASK_KIND` 一樣：
它由**額度與健檢來訪**推導，不由來訪裡的課程類別推導，死線也不是來訪日前一天。

### 鏈條

`syncFollowupTasks()` 現在要走兩段。對每一組配對（健檢額度 → 二返額度）、
每一筆還欠二返的已完成健檢來訪：

| 那一筆健檢的狀態 | 該有什麼 |
|---|---|
| 已完成，沒有追蹤報告任務 | 產生 `追蹤健檢報告`，死線 ＝ 健檢日 ＋ `reportDueDays` |
| 追蹤報告任務還沒勾 | 留著，死線跟著健檢日走 |
| 追蹤報告任務**勾掉了** | 產生 `約二返`，死線 ＝ **那張任務的 `doneAt`** ＋ `followupDueDays` |
| 二返約掉了（`約二返` 勾掉了，或 `owed()` 變 0） | 兩張都收掉未完成的 |
| 健檢被取消／標成未到 | 兩張都收掉未完成的（已完成的不刪，照舊） |

- `doneAt` 是 ISO 字串（`data/tasks.js` 的 `setDone()` 寫的）。取它的日期那一段
  可以借 `domain/confirmations.js` 的 `dayOf()` 的作法 —— 但那支是私有的，
  這裡需要的話搬到 `domain/dates.js` 成為共用的一支，不要抄第二份。
- `doneAt` 讀不出來（舊資料、手動改過）就退回**健檢日 ＋ `reportDueDays`
  ＋ `followupDueDays`**，不要用今天 —— 用今天會讓死線每次讀取都往後跑。

### 既有資料：手上已經有的「約二返」不收掉

Firestore 裡現在就有未完成的「約二返」（她已經在用了）。新規則跑第一次時，
那幾筆會找不到對應的追蹤報告任務，照上面的表會被判成「不該存在」而收掉 ——
**那等於把一件真的還沒做的事默默刪掉。**

所以加一條：**那一筆健檢已經有一張未完成的「約二返」時，就當作報告那一段
已經走過了** —— 不補產生追蹤報告，也不動那張約二返。

### 設定

`DEFAULT_SETTINGS` 多一個 `reportDueDays: 21`，設定頁「排序權重」旁邊那一區
（`followupDueDays` 已經在那裡）加一個欄位，說明寫「健檢做完幾天內要去問報告。
報告通常兩三週出來」。

## 不做

- **不自動幫她問報告**（ADR-0002）。
- **不把「報告拿到了沒」存成健檢來訪上的欄位。** 那張任務的 `done` 就是那個狀態，
  存第二份就會有兩個地方講同一件事而且會不一致。
- 不改「買幾次健檢就有幾次二返」的額度規則（ADR-0022 那一半還活著）。
- 不改 `owed()` 的定義。
