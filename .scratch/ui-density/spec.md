# 介面密度與動線的第二輪調整

Status: done

第 12 步（`.scratch/ui-redesign/`）上線之後的回饋。一句話：
**手機上每樣東西都太大，而且一排標籤會把底下真正要看的內容擠掉。**

## 使用者提出的九件事與處理方式

| # | 原話重點 | 做了什麼 |
|---|---|---|
| 1 | 畫面太緊湊，元件太大，想要留白 | 字級與元件高度整體收小一級（`tokens.css`）。點擊區仍然 44px，但改用 `::after` 撐感應範圍，視覺高度可以是 28–34px |
| 2 | 客戶頁的標籤丸太大、換行壓到下面 | 新的 `.chiprow`：不換行、左右滑、負邊界捲到螢幕邊緣 |
| 3 | 不要「剩餘快用完 / 會籍快到期」，要能改排序 | 改成排序丸（最近來過／最久沒來／新加入的／喜好程度／姓名）加一組課程丸。ADR-0019 |
| 4 | 詳情頁不直觀；要備註（多則、彩色）；順序要換 | 整頁重排，不再是一疊白卡。ADR-0018 + ADR-0019 |
| 5 | 壓表也要縮小，不要「快到期」 | 同上；「結束這批」移到頁尾的小標籤 |
| 6 | 點顧客要置中浮出、左右滑換下一位 | `.deck`，用 CSS scroll-snap。ADR-0017 |
| 7 | 日曆的丸子、換月份、整個日曆都要縮小 | 控制項收成兩列；月檢視格子與色條縮小 |
| 8 | 日曆點日期要像 TimeTree | 月曆留在原地，那一天從底部滑出來。ADR-0018 |
| 8b | 字體要好看，離線再退回原本的 | Noto Serif TC / Noto Sans TC / Inter，非阻塞載入。ADR-0016 |
| 9 | 整體縮小、iPad 一行兩張卡、多用底部滑出與置中卡片 | `.cardgrid`、`components/sheet.js`、`.deck` |

## 兩處與原話不同的地方

**「不能的時間」插在「這個月」與「額度」之間。** 使用者列的順序是
名稱 → 備註 → 這個月 → 額度 → 來訪 → 隨手記 → 任務，沒有提到本輪可用性。
它沒有被拿掉，而是排在「這個月」後面 —— 那兩段回答的是同一個問題
（這個人什麼時候能來），分開放會讓她在兩個地方各看一次。

**方案範本上的「會籍（月）」留著。** 使用者說的是客戶身上不需要會籍到期日，
而範本上的會籍月數是方案文宣本來就有的資訊（見 `CONTEXT.md` 的「方案」）。
它現在只顯示、不再拿去算任何東西。

## 驗證方式

`npm test` 之外，這一輪是用假的 Firebase SDK 把真的畫面跑起來截圖看的
（Playwright + 攔截 `firebasejs` 與 `firebase-config.js`）。抓到兩個只有在
瀏覽器裡才看得到的問題：底部面板掛在 `<body>` 上、換頁時不會消失；
月檢視的色條在 flex 容器裡吃不到 `text-overflow`，名字被從中間切一半。
那份腳本沒有進版控 —— 它依賴一份假資料，不是測試。
