# 日曆上是四類：客戶來訪、待辦、休假、行事備註

Status: 待動工
來源：使用者，2026-08-23
動工前先讀：本資料夾的 `spec.md`、`issues/01`、`SPEC.md` 第 8.6 節、
`docs/adr/0015`、`0020`、`0039`、`0040`

## 原話

> 「不用個人行程，我覺得我需要的類別應該是 1. 客戶（來訪）2. todo 3. 休假 4. 備註」
> 「要記得也更新那個漂浮泡泡以及顏色配置，不能和客戶（來訪）的顏色重疊的」

## 現況

`views/calendar.js` 的 `KINDS` 是三顆：來訪 / 個人行程 / 休假。
`domain/events.js` 的 `CATEGORIES` 是 `personal` / `leave`。

## 要做什麼

### 改名（**id 不動**）

| 現在 | 改成 | 動什麼 |
|---|---|---|
| 來訪 | **客戶來訪** | `views/calendar.js` 的 `KINDS` label |
| 個人行程 | **行事備註** | `domain/events.js` 的 `CATEGORIES[0].label`、`CONTEXT.md` |
| 休假 | 休假 | 不動 |
| — | **待辦**（新） | 見下 |

`events` 文件裡的 `category: 'personal'` **一個字都不改**。改的是 label，
不是資料 —— 這是這一支唯一需要小心的地方。

`CONTEXT.md` 那一條改名之後，**_Avoid_ 那句要留著並加強**：
「不可以簡稱『行程』或『備註』」——「備註」現在是客戶身上那種彩色小丸的名字，
而「行程」是「來訪」的禁用同義詞。改名讓兩個坑都變近了。

### 第四顆篩選：待辦

- `KINDS` 加 `{ id: 'note', label: '待辦', cls: 'kind-todo' }`，排在客戶來訪後面
  （照流程：來訪 → 待辦 → 行事備註 → 休假）。
- `load()` 多讀一份 `notesData.listBetween(from.from, to.to)`，
  跟現有那四個一起放進 `Promise.all`，不多一輪往返。
- `countLine()` 把待辦算進去（`N 筆待辦`）。

### 畫法：**用記號，不用色相**

新 token（`tokens.css` 淺色與深色**兩份都要**）：

```css
--cal-todo: <墨色，字對底 ≥ 4.5:1>;
--cal-todo-bg: <很淡的中性底>;
```

- **月檢視**：一格寬的色條，標題前面加 `☐`（沒勾）或 `☑`（勾了）。
  勾掉的整條 `text-decoration: line-through` 並降到 60% 不透明度 ——
  她要看得出「這件事處理掉了」，不是看不到它。
  借 `visitAsBar()` 的作法寫一支 `noteAsBar(note)`，餵進同一次 `layoutMonth()`。
- **週／日檢視**：跟整天的行程一起釘在最上面（`allDay` 那一區），同樣的記號與刪除線。
- **`.kind-todo` 不吃 `--evcolor-*`**：待辦不能自己挑顏色（ADR-0040 給的是
  個人行程，因為「公出／演講／休假」之間的差別只有她知道；待辦之間沒有那種差別）。

### 懸浮泡泡多一條路

```
＋ ─┬─ 新增來訪        （people 圖示）
    ├─ 新增待辦        （pencil 圖示，跟待辦首頁那顆泡泡同一個）
    └─ 新增行事備註    （calendar 圖示；進去可以切成休假）
```

「新增待辦」開的是 `issues/03` 那張小表單，日期預設是**當下打開的那一天**
（從某一天的面板進來就是那一天，從頁面右下角進來就是今天）。

## 一起要檢查的

- `SPEC.md` 第 8.6 節整節（「上面有兩種各自獨立的東西」現在是三種資料四類）

  並寫明第七種**不吃色相**
- `domain/events.js` 的 `describeCategory()`、`ui/views/eventEditor.js` 的文案
- `public/sw.js` 的 `SHELL`（沒有新檔案就不用動，有的話要加）
- `tests/events.test.js`、`tests/calendar.test.js`
- 補一支 ADR：**日曆上的第四類是待辦，它用記號分辨而不是第七個色相**

## 不做

- 不改 `events` 的資料。
- **不把待辦做成 `events` 的第三個 category。** 見 `spec.md`：那會變成兩份資料。
- 不讓任務（`tasks`）上日曆。
