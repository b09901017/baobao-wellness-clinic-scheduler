# 隨手記可以掛一個日期

Status: 待動工
來源：使用者，2026-08-23
動工前先讀：本資料夾的 `spec.md`、`SPEC.md` 第 8.1 節、
`CONTEXT.md` 的「隨手記」、`.scratch/quick-capture/issues/01`

## 原話

> 「希望可以多一個日期（可以是今天或是跳出日曆讓我選日期）的選擇（不一定要選）
> 但是可以選然後就會紀錄到日曆的 todo 類別」

## 要做什麼

### `domain/notes.js`

- `normalize()` 多一個 `date`：`'YYYY-MM-DD'` 或 `null`。
  空字串一律轉 `null`（同 `customerId` 那一段的理由：「掛了一個叫空字串的日期」
  跟「沒掛日期」在查詢上是兩件事）。
- `validateNote()`：有填就要是合法日期（借 `domain/dates.js` 的 `isValidDate()`）。
  **不擋過去的日期** —— 她會補記昨天那一件。
- 新增 `datedIn(notes, from, to)`：日期落在範圍內的，日期舊的在前，
  同一天照 `createdAt`。日曆讀它，不要在畫面裡自己 filter。
- `sortNotes()` 不動 —— 待辦首頁那一塊的順序（沒勾的在上、新的先）跟日期無關。

### `data/notes.js`

```js
/**
 * 有日期、而且落在這段範圍裡的。日曆用。
 * 含已經勾掉的 —— 日曆上勾掉的要畫成刪除線，不是消失。
 * 需要 (deletedAt, date asc) 複合索引。
 */
export function listBetween(from, to)
```

`date == null` 的那些不會被撈到（Firestore 的型別排序把 null 排在字串前面，
`date >= from` 就把它們濾掉了）—— 這是對的，沒有日期的本來就不上日曆。

### Rules 與索引

- `firestore.rules` 的 `validNote()` 多一條：`date` 沒填或是字串。
  跟其他欄位一樣，Rules 只擋型別，格式在前端擋（SPEC 第 6.7 節）。
- `firestore.indexes.json` 補 `(deletedAt asc, date asc)`。

### 三個輸入的地方都要有日期

**抽一支共用的 `ui/components/noteForm.js`**，三處共用欄位與讀取：
右下角泡泡（`views/home.js` 的 `quickBody()`）、`#/todo/notes` 那一頁、
日曆上的待辦編輯（`issues/03`）。不共用的話這個欄位會有三份寫法，
而三份遲早會有兩份對不上。

日期欄長這樣（**兩顆丸子 ＋ 一個日期輸入**，不是一開始就攤開一個日曆）：

```
[ 今天 ] [ 挑日期 ]        ← 都沒按 = 不掛日期
```

- 「今天」按下去直接填今天，**一次點擊完成**。這是最常見的那一種
  （「他剛剛說下次記得帶健保卡」通常就是今天記、今天處理）。
- 「挑日期」展開一個 `<input type="date">`，用系統原生的日曆 ——
  自己畫一個小日曆是壓表那一頁才需要的（那裡要標紅、標休假），這裡不需要。
- 選過之後那一排變成 `[ 8/25 ✕ ]`，叉叉拿掉日期。
- **預設是沒有日期。** 泡泡那一支的標準是「三秒內記完」
  （`domain/notes.js` 的檔頭），多一個必填欄位就毀了它。

### 顯示

- 待辦首頁那張卡與 `#/todo/notes`：有日期的在文字前面加一顆日期小標籤
  （`8/25`），過期沒勾的用逾期色。
- 客戶詳情頁的隨手記一樣。

## 不做

- **不做時間。** 她選的。
- 不做重複、不做提醒推播。
- 不因為有日期就把它變成任務 —— 任務要有死線且來自來訪（`CONTEXT.md`），
  隨手記的日期是「我想在這天處理」，不是死線。這條界線要寫進 `CONTEXT.md`。

## 驗證

- `npm test`，新測試涵蓋 `normalize()` 的空字串、`validateNote()` 的爛日期、
  `datedIn()` 的邊界（`from`、`to` 當天都要算進去）
- 瀏覽器：泡泡點開 → 打字 → 按「今天」→ 送出 → 那一筆帶著今天的日期
- 瀏覽器：不按任何日期鈕 → 送出 → `date` 是 `null`，行為跟現在一模一樣
