## 三、找到的問題

### P1（小）：幾乎全白、只有細線的圖會被當成「空白」，講成「照片讀不出來」
- 哪一條：拍照那一層（`ui/components/photo.js` 的 `drawTo()` ＋ `looksBlank()`）
- 看到什麼：自己畫的療程單（白底、細黑線、細字）從相簿選進去，app 說「有一張照片讀不出來（可能不是照片，或檔案壞了）。改按中間的快門在 app 裡拍」；同一張圖的 `createImageBitmap` 讀得開
- 期待：能讀的圖不該被擋
- 為什麼：`looksBlank()` 只在整張圖抽約 400 個點，每個色差都不超過 3 就當成空白（為了抓 Safari 超過 canvas 上限畫出一片空白）。幾乎全白的圖抽到的幾乎都是白的
- 重現步驟：
  1. 開 `https://wellness-clinic-staging.web.app/#/settings/treatment-sheets`（須先登入）
  2. 開發者工具 console 用 canvas 畫一張 1000×1200、白底、只有幾條 2px 黑線的 PNG，轉成 File
  3. 設定那個頁面上拍照層的 `[data-cam-album-input]` 的 `files`，派 `change` 事件
  4. 拍照層下方講「有一張照片讀不出來…」，托盤是空的
  5. 同一張圖加一層紙張漸層（multiply 疊 #f8f5ee → #d9d4c6）再重做 → 讀得進去
- 影響：真的紙本照片有光影，不會中；**手機相簿裡的乾淨螢幕截圖（白底表格）有機會中**。她之前拍 Abovee 螢幕沒遇到，所以先記著、不急

### P2（中）：文宣辨識經畫面流程兩次失敗、第三次才成功
- 哪一條：設定 → 方案範本 → 右上「拍文宣」（`masterList.js` → `camera.js` 的 `sendAll()`）
- 看到什麼：從相簿選一張自己畫的文宣（有紙張漸層，不是 P1 那種）→ 按「送出 1 張」→
  第一次「辨識中…」停了超過 100 秒，最後講「第 1 張：辨識失敗，再試一次」；按再試，約 30 秒又講同一句；再按一次，約 10 秒成功。
  **同一張圖直接呼叫 `extract('planFlyer', file)`（9 秒）一次就成功**
- 期待：跟另外三種單子（訂購單、Abovee、療程單，都是 10～20 秒內第一次就成功）一樣
- 失敗那句沒有講原因（`failureSentence()` 沒帶 reason），我沒拿到 `err.reason`
- 我的猜測（沒驗證）：Function 或 Gemini 偶發很慢／逾時，不一定跟文宣這一種有關。**只有一組樣本**，不確定是 app 的問題
- 重現步驟：
  1. 登入 staging → `#/settings/plans` → 右上「拍文宣」
  2. 相機層下面的「相簿」input 塞一張文宣圖（console 用 `draw-flyer` 那段畫，見 `draw-*.js`）
  3. 按「送出 1 張」，每 10 秒看一次 `.cam__say`
  4. 若又失敗：在 console 跑 `const m = await import('/js/data/ai.js'); try { await m.extract('planFlyer', file) } catch (e) { console.log(e.reason, e.details, e.code) }` 讀出原因
- 建議：下一次有機會時重試幾次看是不是常態；若是，讓失敗那句帶上原因（逾時／被擋／模型錯）
