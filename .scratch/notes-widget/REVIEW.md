### R1 打字時收起了導覽列，右下角那一顆泡泡還站在鍵盤上面

- **在哪裡**：`app.css` 的 `@media (max-width: 899px) { html[data-keyboard] .app__nav { display: none } }`（ADR-0181 決定 2）。`.fab`（`app.css:1166`，`position: fixed; bottom: calc(66px + …)`，54px 的圓）沒有跟著收
- **什麼情境會錯**：`interactive-widget=resizes-content` 之後版面縮成鍵盤上面那一截，`position: fixed` 的東西全部跟著站到鍵盤上面 —— 以前它們在鍵盤底下看不到。導覽列收了，泡泡沒收：首頁（`quickFab()`）與 `#/todo/notes` 打字時，右下角離鍵盤上緣 66～120px 那一塊被一顆 54px 的圓蓋著。
  最可能撞到的是**首頁那張卡**：它是頁面裡的一格（不是貼底的抽屜），框的右邊是「記」那一顆，底下是這一輪新加的兩排（跳出來的名字、今天／挑日期／掛給誰／給營養品）。01 在 HTC 上點過的四個入口裡**沒有這一格**（點的是抽屜、改文字卡、日曆編輯器、新增客戶）
- **沒有實機重現**：Chrome 把聚焦的那一格捲到哪裡（置中還是貼著鍵盤）決定撞不撞得到，桌機的 `setViewportSize()` 不會替聚焦的那一格捲。理由跟 ADR-0181 收導覽列同一條：打字時她用不到它、它站到鍵盤上面吃掉一截
- **建議**：同一條規則加 `html[data-keyboard] .fab { display: none; }`（ADR-0181 決定 2 那一句跟著改成「導覽列與右下角那一顆」；ADR-0181 還在這一支 PR 裡、沒合進 develop，直接改那一句）；E2E `100` 加一支：首頁那張卡的框聚焦、`setViewportSize` 縮一半 → `.fab` 看不到。
  **手動驗收清單加一條**（她在 HTC 主畫面那一顆點）：首頁那張卡的「記一筆…」打「王」→ 框、跳出來的名字、四顆丸子、「記」都看得到嗎
- **嚴重程度**：中（首頁那一格是她最常用的入口之一；修法一行）

### R2 「會作用在幾天」同一組講出三個數字

- **在哪裡**：同一件事四種算法 ——
  選單那一行小字 `note.openMenu()` 的 `linkedDays = Math.max(不同的日子, 2)`；
  改文字、掛給誰那張卡（`askText()`／`askCustomer()` 的 `also`）與日曆編輯器那一行（`calendar.js` 的 `data-linkhint`）寫「另外 ${peers.length} 天」—— 數的是**筆**；
  存完的 toast（`runAction()` 的 edit／who）寫「共 ${peers.length + 1} 天」—— 也是筆；
  勾掉的 toast 讀 `setDone()` 回的 `linkedDays`（不同的日子）；清單那一顆是 `linkedBadge()`（不同的日子，只剩一天寫「共 N 筆」）
- **什麼情境會錯**：一組三天（11/6、11/8、11/10），在 11/8 那一筆按「改日期 → 拿掉日期」（她做得到的一條路，選單上講「只改這一天」）。之後長按 11/6 那一列：
  清單「共 2 天」、選單「2 天一起改」、改文字卡「另外 2 天會一起改」、存完「改好了（共 3 天）」、勾掉「勾掉了（共 2 天）」。改日期改到跟另一天撞也一樣。lessons 五：講的要是真的會發生的事，而同一個動作的三句互相對不上
- **建議**：`domain/notes.js` 收一支（例 `linkedReach(note, peers)` → `{ days, notes, label }`，照 `linkedBadge()` 那一條分「天／筆」：兩天以上講天、只剩一天講筆），選單、兩張卡、日曆編輯器那一行、兩種 toast 都讀它。`setDone()` 回的 `linkedDays` 換成同一支算的（它是重讀的那一組，來源照舊）
- **紅燈測試**：`tests/notes-linked.test.js` —— 三筆、一筆沒日期、兩筆同一天，各算一次，選單小字、卡片抬頭、toast 三個字串要講同一個數字同一個單位
- **嚴重程度**：低（要先把一組裡的一天拿掉日期或改到撞才會遇到）

### R3 從「已勾掉的那一筆」複製：toast 講有連在一起、其實沒有；再複製一次同一天會多一份

- **在哪裡**：`domain/notes.js` 的 `copyPlan()` —— 來源已經勾掉時 `linkId = newLinkId`（每一次都是新的 id）、`members = []`（ADR-0179 決定 2：新的那幾筆自己一組，它不拉進來）；
  `note.js` 的 `copyAction()` 存完的 toast 只看開關：`複製到 ${n} 天${picked.linked ? '：勾一天，其他天一起勾' : ''}`；小月曆上「已經有了」那幾天（`askCopy()` 的 `taken`）是**它自己那一組**的
- **什麼情境會錯**：
  1. 長按一筆已勾掉的 →「複製到別天」→ 點**一天**、開關開著 → toast「複製到 1 天：勾一天，其他天一起勾」。新的那一筆自己一組、只有它一筆，跟原本那一筆也沒連 —— 沒有「其他天」（lessons 五）。點兩天時那兩筆彼此連著，但跟原本那一筆照樣沒連，卡片上那一句「連在一起：勾一天，其他天一起勾」也沒講
  2. 同一筆已勾掉的再打開一次小月曆：上一次複製出去的那幾天**沒有圈起來**（不在它那一組），再點同一天就多一份。ADR-0179「為什麼」那一段寫「按兩次不會多一份」—— 只有還沒勾、連在一起時成立
     （同一張卡連按兩下有 `key` 擋著；開關關掉的是她自己選了各自獨立，再複製一次是她要的，不算）
- **建議**：
  - toast 照**真的連起來的**講：`copyTo()` 回 `linkId` 與這一次建了幾筆，連在一起的那一組（含原本那一筆的話算它）只有一筆時不講「勾一天，其他天一起勾」；已勾掉的來源，卡片上那一句改成「新的那幾天連在一起」或在「複製到 N 天」底下講一句「這一筆已經勾了，新的那幾天自己一組」
  - 冪等：已勾掉、自己沒有 `linkId` 的那一筆用**它自己的 id** 當新的那一組的 `linkId`（它自己不寫 `linkId`，所以不會跟新的那幾筆連在一起；`listLinked(note.id)` 下一次就讀得到那幾天 → 圈起來、`skipped`）。它自己已經在一組裡的，照現在用新的 id（或寫清楚不冪等）；ADR-0179 那一句跟著改準
- **紅燈測試**：`tests/notes-linked.test.js` —— `copyPlan(已勾掉的, ['2026-11-08'], { linked: true, group: [上一次複製出去那一筆], newLinkId })` → `skipped` 有 11/8；toast 的字串（拿出來成純函式）一筆時不講「其他天」
- **嚴重程度**：低

### R4 資料健檢「連在一起的隨手記勾得不一樣」：日子排錯、沒有連結

## 查過、不成立或不用改的

- **點跳出來的名字時框失焦、整排先被收掉**（段二自己標的弱點）：做了一個只有輸入框＋一排丸子的小頁面，照 `wireSuggest()` 的寫法（`pointerdown`／`mousedown` 擋預設、`blur` 收起來），Playwright 開觸控模擬（`hasTouch`、`isMobile`、`tap()`，走 Chromium 的手勢那一條）點：
  沒有 `blur`、`click` 照到、值換好、焦點留在框裡。滑鼠那一條也一樣。真的鍵盤（注音組字）照舊要她在 HTC 上點
- **`display: contents` 讓 `hidden` 失效**：全站有 `[hidden] { display: none !important }`（`app.css:25`），`[data-quickwho][hidden]` 另外也寫了；名單 `.notewho__list` 本來就 `flex-basis: 100%`，`order: 1` 落在那一排底下
- **沒有 `linkId` 的隨手記多了一次讀取**：`update()`／`setDone()` 先 `getOne()` 重讀 —— `repo.commit()` 本來就為了稽核的 before 讀同一筆，離線時兩次都從快取回來，行為一樣（寫的還是整份 patch、一個 commit、復原照舊）
- **連在一起的寫入能不能復原**：一組一起變寫在同一個 commit（`writeAll()`），`withUndo()` 只在剛好一批時給復原 → 給得出、而且整組一起退；複製是一個 commit 的 create → 復原是軟刪除那幾筆
- **複製按兩次、失敗重按**：`withSaveState` 帶 `key`；連在一起時 `linkId` 是原本那一筆的 id、`copyTo()` 重讀之後同一組那一天已經有的進 `skipped` → 不多一份。不連在一起（開關關掉）失敗重按會多一份 —— spec 那一條問的是「同組的」，不算
- **`renderNotesLink()` 的 `replaceState`**：保留 `history.state`（`__layer`），之後 `openQuick()`／選單照常 `pushLayer`，返回先收那一層；網址換回 `#/todo/notes` 之後小工具再送同一條網址照樣觸發 hashchange
- **Rules**：`linkId` 沒有／null／1～64 字、跟 `entitlementId` 不能同時有；不經過 `normalize()` 的建立路（買營養品長的提醒、交付、匯入）不帶 `linkId`，`!('linkId' in d)` 放行
- **資料健檢讀到已刪除的**：`data/health.js` 讀 `repo.list('notes')`（不含已刪除），刪掉一筆不會被當成勾得不一樣
- **選了日期之後那一顆「✕」在丸子那一排裡**：issue 02 寫「換到那一排底下自己一行」，實際是跟著日期留在那一排（`9/1(二) ✕`），360 寬時把「給營養品」擠到第二行。
  spec 四（她看過的那一份）寫的是「放不下（例如選了日期字變長）才換到第二行」—— 日期本來就在那一排裡，✕ 是日期自己的那一顆。照 spec，不改；02 的「做完時留下的」也寫了、截圖看過
- **「拆開這一天」、「複製到別天」不靠長按的路只有日曆那張卡**（ADR-0060）：沒有日期的隨手記只有長按 —— 跟既有的「改文字」「掛給誰」同一個舊缺口，不是這一輪造成的；首頁與隨手記那一頁標題旁的 `?` 講了長按做得到什麼

## 段四的手動驗收清單一定要有的

01 的判準「正在打字的那一格與它的『存』那一顆看得到嗎？（每一個入口）」HTC 上只點了四個入口，其餘交給清單（01 自己寫了）。段四寫清單時照這幾條（**寫的人要在本機模擬器真的走過**；鍵盤那幾條只有她在 HTC／三星的主畫面那一顆點得出來，staging 部署之後）：

- **首頁那張卡的「記一筆…」**（R1）：打「王」→ 框、跳出來的名字、四顆丸子、「記」都看得到、右下角那一顆沒蓋住
- 日曆 ＋ → 待辦：鍵盤開著時「記下來」要在抽屜裡往下捲一點（01 寫了）—— 按鍵盤上的 Enter 也送得出去（`<form data-noteform>` 有 submit 那一顆）
- 注音：打「ㄨㄤˊ」選字中不跳一排名字、選好「王」才跳；點一位之後鍵盤不收、游標在名字後面
- 01 沒逐一點的：客戶詳情備註編輯、訊息框、加購／批次建立的數字、長備註「寫給誰」、長備註／備忘錄編輯器、`confirmWithReason`、拍 Abovee 與療程單的搜尋、壓表那疊卡片的時間、設定那幾頁、LINE 回覆模板、客戶清單與壓表的搜尋
- iPad 主畫面那一顆：打字時版面沒有被讓開兩次、底部沒有多一塊空白（Safari 不認 `interactive-widget`）
- 深色主題：「共 3 天」那一顆、跳出來的名字（綠框綠字）、長按選單最上面那一排日子
- WebAPK 會不會接走 `#/todo/notes/note/<id>` 這兩條網址：10 寫明留給 06（裝小工具時在 HTC 上試），**不在這一支的清單裡**
