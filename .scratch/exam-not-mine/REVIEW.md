## 二、要修的（段五）

### 1. 確認框把新加的一般段講成「三返是加約的、不扣」【中低，重現】

- **哪裡**：`public/js/domain/consequences.js` 的 `nthLabels(visit)`（約 621 行；`bookingConsequences()` 259 行用）
- **情境**：一位那一天已經排了一段三返，日曆新增（或壓表）再加一段**扣額度**的復能 → 確認框寫「三返是加約的 —— 這一場不扣任何次數，客戶身上的數字一個都不會變」。
  這一場（復能）會扣。`bookingConsequences({ added: [1] })` 跑出來就是這一句
- **為什麼這一輪修**：既有的（段一中途發現記過），但這支函式這一輪動過（多跳過帶標記的段），而 lessons 五「確認框只講真的會發生的事」—— 講錯的正好是她最在意的次數
- **建議**：`nthLabels(visit, added)`，照旁邊 `giftNames(visit, coursesById, added)` 的寫法只看這一次新加的段；先寫一支會紅的單元測試

### 2. 三返的提醒寫成「二返 還沒選醫師」【低，重現】

- **哪裡**：`public/js/domain/visits.js` 的 `assignmentWarnings()` 那一圈（約 2161、2164 行與診間那幾句，印 `course.name`）
- **情境**：`slotFromPicks({ examNotMine: true, nth: 3 })` 組一段沒選醫師的 → `validateVisit()` 的 warning 是「第 1 個時段：二返 還沒選醫師」。
  一般的 n返 本來就這樣（借二返那門課），但這一輪讓「三返、醫師還沒定」變常見（日曆、壓表新增都會碰到）
- **建議**：那一圈開頭算一次 `const name = nthLabel(nthOf(slot)) ?? course.name`（同一支 2153 行「排在接的那一次健檢之前」已經這樣寫），醫師、診間那幾句都用它

### 3. 編輯器的「保留」那條路安靜地丟掉她改的東西【中低，讀程式確認】

- **哪裡**：`public/js/ui/views/visitEditor.js` 的 `readNotMineSlot()`（約 1200～1236 行）＋ `public/js/domain/slotDraft.js`（`notMine` 時課程只問 `examNotMineCourse()`，`null` → `fail('先選要做什麼')`）
- **情境**：二返那門課後來**停用了**，或主檔上變成**兩門**二返課（另一門課的 `followupCourseId` 指到別門）。編輯器照 `notMineOption(…, { keep })` 照樣畫那一顆、
  `readNotMineSlot()` 自己也退回這一段原本的課程（註解寫「二返那門課後來停用了：這一段照舊是它」）—— 但 `slotFromPicks()` 不知道那一門，回 `null`，
  於是走 `!made` 那條路：回的是 `{ ...原本那一段, … }`，**她剛改的開始時間、診間、治療師、醫師、時長全部沒套上**；`validateVisit()` 照樣放行（課程是某一門的二返，`isFollowupCourse()` 認得），
  存下去的是舊值，一句都沒講。lessons 二「列出來的每一顆，按下去存得下去嗎」的形狀
- **嚴重度**：她主檔上現在剛好一門、而且開著，**今天碰不到**；碰到的那一天是安靜地存錯
- **建議**：`slotFromPicks()` 的 `notMine` 那一支收一個退路（例如 `picks.courseId`：是某一門的二返、`isFollowupCourse()` 認得才用；`examNotMineCourse()` 找得到時照舊用它），
  編輯器把這一段原本的課程傳進去 —— 驗證與組時段講同一句話（都認「任何一門二返」）。單元測試：兩門二返課、停用兩種，改時間存得下去而且是新的時間。
  修完照 ripple-check 看拍 Abovee 的 `picksOf()`（新的列，不帶 `courseId` 就跟現在一樣）

### 4. 文件：照寫的點會點反或少一步【低】

- **a. 收合已經展開時再點會收起來**：她要用這一顆的那種客人（沒有還有剩的額度）`foldOpen()` 一打開就是展開的；
  `docs/操作手冊.md` 388 行（壓表）、394 行（拍 Abovee 第 1 步）、`docs/常見問題.md` 505 行照寫先點「送的／體驗／其他…」，反而把它收起來、「其他 ▸」看不到了。
  383 行（日曆新增）有寫「一打開就是展開的」，另外三處沒有。E2E `85` 的客人有三選一額度（收合收著），量不到這一種。
  建議三處補「（已經展開的話直接點「其他 ▸」）」
- **b. 邊界測試清單 R3**：編輯器把那一段換回二返額度時，「這是哪一次健檢的」**不會先選好**（編輯器從來不預選，`visitEditor.js` 約 1145 行退回這一段原本的 null）。
  R3 的步驟少了「按那一次健檢」，驗收標準卻寫「接著那一次健檢、約二返收起來」。建議步驟補那一下；「約二返」收不收、確認框寫不寫「扣 1 次」段五走的時候照實寫（**未確認**）
- **c. 操作手冊在講規則**（判斷題）：「健檢不是我排的二返、三返」那一節的「跳紅字的兩種」與「它長什麼樣」把紅字、待辦、試算表的規則重講了一遍。
  文件分工：操作手冊「一條業務規則都不定義」，上一輪審查（prelaunch-fixes REVIEW）也照這條改過兩處。建議留「按了會跳紅字就是按錯了，換回一般那一顆」這種操作上的話，規則收成一行連到 ADR-0169
- **d. `CLAUDE.md`「健檢不是我排的」那一列的試算表那一句**只講帶標記的；`rowNthOf()` 也把**沒有標記、沒有額度的舊二返**從「課程名（不算次數）」搬進「二返（不算次數）」、排到體驗與送的前面（ADR-0169 有寫）。
  建議那一句補半句「舊資料裡沒有額度的二返併進同一列（S4）」，下一個改試算表的人才知道那一列不只帶標記的

## 三、提過、這一輪不修的

| # | 是什麼 | 為什麼不修 |
|---|---|---|
| 1 | 同一張照片上還沒存的健檢接不上 n返，那一列講「健檢不是你排的話…」（段三中途發現） | 既有的限制（確認層的「＋ n返」只看存著的健檢，ADR-0145 只做了二返）；句子是條件句，不算講錯；她真的按了「健檢不是我排的」會跳「有 … 的健檢接得上」紅字（`visitsForCheck()` 把同一次要記的健檢算進去了，Spec 軸用 `photoDayPlan()` 跑過）。三返通常跟健檢隔幾個月、很少在同一張照片上。要做就是自己一輪（n返 照 ADR-0145 那一套接同一張照片上的健檢） |
| 2 | 照片是二返、身上有二返額度、沒有健檢 → 照舊 `noExam` 那一句，不提這一顆（段三中途發現） | 她的話「沒有二返額度…就送他一個」—— 有額度就照扣；issue 08 過目 S9 定的。按了也會跳「身上還有二返額度」紅字 |
| 3 | `二返` 那門課不是剛好一門時，收合的字照樣寫「送的／體驗／其他…」、「其他」裡是空的 | 她主檔上剛好一門；那一天真的多一門時，跟二、3 的修法一起想 |
| 4 | Repeated Switches：「健檢不是我排的 → n返 → 送的 → 額度」的先後寫了四處（`optionValueOf()`、編輯器 `readDraft()` 的 `key()` 退路、`entRow()` 的 `value`、`slotCard()` 的旗標） | 判斷題。每一處都在各自那一頁的邏輯裡，E2E `83`～`85` 量著帶標記的三返不被當成 n返；收成一支要動三頁，不在這一輪 |
| 5 | Duplicated Code：「第幾返 2～10」那一排組三次、提示字「健檢不是你排的：這一場不扣…」抄三份（`schedule.js` 1518、`aboveeConfirm.js` 786、編輯器） | 判斷題、低。那一排三頁的畫法本來就各自一套（`data-nmnth`／`s${i}-nmnth`／`data-abl-nmnth`）；提示字段五順手收成 `masterData.js` 一個常數也可以，不強求 |
| 6 | 拍 Abovee 的「第幾返」再按一次不會取消（壓表、編輯器會） | 拍 Abovee 的 n返 那一排本來就這樣（`data-abl-nth` 同一種），不是這一輪弄的 |
