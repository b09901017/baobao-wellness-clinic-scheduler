# 手機的返回鍵要做她以為它會做的事

Status: todo
來源：使用者，2026-08-24
動工前先讀：`ui/router.js`、`ui/components/sheet.js`、`ui/components/card.js`、
`docs/adr/0018`、`0020`、`0021`

## 原話

> 「關於回到上一頁，我發現我按手機的返回鍵，很常不是真的回到剛剛那個頁面
> 而是跳到奇怪的頁面，有時候我按返回鍵就是要關掉我剛打開的東西
> 或是回到我點開某個東西之前的頁面，但現在好像都很不直觀 很奇怪？」

## 三個各自獨立的原因

**這不是一個 bug，是三個。** 三個都要修才會直觀。

### 1. 打開的東西不吃返回鍵

底部面板（`openSheet()`）、浮出的資訊卡片（`openCard()`）、二次確認
（`confirmAction()`）打開的時候**沒有推任何一筆瀏覽器紀錄**。所以按返回鍵
不是關掉它們，是**直接跳走上一頁** —— 而 `openSheet()` 又剛好聽了 `hashchange`
把自己收掉，於是畫面上發生的是「面板消失了，而且頁面也換了」。

她說的「我按返回鍵就是要關掉我剛打開的東西」，講的就是這個。

### 2. 「回上一頁」其實是往前走

`router.go()` 是 `location.hash = path`，那是**推一筆新紀錄**，不是退回去。
每一個 `.backlink` 也都是普通的 `<a href="#/...">`，一樣是推。所以：

```
#/customers  →  #/customers/客戶A  →（按左上角「客戶」）→ #/customers
```

瀏覽器的紀錄裡現在有**三筆**，這時候按手機的返回鍵會回到 `#/customers/客戶A`。
她剛剛才從那裡離開，所以感覺是「跳到奇怪的頁面」。逛久了紀錄會越疊越深，
按十下返回鍵才出得去。

### 3. 原地換掉的畫面沒有自己的位置

客戶詳情的「編輯」「加購」「調整額度」、可用性的「記一次」，
都是**把同一個 `el` 的 innerHTML 換掉**，網址完全沒動。所以在編輯表單上按返回鍵，
瀏覽器只知道「上一個網址是客戶列表」—— 她會整個離開這個人，
而且打到一半的東西沒了。

## 要修成什麼樣

一句話：**畫面上多出來一層東西，就多一筆返回鍵退得掉的紀錄。**

| 她做的事 | 按返回鍵應該 |
|---|---|
| 點一天，抽屜滑上來 | 關掉抽屜，留在那個月 |
| 抽屜裡點一筆，卡片浮出來 | 關掉卡片，留在抽屜 |
| 卡片上按鉛筆，編輯器掛進抽屜 | 回到卡片（或那一天） |
| 客戶詳情按「編輯」 | 回到客戶詳情 |
| 客戶列表 → 客戶詳情 | 回到客戶列表 |
| 客戶詳情按左上角「客戶」 | **不該多一筆紀錄** |

## 三支 issue

- `01` 疊上來的東西（抽屜、卡片、對話框）吃掉返回鍵
- `02` 「回上一頁」改成真的往回退
- `03` 原地換掉的編輯畫面要有自己的一站

## 不在這一輪範圍內

- **不改成 History API 路由。** hash 路由是刻意選的（`router.js` 的檔頭：
  Firebase Hosting 不用特別設定就不會 404）。這一輪加的是 `pushState` 的
  **狀態**，網址一個字都不會變。
- 不做「往右滑回上一頁」的手勢。
