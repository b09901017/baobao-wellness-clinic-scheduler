# 原地換掉的編輯畫面沒有自己的一站

Status: todo
來源：使用者，2026-08-24（spec.md 的原因 3）
動工前先讀：`ui/views/customerDetail.js`（`paintEdit` / `paintEntitlement`）、
`ui/views/availability.js`（`paintForm`）、`issues/01`

## 病灶

客戶詳情的「編輯」「加購」「調整額度」、可用性的「記一次」與「編輯」，
做的都是**把同一個 `el` 的 innerHTML 整個換掉**，網址完全沒動。

所以她在編輯表單上按返回鍵，瀏覽器只知道「上一個網址是客戶列表」——
整個離開這個人，而且打到一半的東西沒了。

同一個問題也在壓表那一頁（卡片牆 ↔ 記錄面板）、匯入那幾頁。

## 要做什麼

用 `issues/01` 那支 `pushLayer()`。**它不是抽屜專用的，是「畫面上多了一層」
專用的** —— 原地換掉的編輯畫面就是一層。

```js
function paintEdit(ctx) {
  const layer = pushLayer(() => paint(ctx));   // 返回鍵 → 畫回詳情
  ...
  // 「取消」與「存好了」那兩條路呼叫 layer.pop()
}
```

三件事要一起做對：

1. **返回鍵 → 退回原本那一頁**，而不是離開。
2. **「取消」那顆按鈕走同一條路**（`layer.pop()`），不要留兩份把畫面畫回去的程式。
3. **存完也走 `pop()`**，然後才重讀資料重畫 —— 不然存完之後按返回鍵
   會回到那張已經存過的表單。

### 要處理的地方

動工時 grep「把 `el.innerHTML` 換掉但沒有換網址」的地方，至少有：

- `customerDetail.js`：`paintEdit()`、`paintEntitlement()`
- `availability.js`：`paintForm()`
- `schedule.js`：卡片牆 ↔ 記錄面板（**這一個要特別小心**，見下）
- 匯入那幾頁的分步驟畫面

### 壓表那一頁要特別小心

記錄面板是「疊在卡片牆上面、置中浮出、左右滑換下一位」（ADR-0017），
而且她一個晚上會開關幾十次。這裡推紀錄有兩個風險：

- 左右滑換人**不能**每滑一位就推一筆 —— 那會變成按返回鍵倒著走過二十幾位客戶。
  換人是**取代**同一層，不是疊新的一層（用 `history.replaceState`）。
- 頻率高，會撞到 `issues/01` 提到的瀏覽器限流。

**所以壓表那一頁排在最後做**，前面幾個穩定了再說。做不到就先不做，
並在 Comments 裡講清楚為什麼。

## 一個要一起想的問題

原地換畫面本來就是這個 app 的一個特色（ADR-0018「詳情頁是一頁，不是一疊卡片」、
ADR-0020「日曆從頭到尾不換頁」）。這一條不是要推翻它 ——
**不換頁講的是不要重畫整頁、不要洗掉脈絡，不是「不要有回得去的位置」。**
這句話值得寫進 ADR，不然下一輪有人會拿 ADR-0020 來反對加瀏覽器紀錄。

## 驗證

- 瀏覽器：客戶詳情 → 編輯 → 返回鍵 → 回到客戶詳情（不是客戶列表）
- 瀏覽器：客戶詳情 → 編輯 → 存 → 返回鍵 → 回到客戶詳情（不是那張表單）
- 瀏覽器：客戶詳情 → 加購 → 取消 → 返回鍵 → 離開這個人（只退一次）
- 瀏覽器：可用性「記一次」打到一半按返回鍵 —— 東西會不見，
  **這一點要不要攔一下？** 二次確認「你打的東西還沒存」可能比較好，
  但也可能很煩。先做不攔的，用過再說。
