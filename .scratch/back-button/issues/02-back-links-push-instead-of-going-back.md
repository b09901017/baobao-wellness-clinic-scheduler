# 「回上一頁」其實是往前走一頁

Status: done
來源：使用者，2026-08-24（spec.md 的原因 2）
動工前先讀：`ui/router.js`

## 病灶

`router.go()`：

```js
export function go(path) {
  location.hash = path;
}
```

那是 `pushState` 的語意 —— **推一筆新紀錄**。而全站每一個「回上一頁」都走它，
或走一個 `<a class="backlink" href="#/...">`（一樣是推）。

所以 `客戶列表 → 客戶詳情 → 按「客戶」回去`，紀錄裡有三筆，
按手機返回鍵會回到客戶詳情 —— 她剛剛才離開的地方。

## 要做什麼

### 1. 一支 `back(fallback)`

```js
/**
 * 回上一頁。真的退，不是再推一筆。
 *
 * 只有在「這一次工作階段裡我們自己推過紀錄」的時候才 history.back() ——
 * 她從 LINE 點連結直接落在客戶詳情的話，退回去是 LINE，不是客戶列表。
 * 那種情況用 fallback，而且用 replace 不用 push。
 */
export function back(fallback) { ... }
```

判斷「有沒有東西可以退」不要靠 `history.length`（它算得到別的網站，不可靠）。
**自己數**：`start()` 之後每一次 `go()` 就加一，每一次 `back()` 就減一。
歸零就走 fallback。

`nav.js` 那一層（`issues/01`）也在推紀錄，兩邊要用同一個計數器 ——
所以這一支跟那一支**寫在同一個模組裡**比較安全。

### 2. 全站的返回入口改用它

- `app.css` 的 `.backlink` 現在是 `<a href="#/...">`。改成
  `<button class="backlink" data-back="/customers">` 或者留著 `<a>`
  但攔截 click（`customerDetail.js` 已經是這樣做的，只是攔完又呼叫 `go()`）。
  **傾向留著 `<a href>`**：中鍵、長按「在新分頁開啟」照樣有意義，
  而且沒有 JS 的時候還是走得掉。攔截 click 之後呼叫 `back(那個 href)`。
- 抽一支 `ui/components/backlink.js`（或塞進既有的地方）產生那一段 HTML 並接好
  事件 —— 現在每一頁各自寫一份 `<a class="backlink">`，共 15 處左右。

### 3. `go()` 保留

真的要**前往**某個地方時（點一位客戶、存完跳走）還是用 `go()`。
這一條加的是第二個動詞，不是取代第一個。

## 要小心的

- **存完之後跳走**（例如新增來訪存完 → 客戶詳情）現在是 `go()`。
  那應該是 `replace` 才對 —— 退回去不該回到一張已經存過的空表單。
  這一條先不改，但在 Comments 裡記下來；`issues/03` 會處理到一部分。
- 底部導覽列（首頁／日曆／客戶／…）**保持 `go()`** —— 那是切分頁，不是往回。

## 驗證

- 瀏覽器：客戶列表 → 客戶詳情 → 按「客戶」→ **再按手機返回鍵，離開這個 app
  或回到上一個分頁**，而不是又回到客戶詳情
- 瀏覽器：直接貼一個 `#/customers/xxx` 的網址進去 → 按「客戶」→ 到客戶列表
  （fallback 那條路）
- 瀏覽器：在四五個分頁之間跳來跳去，返回鍵的行為講得通
