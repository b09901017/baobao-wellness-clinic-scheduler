# 抽屜、卡片、對話框要吃掉返回鍵

Status: done
來源：使用者，2026-08-24（spec.md 的原因 1）
動工前先讀：`ui/components/sheet.js`、`ui/components/card.js`、
`ui/components/dialog.js`、`docs/adr/0021`

## 要做什麼

### 1. 一支共用的「疊一層」

新開 `public/js/ui/nav.js`（或塞進既有的 `router.js`，看哪邊乾淨）：

```js
/**
 * 畫面上疊了一層東西。推一筆瀏覽器紀錄，按返回鍵時呼叫 onPop 把它收掉。
 * 回傳的 pop() 給「用叉叉或手勢關掉」那條路用 —— 它要把剛剛推的那一筆退掉，
 * 不然紀錄會越積越多。
 */
export function pushLayer(onPop) { ... }
```

實作重點：

- **推的是 `history.pushState(state, '', location.hash)`** —— 網址一個字都不變，
  所以不會觸發 `hashchange`，路由不會重畫。
- `popstate` 觸發時比對 state，是自己那一層就呼叫 `onPop()`。
- 由使用者主動關掉（叉叉、灰底、Esc、往下拖）時呼叫 `pop()`，
  它做的是 `history.back()`，然後 `onPop` 會照樣被呼叫一次 ——
  **所以關閉的路只有一條**，不會有「叉叉關掉」與「返回鍵關掉」兩份程式。
- **要能疊好幾層**（抽屜 → 卡片 → 對話框）。用一個遞增的序號當 state 的 key，
  維護一個堆疊；`popstate` 時把序號以上的全部收掉（她可能長按返回鍵一次退兩層）。

### 2. 三個元件接上去

- **`openSheet()`** —— 現在的 `hashchange` 監聽**留著**（換頁時要收掉面板，
  那是對的），另外接 `pushLayer`。
- **`openCard()`** —— 同上。卡片疊在抽屜上面，所以會是第二層。
- **`confirmAction()`** —— 二次確認也要吃返回鍵，而且**返回鍵等於取消**
  （resolve(false)）。這一點很重要：破壞性操作的對話框如果被返回鍵略過，
  那顆「刪除」可能會在她以為自己取消了的時候執行。

### 3. 手勢與返回鍵要對得上

`components/sheet.js` 的拖曳（ADR-0021）走的是 `drag.dismiss()`，
那條路也要經過 `pop()`。**往下甩掉面板之後再按返回鍵，不能又退一頁。**

## 要小心的

- **iOS Safari 的 `popstate`**：在 PWA（加到主畫面）裡沒有返回鍵，
  但有系統的左緣滑動手勢，走的是同一條 `popstate`。行為一致就好。
- **`pushState` 太多次會被瀏覽器限流**（Safari 有每 30 秒的上限）。
  她開關面板很頻繁 —— 一個晚上壓表可能開關幾百次。
  **這一點要實際測**：連續快速開關面板 50 次看看會不會被擋。
  被擋的話退路是「只有抽屜與對話框推紀錄，卡片不推」。
- 開第二張面板時 `openSheet()` 會先 `closeSheet({ instant: true })`。
  那條路**不能**呼叫 `pop()`（不然會退掉一頁），要走「直接移除、
  把堆疊上那一層替換掉」的路。這是整支最容易寫錯的地方。

## 驗證

- `npm test`
- 瀏覽器：日曆點一天 → 返回鍵 → 抽屜關掉，還在同一個月
- 瀏覽器：日曆點一天 → 點一筆 → 返回鍵 → 卡片關掉，抽屜還在
- 瀏覽器：往下甩掉面板 → 返回鍵 → 真的離開日曆（不是又退一次）
- 瀏覽器：刪除的二次確認 → 返回鍵 → 等於取消，東西沒被刪
- 瀏覽器：連續快速開關面板數十次，返回鍵仍然一次退一層
- **手機上真的測**（Android Chrome 的返回鍵、iOS 的左緣滑）

## Comments

**2026-08-24 —— done（ADR-0048）。** `ui/nav.js` 的 `pushLayer()`，
抽屜、卡片、二次確認三個都接上了。

**「關閉的路只有一條」是這一支的關鍵。** 由畫面自己關掉時走 `pop()`
（標記 closing → `history.back()`），返回鍵按下去時走 `popstate`。
兩條路最後都會走到同一個 `close()`，差別只有 `fromBack` 這個旗標決定
要不要再退一筆紀錄 —— 沒有這個旗標的話，往下甩掉面板之後按返回鍵會多退一頁。

`openSheet()` 換第二張面板時走的是 `closeSheet({ instant: true })`，
那條路照樣經過 `close()` 所以照樣 `pop()`。

**頻率上限那件事沒有實測。** issue 要求「連續快速開關面板 50 次」，
我在無頭瀏覽器上跑不出 Safari 的限流（那是 Safari 專屬的）。
壓表那一頁因此**刻意沒有接上去**（見 `issues/03`）—— 那是唯一會高頻開關的地方。

**驗證方式**：寫了一支 `navcheck.mjs`（跟截圖腳本同一組假 Firebase），
