# 「問這輪的時間」綁死下個月，也綁死「身上還有沒有次數」

Status: done
來源：她的四件事，2026-09-02（`../spec.md`）
動工前先讀：ADR-0028（問時間是一列不是佇列）、ADR-0033（已發連結是第三種狀態）、
ADR-0036（哪一份算數看在壓哪個月）、ADR-0053（一份就是一個月）

## 症狀

`#/todo/ask` 現在做兩件她沒有要求過的事：

**一、月份是寫死的下個月。**
`renderAsk()` 裡 `month: addMonths(today, 1).slice(0, 7)`，
產生的連結（`invitesData.create({ month })`）與 LINE 訊息都吃這個值。
她今天（9/2）想補問**九月**剩下的那幾天，或想先開始問**十月**，
這一頁一個入口都沒有 —— 而 `newInvite()` 收得下任何月份，
`monthGrid()` 畫得出任何月份，擋住她的只有這一行。

**二、名單綁死「身上還有沒有次數」。**
`customersToAsk()` 第一道就是 `if (totalRemaining <= 0) continue;`。
所以一位這個月剛用完次數、下個月要續購的客戶**不會出現**，
而她其實想先把時間問起來。

**三、回覆了就從畫面上消失。**
客戶填完 → `formResponses` 多一筆 → 她按「收下」→ 產生一份可用性 →
`currentCollection()` 找得到 → `customersToAsk()` 直接跳過那一位 →
**那一列整個不見了**。她的原話是「不要消失，就把狀態呈現在已發連結這邊」。

## 要做成什麼

### 月份切換器

抬頭底下一排，跟客戶詳情「這個月」與可用性「記一次」共用
`components/monthnav.js`（`monthNav()` + `steppedMonth()`）。
**排版照客戶詳情的「不能的時間」那一段**（她指名的參考）：
`.section` 的抬頭 + 右邊兩顆箭頭，中間印月份。

```
問這輪的時間
   ‹   9 月   ›            ← 上個月 / 本月 / 下個月都走得到，不設上下限
   問 9 月哪幾天方便。
```

**預設仍然是下個月**（她問時間的節奏是月底問下個月，ADR-0053），
切換**不重新讀資料**，就地重畫（同 `askTab`，ADR-0038）。
選中的月份存在模組變數裡不進網址 —— 它是看法不是位置（同這一頁其餘的切換）。

產生連結時帶的就是**選中的那個月**（`invitesData.create({ month: askMonth })`），
LINE 訊息裡那句「問您 9 月哪幾天方便」也吃同一個值。這一條是這個 issue 的重點：
現在她想問十月只能等到九月底。

### 名單改成看「這個月」，不看「還有沒有次數」

新增一支 `domain/scheduling.js` 的 `customersToAskForMonth()`。
**`customersToAsk()` 一個字都不改** —— 它回答的是「現在還沒問到誰」，
首頁那一列與資料健檢用的是那一句話（ADR-0028、0033 的同一個判準）。

```js
customersToAskForMonth({ customers, availabilityBy, month })
//   → [{ customerId, customerName, hasCollection, collectedAt, banCount, remaining }]
```

判斷「那個月問到了沒」用 `domain/availability.js` 的
**`collectionFor(collections, monthFrom, monthTo)`**，不是 `currentCollection()`。
CLAUDE.md 的連動表寫得很清楚：綁月份的畫面用前者、問「現在」的用後者，
挑錯的後果是假的「可用 0 天」把人推到排序第一位。這一頁從今天起是**綁月份的**。

`remaining` 照樣算出來（`customerPools()`）但**只當一行灰字顯示，不當濾網** ——
她要看得出「這個人身上沒次數了」，但那不該決定要不要問他。

### 兩區 + 一個摺疊區

```
[ 還沒發連結 8 ]  [ 已經發出 5 ]

還沒發連結
  王小明   從來沒問過・還剩 4 次          [ 產生 9 月的連結 ]
  陳小美   上次 7/28 問的・還剩 0 次       [ 產生 9 月的連結 ]

已經發出
  林小華   9/1 發出                   ⏳ 等待回覆     [重發]
  張小龍   8/30 發出・9/1 填好          ✍ 已填寫時段   [ 去收下 ]
  李小美   8/28 發出・9/1 收下          ✓ 已確認排定   [ 看 9 月的時間 ]

▸ 這個月已經問到了（3 位）        ← 摺疊，她自己記的那幾位收在這裡
```

**三顆狀態徽章怎麼算**（`domain/availabilityForm.js` 新增一支
`inviteProgress({ invite, response, collection })`，判斷只有這一份）：

| 徽章 | 條件 | 樣子 |
|---|---|---|
| `等待回覆` | 有邀請、`formResponses` 裡沒有那個 token | `.badge`（灰） |
| `已填寫時段` | 有回覆、`takenAt` 是空的 | `.badge--soon`（琥珀，她要去按收下） |
| `已確認排定` | 回覆已收下，或那個月有一份可用性 | `.badge--ok`（綠） |

**已確認排定的那一列不消失**（她指名的那一句）。它留在「已經發出」那一格，
右邊那顆按鈕換成「看 9 月的時間」，連到那位客戶的詳情。

**過期的邀請**：ADR-0033 說過期的不算「已經發出」。這裡不一樣 ——
這一頁問的是「9 月這一輪」，而 9 月的邀請在 9/30 就過期了，
照舊規則整格會在月底突然清空。所以這一頁的分區看的是
**邀請的 `month` 欄位**（`newInvite()` 已經有了），不是有沒有過期；
過期的那幾筆在徽章上多一句「連結已過期」。

### 「這個月已經問到了」為什麼要留一個摺疊區（她 2026-09-02 決定：**留**）

那幾位（她自己在 LINE 問完、直接記進「不能的時間」的）在新規則下
不屬於任何一區。整個不列是最乾淨的，但這個 repo 反覆踩過的錯就是
「東西不見了而畫面上什麼都沒說」（`customersToBook()` 的註解、
ADR-0009、ADR-0053 都在講同一件事）。

所以：**摺疊起來、只給一個數字**，點開是一行一位、寫著哪天問的、幾條限制
（`summarizeCollection()`，跟可用性那一頁同一支）。

### 首頁那一列的數字（她 2026-09-02 決定：**不動**）

**不動**：它仍然是 `customersToAsk()`（「現在還沒問到誰」，ADR-0028）。
理由是月份版的數字會**永遠不歸零** —— 每個月一號，全部二十幾位都還沒有
下個月的時間，那一列就會寫著 25，而 `bookGroupRow()` 為了同一件事已經
把數字整個拿掉了（她的原話：「看了就會很煩」）。

代價是那一列的數字（5）與點進去看到的（8）對不起來，所以那一列的說明
要加一句：「點進去可以換月份」。

（另一個被否掉的選項：首頁那一列也改成月份版、照 `bookGroupRow()` 不給數字。）
