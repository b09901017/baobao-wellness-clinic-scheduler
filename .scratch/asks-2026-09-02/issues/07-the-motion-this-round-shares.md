# 這一輪四個新動作共用的一組動態

Status: 動工中
來源：她的四件事，2026-09-02（`../spec.md`）
動工先讀：ADR-0038（選一個選項不重畫整頁）、`app.css` 開頭那段關於
「只有把畫面接上去的東西才配有動畫」的註解

## 她要的

> 加入滑順的 CSS 過場動畫……提升整體的沉浸感與細緻度。
> 所有的視覺表現與動畫必須**點到為止**，嚴格保持「簡潔、直觀、乾淨」，
> 絕不能過度設計導致眼花撩亂或拖慢操作節奏。

兩句話是有張力的，所以先把判準寫死：

> **一個動畫要留下來，它得回答「剛剛發生了什麼」或「這個東西從哪裡來的」。
> 只是好看的，刪。**

這條判準會刷掉的東西：列的淡入、數字的滾動、卡片的陰影呼吸、任何 loading 骨架的閃爍。

## 一組變數，不是四組

`tokens.css` 新增四個，**放在 `/* ---------- 淺色 ---------- */` 那一行的上面**
（跟 `--space-*`、`--radius-*`、`--text-*` 同一區）。`tests/tokens.test.js`
只檢查那個標記**之後**定義的東西有沒有深色版 —— 時長與曲線不是顏色，
不該有第二份值，放對位置就不用重複寫，放錯位置測試會當場紅給你看。

```css
--motion-fast: 120ms;    /* 按壓回饋、丸子選中 */
--motion-base: 180ms;    /* 狀態變化、顏色漸變 */
--motion-slow: 260ms;    /* 抽屜、月份換頁 */
--ease-out: cubic-bezier(.22, 1, .36, 1);
```

`components/sheet.js` 現在的抽屜動畫是自己寫的時長，改成吃 `--motion-slow`
—— 不然這一輪加的東西跟既有的抽屜快慢不一樣，那比都沒有動畫更明顯。

## 四個新動作各自要什麼

| 動作 | 做什麼 | 為什麼 |
|---|---|---|
| **抽屜滑出**（issue 01） | 沿用 `sheet.js` 既有的，只統一時長 | 已經有了，不要再寫一支 |
| **列的按壓回饋** | `:active` → `scale(.985)`，`--motion-fast` | 手機上她需要知道「按到了」；長按選單那幾顆已經有類似的，共用同一組值 |
| **勾掉一筆** | 打勾 `--motion-fast` 淡入 + 整列文字 `--motion-base` 轉灰並劃掉 | 回答「剛剛那一下有沒有生效」。**不做高度動畫、不做位移** —— 那一列不會消失 |
| **月份切換**（issue 02） | 名單那一塊 `--motion-base` 的 8px 橫向位移＋淡入，方向跟著箭頭 | 回答「往哪個方向走了」。只動名單那一塊，抬頭與切換器不動（ADR-0038） |
| **n返 那兩排展開**（issue 04） | `--motion-base` 高度展開＋淡入 | 回答「這兩排是剛剛那一顆丸子叫出來的」 |

## 三條硬規矩

1. **`prefers-reduced-motion` 一律吃得到。**
   `app.css` 底部已經有那一段（第 5022 行起），新加的每一條都要進去。
   她自己不一定開，但這是無障礙的底線，而且它讓「動畫壞掉」有一個關得掉的開關。

2. **不做整頁重畫的動畫。** 壓表那一頁的教訓（ADR-0038）：
   她一位客戶要點五六下，重畫的代價是閃一下加捲回最上面。
   月份切換與勾選都是**只換真的變了的那一塊**。

3. **動畫不可以擋住下一次點擊。**
   所有的 `transition` 都不加 `pointer-events` 的變化，抽屜播進場動畫時
   裡面的按鈕就要按得動 —— 她的節奏是「點、點、點」，等 260ms 才能按下一下
   等於把系統變慢。
