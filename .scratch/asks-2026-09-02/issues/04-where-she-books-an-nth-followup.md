# n返：她在哪裡約得到它

Status: 動工中
來源：她的四件事，2026-09-02（`../spec.md`）
前置：issue 03（資料形狀）
動工先讀：ADR-0014（一批是一個月的一串客戶）、ADR-0038（壓表不整頁重畫）、
ADR-0056（只有日曆改得了一筆來訪）

## 兩個入口，一份規則

一筆來訪只有兩個地方生得出來：

| 入口 | 檔案 | 現在怎麼選「這一段是什麼」 |
|---|---|---|
| 壓表 | `views/schedule.js` 的 `courseOptions(row)` | 從 `row.pools`（剩餘 > 0 的額度）生一排丸子 |
| 來訪編輯器（日曆的鉛筆） | `views/visitEditor.js` 的 `slotCard()` | 從 `entitlements` 生一排「額度」丸子 |

兩邊都是**先選額度、再由額度決定課程**。n返 沒有額度，所以兩邊都要多一顆
**不是額度的丸子**。

```
額度
[ 復能 剩 11 ] [ 8萬健檢 剩 1 ] [ 二返（8萬健檢） 剩 1 ] [ ＋ n返 ]
                                                          ↑ 一直在，只要他有做完的健檢
```

選了那一顆之後，底下長出**兩排**（其餘欄位跟二返完全一樣：醫師、診間、時間）：

```
第幾返                 ← 預設是下一個沒被用掉的數字
[ 三返 ] [ 四返 ] [ 五返 ] … [ 十返 ]

這是哪一次健檢的        ← 必選。已經有回訪的那幾次標出來但**點得下去**
[ 7/13  二返·三返 ] [ 8/20  二返 ]
```

### 三個跟二返刻意不一樣的地方

1. **健檢候選不會被「認領」掉。** 二返是一對一，所以
   `examChoicesFor()` 會把被別的二返佔走的那幾次 `disabled`。n返 沒有上限，
   每一次健檢都可以再約 —— 所以全部點得下去，只是標出「已經有幾返了」。
2. **不自動幫她選。** 壓表那邊有 `pickExamIfObvious()`（只有一個候選就先選好）。
   n返 不做：二返是「一定要約的那一次」，自動選省她一下點擊；n返 是她**特地**
   要加的一場，替她決定接哪一次健檢會讓她漏看。
3. **「第幾返」有預設值但一定看得到。** 預設 = 那一次健檢底下最大的返數 + 1
   （二返算 2，所以第一次加約預設就是三返）。她改得動。

### 那顆丸子什麼時候出現

`他名下有至少一次「已完成」的健檢來訪`。沒有的時候**整顆不畫**（不是畫成
disabled）—— 一顆永遠按不下去的丸子只會讓她每次都試一下。

壓表那一頁的來訪只讀回 180 天（`loadAll()`），所以更早的健檢在那裡列不出來。
這跟二返現在的行為一模一樣，而且 `examField()` 的註解已經寫了理由：
真的要接一場半年前的健檢，走日曆的來訪編輯器（那裡讀 `listByCustomer()` 完整的一份）。
n返 沿用同一條，不另外開一個「載入更多」。

### 換掉那顆丸子時要清乾淨

壓表那一頁有 `resetCourseBoundPicks()`（換額度時把器材／醫師／健檢清掉）。
`followupNth` 要一起進那一支 —— 不然她點了「三返」再改回「復能」，
`followupNth: 3` 會跟著存進一段復能裡。這是這個 issue 最容易漏的一行。

## 存檔那一段

兩邊的 `readSlots()` / 送出組裝都要多帶 `followupNth`，而且**不是 n返 一律寫 `null`**
（同 `followupForVisitId` 那一行既有的判斷：「不是二返就一定是 null ——
帶著一個不相干的 id 會讓試算表把註記寫到別的地方」）。

## 存檔前那張「會發生什麼」的確認

`domain/consequences.js` 已經會講「待辦會多一張追蹤健檢報告」這種話。
n返 要多一句，因為她加約的當下最需要確認的就是這件事：

```
存成待客人確認？
  9/20 14:00 三返（接 7/13 的健檢）
  客人確認之後會多兩張待辦：Examine、耀聖
  三返不用簽療程單，但那一天照樣要在「簽療程單」那一列結案
  **這一場不扣任何次數**            ← 她最會擔心的那件事
```

最後那一句是刻意的：她整套系統的核心焦慮就是次數對不對得起來，
而一場「不用先加購」的來訪憑直覺看起來像會偷扣一次。

## 客戶詳情要看得到

那一頁現在按額度分卡（`poolCard()`），而 n返 沒有卡可以掛。
接在**那一筆健檢額度的卡片底下**，跟既有的 `followupLine()`（「健檢做完 3 次，
二返還欠 2 次」）同一個位置、同一個字級：

```
8萬健檢                    剩 1
  健檢做完 2 次，二返已經約掉 2 次
  加約：7/13 的健檢 → 三返 9/20 ・ 四返 10/8      ← 新增這一行
  [ 加約一場 n返 ]                                ← 不做（見下）
```

**不放「加約」按鈕。** ADR-0056 定了「只有日曆改得了一筆來訪」，而加一場
n返 就是建一筆來訪。從客戶詳情給一顆按鈕等於在這個決定上再開一個洞。
她的路徑是壓表或日曆，跟排任何一場來訪一樣。

## 驗證

- `npm test`
- 壓表：選一位有做完健檢的客戶 → 額度那一排看得到「＋ n返」→ 點下去 →
  第幾返預設「三返」→ 選健檢 → 選醫師 → 存 → 客戶詳情看得到那一行、
  日曆上那一天看得到「三返」、次數一次都沒少

- 一位沒有健檢的客戶 → 那顆丸子整顆不出現
