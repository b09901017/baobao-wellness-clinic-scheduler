# 壓表的卡片組不吃返回鍵

Status: done
來源：使用者，2026-08-25（動工中確認）
動工前先讀：`docs/adr/0048`、`0017`、`0038`

## 問題

ADR-0048 定的原則是「畫面上多出來一層東西，就多一筆返回鍵退得掉的紀錄」，
但它自己在代價那一段把壓表排除掉了（怕 Safari 的 `pushState` 頻率上限）。

結果是日曆的抽屜、客戶詳情的編輯、二次確認全都退得掉，**唯獨她用最多的
那一頁沒有** —— 卡片面板開著按返回鍵是跳走整頁，而那正是 ADR-0048
一開始要修的症狀。

## 要做什麼

`openDeck()` 推一層、`closeDeck()` 收掉。**換人、點丸子、換日子一筆都不推。**

會撞到頻率上限的是後面那幾個高頻動作，而它們本來就不該推 —— 換人不是
「多一層東西」，是同一層裡換內容。

## 驗證

- `npm test`
- 手機：壓表 → 點一位 → 按返回鍵 → **關掉面板回到卡片牆**，不是跳走
- 手機：滑過好幾位之後按返回鍵 → 一次就回到牆上，不是倒著走過每一位
- 手機：面板裡按「這位壓完了」跳出二次確認 → 返回鍵先收掉確認框，
  再按一次才關掉面板
