# 13 用匯出的 .xlsx 驗真的 Google 畫得對不對（工具）

Status: done
Blocked by: 08～12（拿新的畫法驗）

## 為什麼要

替身（`tests/helpers/appsScriptStub.js`）終究不是 Google。11/5 主控用她匯出的試算表驗了兩次（正式站早上那一份、staging 下午那一份）：
試算表裡藏著的 `_data` 分頁就是那一次推過去的原始整包 —— 拿它餵給 `.gs`（替身）畫一次，跟匯出檔逐格比（值、底色、字級），
不一樣的就是「真的 Google 跟替身不一樣」或「推過去之後被人動過」。那兩次的腳本在主控 session 的暫存區，沒進 repo；這一支把它做成 `scripts/` 底下的工具，第三輪改完版面拿來驗。

## 做法

- `scripts/sheet-xlsx-verify.mjs <匯出的.xlsx>`：
  1. 讀 xlsx：這台有 python ＋ openpyxl（`python -I`），node 沒有 xlsx 套件 —— 用一支小 python 把每一張分頁的值、底色、字級、合併、凍結、備註倒成 JSON（放在 `scripts/` 旁邊、或 `scripts/lib/`）
  2. `_data` 的 A2 起接回整包（`stashRawData()` 切 45000 字一格）
  3. 用替身跑一次現在的 `.gs`（`loadAppsScript()` ＋ `post({ bundle })`）→ `snapshotOf()`
  4. 逐頁逐格比，**只印數字**（哪一種不一樣、幾格）；有真名的細節寫進 `.local/references/`（參數或預設路徑）
- 已知會不一樣、要先處理掉才比得準的：Google 把 `2026-10-20` 這種字自己認成日期（08 寫成文字之後就不會了）；替身時鐘固定在 0 → `_data` 的 B1（計時）跳過；產生時間那一格跳過
- 讀 `.local` 一律接 `| node .local/references/redact.mjs`

## 判準

- 拿 staging 那一份（第三輪貼上去、整份重畫之後她匯出的）跑：每一頁每一格都一樣嗎？不一樣的有沒有一條一條講得出原因？
- 工具本身有一支小測試嗎？（假的 xlsx 倒出來的 JSON → 跟替身比 → 0 個不一樣；故意改一格 → 1 個不一樣）

## 做完時留下的

- **三支**：`scripts/sheet-xlsx-verify.mjs`（入口）、`scripts/lib/xlsx-dump.py`（openpyxl 攤開 xlsx，一個字都不判斷）、`scripts/lib/sheetXlsxCompare.mjs`
  （兩邊收成同一種形狀再比；**Google 的預設值與單位換算只寫在這裡**）。用法：
  `node scripts/sheet-xlsx-verify.mjs <匯出的.xlsx> [--gs <試算表上貼的那一版.gs>] [--bundle <整包.json>] [--out <細節.json>]`。
  畫面只印數字（`diffs` 要查的、`known` 已知的、有差的是「第幾頁」）；哪一格、兩邊各是什麼寫進 `.local/references/試算表驗證/<檔名>-<時間>.json`（有真名）
- **比的**：值、底色、字級、粗體、字色、字型、左右／上下對齊、換行、數字格式、備註、框線（每一條邊：相鄰兩格各寫一次 → 收成一條，粗的算數）、
  合併、欄寬、列高、凍結、格線、藏起來了沒。**不比**：鎖（匯出檔沒有）、分頁先後與大小。合併區裡左上角以外的格子格式不比（Google 看左上角），
  但替身在那裡留了值的算 `value.inMerge`（真的 Google 合併時丟掉）
- **已知、不算錯**（`known`）：產生時間那一格（`stamp`）、Google 自己把折行的列長高（`rowHeight.grew`：`setRowHeights()` 不是強制的）、
  她自己開的分頁（`extraSheet`，例如「工作表1」）、備註前面多了作者（`note.prefixed`，還沒看過真的匯出檔帶不帶）。`_data` 的 B1（計時）不比
- **單位**（11/5 staging 那一份對出來的）：欄寬匯出成「像素 / 8 + 0.125」（190／62／58／預設 100 → 23.88／7.88／7.38／12.63）、列高是點（26 → 19.5）、
  凍結 `F6` ＝五列五欄、置中匯出成 `center`、顏色 `FFRRGGBB`、預設字型 Arial 10（主題色當黑）
- **對過兩份真的匯出檔**（只印數字）：
  - staging 11/5 下午那一份 ＋ 當時部署的 `.gs`（develop `532c1a4d`）：35 頁 22,372 格，**只有 9 格待辦的日期被 Google 認成日期**（`value.date` 9 ＋ 那幾格的日期格式），
    跟主控 11/5 用暫存腳本找到的一樣；框線、欄寬、列高、字型、合併、凍結 0 個不一樣。另外 1 格空的格子帶著日期格式（第 5 頁 M28，舊的那一次畫的痕跡）
  - 正式站 11/5 早上那一份 ＋ develop `3dd2ee12` 的 `.gs`：35 頁 21,535 格，只有 10 格日期（同一件事）
  - 同一份 staging 匯出檔拿**這一輪的 `.gs`** 跑：每一頁都抓得到版面的差（凍結欄、格線、合併、字級…）—— 工具分得出新舊畫法
- **測試** `tests/sheet-xlsx-verify.test.js`：替身畫一次 → 照匯出慣例攤成 dump（`dumpLike()`）→ 0 個不一樣；改一格的字、日期被認成日期、短備註被認成數字、
  粗線變細、格線、列高矮了／高了、凍結欄、合併、備註、產生時間、多一頁、少一頁、`_data` 的 B1 與 A 欄各一條。這台有 openpyxl 的話再把 dump 真的寫成 .xlsx、
  整支工具跑兩次（一樣 → exit 0、改一格 → exit 1，畫面上沒有分頁名）；CI 沒有 openpyxl → 那兩條跳過
- **它驗不到的**：合併的那幾列估的高度夠不夠（匯出檔只有設下去的高度 —— Google 不替合併的格子長高；要看畫面）、鎖、真的快不快
- **做的時候看到的**（段二審查一起看）：12 把短備註改成一則一格之後，**看起來像數字或日期的一則**（例如 `0912345678`、`5/20`）寫進去會被 Google 認成數字／日期
  （跟待辦日期同一件事；以前全部塞在一格裡、混著別的字就不會）。正式站那一包 79 則短備註 0 則中 —— 還沒發生，但只要一則就會掉前面的 0。**段二審查修了**：`noteBlock()` 每一行文字格式（見 HANDOFF「第三輪段二」）
- **11/5 深夜第四輪 staging 那一份**（HANDOFF「第四輪 staging 逐格驗」）：多一種已知 `numberFormat.leftover`（兩邊都空、替身沒下格式、匯出檔留著一個 —— `sheet.clear()` 清值不清數字格式）；
  第四輪加的 `spreadMergeEdges()` 對真的匯出檔猜錯（假報 120 條框線），拿掉了
