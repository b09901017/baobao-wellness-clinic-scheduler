## 一、會讓次數或資料出錯的

### 1. 健檢沒做，二返也能被扣掉

- 看到：同一天排健檢＋二返，二返那一段「這是哪一次健檢的」一個都按不下去（當天那次健檢還沒做完，`examChoicesFor()` 只有已完成的 `pickable`）。存檔只跳「第 2 個時段：二返 還沒指定是哪一次健檢的」→「知道了，繼續」就存了。簽療程單健檢 ✗、二返 ✓ → 二返額度扣掉、整天已完成、多一張「寫紀錄」。
- 重現（畫面走過）：假客戶 → 加購 → 健檢 → 日曆 → 今天 → ＋ → 健檢 →「＋新增一個時段」→ 二返 → 記錄這次來訪 →「知道了，繼續」→「已確認，記錄」→ 待辦 → 簽療程單 → 那位的 ✓ → 健檢 ✗、二返 ✓ →「記下來」→ 客戶詳情：二返剩 0。
- 為什麼：沒連結的二返刻意只是 warning（`domain/visits.js:1628-1631` 的註解、`:1792`；舊資料沒有這個欄位，ADR-0011 那一條原則）。連到「還沒做完的健檢」才擋（`:1650-1656`，2026-09-24）。結案 `closeVisit()`（`:1021`）與簽療程單 `ui/views/home.js` 的 `applyClose()`（`:3529` 起）都不問二返的健檢做了沒。
- **她 10/7 決定**：「(A) 排定二返時：在日曆／壓表存檔時，若沒有連結到已完成的健檢就觸發。+僅提醒，仍可繼續操作」。
  現在存檔時**已經**有一句 warning（「還沒指定是哪一次健檢的」），所以這一條實際上是**把那一句講清楚**：講出「沒有接到一次做完的健檢」、同一天的健檢還沒做時講出來、打勾時會扣掉一次二返。仍然是 warning、不擋。三個入口（壓表、日曆編輯器、拍 Abovee）走同一支 `validateVisit()`。
  簽療程單那一層**她沒選**（存檔時健檢還只是排定，看不出後來會沒來）——已經跟她講過這個缺口，她說要再加才加。牽涉 ADR-0011、0022、0112。**不要碰「舊資料沒連結也存得下去」那一條**。

### 2. 日曆編輯器換額度時，上一次點的器材留著

- 看到：先點「復能-三選一」→ INDIBA，再點「復能-SIS」：抬頭還寫 IN(60)、器材那排 SIS 沒選上、存檔被擋「第 N 個時段：這個器材不在「復能-SIS(60)」的擇一池裡」——沒說是哪一台，畫面上已經看不到 INDIBA。
- 重現：同時有三選一與單台 SIS 額度的客戶 → 日曆 → ＋ → 三選一 → INDIBA → 復能-SIS → 看抬頭 → 記錄這次來訪。
- 為什麼：`ui/views/visitEditor.js:969`、`:1011` 讀 `v['s{i}-equip']`（那一排的 hidden input 還是 INDIBA），換額度不清。錯誤訊息在 `domain/visits.js:1624-1626`，不帶器材名。
- 牽連：**壓表沒有這個問題**（`ui/views/schedule.js` 的 `resetCourseBoundPicks()`）。拍 Abovee 走 `pickOption()`，沒查到同樣的問題，要確認一次。新的額度只有一台時要不要直接選好它，也一起想。

### 3. 營養品：只打新的一款存不下去；新舊混著選名字少一款；失敗也會建主檔

- 看到：(a) 加購 → 營養品 → 只按「＋新增…」打一個名字 → 存 →「額度名稱不可空白」（那一格藏在「進階設定」）。(b) 勾 GABA ＋ 新增一款 → 存得進去，但額度名字只有「營養品 3,000（GABA）」，提醒隨手記寫「GABA＋新的那款」。(c) (a) 失敗那一次，新打的那一款照樣進了 設定 → 營養品 清單。
- 重現：客戶詳情 → 加購 → 營養品 →「＋新增…」→ 打「測試魚油」→ 加購；再去 設定 → 營養品 看清單。新增客戶 →「＋加一項」→ 同樣的步驟，同一句錯誤。
- 為什麼：`ui/components/buy.js:830` 的 `commitNewProduct()` 先 `createProduct` 再交回去驗證（c），而且沿用 `draft.label`、不重算名字（b）。客戶詳情那一條還用 `{ ...live, ...readEntitlement(form) }`（`ui/views/customerDetail.js:1698`）把空的 label 欄位蓋上去（a）。驗證在 `domain/entitlements.js:761`，名字在 `domain/products.js` 的 `productLabel()`。
- 牽連：三個入口共用（客戶詳情加購、新增客戶「加一項」、批次建立微調的「加一項」——後兩個走 `ui/components/buySheet.js:78`）。CLAUDE.md 連動表「營養品的名字或金額」那一列。

### 4. 同一位客戶同一天時間撞在一起，沒有提醒（**她：要提醒、不要擋**）

- 看到：那一天已完成之後再幫同一位加一段（會另開一筆來訪，ADR-0083），時間跟已完成那段一模一樣，只問「還沒選醫師」。
- 重現：假客戶今天 14:30–15:00 功醫門診、簽成已完成 → 日曆 → 今天 → ＋ → 選他（上面寫「這是另外一次來訪」）→ 功醫門診 → 14:30 → 記錄。
- 為什麼：`domain/visits.js` 的 `overlapWarnings()`（`:1732`）只比同一筆來訪裡的段；`conflictWarnings()`（`:1859`）只比同診間（算人頭）與同治療師，不比「同一個客人」。
- 修的位置：**只要在 domain 加一次**。三個入口都經過 `validateVisit()`（`schedule.js:2163`、`visitEditor.js:1244`、`aboveeConfirm.js:165/169`），`sameDayVisits` 與 `customerVisits` 都已經傳進去了。
- **她 10/7 決定**：只提醒不擋；同一間診間時既有的撞期提醒已經會講，不要同一件事出兩句。
- 注意：同一間診間的話，`conflictWarnings()` 已經會講「已經排了 客戶A那天的另一次來訪」（`whoOf()`），新的那一句不要讓她同一件事看到兩次。取消的段不算（`isLiveSlot()`）。資料健檢的 `checkConflicts()` 要不要跟著多一種，一起想。

### 5. 進度追蹤與客戶詳情「這個月」把取消的段算進「N 段」

- 看到：一天裡只取消一段時，那一段照畫（寫「已取消」）、算進「N 段」，○△✓✗ 卻不算它 → 對不起來。進度追蹤的 ? 寫「取消掉的時段不畫」。
- 重現：假客戶某天兩段 → 長按其中一段 → 取消這一段 → 客戶 → 看這個月的進度：「3 段」但 ○1 ✓1；客戶詳情「這個月」一樣。
- 為什麼：`domain/progress.js` 的 `buildProgress()` 只用 `isActive(v)` 濾**整筆**（逐段取消 ADR-0081 之前那是全部的取消），`dayFor()`／`rowFor()`（`:85-145`）每一段都收。提示字在 `ui/views/progress.js:164`。
- 牽連：`progressDayHtml()`／`tallyHtml()` 兩頁共用（CLAUDE.md 連動表「進度追蹤或客戶詳情的『這個月』」）。**她 10/7 決定：不畫、不算**（「這個頁面的核心目的是回答『這個人這個月實際上做了多少』，而取消的段實際上並未發生」）。日曆上照樣看得到灰的。

### 6. 簽療程單之後的 toast「扣掉 N 次」把不算次數的段也算進去

- 看到：抽屜寫「做了的 2 段裡 1 段扣掉次數」，toast 寫「記好了，扣掉 2 次」。資料是對的。

## 六、驗證時另外找到的

## 四裡她挑的四條

- **資料健檢太長，重新設計 UI／UX**：用她的資料 33 塊、31 塊是「沒問題」，手機上整頁約 7,600 像素，「資料過期」一塊 77 行（一人好幾行）。三裡那幾條用語也在這一頁，一起做。她 2026-09-10：「非常占版面，一眼看下去非常雜亂，會視覺疲勞」；記憶裡 10/5 那份報告她說「資訊太多太複雜了，我認知疲勞了」。修法動工前先給她看畫面（mockup 或截圖），不要直接改。程式在 `ui/views/health.js`（掃描與每一塊的修正按鈕）、`domain/health.js`（每一項的說明與 `FIX_COPY`）。
