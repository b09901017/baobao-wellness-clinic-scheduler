## 四件事

### 一、`ROOM_TYPES`：`ILIB室` 換成 `VIP室`

```js
export const ROOM_TYPES = ['治療室', '點滴室', 'ILIB室'];   // 現在
export const ROOM_TYPES = ['治療室', '點滴室', 'VIP室'];    // 之後
```

唯一那一間 ILIB 室是 `ILIB4` —— **它有個 4**，而且 ILIB 的智慧排序寫的是
`.10、治2、治3`，本來就不排在 ILIB 室。

**ILIB 那個課程的 `allowedRoomTypes` 要一起改**（現在是
`['ILIB室','治療室','點滴室']`）。不改的話那個課程會指著一個不存在的類型，
而症狀跟「沒有可用診間」長得一模一樣。

### 二、簡寫是**新欄位**，不是改名字

```js
{ id: 'room-iv2', name: '點滴2', shortName: '.2', type: '點滴室' }
```

**不要拿 `name` 當簡寫**：試算表、稽核紀錄、既有來訪讀的都是 `name`，
改掉等於歷史紀錄整片跟著變；而 `.2` 單獨出現在稽核紀錄上沒有人看得懂。

畫在哪，跟課程與器材同一支（`domain/naming.js` 的 `nameOf()`）：

| 場合 | 印 |
|---|---|
| 月檢視、日／週那一列、讀取卡片 | 簡寫（`.2`） |
| 主檔清單、設定頁、確認框、試算表、稽核 | 全名（`點滴2`） |

### 三、治7、治9、治10、ILIB4 **刪掉**（A9）

走這個 app 既有的刪除：進「已刪除項目」，**還原得回來**。

- 她知道代價：既有來訪上那幾筆從此印不出診間名字
- 一鍵刪除的確認框要照 **ADR-0070** 逐條講出真的會發生什麼：
  「排班時選不到」「已經排在那裡的來訪印不出診間」「在已刪除項目裡還原得回來」
- **不要順手把它們從既有來訪身上清掉** —— 那是另一件事，她沒有要

### 四、床位**連舊資料一起清掉**（A10）

三層一起做：

1. 主檔那一頁不再給填床位；`validate('rooms')` 不再驗床位；
   `roomSlots()` 一間就是一個選項（`點滴8A`／`點滴8B` 不再出現）
2. **既有來訪身上的 `bed` 一併清空**。只有排進點滴8 的那幾筆有，量很小
3. `conflictWarnings()` 的 `sameRoom` 那一行**不要改**：`bed` 全變成 `null`
   之後它自然退化成只比 `roomId`，也就是「同一間、同一個時間、兩個人」會被
   標出來 —— 那正是取消床位之後對的行為

清 `bed` 那一步要**看得到、按得到**：資料健檢新增一列「來訪上還記著床位」，
列出是哪幾筆，一鍵清掉。不要在載入時偷偷改 —— 那會是一次沒有人按過的寫入。

## 既有資料庫怎麼跟上

`loadSeed()` 只建不覆蓋（她可能改過了），所以改種子資料對她現有的資料庫
沒有作用。**跟 `seedEquipment` / `seedDuration` 同一個形狀**，資料健檢新增一列：

> **「診間清單跟建議的不一樣」**
> 少了哪幾間（VIP2…VIP7）、多了哪幾間（治7、治9、治10、ILIB4）、
> 哪幾間沒有簡寫。一鍵補上少的、刪掉多的、補上簡寫。
> 她自己加過的診間**不列**（那是她的決定）。
