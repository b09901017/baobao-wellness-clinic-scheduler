# 逐字讀取與閉環挖掘

目錄：什麼時候需要 → 逐字讀取怎麼運作 → 十個設計決定（每一個都是修過的 bug）→ 短字串與長字串判準不同 → 閉環 → 成本 → 讀不出來時怎麼判斷 → 參數

## 什麼時候需要

候選列得完的欄位（日期、時段、是／否、已知的清單）用窮舉，不需要這裡的東西。
候選列不完的 —— 姓名、電話、編號、沒看過的品項、備註 —— 才逐字讀。

先想能不能把它變成列得完的：

- 有別的資料來源（名冊、歷史匯出、另一個系統的清單）就拿來當 `vocab`。**那只是候選**，像素不吻合就不算數，
  所以灌錯的、灌多的都沒關係，只是白畫。實戰裡常客的姓名都是靠名冊的候選直接吻合的，逐字讀的只有名冊上沒有的那些人。
- 有結構的（電話是十個數字、編號是八位數前面補零）用小字集＋`prefix`：十個字的字集讀一格只要一兩秒。

## 逐字讀取怎麼運作（`pxx/reader.py` 的 `read()`）

```
前綴 = [起點]                              # 可以從已知的開頭起步（prefix=），也可以從上次停下來的地方接著讀
重複：
  粗篩：每一條前綴 × 字集裡每一個字，在「目前吻合的起始位置範圍」的頭與尾各畫一次
        → 算尾段誤差，分寬／中／細三類各留前幾名
  細篩：留下來的候選 × 目前的範圍（往兩邊各放寬一點）裡每一個位置
        → 尾段誤差 < 2.0 的才留；記下它在哪些位置吻合，跟前兩步取交集，當成下一步的範圍
  有候選畫出來的寬度到了整格的寬度、而且過得了結尾的檢查 → 讀完
  排名：乾淨吻合的（< 1.3）裡最寬的優先，勉強過關的留一條；其餘的放進退路
  下一步一個候選都沒有（死路）→ 從退路拿最近的一批出來試（先試「後面接空白」）
```

**尾段誤差**：只比合成字串最後兩個字寬（約 12 欄像素）的那一段，最右邊一欄不比（下一個字的邊緣會滲進來）；
分母是合成那一側有墨的通道數，有下限（空白、標點的地方幾個灰階不該被放大）。

## 十個設計決定

每一個都是先做錯、看到症狀、才改成現在這樣。動這一段之前先讀。

**1. 只留「像素對得上」的前綴，不是留「誤差最小的幾條」。**
用整格的殘差排名（還沒解釋到的墨也算誤差）時，錯的寬字會贏：筆畫多的錯字蓋掉的像素多，殘差反而比正確但窄的字小。
現在是硬門檻：接上去的那個字有像素明顯對不上，就丟掉，不留著「看看後面會不會變好」。

**2. 判斷「接上去的這個字對不對」只看尾段，不看整條前綴。** ✦
整條前綴一起平均的話，前綴越長、新接上去的字佔的比例越小：讀到第 25 個字，一個完全錯的字只讓平均多 0.6，照樣過關。
症狀是長句讀得出來、整格誤差也在門檻內，但裡面夾著錯字。尾段誤差不管讀到第幾個字，敏感度都一樣。

**3. 粗篩分寬、中、細三類各留一些。**
細的字（`l` `.` `|` `i` `1` 與一堆標點）只蓋到一兩欄像素，幾乎放在哪裡都「局部吻合」。只照誤差排，
前三十名全是細字，真正的寬字整批被擠出名單，症狀是中文字串一個字都讀不出來。

**4. 排名分兩層：乾淨吻合的在前，勉強過關的在後。** ✦
只照「蓋得寬的優先」排的話，一個勉強過關的寬候選（空白＋一個橫畫的字，蓋在一個逗號上，誤差 1.25）
會排在乾淨吻合的窄候選（那個逗號，0.5）前面。實戰裡六則備註的全形逗號就這樣被讀成了全形減號或間隔點 ——
整格誤差全部在門檻以內，是後來加了區域誤差才看到的。

**5. 走到死路要退回去，不要整格放棄。**
細小的字在它自己那一步分不出誰對（逗號、`l`、`|`、`.` 都過關），留下來的那一兩條可能全是錯的，下一步就沒有任何字接得上。
每一步沒被選上的候選留在退路裡，死路時拿最近的一批出來試（最多退六次）。

**6. 空白放在退路裡，不每一步都畫。**
空白不佔墨，接了空白的前綴畫出來跟沒接一模一樣，靠誤差選不出來。早期的做法是每一步多開一條「後面接空白」的前綴 ——
每一步多畫一倍。現在把它放進退路的最上面：空白後面的字位置差一兩個像素，不接空白一定走到死路，那時候第一個試的就是它。
半形與全形空白（`charset.BLANKS`）各一條。

**7. 細篩用「整段」可能的起始位置；粗篩畫範圍的頭與尾，不要只畫中間。** ✦
一個字串吻合的起始位置是一段範圍（0.05～0.13 個像素寬），每一對相鄰的字範圍的邊界都不一樣。
只畫中間點的話，下一個字吻合的範圍剛好在另一頭時（實測：前綴在 0.201～0.217 吻合、下一個字只在 0.215～0.217），
正確的字在粗篩就排不進前 16 名。症狀很有特徵：**某個字就是讀不下去，而且只花幾秒** —— 不是讀得慢，是候選一開始就沒進名單。

**8. 起始位置是「跟著走」的，不是整條字串共用一個。** ✦
直覺是：同一個字串當然只有一個起始位置，所以把每一步吻合的範圍一路取交集。十個字以內這是對的。
但模型的字距只準到大約 0.01 像素，而每一步的範圍只有 0.08 像素寬、邊界各不相同 —— 三十個字的交集常常是**空的**，
正確的字串也會「讀到第二十幾個字突然沒有任何字接得上」。
現在只要求最近三步的範圍有交集，而且下一步可以往兩邊各漂 0.023 像素（`reader.PAD`）。
（排除過的其他解釋：每個字多一點字距 —— 掃過，0 最好；字級差一點 —— 用長字串細掃過，現值就在最好的範圍裡。）

**9. 校出來的範圍要留餘裕，不要只留「誤差最小」的那幾個位置。**
`calibrate()` 原本只回傳誤差等於最小值的位置。真正的位置不一定是誤差最小的那一個（差 0.05 是常態），
只留最小的話會留到隔壁那一段。現在留 0.3 的餘裕（位置真的不對時誤差是跳上去的，1 以上，不會被收進來）。
同理，一欄裡有一個讀得差一點的詞當了錨點，整欄的校正會被它拖垮 —— `Field._apply` 會把最差的錨點拿掉再校。

**10. 細字還是最難的。**
一個像素寬的字（`I` `l` `1` `|`）整個落在「最右邊一欄不比」的那一欄裡，這一步分不出它們，要靠下一個字接上去才看得出誰對。
現在靠退路處理：選錯了下一步會死路，再回來試別的。實戰裡以細字開頭的（`I` 開頭的英文縮寫接數字）讀得出來；
連續好幾個細字（`III`、`1l1`）沒有測過。

## 短字串與長字串，「吻合」的判準不一樣

| | 短（寬度 ≤ 16 個字，`reader.LONG`） | 長 |
|---|---|---|
| 讀完的條件 | 整格誤差 < 1.6（同一個起始位置） | 一路上每一步的尾段誤差都過關，結尾那一段（含最後一欄）也過關 |
| 回報的誤差 | `err`＝整格誤差；`local`＝最差的那一個字寬的誤差 | `err`＝一路上最大的尾段誤差；`piecewise=True` |
| 事後檢查 | `refine()`：`local` > 2.0 的那個位置逐一換字 | `check()`：照同一套規矩一步一步重對 |
| 最後驗證 | `match.verify_local()` | `reader.check()` |

為什麼不能都用整格誤差：

- **整格誤差是平均，會稀釋。** 30 個字裡錯 1 個，平均只多 0.4。長得幾乎一樣的字（差一兩個像素的那種）、
  選錯的標點，連 12 個字的字串都看不出來。`local_err()` 用一個字寬的滑動視窗找最差的地方：
  實測正確的字串最大的區域誤差 1.0～1.4，選錯標點 2.5～5，錯一個字 5～17。
- **長字串在單一起始位置上對不齊。** 見上面第 8 點。同一則 30 個字的備註，整格在同一個位置上比，尾巴的區域誤差是 15（看起來像錯字）；
  一步一步對，最大 1.0。所以長字串不要用 `verify()`／`local_err()` 判，會把對的判成錯的。

`check()` 驗過：正確的長句 0.85～1.03；故意把第 21 個字換掉，14.3。

## 讀完之後：換字比對與撤回（`Field.refine_suspects()`）

讀取器只能選字集裡有的字。字集裡沒有的字（一種沒收進來的破折號），它會挑一個「最像的」頂替，整格誤差照樣過關。
所以自由文字讀完之後一定要跑這一步：

- 短字串：區域誤差 > 2.0 的那個位置（與左右各一個字），逐一換成大字集裡的每個字，取區域誤差最小的。換了有改善才算（log 寫「修正」）。
- 長字串：`check()`。不過的話從可疑的位置前兩個字**撤回重讀**（一格只撤一次；log 寫「撤回」）。
- 換字、重讀都沒有更好：log 寫「可疑」，在產出裡照實標出來（第幾個字附近）。

字集（`charset.TEXT`）已經收了一批人打字會用到、長得又很像的符號（`SYMBOLS`：各種破折號、間隔點、注音、全形英數標點）。
遇到新的頂替情況，把那一類符號加進去。

## 閉環（`pxx/discover.py` 的 `Field`）

```
套用已知詞彙（每張圖每一欄：先粗比 → 拿明顯吻合的當錨點校起始位置 → 再比一次）
重複，直到沒有沒吻合的格子、或到時間上限：
  沒吻合的格子照「長得一模一樣」分組        ← 同一個值在同一張圖同一欄，像素完全相同
  挑一組：order='common' 最常出現的先讀；order='short' 最窄的先讀
  逐字讀它；讀不下去就換下一個字集，**從讀到的地方接著讀**，不重頭來
  讀出來 → 加進詞彙 → 套到所有圖的這一欄    ← 全域反套
  讀不完 → 記下讀到哪裡（failed），這一格這次不再試
  到時間上限 → 記下讀到哪裡（partials），下次從那個字接著讀
  存檔
最後：finalize()（還差一點的格子在所有位置上再比）、refine_suspects()（自由文字）
```

為什麼這樣排：

- **分組**讓同一個值只讀一次。25 列的圖裡同一個品項出現 8 次，是 1 次讀取不是 8 次。
- **全域反套**是整個方法省最多的地方。讀一格幾十秒，套一個詞到幾百格一兩秒。實戰：品項那一欄 75 格、17 種值，
  從空的詞彙開始，讀 17 次就全部吻合。
- **`order='short'`** 給自由文字：短的便宜，先收掉；讀出來的句子又常常是別則的一部分。
- **log 就是進度**，一行一行照順序讀回來：「讀到」加進詞彙、「修正」換掉、「撤回」拿掉。順序要緊 ——
  撤回之後重讀、讀出來是同一個字串的話它是算數的。斷電、逾時、手動停掉，都是再跑一次同一個指令。
- **一格讀到一半也能接。** 一則 40 個字的備註要讀十幾分鐘，超過單次的時間上限。`read()` 被打斷時交回讀到的地方，
  `Field` 存起來，下次用 `prefix=` 從那裡起步。沒有這個的話，長格子每次都從頭讀、每次都讀不完。

`Field` 的參數：

| 參數 | 意思 |
|---|---|
| `segs` | `{stem: [欄號]}` 或 stem → 清單的函式。這個欄位在每張圖的哪一欄 |
| `vocab` | 已知或猜得到的詞。錯的不會有事 |
| `alphabet`／`fallbacks` | 第一輪的字集、讀不下去時依序換的字集。由小到大 |
| `prefix` | 整欄共同的開頭。省掉前幾個字，也讓第一步不用試全部位置 |
| `obs_fn` | 這一欄的格子要自己切（去掉圖示、按鈕）時給。見 `recipes.md` |
| `maxlen` | 最多讀幾個字。`None`＝照那一格的寬度算（自由文字用） |
| `K` | 每一步留幾條前綴（預設 2） |

`run()` 的參數：`max_minutes`（這一輪最多畫幾分鐘）、`order`、`retry_failed`（讀不完的格子退兩個字再試）。

### 接上別則的結尾（不在腳本裡，值得手動試）

同一位客人的備註常常是同一句話改幾個字。讀到一半的格子，拿「已經讀到的前綴」接上「別則備註的後綴」當候選，
整格（長的用 `check()`）比一次，只畫幾百個字串。實戰裡有兩格是同一句話：第二格直接拿第一格讀到的前 29 個字去 `check()`，
一路上最大 0.93，就不用再逐字讀一次。

## 成本

一步＝（前綴條數）×（字集大小 × 粗篩 2 個位置 ＋ 細篩候選 × 幾十個位置）個磁磚；一格＝字數 × 那麼多，
加上走到死路退回去的那幾步。`reader.estimate(字數, 字集)` 給的是下限。實測（12 核筆電、兩個瀏覽器）：

| 讀什麼 | 字集 | 一格 |
|---|---|---|
| 8 位數編號（前 4 位已知） | 10 | 1～2 秒 |
| 4～6 個字的品項、房間 | 5,700 | 25～60 秒 |
| 4 個字，其中一個不在 Big5 | 21,000 | 100 秒 |
| 12～15 個字的句子 | 5,700 | 2～3 分鐘 |
| 30～39 個字的句子 | 5,700 | 8～12 分鐘（每個字 16～26 秒） |

**自由文字是另一個量級。** 表格裡的短欄位值會重複（讀十幾次收一整欄）；備註每一則都不一樣、又長。
實戰：18 則沒讀出的備註（3～70 個字）重讀，加上邊讀邊修讀取器，畫了兩個多小時；用現在的讀取器從頭跑，估計也要一個多小時。
開跑前把「幾則 × 每則多久」算給使用者看，並且給他替代方案：

- 只讀短的（`order='short'` 加一個短的時間上限）。
- 把已經讀出來的句子當詞彙套一次、把讀到一半的接上別則的結尾試一次 —— 都不用逐字讀。
- 請他回原畫面看那幾筆，或把那幾列用 100% 縮放重截 —— 幾十格的話這通常最快。

## 讀不出來時怎麼判斷

看 log 那一行：讀到幾個字、花了幾秒、整格多寬。再用 `verbose=True` 單獨讀那一格，看每一步留下的候選。

| 樣子 | 原因 | 怎麼辦 |
|---|---|---|
| 0 個字、幾秒 | 第一個字不在字集；或這一欄校出來的起始位置不對 | 換大的字集；用 `phs=None` 單獨讀那一格 |
| 某個字就是讀不下去、verbose 裡正確的字根本沒出現 | 粗篩沒抓到（位置） | 用 `phs=None` 從前一個字起步（`prefix=`）；看第 7 點 |
| 讀了幾個字、斷在不起眼的地方，重跑斷在別處 | 渲染有空白磁磚 | 看 `synth.stats()` 的 `repainted`；見 `pitfalls.md` |
| 停在一個標點或細字後面 | 那一步選錯了細字，退路也用完了 | `K=3` 再讀；或從那個字之前 `prefix=` 起步 |
| 讀到大約整格的寬度、結尾過不了 | 最後一個字後面貼著別的東西（圖示、被截掉的字） | 自己切那一格（`obs_fn`） |
| 整格誤差 1.2～1.5、區域誤差很大，但字看起來很合理 | 短字串：有一個字被頂替了。長字串：正常（見上一節），用 `check()` | `refine_suspects()` |

單獨除錯一格：

```python
from pxx import grid; from pxx.reader import read, check; from pxx.charset import TEXT_ALL
o = grid.obs_cell(stem, grid.ri_of(stem, 列), 欄)
r = read(o, phs=None, alphabet=TEXT_ALL, maxlen=8, verbose=True)       # 每一步留下的前綴都印出來
r = read(o, phs=None, prefix='已經確定的開頭', K=3, verbose=True)        # 從中間起步、多留幾條
print(check(o, '我猜的整句'))                                           # 已經知道或猜到答案：不要讀，直接對
```

`python scripts/peek.py <stem> <列> <欄> "猜的字串"` 是短字串版的同一件事（並排印出像素）。

## 參數（改之前先知道它為什麼是這個值）

| 參數 | 值 | 為什麼 |
|---|---|---|
| `K`（留幾條前綴） | 2 | 乾淨吻合裡最寬的一條＋勉強過關的一條。其餘靠退路。3 以上每一步多畫一半，只在卡住時用 |
| `M`（粗篩每類留幾個） | 16／8／8 | 寬字 16、中等與細字各 8。再多只是細篩多畫 |
| `tail`（尾段多寬） | 2.2 em | 兩個字寬多一點：新接上的字加上它前面那個字的右半 |
| `sure`（乾淨吻合） | 1.3 | 正確的字尾段誤差多半 0.5～1.0，少數到 1.4（那些落在第二層，還是留得住） |
| `pfx_ok`（尾段門檻） | 2.0 | 錯的字 5 以上；長得很像的字 1.5～3，留在第二層 |
