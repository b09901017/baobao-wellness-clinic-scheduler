# 各種欄位的做法

目錄：先分類 → 封閉候選 → 編號與電話 → 姓名 → 顏色 → 格子裡有別的東西 → 自由文字 → 被截掉的字 → 互相對 → 輸出格式

範例裡的名字、編號都是假的。

## 先把每一欄分類

照 `slice_grid.py` 的統計與表頭，每一欄歸到一類，**由便宜到貴**做：

| 類別 | 例子 | 做法 | 成本 |
|---|---|---|---|
| 顏色 | 狀態徽章、標籤 | `badges` | 不渲染 |
| 封閉候選 | 日期、時段、是／否、性別、已知的品項清單 | `closed_field()` 窮舉 | 幾秒～一分鐘一欄 |
| 小字集 | 編號、電話、車牌、金額 | `Field` ＋ `DIGITS`（或加幾個符號）＋ `prefix` | 一格一兩秒 |
| 開放、值會重複 | 品項、房間、經手人、取消原因 | `Field` ＋ `TEXT`，從空的詞彙開始也行 | 一種值 20～40 秒 |
| 開放、值很多 | 姓名 | `vocab` 先灌候選，剩下的 `Field` ＋ 大字集 | 一個名字 30～100 秒 |
| 自由文字 | 備註 | 最後做，先算成本、先問使用者 | 一則幾分鐘起跳 |

整欄只有一兩種樣子的（`slice_grid.py` 印「2 種樣子」）不管表面上是哪一類，都當封閉候選：猜一兩個詞丟進 `vocab` 就結束了。

## 封閉候選

`job_template.py` 的 `closed_field(field, cands, prefix=None, more=None)`。

**日期**：候選＝涵蓋範圍內的每一天，`prefix` 給年份（`'2026-'`）。整欄共同的開頭讓它不用先知道任何一格就能校起始位置。
格式要跟畫面上一模一樣（`2026-05-21`、`2026/5/21`、`05/21（四）` 是三種不同的像素）；不確定就用 `peek.py` 拿一格試。

**時段**：`'09:00 - 10:30'` 這種，候選是（開始 × 長度）的組合。先給十五分鐘一格的常見組合（幾百個），
沒吻合的才用五分鐘一格的完整組合（一萬個）去比那幾格。空白的數量也是像素：`09:00-10:30` 與 `09:00 - 10:30` 不一樣。

**是／否、性別這種單一個字的**：吻合時誤差會比長字串高（實測有一批落在 1.098、一格 1.22）。
單一個字的有墨像素少，一兩個灰階的差佔的比例就大。這種欄位看的是**另一個候選差多遠**（實測 44），不是絕對值。

結果一律印「最大誤差」與「第一名和第二名最小的差距」。差距小於 1 的格子單獨拿出來，兩個候選都列。

## 編號與電話

```python
OPEN['id']    = dict(vocab=[], alphabet=DIGITS, maxlen=10, prefix='0000')         # 八位數、前面補零
OPEN['phone'] = dict(vocab=[], alphabet=DIGITS + list('-#() +'), maxlen=14, obs_fn=phone_cell)
```

- `prefix` 是整欄共同的開頭。不確定是不是每一格都有（有的編號不補零）就不要給，貴一點而已。
- 數字讀完之後**跟別的欄互相對**（見下面）。數字沒有冗餘，讀錯一位長得跟讀對一樣；一個編號對到兩個名字是最有效的警報。
- 一樣的電話會出現很多次（同一位客戶來很多次），所以實際要讀的次數是「幾個人」不是「幾列」。
- 佔位用的假號碼（整串同一個數字、一二三四連號）在真實資料裡很常見，照實輸出，在報告裡提一句。

## 姓名

1. 有任何別的來源的名單（名冊、舊表的分頁名、行事曆標題裡切出來的二到四個字）就全部灌進 `vocab`。
   它們只是候選：吻合的省掉一次逐字讀取，不吻合的什麼都不會發生。
2. 剩下的逐字讀。字集的順序：`L1`（常用字）→ `L1 + L2` → 整個 CJK（`charset.CJK`）。
   名字裡的字不在 Big5 是會發生的；症狀是第一個字就放棄、只花幾秒。
3. **讀出來的名字跟名單上的差一個字時，不要修。** 逐像素確認兩個寫法各自吻合哪幾格，照實輸出，
   並在報告裡列「同一個編號出現兩種寫法」。那可能是原系統裡真的打錯字 —— 而那正是使用者要拿這份資料去比對的原因。
4. 讀到的名字不在任何名單上時，在報告裡單獨列一張表（誰、哪幾天、做什麼）。那是使用者最想知道的事之一。

## 用顏色分的欄位

```python
from pxx import badges
print(badges.colors(欄號))                       # 先看有幾群顏色、各幾格
out = badges.classify(欄號, {'完成': (90, 152, 245), '取消': (230, 115, 130)})
```

- 色票的值從 `colors()` 印出來的抄，不要用設計系統的標準色去猜 —— 量到的是「有顏色的像素的中位數」，
  混了白字的邊緣，跟純色差一截。猜的色票會讓一整類變成 `?`（這是設計好的：寧可問號，不要硬塞）。
- 每一種顏色對應的字，放大一格用看的確認，並在產出裡寫明這一欄是看顏色分的、不是逐像素讀字的。
- 徽章的**寬度**也是資訊（`badge()` 回傳）：同一種顏色、不同寬度，可能是兩種不同長度的標籤。

## 格子裡除了字還有別的東西

`slice_grid.py` 印出「高度特別高」「寬度有好幾種」的文字欄，多半是字旁邊貼著圖示或按鈕。用 `peek.py` 看字元畫確認，然後自己切（`pxx/cut.py`）：

```python
from pxx import cut
def name_cell(stem, ri, si):          # 字的前後有比字高的圖示／方塊
    return cut.strip_tall(stem, ri, si)[0]
def phone_cell(stem, ri, si):         # 字後面隔一點空白跟著小圖示：在第 28～37 欄像素之間的第一個空欄切開
    return cut.cut_after(stem, ri, si, 28, 37, fallback=32)   # 數字是那一批圖的（em 5.33、十位數約 30 像素寬），照實際量
Field('name', segs, obs_fn=name_cell, ...)
```

三個實戰裡踩到的細節：

- **字貼著後面的方塊、中間沒有空欄**：兩個連成一組，整組被當成圖示丟掉，那一格變成「沒有字」。
  `strip_tall` 在方塊的左邊框（整欄都有墨）切開。前面有圖示的格子，字的起始 x 跟沒有圖示的不一樣 ——
  **起始位置要分開校**（把有圖示與沒圖示的當成兩個欄位各跑一次 `Field`）。
- **切的時候不要把很淡的邊緣切掉**：分組用高一點的門檻（10）才不會把相鄰的東西黏在一起，
  但最後裁切要用跟合成一樣的門檻（4）、而且範圍往外放 1 個像素。
- **「在第一個空欄切開」遇到細的字會切錯**：一串 `1` 的每個 `1` 後面都有一欄空白，最後一個 `1` 被當成圖示切掉，
  而少一位數的字串在切短的小塊上照樣吻合（誤差 0.88）。比較穩的規則是「在第一段**兩欄以上**的空白切開」（字距是一欄、字與圖示之間是三欄）。
  驗證時不要猜：`cut.crops()` 把每一種切法都交給 `verify()`；有兩種切法各自吻合不同長度的字串時，**取長的**，並回頭看字元畫確認。

## 自由文字

先做便宜的三件事，再決定要不要逐字讀：

1. **把所有已經讀出來的值當詞彙套一次**（別的欄讀到的句子、同一欄已經讀出來的）。備註常常是複製貼上的。
2. **照寬度排**。短的（三四個字）跟一般欄位一樣便宜，先讀；讀出來的又可以反套。
3. **算剩下的要多久**（`reader.estimate`），連同替代方案（回原畫面查、重截那幾列）一起告訴使用者。

逐字讀的時候時間上限設短（一輪 5～10 分鐘），一輪一輪跑：讀出來的詞、讀到一半的格子都會接著做。
讀完跑 `refine_suspects()`（選錯的標點、長得像的字只有這一步看得出來），最後長句用 `check()` 驗。
讀不完的在輸出裡留三樣東西：大約幾個字（寬度 ÷ em）、已經讀到的開頭、哪張圖第幾列。
「開頭讀到『下次改到…』、約 12 個字」對使用者是有用的，他多半一看就知道是哪一則。

實戰裡備註最常出錯的是**標點**：全形逗號、頓號、間隔點、各種破折號在五個像素高的時候只差一兩個像素，
而且整格誤差完全看不出來。標點不影響意思，但影響「這份資料能不能逐字相信」—— 照實驗、照實改。

沒有表頭、兩欄備註分不出誰是誰的時候，照實寫「兩欄之一，截圖沒有表頭」，不要猜。

## 被截掉的字

兩種，都**不能**當成完整的格子去比：

- **被截圖的邊緣切掉的最後一欄**：最右邊那一欄的字只有一半。在 `COLMAP` 裡標成 `clipped`、跳過，並在 README 寫「這一欄沒有截到」。
- **被欄寬截掉、尾巴是「…」的長字串**：畫面上本來就沒有後半。字集裡有「…」，讀得出「前半…」，
  輸出時標明這是畫面上顯示的樣子，不是完整內容。

## 互相對：免費的檢查

各欄各自獨立讀出來之後，它們之間的關係不花任何渲染：

| 檢查 | 抓得到什麼 |
|---|---|
| 每張圖裡，日期＋開始時間是遞增的（清單本來就照時間排） | 日期或時段讀錯一格。注意：開始時間一樣的先後不保證 |
| 分鐘都落在 5 的倍數（或那個系統的最小單位） | 時段讀錯 |
| 結束時間晚於開始時間、長度是合理的 | 時段讀錯 |
| 一個編號只對到一個名字；一個名字只對到一個編號、一支電話 | 任何一邊讀錯一個字。也會抓到原始資料真的不一致 |
| 相鄰兩張截圖重疊的列，內容完全一樣 | 兩張圖的校正有一張是歪的 |
| 每一欄出現過的值列出來看一眼 | 「會議室2」與「會義室2」這種只出現一次的近似值 |
| 狀態是「已取消」的才有取消原因 | 欄位對應錯了一欄 |

**對不上的每一個都回頭逐像素確認**（`peek.py` 把兩個寫法都拿去比那一格），再分兩種：
讀錯的修掉；原圖真的那樣的留著，寫進報告的「值得注意的地方」。不要為了讓檢查通過去改資料。

## 輸出格式

```json
{
  "meta": {"說明": "…", "截圖": ["shot1.png", "…"], "筆數": 353,
           "獨立驗證": "5462 格重畫再比：5461 格 < 1.1、1 格在 1.1～1.6、0 格更大",
           "欄位": {"note": "備註（兩欄之一，截圖沒有表頭）", "status": "看徽章顏色分的"}},
  "rows": [
    {"id": "A001", "src": "shot1.png", "row": 1,
     "status": "完成", "date": "2026-05-21", "start": "09:00", "end": "10:00",
     "no": "00001234", "name": "王小明", "item": "課程A 60", "note": null,
     "noteUnread": {"約幾個字": 12, "開頭讀到": "下次改到"},
     "_verify": {"date": 0.74, "no": 0.81, "name": 0.69, "item": 0.77},
     "_issues": ["備註有字但沒讀出（約 12 個字）"]}
  ]
}
```

- `id` 是這份清單自己的編號（照時間排序後給），報告裡指到某一筆時用它。
- `src`＋`row` 讓任何人都能回到原圖的那一列。
- `_verify` 每一欄的誤差；`_issues` 這一筆所有不是「乾淨吻合」的事。兩個都是給下游用的：比對時遇到不一致，先看這裡。
- 空的格子是 `null`；「有字但沒讀出」是另一個欄位，不要混在一起。

Markdown 那一份至少有：總覽（幾筆、各狀態幾筆、驗證結果）、逐筆清單、每一欄出現過的值與次數、
值得注意的地方、沒讀出的格子（每一格附 `id`、日期、哪張圖第幾列）。
