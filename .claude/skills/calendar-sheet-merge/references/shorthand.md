# 她的速記語法

行事曆事件的標題就是 `docs/legacy/README.md` 第 4 節那套手寫白紙的速記，原封不動搬到
TimeTree 上。這份是解析用的對照表。**例子裡的客戶姓名一律匿名**（客戶A、治A），
真名只出現在 `.local/aliases.json`（不進版控）。

一則典型的標題把五件事擠在一起：

```
3.30客戶A EECP治5
└時間 └名字  └課程└診間

1.客戶B SIS治A
                └治療師

10.15客戶C IL .9      → 10:15  靜脈  點滴9
```

## 時間

**標題裡寫的時間才是準的**，行事曆自己的時間欄只當佐證。實測 317 筆裡有 4 筆兩者不一致，
最誇張的一筆標題寫 `3：45`、時間欄存成 `18:00`。理由也很直觀：標題是她打的字，
時間欄是她在畫面上點的那一格。

| 寫法 | 意思 |
|---|---|
| `3.30`、`3：30`、`3:30` | 15:30 |
| `2.` | 14:00 |
| `9.15`、`9：15` | 09:15 |
| `1~3.`、`11.～12.30` | 區間，取起點 |

**小於 8 一律是下午。** 院內作業時間是 8:00–20:00，`2.` 不可能是凌晨兩點。

**兩小時的區間是兩個時段。** `1~3.客戶A SIS治A` = 13:00–15:00，那是連著做的兩次復能——
試算表那天也會有兩個勾（見 `findings.md` 的「同一天兩欄」）。

事件的結束時間**不可信**：317 筆裡有 293 筆剛好 60 分鐘，那是 TimeTree 的預設值。
結束時間要用課程時長算。

## 課程與器材

| 簡寫 | 課程 | 器材 |
|---|---|---|
| `IL`、`ILIB`、`靜脈` | ILIB | — |
| `IN`、`INDIBA` | 復能 | INDIBA |
| `SIS`、`超磁` | 復能 | SIS |
| `高能`、`高60`、`雷射` | 復能 | 高能量雷射 |
| `復能`、`賦能` | 復能 | （沒寫器材） |
| `EECP` | EECP | — |
| `二返`、`2返` | 二返 | — |
| `健檢` | 健檢 | — |
| `<名字>13`、`13健檢` | 健檢 | 13健檢＝付 1 萬換 3 萬的健檢（她 2026-09-15），**不是 13 萬**。`13：30` 那種是時間 |
| `X光` | **不是時段** | 復健科門診的一部分（看門診前先照）。不拿它的時間補任何一段 |
| `復健科`、`復健門診` | 復健科醫師門診 | — |
| `心臟評估`、`心臟門診`、`心超`、`HRV`、`ABI` | 心臟科評估 | — |
| `點滴`、`雪顏`、`護肝`、`腸道` | 營養點滴 | 品項簡寫，主檔是全名（雪顏亮彩／護肝排毒／腸道修復） |
| `.5雪`、`.5肝`、`.8腸` | 營養點滴 | 點滴室後面接**一個字**的品項：雪＝雪顏亮彩、肝＝護肝排毒、腸＝腸道修復（2026-09-15）。「腸胃鏡」的腸不算 |
| `營養諮詢` | 營養師諮詢 | — |
| `物理諮詢` | 物理治療師諮詢 | — |
| `Inbody`、`體脂` | 身體組成分析 | — |
| `體適能` | 體適能檢查分析 | — |

一句話可以同時提到好幾件事（`8：50客戶A 13健檢+Line+2返X光`），所以比對時要把**全部**
命中的收下來，不能第一個贏 —— 第一個贏會把這一句判成「二返」，而她那天做的是健檢。

**療程名稱後面接的數字有兩種意思**，要靠位置分：`IL.9` 的 9 是診間，
`客戶A 13` 的 13 是健檢的金額等級（13萬健檢）。

## 診間

| 寫法 | 意思 |
|---|---|
| `治2`、`治3`、`治5`、`治7`、`治8` | 治療室 |
| `IL.9`、`IL .10`、`IL3` | **點滴室**（使用者確認過：IL 後面的數字是點滴室，不是治療室） |
| `IL治2` | 靜脈，在治療室2 |
| `腸道點滴.9`、`IL（點3` | **點滴室** |
| `.5雪`、`雪顏.2`、`.8（躺）` | **點滴 N**（她 2026-09-15，推翻了「裸數字不認」）。前面是數字的點是時間（`3.30`），大於 10 的是日期（`.20這週`）|
| `IL.10100元` | 點滴 10。數字最多讀兩位，後面那串是錢 |

**目前有的診間**（2026-08-19 使用者確認）：治2、治3、治5、治7、治8、
點滴3、點滴5、點滴6、點滴7、點滴9、點滴10。

種子資料裡還留著治9、治10、點滴2、點滴8、ILIB4 —— 她講的可能是「最近用到的」
而不是「全部的」，多一間只是選單長一點，少一間會排不進去。看到新的診間要問。

## 治療師

寫在器材或課程後面，有時包在括號裡：`SIS治A`、`復能（治A`、`高60（治A`。

**物理治療師**（會被指派到時段上，`config/staff` 裡有）：

| 主檔的正式名字 | 她在行事曆上寫 |
|---|---|
| 騰崴 | 騰威、藤威、騰 |
| 欣穎 | 新穎、欣潁 |
| LuLu | LU、LULU、**佳璐** |
| 珮喩 | 珮 |
| 芝寧、耕宇、姿璇、怡婷、王婷 | 一樣 |

輸出到合併檔的**一定是左邊那一欄** —— app 拿名字去對主檔，送右邊那欄過去會對不到。

`佳璐` 是 2026-09-15 冒出來的寫法，當時當成新的一位。**她 2026-09-16 確認了
「是同一個人」**（＝LuLu），所以它是別名不是第十位治療師 —— app 那一側一行都
不用改（匯入從來不建立 `staff`），要改的是她那份 `.local/references/aliases.json`
的 `therapistAliases`，然後**重跑一次產檔**。不改的代價：那 2 段來訪的治療師留空。

**醫師**：夏、許、李。只有一個字，出現在二返與健檢的句子裡（`二返*許`、`二返.李`）。
**刻意不放進 `config/staff`** —— 他們不會被指派到時段上。但要認得，
否則「沒寫名字的事件」那條規則會把那個字當成別的客戶而放棄整筆。

**不是人的字**：惠佳、Mia、賴（2026-09-15：提醒自己要加客人的 LINE）。看起來像名字但什麼都不是，放在對照表的 `noise` 裡。

括號裡也常常不是人（`（要生日`、`（療程單`、`（預約系統！`），所以對不到名單就別當人名。

## 名字

下面這幾列的規則跟名字的**字數與結構**有關，光寫「客戶A」看不出來，
所以用假名舉例。**王陳小明、王小明、王小名都是虛構的**，真名只在
`.local/aliases.json`。

| 情況 | 例 |
|---|---|
| 全名 | `客戶A` |
| 只寫名（去姓） | 王陳小明（複姓兩個字） → `小明`、`王陳` |
| 只寫姓 | `陳`、`黃` |
| 只寫中間一個字 | 王小明 → `小` |
| 暱稱 | 某位客戶在行事曆上寫成家屬稱謂／英文名 |
| 分頁名打錯 | 分頁叫「王小名」但 A2 是「王小明」—— **以 A2 為準**，分頁名是她打錯的 |
| 異體字 | 啟↔啓 |
| 錯字 | 惠↔慧 |
| 一張分頁兩個人 | 第二位可能只寫在**日期欄底下那一格**（家屬稱謂），行事曆上也用稱謂。新的一批檔案先掃一次那幾格 —— 沒補別名的話那幾筆會被「只寫一個姓」那條規則亂配 |

**只寫一個字的，只有在同一句裡也寫了療程、而且那天只有這位客戶勾了那個療程時才算數。**
放寬名字比對的風險由「療程也要對得上」那一關擋住。

### 2026-08-19 之後她改了寫法

那天起她約定：**同一位客戶固定寫同一種叫法** —— 一位寫英文暱稱、一位寫配偶的名字，
其餘一律寫本名。所以新的資料裡暱稱只會有那兩個，舊的資料仍然什麼寫法都有。
對照表兩邊都要留著，不要因為「以後不會這樣寫了」就把舊的拿掉。

## 不是來訪的東西

行事曆上大部分事件其實不是來訪：`公出`、`請假`、`休`、`高齡博覽會`（行事備註），
以及一大堆待辦（`H2U電話`、`蒐集客人復能時間`、`記復能行事曆`、`X通知`、`提醒X外檢`）。

**取消、預約、改、紀錄、約 的句子一律不是來訪**（2026-09-15）：`<名字>健檢EX取消`、`<名字>二返預約`、
`27改<名字>.20這週約復健`、`紀錄<名字>復能`。人名與療程都對得上，但講的是另一件事 —— 不進「行事曆有、舊表沒勾」。

**`壓` 是她「壓進某個系統」的動詞**，Abovee、Examine、Outlook 三件事都用它（`壓表`、`休假壓outlook`）—— 後面那一種還會跟休假詞黏在一起，那仍然是待辦不是休假。

**顏色分不出來** —— 實測 9 種顏色每一種底下都混著來訪與雜事，不要拿顏色當分類依據。
待辦類的特徵是**標題裡沒有寫時間**（時間欄有，但那是隨手丟的），這一點比顏色可靠。
