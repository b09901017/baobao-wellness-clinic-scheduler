# 她的速記語法

行事曆事件的標題就是 `docs/legacy/README.md` 第 4 節那套手寫白紙的速記，原封不動搬到
TimeTree 上。這份是解析用的對照表。**例子裡的客戶姓名一律匿名**（客戶A、治A），
真名只出現在 `.local/aliases.json`（不進版控）。

一則典型的標題把五件事擠在一起：

```
3.30客戶A EECP治5
└時間 └名字  └課程└診間

1.客戶B SIS治A
                └治療師

10.15客戶C IL .9      → 10:15  靜脈  點滴9
```

## 時間

**標題裡寫的時間才是準的**，行事曆自己的時間欄只當佐證。實測 317 筆裡有 4 筆兩者不一致，
最誇張的一筆標題寫 `3：45`、時間欄存成 `18:00`。理由也很直觀：標題是她打的字，
時間欄是她在畫面上點的那一格。

| 寫法 | 意思 |
|---|---|
| `3.30`、`3：30`、`3:30` | 15:30 |
| `2.` | 14:00 |
| `9.15`、`9：15` | 09:15 |
| `1~3.`、`11.～12.30` | 區間，取起點 |

**小於 8 一律是下午。** 院內作業時間是 8:00–20:00，`2.` 不可能是凌晨兩點。

**兩小時的區間是兩個時段。** `1~3.客戶A SIS治A` = 13:00–15:00，那是連著做的兩次復能——
試算表那天也會有兩個勾（見 `findings.md` 的「同一天兩欄」）。

事件的結束時間**不可信**：317 筆裡有 293 筆剛好 60 分鐘，那是 TimeTree 的預設值。
結束時間要用課程時長算。

## 課程與器材

| 簡寫 | 課程 | 器材 |
|---|---|---|
| `IL`、`ILIB`、`靜脈` | 靜脈 | — |
| `IN`、`INDIBA` | 復能 | INDIBA |
| `SIS`、`超磁` | 復能 | 超磁場 |
| `高能`、`高60`、`雷射` | 復能 | 高能量雷射 |
| `復能`、`賦能` | 復能 | （沒寫器材） |
| `EECP` | EECP | — |
| `二返`、`2返` | 二返 | — |
| `健檢` | 健檢 | — |
| `復健科`、`復健門診` | 復健科醫師門診 | — |
| `心臟評估`、`心臟門診`、`心超`、`HRV`、`ABI` | 心臟科評估 | — |
| `點滴`、`雪顏`、`護肝`、`腸道` | 營養點滴 | 品項簡寫，主檔是全名（雪顏亮彩／護肝排毒／腸道修復） |
| `營養諮詢` | 營養師諮詢 | — |
| `物理諮詢` | 物理治療師諮詢 | — |
| `Inbody`、`體脂` | 身體組成分析 | — |
| `體適能` | 體適能檢查分析 | — |

一句話可以同時提到好幾件事（`8：50客戶A 13健檢+Line+2返X光`），所以比對時要把**全部**
命中的收下來，不能第一個贏 —— 第一個贏會把這一句判成「二返」，而她那天做的是健檢。

**療程名稱後面接的數字有兩種意思**，要靠位置分：`IL.9` 的 9 是診間，
`客戶A 13` 的 13 是健檢的金額等級（13萬健檢）。

## 診間

| 寫法 | 意思 |
|---|---|
| `治2`、`治3`、`治5`、`治7`、`治8` | 治療室 |
| `IL.9`、`IL .10`、`IL3` | **點滴室**（使用者確認過：IL 後面的數字是點滴室，不是治療室） |
| `IL治2` | 靜脈，在治療室2 |

**目前有的診間**（2026-08-19 使用者確認）：治2、治3、治5、治7、治8、
點滴3、點滴5、點滴6、點滴7、點滴9、點滴10。

種子資料裡還留著治9、治10、點滴2、點滴8、ILIB4 —— 她講的可能是「最近用到的」
而不是「全部的」，多一間只是選單長一點，少一間會排不進去。看到新的診間要問。

## 治療師

寫在器材或課程後面，有時包在括號裡：`SIS治A`、`復能（治A`、`高60（治A`。

**物理治療師**（會被指派到時段上，`config/staff` 裡有）：

| 主檔的正式名字 | 她在行事曆上寫 |
|---|---|
| 騰崴 | 騰威 |
| 欣穎 | 新穎 |
| LuLu | LU |
| 芝寧、耕宇、姿璇、怡婷、珮喩、王婷 | 一樣 |

輸出到合併檔的**一定是左邊那一欄** —— app 拿名字去對主檔，送右邊那欄過去會對不到。

**醫師**：夏、許、李。只有一個字，出現在二返與健檢的句子裡（`二返*許`、`二返.李`）。
**刻意不放進 `config/staff`** —— 他們不會被指派到時段上。但要認得，
否則「沒寫名字的事件」那條規則會把那個字當成別的客戶而放棄整筆。

**不是人的字**：惠佳、Mia。看起來像名字但什麼都不是，放在對照表的 `noise` 裡。

括號裡也常常不是人（`（要生日`、`（療程單`、`（預約系統！`），所以對不到名單就別當人名。

## 名字

| 情況 | 例 |
|---|---|
| 全名 | `客戶A` |
| 只寫名（去姓） | 陳何淑子 → `淑子`、`陳何` |
| 只寫姓 | `陳`、`黃` |
| 只寫中間一個字 | 林際娟 → `際` |
| 暱稱 | 某位客戶在行事曆上寫成家屬稱謂／英文名 |
| 分頁名打錯 | 分頁叫「潘若蜜」但 A2 是「潘若寧」—— **以 A2 為準**，分頁名是她打錯的 |
| 異體字 | 啟↔啓 |
| 錯字 | 惠↔慧 |

**只寫一個字的，只有在同一句裡也寫了療程、而且那天只有這位客戶勾了那個療程時才算數。**
放寬名字比對的風險由「療程也要對得上」那一關擋住。

### 2026-08-19 之後她改了寫法

那天起她約定：**同一位客戶固定寫同一種叫法** —— 一位寫英文暱稱、一位寫配偶的名字，
其餘一律寫本名。所以新的資料裡暱稱只會有那兩個，舊的資料仍然什麼寫法都有。
對照表兩邊都要留著，不要因為「以後不會這樣寫了」就把舊的拿掉。

## 不是來訪的東西

行事曆上大部分事件其實不是來訪：`公出`、`請假`、`休`、`高齡博覽會`（個人行程），
以及一大堆待辦（`H2U電話`、`蒐集客人復能時間`、`記復能行事曆`、`X通知`）。

**顏色分不出來** —— 實測 9 種顏色每一種底下都混著來訪與雜事，不要拿顏色當分類依據。
待辦類的特徵是**標題裡沒有寫時間**（時間欄有，但那是隨手丟的），這一點比顏色可靠。
