# 月底對帳

## 這件事是什麼

她平常在 Abovee 壓表、在 app 拍 Abovee 記下來、app 自動推試算表。三邊照理不會對不上 —— 這支 skill 是**多一層保障**：
月底或下個月初，她把那個月的 Abovee 預約清單截圖放進資料夾，你讀截圖、讀 Firebase、用 app 自己的程式算試算表，
三邊對一次，給她一頁「全部對得上 ✓」或「這幾件要看」。

她最在意的是**有額度的來訪的次數**。治療師、診間、時間不一樣是小事（收在最後面）。

三邊各是什麼：

| | 來源 | 怎麼拿 |
|---|---|---|
| Abovee | 她給的截圖（預約清單，整個月） | 派 subagent 用看的抄，再**逐像素驗證每一格**（`pixel-exact-screenshot-extraction` 的 pxx） |
| app | 正式站 Firestore | `snapshot.mjs` 唯讀拍一份快照 |
| 試算表 | app 推過去的那一份的算法 | 拿同一份快照跑 `domain/sheetReport.js` 的 `syncBundle()`（她 2026-10-16 選的：直接讀 Firebase，不打開 Google 試算表） |

「哪一列對到 app 的哪一段、算不算對不上」**一律用 app 自己的函式**（拍 Abovee 用的 `readAbovee()`、`absentFromPhoto()`；
次數 `counts()`）。不要在這支 skill 裡另寫一套規則 —— 兩套遲早有一套落後，而月底對帳要檢查的正是 app。
唯一的差別寫成選項：`absentFromPhoto(…, { everyone: true })` —— 拍 Abovee 照片上只有一兩位時只對那幾位（ADR-0153），月底要對每一位。

## 四條鐵則

1. **Firebase 只讀不寫。** `snapshot.mjs` 把 firebase-admin 每一個會寫的入口都換成丟錯。發現 app 的資料要改，寫進報告讓她去 app 改，不要自己動。
2. **有真名的東西只放 `.local/references/月底對帳/`。** 截圖、抄本、快照、報告全都有客戶姓名。不發佈成 Artifact、不貼進 commit／PR；
   終端機與回報只講數字、日期、第幾張第幾列。新開一個資料夾先 `git check-ignore -v <路徑>`（`run.mjs` 也會檢查）。
3. **像素說了算。** 抄的字對不上就換成像素認出來的那一個（候選從整個月同一欄、app 的名字與病歷號來，但吻合與否只看像素）；
   讀不出來就標「讀不準」，不填一個最像的。報告裡講逐像素驗證了幾格。
4. **不要把她的機器跑滿。** 渲染一次最多兩個瀏覽器（pxx 的全機上限），整條流程一到兩分鐘；從零校正約兩分鐘。
   比這久很多就是哪裡錯了 —— 停下來看，不要丟到背景放著跑。

## 資料夾

```
.local/references/月底對帳/
  README.md            給她看的：怎麼放截圖、怎麼叫你
  校正/                字型、字級、色調（profile.json、lut.npy）。同樣縮放的截圖每個月沿用
  2026-10/
    截圖/              她放的 Abovee 截圖（檔名照時間排，例：01-05.png、05-06.png…）
    結果/              對帳結果-2026-10.html ← 她看這一個
    過程/              中間檔（抄字/、pxx/、快照、比對.json）—— 她不用打開
```

月份資料夾不存在就建（`截圖`、`結果`、`過程` 三格）。README 沒有的話 `run.mjs` 會放一份範本（`references/her-readme.md`）；已經有了不要重寫。

## 流程

```bash
M=2026-10
ROOT=.local/references/月底對帳
S=.claude/skills/month-end-reconciliation/scripts
```

### 1. 先看截圖

- 數幾張；用 Read 看第一張和最後一張：縮放大概多少（100% 左右字是 12px，抄得出來）、表頭有沒有拍到、
  最早那一列是哪一天、最後那一列是哪一天、**有沒有拍到分頁那一句（「共 N 筆」「第 16/16 頁」）**。
- **拍齊了沒**決定頭尾那兩天怎麼算（2026-10-16 冷測試抓到的：她說「截到 10/9」，最後一張停在 10/9 早上，那天下午的段截圖上本來就沒有）：
  - 拍到「共 N 筆」、跟抄出來的列數一樣 → 拍齊了，整個範圍都算。
  - 沒拍到 → 程式**只信第一列到最後一列之間**（跟 app 拍 Abovee 一樣），頭尾那兩天只截到一部分、不算次數，月曆上標「部分」。
    要整個月都算，問她一句「第一張是第一頁、最後一張是最後一頁嗎？」—— 是的話加 `--complete yes`。
    **最後一列的日期剛好是她說的訖日時特別要問**：那一天多半沒截完。
- 只截了一段（例：只到 20 號）、截圖上又沒拍到上方的「預約日期(起)／(訖)」→ 照她說的範圍跑（`--from`／`--to`）。
- 縮到很小（字只有四五個像素）就不要用看的抄 —— 改走 `pixel-exact-screenshot-extraction` 的完整流程，或請她用 100% 重截。

### 2. 抄字（派 subagent）

一個 subagent 抄 4 張左右，**同一個 turn 一起派出去**（背景跑）。你自己就是 subagent 的話不要背景派 ——
你一結束 turn 就得交報告；前景派，或張數少就自己抄。給每一個的 prompt 照這個樣子（路徑換成這個月的）：

```
你要把 4 張 Abovee 預約清單截圖抄成 TSV。做法、欄位、檔案格式全部寫在這份說明裡，先完整讀它再動手：
<repo>\.claude\skills\month-end-reconciliation\references\transcribe.md

- 截圖資料夾：<repo>\.local\references\月底對帳\<M>\截圖\
- 你負責的 4 張（照這個順序）：…
- 輸出（TSV）寫到：<repo>\.local\references\月底對帳\<M>\過程\抄字\
- 放大的圖寫到：<repo>\.local\references\月底對帳\<M>\過程\放大\
- 放大工具（工作目錄用 repo 根目錄）：node .claude/skills/month-end-reconciliation/scripts/zoom.mjs <截圖> <放大資料夾>
- 只寫進上面兩個資料夾；不要改 repo 裡任何其他檔案、不要 git 任何東西；檔案用 Write 寫（UTF-8、真的 Tab）。
- 回報一張一行（幾列、幾格打了 ??），不要寫任何姓名、病歷號或格子的內容。
```

大部分截圖沒有表頭，欄位照有表頭的那一張對 —— 說明裡寫了。抄錯沒關係，下一步每一格都會驗。

### 3. 跑完整條

```bash
node $S/run.mjs --month $M                     # 正式站；--project staging 對 staging
# 她說整個月都截了（截圖上沒拍到「共 N 筆」）：  … --complete yes
# 只截了一段：  node $S/run.mjs --month $M --from 2026-10-01 --to 2026-10-20
```

它依序做：快照（只讀）→ 合成抄本（`assemble.mjs`：兩張重疊的列去掉、日期順序、同一個病歷號只對一個名字）→
候選字（`vocab.mjs`）→ **逐像素驗證**（`pixel_verify.py verify`；校正不合這一批截圖會自己重新校正一次）→
套上逐像素的結果 → 比對（`reconcile.mjs`）→ 那一頁（`report.mjs`）→ 截兩張圖給你看（`look.mjs`）。
資料夾裡沒有她的 README 就放一份（`references/her-readme.md`）。
「今天」預設是今天；這一天以後的預約還沒發生，不算對不上（`--today` 可以改）。

看終端機的幾行：

- 合成那一行：`（拍齊了）` 還是 `（沒拍齊…）` —— 跟你第 1 步判斷的一樣嗎。
- `逐像素：N/N 格吻合` —— 沒有全部吻合就看它列出來的那幾列（見「卡住的時候」）。
- `要看的 N 件` 底下 `!` 開頭的那幾行要看；**`備註 N 件`不用一條一條看**（大多是「打了 ??」，驗證過的格子 ?? 會拿掉）。
- 比對那一行的 `fix`（要處理的件數）、`strangers`（app 裡沒有的人）、`totals`（三個數字）。

### 4. 自己看一眼那一頁，再交給她

`run.mjs` 最後截了桌機與手機兩張（`過程/看一眼/`），用 Read 看，確認結論那一句跟數字對得起來、沒有橫向捲動、沒有錯誤。
有一件「要處理的」看起來怪（例：只有一件、剛好在頭尾那一天），先自己追到底再交 —— 冷測試那一次的唯一一件就是沒截完造成的。然後回報：

- 一句結論（「10 月三邊都對得上」或「有 N 件要看，多半是 X」）
- 檔案路徑（完整的絕對路徑，她在檔案總管點兩下打開）
- 有事的話挑最要緊的兩三件，用白話講（不要貼名字以外的個資；名字在本機對話裡可以講）

**不要發佈成 Artifact**（有客戶姓名）。

## 報告上每一種是什麼

| 那一類 | 意思 | 多半是 |
|---|---|---|
| Abovee 做完了，app 還沒簽療程單 | Abovee 課程完成、app 還是待確認／已確認 | 她還沒簽，次數還沒扣 |
| Abovee 做完了，app 還簽不了 | 二返接的那一次健檢還沒做完（app 的閘門） | 先簽健檢那一段 |
| Abovee 做完了，app 沒有這一段 | app 那個時間沒有這一段 | 忘了拍 Abovee 記進 app |
| Abovee 做完了，app 把這一段取消了 | | app 取消錯了，或 Abovee 沒改 |
| 日子過了，Abovee 還沒結案，app 也沒有 | Abovee 待確認／確認前往、app 沒有 | 那天有來的話兩邊都要補 |
| app 扣了一次，Abovee 上找不到 | app 已完成、截圖上沒有 | Abovee 漏壓，或 app 記錯；**也可能是截圖少了一頁** |
| 日子過了，app 還排著，Abovee 上找不到 | app 待確認／已確認、截圖上沒有 | 同上 |
| Abovee 取消了，app 還排著 | | app 忘了取消（還佔著一次） |
| 兩邊的狀態不一樣 | 失約 vs 完成、取消 vs 完成 | 逐列講 |
| app 做完了，Abovee 還沒改成課程完成 | | Abovee 那邊沒改；**截圖比 app 的資料舊也會這樣**（例：月中截的） |
| 日子過了，兩邊都還沒結案 | 兩邊都是確認前往／已確認 | 那天有來的話兩邊都要結 |
| 同一個時間，課程不一樣 | 次數會扣到不同的額度 | 她可能刻意的（先暫記別的） |
| 課程認不出來 | Abovee 上那個寫法 app 的主檔沒有 | 設定 → 課程，把寫法加到「Abovee 上的寫法」 |
| 認不出是 app 裡的哪一位 | 名字跟病歷號在 app 裡對到不同人、或同名兩位 | app 的客戶資料要修 |
| app 畫面上的次數要重算 | 額度上存的次數跟重算的不一樣 | 資料健檢有一項會修 |
| 試算表算的跟 app 不一樣 | 照理不會（同一支 `counts()`） | **程式的問題**：查 `sheetReport.js` |
| Abovee 上有、app 裡沒有的人 | 認不出是 app 裡的哪一位，**不算進要處理的** | 體驗、別人的客人；或名字寫法不一樣（「可能是同一位」那一句） |
| 順便看看 | 治療師、診間、時間不一樣，還沒到的預約 | 不影響次數 |

「哪一位」那一塊：每一位每一項（一筆額度、或送的／體驗／n返）這個月做了幾次，Abovee 課程完成、app 已完成、試算表 ✓。
試算表那一格**只有額度才有**（送的／體驗／n返 在試算表上是另外幾列，這裡寫 —）。不在 Abovee 壓的課（健檢、HRV）Abovee 那一格寫「不壓」、不拿來比。
最上面那三個數字只加「有額度、壓在 Abovee」的那幾格，所以會比 Abovee 的「課程完成」少幾個（體驗、送的）—— 那是對的。

## 卡住的時候

| 看到什麼 | 多半是 | 怎麼辦 |
|---|---|---|
| `snapshot.mjs` 權限錯誤／沒有憑證 | 她的 ADC（`%APPDATA%\gcloud\application_default_credentials.json`）失效或不在這台 | **不要叫她重新 `gcloud auth …`**：這台的 gcloud 連網會被防毒擋（SSL 驗證失敗），Node 才讀得到。改請她在 Firebase 主控台 → 專案設定 → 服務帳戶產一把金鑰，存成 `.local/references/<名字>-sa.json`（`*-sa.json` 在哪一層都被 .gitignore 擋），再 `GOOGLE_APPLICATION_CREDENTIALS=<那個檔> node $S/run.mjs …`。那把金鑰寫得進去，所以「只讀」靠的是 `snapshot.mjs` 的守衛 |
| `切出 N 列，抄本是 M 列` | 截圖裡多了別的東西（分頁列、對話框），或抄本漏了一列 | 看那一張；抄本漏列就補抄 |
| 日期那一欄大部分對不上 → 重新校正後還是不行 | 字型換了、或縮放太小 | `pixel_verify.py calibrate --font "'Microsoft JhengHei'"` 試別的字型；縮放太小走 pixel-exact skill 的完整流程 |
| 某幾格 `沒有吻合` | 抄錯、而且候選裡沒有正確的字（多半是名字） | 用 `zoom.mjs` 放大那一列自己看，改抄本再跑；還不行用 pixel-exact skill 的 `reader` 逐字讀那幾格 |
| `課程與預約來源之間有 N 塊沒對到的字` | 合併扣課／實際扣課病歷號／關係那幾欄有字、抄本是空的 | 回那一張看、補抄 |
| 一大串「app 扣了一次，Abovee 上找不到」集中在月底或月初 | 截圖少了頭或尾那幾頁 | 問她；或照實際範圍給 `--from`／`--to` |
| 同一個病歷號有兩種名字（逐像素確認過） | Abovee 上真的那樣寫 | 不用修；報告不列 |

名字前面的小圖示（蛋糕）、後面的藍色按鈕、電話後面的圖示，`pixel_verify.py` 已經會切掉。
ClearType 的黑字每個邊緣像素都偏紅或偏藍，**判斷「這一塊是不是彩色的圖示」要看整塊的平均色**（黑字平均是灰的），不要看每個像素的色差。

## 程式

| 檔案 | 做什麼 |
|---|---|
| `scripts/run.mjs` | 抄完字之後的整條流程（下面每一支依序叫） |
| `scripts/zoom.mjs` | 把截圖切兩半放大兩倍，給抄字的人看 |
| `scripts/assemble.mjs` | 抄本 → `abovee.json`；免費的檢查；`--verify` 套上逐像素的結果（像素認出的字蓋掉抄的） |
| `scripts/snapshot.mjs` | Firestore 唯讀快照（正式站、staging、模擬器） |
| `scripts/vocab.mjs` | 逐像素驗證的候選字：app 的名字、病歷號（補滿 8 位）、主檔上 Abovee 的寫法 |
| `scripts/pixel_verify.py` | `calibrate`（字型、字級、色調）／`verify`（每一格重畫、在那一列裡找吻合的那一塊；徽章看顏色） |
| `scripts/reconcile.mjs` | 比對本體：組 app 要的資料、叫 `readAbovee()`／`absentFromPhoto()`／`counts()`／`syncBundle()`、分類、數次數 |
| `scripts/report.mjs` | 比對結果 → 那一頁（一個離線打得開的 HTML） |
| `scripts/look.mjs` | 那一頁截桌機與手機兩張、量橫向捲動與錯誤 |
| `references/transcribe.md` | 給抄字的 subagent 的說明 |
| `references/her-readme.md` | 她那個資料夾的 README 範本 |

`reconcile.mjs` 讀 app 的 domain（`public/js/domain/`）。那幾支改了回傳的形狀，`tests/month-end-reconciliation.test.js` 會紅 ——
那支測試用假資料把比對整支跑一次（乾淨的一個月 0 件、四種最常見的不一樣各分對類）。

## 這支 skill 是怎麼驗過的（2026-10-16）

拿她 10/13 截的 10 月 16 張（100% 縮放、151 列）：四個 subagent 分頭抄，跟 10/13 另一份獨立的讀法 1,510 格只差 1 格（一個看不清楚的名字）；
逐像素 1,273 格全部吻合（誤差最大 0.86，門檻 1.1），那一格名字由像素從候選裡認出來。故意改壞六格（時間、課程、病歷號、名字、
漏抄合併扣課、狀態）全部被抓到。比對對著模擬器裡匯入的 10/14 合併檔跑：10/1–10/12 三邊 27＝27＝27、0 件；
整個月的差異全部是真的（截圖比合併檔早三天、她刻意暫記的一段、不在名單上的人）。
最後請一個沒看過這段對話的 subagent 只照這份說明書對 10/1–10/9 那 4 張（9.5 分鐘，`run.mjs` 本身 36 秒）：做得出來，
抓到的說明書問題（最後一天沒截完的假警報、範例列少一欄、?? 驗證後沒拿掉、少寫的幾種類別）都已經修進這一版。
