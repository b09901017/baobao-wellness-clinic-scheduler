# baobao-wellness-clinic-scheduler

> 健康管理師個人排課系統：客戶次數追蹤、壓表排程、系統掛號待辦。
> 手機／iPad PWA + Firebase，取代白紙與 Google 試算表。

---

## 這是什麼

一位健康管理師每天要幫二十幾位客戶安排療程課程。她的流程是：LINE 問時間 → 寫在白紙上 → 坐到公司電腦前壓表 → 再問客戶可不可以 → 記進 TimeTree 和 Google 試算表 → 客戶來之前還要到另外幾個系統掛號。

中間所有的「誰回覆了沒」「這個人還剩幾次」「他哪天不能來」「哪個系統還沒登記」，全部記在腦袋裡。

**這個 app 就是那顆腦袋的外接硬碟。**

## 為什麼沒有桌機版

因為公司的電腦連不了外網 —— 這個 app 在那台電腦上打不開。

實際的使用姿勢是：**一手拿自己的裝置看 app，一手在公司電腦上操作公司的預約系統**。載具只有 Android 手機和 iPad，各約一半。

這決定了整個 UI：全觸控、無 hover、無拖拉；把判斷所需的資訊一次攤開，她自己決定後在公司系統上輸入，回來只要快速記錄。

手機負責走動時的待辦勾選和臨時查詢，iPad 負責坐下來的壓表作業和資料整理。但**不做兩套 app、也不做只有某台裝置能用的功能** —— 同一組元件三段斷點，iPad 只是看得更多。壓表進度存在雲端，壓到一半換裝置接著做。

## 為什麼不用現成的預約系統

因為問題不在「預約」，在**排班前的決策**和**排班後的收尾**：

- 公司的預約系統只管時段有沒有被佔走，不知道這位客戶的復能還剩幾次、他這個月哪幾天出國、他體內有金屬所以不能用超磁場。
- 試算表可以記次數，但記不住狀態 —— 壓了表但客戶還沒回覆的那段空窗，是最容易掉東西的地方。
- 一次壓十幾個人，每個人後續要做的系統登記都不一樣，來不及一一記錄。

這不是預約系統，是**決策支援 + 待辦收尾**工具。壓表本身仍然在公司系統上做。

## 核心功能

**壓表模式**
一批是一個月的一串客戶，不是一個課程 —— 她面對的是公司系統上的一張時段表，看到空的就搶，而且習慣把一個客人的所有課程壓完再換下一個人。卡片上最大的一塊是「不能的時間」（只有解析出來的條件，原文收在一摺裡），旁邊是各課程剩餘次數、這個月與上個月來幾次、特殊備註。可用性照**壓的那個月**挑，那個月沒問過就寫「還沒問 9 月的時間」。記錄用小日曆挑日子（他說不行的紅色劃掉、你休假的霧藍、已經過去的變淡），課程、時段、器材、治療師、診間全部用點的，而且**選一個東西不會重畫整頁**。

系統依「可用天數最少 › 喜好 › 急迫度」排序，並把理由攤成人話標籤，但那只是預設順序，她隨時可以跳著處理，也可以整個換一種排法（喜好、剩最多次、最久沒來、問到時間的先）或直接搜尋姓名。**不出建議時段** —— 判斷是她的，app 只負責把資訊攤開與記錄結果。

**來訪編輯器**
排班的單位是「某人某天來一次」，一次含 2–3 個連續時段。**沒有任何一種硬性阻擋** —— 體內金屬這種警示會在你選到那一台的時候跳一句提醒並建議改用別台，但擋不住你（[ADR-0074](./docs/adr/0074-a-contraindication-warns-it-does-not-block.md)）。診間與治療師衝突也只提示，因為 app 看不到同事在 Abovee 上壓了什麼。

**復能與 ILIB**
復能是**一組器材共用一份次數**。加購時「復能」與「ILIB」永遠並排，點復能之後是五顆丸子（三選一／四選一／高能量雷射／SIS／INDIBA）再選 30 或 60 分鐘，名字自己組出來：`復能 - 三選一（60）`、`復能 - SIS（60）`。四選一那一筆跨兩個課程 —— 前三台要物理治療師、ILIB 要診間 —— 所以**那一段算哪一個課程由選到的器材決定**（[ADR-0075](./docs/adr/0075-the-equipment-decides-the-slots-course.md)）。畫面上寫的是那天真的做了什麼而不是當初買的那一筆，而且**三種寫法有三種讀者**：月檢視 `SIS`、日曆點開 `復能(SIS)`、**貼給客戶的 LINE 草稿只寫 `復能`**（[ADR-0077](./docs/adr/0077-the-line-draft-never-names-the-machine.md)）。

**待辦中心**
首頁只放分類與數字，完整內容點進去看。每筆來訪自動產生對應的系統任務，依死線排序，逾期變紅。客戶改時間時自動產生「回去取消舊登記」的任務。

壓表記完之後會長出「跟客人確認時間」：按打勾跳出確認畫面，把這個人所有時段攤開，客人說哪幾段不行就逐筆退回，其餘照樣成立並排進日曆。另外有**隨手記**收客人的零碎小要求，可勾掉、可掛在某位客戶身上。

**時段反查**
臨時空出一格時，輸入時段，系統推薦誰可以補。

**次數三段式**
不再只有「已排」一個數字，而是 `已完成 / 已排未上 / 剩餘`，並在來訪真正發生後才扣。

**二返**
健檢做完之後要再約一次回院聽報告。買幾次健檢就有幾次二返，所以它有自己的額度，
跟著健檢的額度成對建出來。中間還有一站：**報告通常兩三週才出來**，所以健檢結案
先長「追蹤健檢報告」（死線健檢日 + 21 天），那一張勾掉了才長「約二返」
（死線是**拿到報告那天** + 7 天）—— 兩個間隔都可以在設定頁調。約掉了就自己收起來。
**系統不會自動幫她約，也不會自動去問報告** —— 那兩件事都是她跟人談出來的。

**日曆**
日／週／月三種檢視，**可以直接編輯**，取代 TimeTree。上面有**四類，來自三個集合**：**客戶來訪**（綁客戶、產生任務、扣次數）、**待辦**（有日期的隨手記本人，不是另一份資料）、**行事備註**（公出、演講，不綁客戶，可以跨天）與**休假**。月檢視把跨天的東西畫成橫跨格子的色條；待辦不搶色相，走方框勾勾記號，勾掉了畫刪除線。

只顯示她自己排的來訪 —— 同事在 Abovee 上壓的看不到，所以空的格子不等於那個時段真的空著。

**舊資料匯入**
`.claude/skills/calendar-sheet-merge` 這支 skill 把舊試算表與 TimeTree 行事曆對照過，
補上時間、診間、治療師與器材，並且把兩邊對不起來的地方全部列出來 ——
行事曆記了卻忘記回試算表打勾是最常見的一種，而它在試算表上看不出來。
行事曆上對不到客戶的那些（休假、待辦、行事備註）也分好類，每一列可以自己改。
產出的 JSON 貼進「設定 → 舊資料匯入」就寫得進去。

只有這一條路。「把試算表文字直接貼進來」那條 2026-08-23 拿掉了 ——
它讀得到的是這條路的子集，留著只是多一個匯得比較少的入口（ADR-0047）。

**LINE 訊息**
問這輪的時間、問壓好的時間可不可以、來訪前提醒、臨時空一格的邀約，四種草稿一鍵複製。打錯一個日期就是白跑一趟。

## 資料是不能弄丟的

這是內部工具，但處理的是客戶的療程次數和健康資訊，錯一筆就是實際損失。所以：

- **永不硬刪除** —— Security Rules 直接禁止 delete，刪除只是標記
- **全量稽核紀錄** —— 每次寫入都留 before/after，可回溯
- **關鍵操作可復原** —— 手機單手操作最容易誤觸
- **資料健檢頁** —— 定期對帳次數、找孤兒資料、抓狀態異常，發現問題顯示差異而不自動偷改
- **雙層驗證** —— 前端擋一次，Firestore Rules 再擋一次
- **試算表唯讀** —— 它現在是報表不是資料來源。app 產生後貼回去，或讓 app 自動推過去；在試算表上改的東西會被當場還原，不做雙向同步
- **備份還原得回去** —— 匯出的 JSON 有一支讀得回它的腳本（`scripts/restore-backup.mjs`），
  而且**每個月在 staging 上真的演練一次**。沒有還原過的備份不是備份，只是一個 JSON 檔
- **離線不假裝** —— Firestore 的寫入 Promise 在離線時既不成功也不失敗，
  所以畫面自己有一道逾時：8 秒還沒送出去就換一句話講清楚「資料在這台裝置上，
  連上網路會自動補送」。**不會說成失敗** —— 說失敗她會再存一次，那才真的變成兩筆

## 開始開發

沒有 build 步驟，**app 自己也沒有任何相依套件** —— `package.json` 裡那幾個
全部是測試才用得到的（Playwright、Firebase 模擬器）。瀏覽器載的還是原始檔。

```
npm install                 # 只裝測試與維運腳本要用的東西
npm test                    # domain 純函式測試與分層守衛，不用模擬器
npm run test:rules          # Security Rules，會自己起一個模擬器再關掉
npm run emulators           # 本機跑 Auth + Firestore + Hosting
npm run verify              # 日常就用這個：單元測試 ＋ 這次改動相關的 E2E
npm run test:e2e:related    # 只跑相關的那幾支
npm run test:e2e:smoke      # 只跑 00-smoke（地基通不通）
npm run test:e2e            # 全部，無頭。**要先把 emulators 那行跑起來**
npm run test:e2e:watch      # 全部，看得到瀏覽器（慢一倍）
```

E2E **全跑一次 20 分鐘（無頭）／25 分鐘（headed）**，所以日常不要全跑：
`--related` 會拿 git 的差異去查 `tests-e2e/related.js`，只挑摸得到那幾個檔案的
spec（外加永遠會跑的 `00-smoke`）。認不出來的檔案一律退回全跑，
所以**漏列的代價是多跑幾支，不是安靜地少跑一支**。全量交給 CI 與上線前。

本機一律連模擬器，專案 id 是 `demo-scheduler`（`demo-` 開頭讓 Firebase 進入
完全離線模式）。**要 staging 或正式環境的操作看
[`docs/STAGING.md`](./docs/STAGING.md)** —— 環境是照網址挑的，
一份原始碼跑兩個環境，沒有 build 步驟也沒有環境變數。

端對端那一套在 `tests-e2e/`：真的模擬器、真的登入、真的點擊，一支一支走完
她會走的動線。跑出來的東西（報告、截圖、錄影、trace）全部落在 `.artifacts/`，
不進版控 —— 那是那一次的證據，不是原始碼。

### 架構圖（graphify）

`graphify-out/` 是一張可以查詢的程式碼知識圖，**不進版控**（build artifact）。
這台機器裝了 graphify 的 git hook：

```
graphify hook install       # 裝好之後每次 commit 就在背景重建一次
graphify hook status        # 看裝了沒
```

它只讀程式碼（AST），**不呼叫 LLM、不花錢**；文件與圖片的改動它不管，
那要手動跑 `/graphify --update`。hook 裝在 `.git/hooks/` 裡，
所以**換一台機器要自己再跑一次** —— git 不會帶著它走。

第一次要做三件事，都在 Firebase Console：

1. 建專案，把前端 config 填進 `public/js/firebase-config.js`（那串不是密鑰，可以 commit）
2. `.firebaserc` 填專案 ID
3. 開 Google 登入，然後在 Firestore 手動新增一份空文件 `allowedUsers/{你的 uid}` —— 沒有這步，登入了也讀不到任何資料

自動部署需要一個 repository secret：`FIREBASE_SERVICE_ACCOUNT`（服務帳號 JSON 全文）。push 到 main 就會跑測試並上線。

那個服務帳號還需要在 Google Cloud IAM 加上 **Firebase Rules Admin** 與 **Cloud Datastore Index Admin** 兩個角色，否則 Rules 與索引會部署失敗（預設角色只夠讀寫資料）。

第 16 步（2026-09-03）是她把自己手寫的流程筆記整份貼過來之後的三件事。
那份筆記底下她問的是同一個問題 —— **「哪些該變成待辦、哪些我自己記得就好」**
—— 所以這一輪先寫下判準（`.scratch/asks-2026-09-03/spec.md`）：

> 忘了會有一個人白跑一趟、或一筆錢收不回來 → **待辦**
> 忘了只是那一次做得比較慢、比較不順 → **備忘錄**
> 忘了會讓她在客人身上做錯一件事 → **標記**

三件事各自對到一種：

- **壓表的時候看不到「血管難打」。** 永久限制底下開第二層：醫療禁忌會擋、
  **臨床提醒不擋但要一眼看得到**、其餘不畫在卡片牆上。名單是她自己維護的
  一份主檔，所以「第一針」「怕痛」不用改程式
  （[ADR-0064](./docs/adr/0064-a-clinical-alert-is-a-permanent-limit-that-blocks-nothing.md)）。
  2026-09-06 那一層併掉了：既然一台都不擋，「會不會擋」這條界線就不存在了
  （[ADR-0074](./docs/adr/0074-a-contraindication-warns-it-does-not-block.md)）。
- **報告到手的那一刻有兩件事要做**，不是一件：寄給醫師與約二返。
  兩張的死線一樣，但**寄報告走在「還欠幾次二返」那道閘門外面** ——
  擠進去的話，她一約好二返，還沒寄出去的那一張會被靜默收掉
  （[ADR-0065](./docs/adr/0065-two-things-happen-when-the-report-arrives.md)）。
- **客人走了之後要寫的那一份**：任務因此有了第二個時機。掛號那一族在客人
  確認之後長，紀錄那一族在那一場**做完**之後才長，死線是來訪那一天
  （[ADR-0066](./docs/adr/0066-a-record-is-a-task-that-is-born-after-the-visit.md)）。
- **備忘錄 / SOP**：她自己整理的流程與心得，綁課程不綁人、不上日曆、
  **勾不掉**。掛了課程的那一份會在她真的在做那件事的時候自己浮出前幾行 ——

  而且問不到就不講、不編一個
- **「今天做了什麼」多一種照人分組**（預設），照流程那一種留著 ——
  兩種回答的是兩個問題：「這個人今天處理完了沒」與「哪一類整個漏了」
  （[ADR-0062](./docs/adr/0062-today-is-a-plain-language-view-of-the-audit-log.md)
  補了一段）
- **一列任務只寫得出 `Examine`**。來訪日與課程名不在任務身上（也不該在，
  那會是第二份會對不起來的資料），而兩個畫面手上本來就有那筆來訪。
  日期取**來訪那一天**不是死線，判斷收進 `taskLine()` 給三個地方共用
- **丸子貼著輸入框**。四個入口確實共用 `components/note.js`，但**包住它們的
  那一層沒有共用** —— 兩個入口包了 `.notemeta`，另外兩個裸放
- **試算表推送被拒絕**：程式沒壞，是試算表那一側的指令碼還沒重貼。
  但順手修掉一個實測抓到的不一致（交付日期在兩條路上印得不一樣），
  並把營養品那一區從零覆蓋補到七條測試

第 21 步（2026-09-06）是她指名的四件事，收在
`.scratch/rehab-items-plan-tuning-and-partners/`。**四件的共同點是「她講的話跟
資料的形狀對不起來」** —— 她講「四選一」，資料裡是一個沒有名字的器材陣列；
她講「這一套方案少五次」，資料裡只有一份不能動的範本。

- **復能不是一個課程，是一組買法**：三選一／四選一／單買一台 × 30／60 分鐘。
  名字自己組出來（`復能四選一(60)`、`超磁場(30)`），加購那一張表因此長出
  兩排會跟著展開的丸子。ILIB 從「靜脈」正名，而且它自己也是一種買法
- **四選一那一筆跨兩個課程**：前三台要物理治療師、ILIB 要診間。
  不在池上加 `courseId`（那正是 ADR-0005 拒絕過的「池說是 A、器材清單說是 B」），
  改成**器材自己帶課程**
  （[ADR-0075](./docs/adr/0075-the-equipment-decides-the-slots-course.md)）
- **醫療禁忌不再擋**。她說「只要儀器不要在金屬的上方或附近」就做得了 ——
  硬擋擋掉的是一件真的做得到的事，而 app 看不到儀器擺在哪裡。
  永久限制因此從三層併成兩層，**這個 app 從此一條業務規則都不擋**
  （[ADR-0074](./docs/adr/0074-a-contraindication-warns-it-does-not-block.md)）。
  警示的顏色與實心／空心由她自己在主檔上挑
- **加購一整個方案可以微調**：逐項改次數、改成 0 就是不建立、再加幾項。
  **範本一個字都不會變** —— 微調只影響這一位客戶這一次。三個加購入口
  共用同一份表單與同一份接線（`ui/components/planTweak.js`）
- **「買過什麼」**：一次購買的那幾筆收在一起，看得出哪幾項被微調過。
  這一頁只有一件事改得動 —— **購買日期**，因為她記錄的日期跟客人真的買的
  那一天常常不同。改的是整組，有到期日的跟著位移一樣的天數
- **同一個東西三種寫法，三種讀者**：月檢視 `SIS`（她）、一般 `復能(SIS)`（她）、
  **LINE 草稿只有課程**（客戶）。組法只在 `domain/naming.js`，
  設定多一頁「名稱怎麼寫」把它畫出來。寫的是**那天真的做了什麼**而不是
  當初買的那一筆；是同一件事的時候不加括號，所以 ILIB 不會變成 `ILIB(ILIB)`
  或 `ILIB(IL)`（[ADR-0077](./docs/adr/0077-the-line-draft-never-names-the-machine.md)）
- **合作機構（自然美）**是標籤不是課程：跟著名字走、**一張待辦都不生**，
  備忘錄可以掛在上面
  （[ADR-0076](./docs/adr/0076-a-memo-can-hang-on-a-partner.md)）
- 試算表 `SYNC_FORMAT` 升到 4：四選一那一列照扣，**當天那一列底下多一行**
  寫真的用了哪一台。**她要回 Google 試算表重新貼一次並重新部署**
- staging 的假資料整份重種：假名一律「客戶A、客戶B……」，
  退休的 `Abovee`／打電話與「記得帶健保卡」全部清掉，
  而那句「星期三下午不行」以前寫成一個 `blocks()` 認不得的 `kind`
  —— **一天都沒有真的擋掉，而畫面上完全看不出來**

## 隱私

資料含客戶健康資訊。

**Repo 私有不等於網站私有** —— 部署出去的站是公開網址，前端程式碼人人可看。真正的防線是 Firebase Auth + Firestore Security Rules，判準只有一條：沒登入的人查不到任何一筆資料。

- Firebase 前端 config 可以 commit，那不是密鑰
- **Service account 金鑰、任何含真實客戶資料的匯出檔或截圖，絕對不能 commit** —— 進了 git 歷史就拿不掉了
- Rules 絕不使用測試模式的全開規則，並用 Emulator Suite 寫測試驗證

細節見 [`SPEC.md`](./SPEC.md) 技術棧章節。
