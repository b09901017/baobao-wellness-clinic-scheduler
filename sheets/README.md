# 試算表這一側

`readonly-report.gs` 是貼進 Google 試算表的 Apps Script。它是**收件口 + 排版工**，
不是資料來源，也不算任何數字。

## 資料怎麼過來

```
app ──寫入成功──> Firestore
  └──安靜 10 秒後──> POST 整包報表 ──> readonly-report.gs ──> 試算表
```

方向只有一個。試算表上改的東西不會回到 app，而且下一次同步就會被蓋掉 ——
`onEdit` 會當場還原並跳一句話說明。

Apps Script 這一側**沒有任何 Google 或 Firebase 憑證**，它拿不到資料庫，
只能等別人送上門。為什麼是這個方向見
`../docs/adr/0013-sheet-sync-is-a-push-not-a-pull.md`。

## 安裝

安裝步驟寫在 `readonly-report.gs` 的檔頭，跟著做一次就好。要點：

1. 指令碼屬性加一組 `SYNC_TOKEN`，自己想一串長亂碼。
2. 部署成網頁應用程式，執行身分「我」、存取權「所有人」。
   —— 必須是「所有人」，因為 app 從瀏覽器直接送過來，帶不了你的 Google 登入。
   **擋住不速之客的是那組密鑰**，不是這個選項。
3. 網址與密鑰填進 app 的「設定 → 試算表報表」。密鑰存在 Firestore 的
   `config/app`，被 Security Rules 的白名單守著 —— **不要寫進前端程式碼**，
   部署出去的 JS 是人人看得到的。
4. 舊的 `onEdit` 指令碼（`../docs/legacy/apps-script.gs`）整份刪掉。

## 排版是這裡做的，數字不是

三段式次數在 app 的 `domain/sheetReport.js` 算完才送過來，那裡有測試。
這支只決定「哪幾格要合併、多寬、什麼顏色、鎖不鎖」。

同一個算法擺兩份實作遲早會對不起來，而對不起來的那天沒有人會發現。

## 版面

每位客戶一張分頁，骨架跟舊表一樣（療程項目 × 日期的矩陣），兩處不同：

- 次數從「應有／實際」變成 **應有／已完成／已排未上／剩餘**。
  舊表的兩欄講不出「已排未上」，而那正是最容易掉東西的一段。
- 舊表 TODO 區塊的位置改成**備註區**：永久限制、備註，以及每一次來訪的
  時間、器材、品項、診間、治療師 —— 舊表從來記不住的那些。

再加一張「總表」，每位客戶一列，剩餘為 0 的整列標紅。
