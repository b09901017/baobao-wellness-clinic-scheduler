# 試算表這一側

兩支 Apps Script，用途完全不同：

| 檔案 | 貼進哪一份試算表 | 什麼時候用 |
|---|---|---|
| `readonly-report.gs` | **新的**唯讀報表 | 長期。收 app 推過來的資料並排版上鎖 |

`readonly-report.gs` 有測試（`tests/sheet-script.test.js` 用替身把 Apps Script 的 API
做出來，讓那 400 多行真的跑一遍）。抓得到邏輯錯與 API 用錯，抓不到 Google 那一側的
行為差異 —— 第一次部署如果炸了，是預期內的。

---

## `readonly-report.gs`

它是**收件口 + 排版工**，不是資料來源，也不算任何數字。

## 資料怎麼過來

```
app ──寫入成功──> Firestore
  └──安靜 10 秒後──> POST 整包報表 ──> readonly-report.gs ──> 試算表
```

方向只有一個。試算表上改的東西不會回到 app，而且下一次同步就會被蓋掉 ——
`onEdit` 會當場還原並跳一句話說明。

Apps Script 這一側**沒有任何 Google 或 Firebase 憑證**，它拿不到資料庫，
只能等別人送上門。為什麼是這個方向見
`../docs/adr/0013-sheet-sync-is-a-push-not-a-pull.md`。

## 安裝

安裝步驟寫在 `readonly-report.gs` 的檔頭，跟著做一次就好。要點：

1. 指令碼屬性加一組 `SYNC_TOKEN`，自己想一串長亂碼。
2. 部署成網頁應用程式，執行身分「我」、存取權「所有人」。
   —— 必須是「所有人」，因為 app 從瀏覽器直接送過來，帶不了你的 Google 登入。
   **擋住不速之客的是那組密鑰**，不是這個選項。
3. 網址與密鑰填進 app 的「設定 → 試算表報表」。密鑰存在 Firestore 的
   `config/app`，被 Security Rules 的白名單守著 —— **不要寫進前端程式碼**，
   部署出去的 JS 是人人看得到的。
4. 舊的 `onEdit` 指令碼（`../docs/legacy/apps-script.gs`）整份刪掉。

**指到一份專門開給 app 的試算表**，不要指到舊的那一份。分頁是用客戶名字命名的，
撞名時 `resetSheet()` 會認第一列那句提醒 —— 認不出來就跳過那一位並在回傳的
`skipped` 裡講出來，一個字都不會動到。所以指錯不會吃掉資料，但那幾位也不會更新。

## 排版是這裡做的，數字不是

三段式次數在 app 的 `domain/sheetReport.js` 算完才送過來，那裡有測試。
這支只決定「哪幾格要合併、多寬、什麼顏色、鎖不鎖」。

同一個算法擺兩份實作遲早會對不起來，而對不起來的那天沒有人會發現。

## 版面

**一位客戶一張分頁，沒有總表** —— 她要的是「和我原本那個一樣」，而舊表從來沒有總表
（2026-08-20；見 `docs/adr/0024-the-sheet-mirrors-her-old-one.md`）。

骨架跟舊表一樣（療程項目 × 日期的矩陣），四處不同：

- 次數從「應有／實際」變成 **應有／已完成／已排未上／剩餘**。
  舊表的兩欄講不出「已排未上」，而那正是最容易掉東西的一段。
- 日期欄不是一個勾，是**四種符號**：`○` 待確認、`△` 已確認、`✓` 已完成、`✗` 未到。
  同一天用兩次帶數量（`✓2`），兩次狀態不一樣就兩個都印（`✓✗`）。
  符號在 `domain/visits.js` 的 `MARKS`，圖例從那裡產生，這裡不重寫。
- **TODO 與 FINISHED 兩塊由 app 填**，位置照舊表（TODO 在 A 欄、FINISHED 在 K 欄）。
  沒有核取方塊 —— 舊表要她手動勾，結果 FINISH 永遠是空的。
- **備註區**放回她手寫的那一段（永久限制、備註），底下接每一次來訪的
  時間、器材、品項、診間、治療師 —— 舊表從來記不住的那些。

二返約在哪天，寫在**那次健檢被勾起來的那一欄**底下，就是她原本記的位置。
